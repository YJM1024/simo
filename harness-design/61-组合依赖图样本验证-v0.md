# 组合依赖图样本验证 v0

本文用三个构造样本给 R21 的组合依赖图无环判据做手工验算，目的是回答这条判据能不能真的拦住环，材料只取 34 v1.6、57、31 v1.4、33 v1.5 与 53 的相关段落，不修改任何既有文件。三个样本的结论是：三角无环通过，二元环不通过，跨两个组合条目的环不通过，判据在单版本、成员全为已登记类型、声明一致的窄条件下可用，超出这个窄条件以后有十处需要补定义，其中七处属规则本身，三处属字段不够，另有三类情形没有被样本覆盖。

## 0 口径

### 0.1 R21 规则原文

34 §5.1 的 R21 小节在第 958 至 964 行，正文分要求、判定、执行点三段，原文如下。

> **要求**：组合条目的字段 3 与成员类型行 22a 的依赖边合成一张有向图 **D**，节点是字段 1 的全部成员引用加所有已登记类型的 `id@版本`，边是字段 3 的边（上游成员指向下游成员）与成员行 22a 的边（本类型指向被依赖类型）。22a 指向外部持证主体时，该主体是汇点，没有出边，不参与环。状态机的回退边不进 D，另按"回退目标必须在前驱集合"判定。D 检出环即不通过，环上的成员引用按遍历顺序回写进错误信息。字段 3 的边集必须等于成员行 22a 中指向本组合其他成员的边集，比对边是否存在、方向、降级枚举、是否阻塞四项，四项全一致才通过。
>
> **判定**：①**环检测**：对 D 做深度优先遍历、拓扑排序或强连通分量分析，检出环即不通过，二元环、三元环、组合内环与跨组合环共用这一次检测；②**字段 3 与 22a 一致**：边、方向、降级、阻塞四项任一不一致不通过；③**回退目标在前驱集合**：状态机回退边的目标不在目标阶段的前驱集合内不通过；④**环路径回写**：检出环时必须把环上节点按遍历顺序写进错误信息，便于登记人定位。
>
> **执行点**：类型注册（22a 边变化）与组合登记（字段 3 边变化）两处各跑一次，两处跑同一个算法，不设第二套判据。只在组合登记时跑会漏掉类型录入时新增的 22a 边，只在类型注册时跑会漏掉组合登记时新增的字段 3 边。组合件不能作为成员（33 F10.5 的这条限制保留），组合之间的环只能经成员类型的 22a 边形成。

配套素材有三处。字段 1 的成员对象域与字段 3 的写法在 34 §4.8 第 767 至 769 行，字段 3 与 22a 一致性约束是 §4.8 约束第 6 条，在第 783 行；22a 的五项写法在 34 §4.2.22 第 574 行，方向由所在行隐含、含义是本类型调用对方，在第 579 行；可自动化判定在 34 §5.3 第 1039 行，定义 R21 只有环路径回写一项属人判。

### 0.2 七步判法

57 §一的方案区第 45 至 57 行给出七步判法，第 59 行另有第八步写"判不了的边界"，不计入七步。七步依次是：第一步（57 第 45 行）固定字段 3 的边写法，把"方向"从一句话改成两个可解析的端点，降级与是否阻塞挂在这条边后面；第二步（57 第 47 行）把两套边分成两张图，依赖图 D 的节点是字段 1 的全部成员引用加所有已登记类型的 `id@版本`，边是字段 3 的边加 22a 的边，状态机图 S 的回退边不进 D；第三步（57 第 49 行）对 D 做深度优先遍历或拓扑排序，检出环即不通过，按遍历顺序把环上成员回写；第四步（57 第 51 行）类型注册与组合登记两处各跑一次，同一个算法，不设第二套判据；第五步（57 第 53 行）字段 3 边集必须等于成员行 22a 中指向本组合其他成员的边集，比对边、方向、降级、阻塞四项；第六步（57 第 55 行）定三条拒绝文本，组合内成环、跨组合成环、回退边越界各一条；第七步（57 第 57 行）不新增字段，新增 R21，R16 里"循环依赖必须由回退边显式表达"一句改为指向 R21。第 45 行之前是三个子问题的结论，本文只用第 7 行那一句"三个子问题落在同一张有向图上，一次环检测就能判完"作为验证目标。

### 0.3 行号与版本口径

57 内部引用 34 的行号基于 34 v1.5，与 v1.6 的行号有偏移，例如 57 第 19 行写 §4.8 在第 748 至 769 行，v1.6 的 §4.8 在**第 761 至 783 行**；57 第 21 行写 22a 在第 562 与 567 行，v1.6 的 22a 写法在第 574 与 579 行。本文引 34 一律用 v1.6 的行号，引 57 用 57 自己的行号，两者不混用。

### 0.4 样本是构造数据

三个样本的组合条目、成员 id、降级取值与阶段名都是构造出来的，没有一条来自真实注册表，也没有写程序跑过环检测，遍历是纸上按邻接表手推的。构造 id 取 T901 至 T911 段，避开了真实库的 T001 至 T221，并在每个样本里假定这些类型已经登记，否则 R21 的节点集与字段 1 的成员解析都不成立；构造环境里其余已登记类型的入边与出边均为空，所以节点清单只列与样本相关的那些。降级取值用"转人工、降级为只读、跳过"三个，来源是 53 第 588 行记录的 22a 四值口径，34 §4.8 字段 3 本身没有给枚举，这一点构成 §5 的一处字段缺口。回退边只写字段 2，不进 D，这是判据的规定，三个样本都遵守。样本形态参照 53 的六个组合件（事故处置、并购尽调、月结关账、发布协调、临床路径、供应链对账），取的是"成员席位加阶段状态机"的形态，不引用它们的 id 与取值。

## 1 样本一：三角无环

### 1.1 组合条目字段 1、字段 2、字段 3 原文

组合 id 与所有者为 `C-SAMPLE-TRI@v1`，组合所有者是构造所有者。字段 1 的成员清单是 `T901-plan@v1`（计划席）、`T902-exec@v1`（执行席）、`T903-review@v1`（复核席），三个成员都是构造环境里已登记的注册表类型，行 22 各写一句"组合成员声明见组合条目 C-SAMPLE-TRI@v1"。

字段 2 的原文如下。

> P1 计划，P2 执行，P3 复核，P4 归档。回退边两条：P4 可退回 P3（归档时发现复核记录缺失）；P3 可退回 P2（复核不通过）。前驱按阶段序列里位置更早的阶段定义，P2 的前驱是 P1，P3 的前驱是 P1 与 P2，P4 的前驱是 P1、P2 与 P3，两条回退边的目标都落在前驱集合内。每阶段进入与退出条件：P1 进入需组合所有者确认计划输入，退出以 `D-plan@v1` 签字为准；P2 进入需 P1 退出条件成立，退出以 `D-exec@v1` 逐项结果齐全为准；P3 进入需 P2 退出条件成立，退出以复核结论为通过准；P4 进入需 P3 退出条件成立，退出以归档清单签字为准。

字段 3 的原文如下。

> 边一：上游 T901-plan@v1，下游 T902-exec@v1；缺失时降级=转人工；是否阻塞启动=是。
>
> 边二：上游 T902-exec@v1，下游 T903-review@v1；缺失时降级=降级为只读；是否阻塞启动=否。

字段 3 的边方向从上游指向下游，两条边的两端都是本组合成员，可以解析成两条有向边。组合另一条声明是"T903-review@v1 不依赖任何成员"，它不出边，这也是"三角无环"的末尾。

### 1.2 成员类型行 22a 原文

> T901-plan@v1 行 22a：依赖 T902-exec@v1；方向由所在行隐含，本类型调用对方；缺失时降级=转人工；是否阻塞启动=是；是否指向外部持证主体=否。行 22 组合成员引用：组合成员声明见组合条目 C-SAMPLE-TRI@v1。

>
> T903-review@v1 行 22a：依赖：无。行 22 组合成员引用：组合成员声明见组合条目 C-SAMPLE-TRI@v1。

### 1.3 依赖图 D 的节点与边

节点三个：`T901-plan@v1`、`T902-exec@v1`、`T903-review@v1`。节点集按 R21 还应包含构造环境里其余已登记类型，那些类型没有与样本相关的边，不影响判定，不列。

边有两条，字段 3 与 22a 两个来源在去重后完全重合。

| 来源 | 上游成员 | 下游成员 | 缺失时降级 | 是否阻塞启动 |
|---|---|---|---|---|
| 字段 3 边一，22a 重合 | T901-plan@v1 | T902-exec@v1 | 转人工 | 是 |
| 字段 3 边二，22a 重合 | T902-exec@v1 | T903-review@v1 | 降级为只读 | 否 |

### 1.4 检测过程与遍历顺序

起点取字段 1 声明顺序的第一个 `T901-plan@v1`，邻接表顺序取字段 3 的声明顺序，然后接 22a 中不重复的边。深度优先遍历的过程如下。`T901-plan@v1` 入栈并标为灰色，它的邻接是 `T902-exec@v1`，`T902-exec@v1` 入栈并标为灰色；`T902-exec@v1` 的邻接是 `T903-review@v1`，`T903-review@v1` 入栈并标为灰色；`T903-review@v1` 没有出边，完成并出栈；回到 `T902-exec@v1`，无剩余邻接，完成并出栈；回到 `T901-plan@v1`，无剩余邻接，完成并出栈。全程没有指向灰色节点的边，即没有回边，完成次序是 `T903-review@v1`、`T902-exec@v1`、`T901-plan@v1`，反向得到拓扑序 `T901-plan@v1`、`T902-exec@v1`、`T903-review@v1`。

字段 2 的两条回退边 `P4` 到 `P3` 与 `P3` 到 `P2` 是阶段之间的边，阶段不是 D 的节点，这两条边没有进入邻接表，遍历中没有出现。这一点是判据要求的分工，样本一按分工执行。

### 1.5 判定结论与报错文本

判定**通过**。字段 3 与 22a 四项一致，回退目标都在前驱集合内，D 无环，R21 的四条判定都不触发。报错文本为空，不做构造。

## 2 样本二：二元环

### 2.1 组合条目字段 1、字段 2、字段 3 原文

组合 id 是 `C-SAMPLE-PAIR@v1`，组合所有者是构造所有者。字段 1 的成员是 `T904-apply@v1`（申请席）与 `T905-approve@v1`（审批席），两者都是构造环境里已登记的类型。

字段 2 的原文如下。

> P1 申请，P2 审批，P3 归档。回退边两条：P3 可退回 P2（归档时发现审批记录缺失）；P2 可退回 P1（审批驳回）。前驱按阶段序列里位置更早的阶段定义，P2 的前驱是 P1，P3 的前驱是 P1 与 P2，两条回退边的目标都落在前驱集合内。每阶段进入与退出条件：P1 进入需申请单编号已生成，退出以申请单进入待审队列为准；P2 进入需 P1 退出条件成立，退出以审批结论签字为准；P3 进入需 P2 退出条件成立，退出以归档清单签字为准。

字段 3 的原文如下。

> 边一：上游 T904-apply@v1，下游 T905-approve@v1；缺失时降级=转人工；是否阻塞启动=是。
>
> 边二：上游 T905-approve@v1，下游 T904-apply@v1；缺失时降级=转人工；是否阻塞启动=是。

两条边成对互指，组合所有者的解释是"审批完成后要回调申请席更新状态"，但字段 3 只认依赖方向，这个解释不能把第二条边从依赖里摘出去，所以按判据它仍然是一条由审批席指向申请席的依赖。

### 2.2 成员行 22a 原文

> T904-apply@v1 行 22a：依赖 T905-approve@v1；方向由所在行隐含，本类型调用对方；缺失时降级=转人工；是否阻塞启动=是；是否指向外部持证主体=否。行 22 组合成员引用：组合成员声明见组合条目 C-SAMPLE-PAIR@v1。
>
> T905-approve@v1 行 22a：依赖 T904-apply@v1；方向由所在行隐含，本类型调用对方；缺失时降级=转人工；是否阻塞启动=是；是否指向外部持证主体=否。行 22 组合成员引用：组合成员声明见组合条目 C-SAMPLE-PAIR@v1。

### 2.3 依赖图 D 的节点与边

节点两个：`T904-apply@v1`、`T905-approve@v1`。

边有两条，字段 3 与 22a 重合。

| 来源 | 上游成员 | 下游成员 | 缺失时降级 | 是否阻塞启动 |
|---|---|---|---|---|
| 字段 3 边一，22a 重合 | T904-apply@v1 | T905-approve@v1 | 转人工 | 是 |
| 字段 3 边二，22a 重合 | T905-approve@v1 | T904-apply@v1 | 转人工 | 是 |

一致性比对四项全过：边集相等，方向都是本类型调用对方，降级与阻塞逐字相同。这一步通过正是样本二的关键，它说明第五步的一致性比对管不了环，若只有一致性比对，这个二元环会被放行。

### 2.4 检测过程与遍历顺序

起点取字段 1 声明顺序的第一个 `T904-apply@v1`，邻接表顺序取字段 3 的声明顺序。`T904-apply@v1` 入栈并标为灰色，邻接是 `T905-approve@v1`，后者入栈并标为灰色；`T905-approve@v1` 的邻接是 `T904-apply@v1`，该节点当前是灰色，说明存在一条指回栈中节点的边，检出回边。环按栈底到栈顶取节点为 `T904-apply@v1`、`T905-approve@v1`，闭合回到起点，环长 **2**。检出后立即停止，`P3` 到 `P2` 与 `P2` 到 `P1` 两条回退边仍不在图中，与环无关。

### 2.5 判定结论与报错文本

判定**不通过**。触发的是 R21 判定第①条环检测，其余三条都不触发：一致性四项全过，回退目标都在前驱集合内，环路径已回写。

报错文本按 57 第 55 行第一条模板生成，内容如下。

> 组合条目 C-SAMPLE-PAIR@v1 的字段 3 存在依赖环，环上成员依次为 T904-apply@v1、T905-approve@v1、T904-apply@v1；环上的依赖必须改成单向，或改用回退边表达状态上的回退。

这条文本按闭合写法把起点写了两次，模板原句是"环上成员依次为……"，没有规定是否重复首节点，本文取闭合写法，另一种实现可能只写一次，两者的判定结论相同，文本不同，这一点构成 §5 的一处规则缺口。改正方向不属本文范围，只指出：把边二改成回退边表达，字段 2 需要给出从审批结论回到申请状态的阶段与前提，否则这个"回调"在判据下没有合法位置。

## 3 样本三：组合内外混合

### 3.1 两个组合条目的字段 1、字段 2、字段 3 原文

组合一是 `C-CROSS-A@v1`（投放组合），字段 1 的成员是 `T908-dispatch@v1`（投放调度席）与 `T910-notify@v1`（通知席）。组合二是 `C-CROSS-B@v1`（回收组合），字段 1 的成员是 `T909-recover@v1`（回收执行席）与 `T911-audit@v1`（回收审计席）。四个成员都是构造环境里已登记的类型，行 22 各写一句"组合成员声明见组合条目 C-CROSS-A@v1"或"组合成员声明见组合条目 C-CROSS-B@v1"。

`C-CROSS-A@v1` 的字段 2 原文如下。

> P1 预备，P2 投放，P3 收尾。回退边一条：P3 可退回 P2（收尾时发现投放记录缺失）。前驱按阶段序列里位置更早的阶段定义，P2 的前驱是 P1，P3 的前驱是 P1 与 P2，回退目标落在前驱集合内。每阶段进入与退出条件：P1 进入需投放单已批准，退出以投放清单签字为准；P2 进入需 P1 退出条件成立，退出以投放结果逐项回执为准；P3 进入需 P2 退出条件成立，退出以收尾报告签字为准。

`C-CROSS-A@v1` 的字段 3 原文如下。

> 边一：上游 T908-dispatch@v1，下游 T910-notify@v1；缺失时降级=跳过；是否阻塞启动=否。

`C-CROSS-B@v1` 的字段 2 原文如下。

> P1 接收，P2 处理，P3 归档。回退边一条：P2 可退回 P1（接收记录与实际到货不符）。前驱按阶段序列里位置更早的阶段定义，P2 的前驱是 P1，P3 的前驱是 P1 与 P2，回退目标落在前驱集合内。每阶段进入与退出条件：P1 进入需回收单已登记，退出以到货记录签字为准；P2 进入需 P1 退出条件成立，退出以处理结果与差异清单签字为准；P3 进入需 P2 退出条件成立，退出以归档清单签字为准。

`C-CROSS-B@v1` 的字段 3 原文如下。

> 边一：上游 T909-recover@v1，下游 T911-audit@v1；缺失时降级=转人工；是否阻塞启动=是。

两个组合条目的字段 3 都只写本组合成员之间的边，跨组合的两条依赖不在字段 3 里，它们出现在成员类型的 22a 里，这是 34 §4.8 字段 1 与字段 3 的对象域决定的，组合本身不能作为成员，跨组合依赖只能经 22a 形成（34 第 767 行与 962 行）。

### 3.3 依赖图 D 的节点与边

节点四个：`T908-dispatch@v1`、`T910-notify@v1`、`T909-recover@v1`、`T911-audit@v1`。

边四条，两个来源去重后如下。

一致性比对要按组合各算一次。`C-CROSS-A@v1` 的字段 3 边集是 `T908-dispatch@v1` 到 `T910-notify@v1` 一条，22a 中指向本组合其他成员的边集也是一条，四项一致；`T908-dispatch@v1` 到 `T909-recover@v1` 这条边的下游不是本组合成员，按 34 第 783 行不进比对，所以比对通过。`C-CROSS-B@v1` 同理，字段 3 一条与 22a 指向本组合成员的一条四项一致，指向 `T908-dispatch@v1` 的那条不进比对，比对也通过。两个组合条目的四项比对都通过，而全图仍然有环，这是样本三要证明的核心事实。

### 3.4 检测过程与遍历顺序

起点取先登记的组合 `C-CROSS-A@v1` 字段 1 声明顺序第一个 `T908-dispatch@v1`。`T908-dispatch@v1` 入栈标灰，邻接表顺序按字段 3 先、22a 后，第一条邻接 `T910-notify@v1`；`T910-notify@v1` 入栈标灰，没有出边，完成出栈；回到 `T908-dispatch@v1`，第二条邻接 `T909-recover@v1`，入栈标灰；`T909-recover@v1` 的邻接表同样是字段 3 先、22a 后，`T911-audit@v1` 入栈标灰，没有出边，完成出栈；回到 `T909-recover@v1`，第二条邻接是 `T908-dispatch@v1`，该节点当前是灰色，检出回边。环按栈底到栈顶取节点为 `T908-dispatch@v1`、`T909-recover@v1`，闭合回起点，环长 **2**，环上两个节点分属两个组合条目。

跨组合的检出依赖一个前提：D 必须是全图。若实现按组合条目各建一张子图，`C-CROSS-A@v1` 的子图只有一条边且无环，`C-CROSS-B@v1` 的子图也只有一条边且无环，两个子图都判通过，环就漏了。R21 第 960 行的节点定义是"字段 1 的全部成员引用加所有已登记类型的 `id@版本`"，边是全部字段 3 与 22a 的边，按这个定义建的是全图，样本三的检出成立；如果实现把"本组合相关的成员"当成节点子集，就偏离了这条定义。

执行点的先后会改变报错位置。若两条 22a 跨组合边在组合登记之前已经登记，`T909-recover@v1` 的 22a 在类型注册时就完成了一次全图检测，环在类型注册这一步被拦，两个组合登记根本不会发生，报错文本里也就没有组合 id 可写。若两个组合先登记，字段 3 的边先入图，此时两条跨组合的 22a 边还没有写，两个组合登记都通过；随后写 `T909-recover@v1` 的 22a 时第二条跨组合边入图，环在类型注册这一步检出。两种顺序都能拦住，但报错落点不同，R21 没有规定同一批提交里类型注册与组合登记的先后，这一点构成 §5 的一处规则缺口。

### 3.5 判定结论与报错文本

判定**不通过**。触发的是 R21 判定第①条环检测，一致性四项在两个组合上分别通过，回退目标都在前驱集合内，环路径已回写。

报错文本按 57 第 55 行第二条模板生成，内容如下。

> 类型 T908-dispatch@v1 与 T909-recover@v1 通过 22a 互相依赖，环跨组合 C-CROSS-A@v1 与 C-CROSS-B@v1；跨框架的依赖走上交 22b。

样本三证明了跨组合环能被检出，也证明检出靠的是全图而不是单个组合条目。这条模板有两个不够用的地方：模板只给"类型 T1 与 T2"两个位置，环长超过 **2** 时装不下环上其余成员；模板末句"跨框架的依赖走上交 22b"说的不是组合之间，而是跨框架的依赖处置，把两种情形放在同一句里，报错时容易把组合间环误写成跨框架问题。

## 4 逐条走查七步判法

三个样本对七步的适用情况先列一张对照表，判据内容按 57 的行号定位，单元格里只写是否够用与一句话理由。

| 步骤 | 样本一 | 样本二 | 样本三 | 信息是否足够 |
|---|---|---|---|---|
| 第一步 固定字段 3 写法（57 第 45 行） | 够用 | 够用 | 不够用，跨组合边无字段 3 落点 | 字段 3 的对象域只到本组合成员 |
| 第二步 分图建 D（57 第 47 行） | 够用 | 够用 | 够用，全图才能检出 | 版本与三类成员未定 |
| 第三步 遍历检环（57 第 49 行） | 够用，无环 | 够用，环长 2 | 够用，环长 2 跨组合 | 起点顺序与多环报法未定 |
| 第四步 两个执行点（57 第 51 行） | 够用 | 够用 | 够用，但报错落点随先后变 | 同一批提交的先后未定 |
| 第五步 一致性四项（57 第 53 行） | 一致 | 一致且成环 | 两组合都一致且成环 | 降级枚举没有取值域 |
| 第六步 错误文本（57 第 55 行） | 不需要 | 够用 | 够用，两处不够 | 闭合写法与长环未定 |
| 第七步 落点与字段取舍（57 第 57 行） | 不影响判定 | 不影响判定 | 结论与样本三冲突 | "不新增字段"只在小范围成立 |

第一步的信息不足出现在样本三。字段 3 的对象域是"本组合成员之间"，34 第 769 行写"每条依赖写成上游成员引用与下游成员引用"，没有写跨组合的两个成员分属两个组合条目时往哪里写；一致性约束第 6 条（34 第 783 行）把比对范围限定在"指向本组合其他成员的边"，等于承认跨组合边不在字段 3 的管辖内。样本三的两条跨组合边只能写在 22a 里，组合条目读出来是"本组合内部无依赖"，登记人从组合条目看不到环，必须等检测报出来。

第二步的信息不足不在样本的判定上，而在判据没有写清的三类节点。R21 第 960 行的节点是"字段 1 的全部成员引用加所有已登记类型的 `id@版本`"，类型 id 带版本，同一个类型的两个版本就是两个节点，判据没有说跨版本的节点之间算不算环，三个样本都只用单版本，没有覆盖。字段 1 允许四类成员（34 第 767 行），其中轻量节点与待建类型没有行 22a，外部主体被 R21 写成汇点，另外两类在 D 里的出边规则没有写；三个样本的成员全是已登记类型，没有碰到这两类，属未覆盖而不是已验证。

第三步的信息不足在环路径的不唯一。判定本身确定，有环就是不通过，但 57 第 49 行与 34 第 961 行都只要求"按遍历顺序回写"，没有固定起点顺序，也没有固定邻接表顺序；同样的图换起点或换邻接顺序，报出的环与成员次序会不同。样本二与样本三各只有一个环，没有碰到多环时报哪一条的问题，判据也没有规定。

第四步的信息不足在提交次序。两个执行点各自跑一次是对的，样本三按两种先后各走一遍都能拦，但 R21 没有规定同一批提交里类型注册与组合登记的先后，同一个环可能在类型注册被拦而在组合登记根本没发生，也可能组合先登记通过、类型注册再拦，报错文本里的"组合条目"部分就会时有时无。另有一个更窄的窗口：22a 的依赖对象是否必须已登记，34 第 589 行判定第②条只要求"方向、降级与阻塞要具体"，没有要求对象可解析，如果实现允许 22a 指向还没登记的类型，D 里会出现悬空端点，环可能被推迟发现或者被忽略。

第五步的信息不足在降级枚举没有取值域。41 行与 34 第 961 行都要求比对"降级枚举是否一致"，34 第 783 行也这样写，但字段 3 只写"每条边后挂两个值：缺失时降级、是否阻塞启动"（34 第 769 行），没有给降级取值的清单。本文字段 3 与 22a 用的是"转人工、降级为只读、跳过"三个值，来源是 53 第 588 行记录的 22a 四值口径，不是 34 的规定，所以四项比对里的第三项目前只能靠实现自定枚举，两个实现可能对同一句话判出不同的一致结论。

第六步的信息不足在文本边界。模板没有说闭合节点要不要重复写，样本二按闭合写法报，另一种实现只报一次；模板跨组合那一条只给两个类型位置，环长超过二时装不下其余成员；模板末句把跨框架的依赖处置与组合间环写在同一句里。这三处都不影响拦不拦得住，影响的是报错能不能被人直接用。

第七步的信息不足在结论的适用范围。57 第 57 行写"不新增字段"，依据是成员引用、22a 方向、成员行组合引用、字段 3 四件都已在位。样本三说明这四件在位不等于跨组合依赖有落点：成员引用在字段 1，方向在 22a，组合引用在行 22，字段 3 只管组合内，跨组合依赖确实没有组合条目的位置。如果坚持不新增字段，就必须接受"组合条目读不出跨组合依赖，只有全图检测能发现"这个限制，并把这条限制写进 R21 的边界，否则读者会以为组合条目自身足以证明无环。

还有一处样本层看不出来的问题，与第一步的"分清回退边与依赖边"有关。判据用"回退边不进 D"来防止误判，但字段 2 的阶段标识与字段 3、22a 的成员标识在数据上本来就是两套对象，阶段名不是成员引用，D 的节点集里没有阶段。三个样本的回退边都只写了阶段，于是"不进 D"这件事在样本上自动成立，并没有真正压到"实现会不会误把字段 2 读进 D"这个动作。真正能压到这个动作的样本，要么把阶段按成员命名，要么让阶段引用责任成员，三个样本都没有这样做。这一条属未验证，不是判据的缺口。

## 5 结论

### 5.1 R21 能拦住什么

**能拦住**组合内的二元环，样本二证明检出并给出了环路径；**能拦住**经 22a 形成的跨组合二元环，样本三证明两个组合条目各自一致、各自无环，全图仍有环且被检出；**不误报**三角无环的组合，样本一证明三个成员两条边的图判通过，回退边存在也没有被误判成环。这三条是样本直接验证的。

三元环与二元环共用一个深度优先遍历，算法上同一条判据，但三个样本里没有三元环，样本一是无环三角，不是有环三角，所以"三元环能拦住"是算法推论，不是本文验证的结论。同理，五元以上的环、多个环同时存在、环上含轻量节点或待建类型成员的图，都没有样本。

### 5.2 拦不住与未覆盖

按样本三与 §4 的走查，R21 在下面这些情形里不可用或未经检验。跨组合依赖只能写在 22a，组合条目自身没有跨组合依赖的落点，所以"组合登记时只读本条目就能自证无环"做不到，必须依赖全图检测。类型 id 带版本，跨版本的节点关系没有规则。轻量节点与待建类型没有 22a 行，它们在 D 里的出边规则没有写。多环时报哪一条没有规定。遍历起点与邻接顺序没有固定，环路径不唯一。降级枚举没有取值域，一致性比对第四项中的降级项只能靠实现自定。22a 的依赖对象是否必须已登记没有规定。同一批提交里两个执行点的先后没有规定。回退边越界这一条（R21 判定第③条）三个样本都没有构造越界回退，未被验证。以上各项里，三元级以上环、越界回退、含轻量节点或待建类型成员的图这三类属于没有样本覆盖，其余落进下面的缺口清单。

### 5.3 规则本身的缺口

规则缺口指 R21 与七步判法内部没有定义清楚、不改字段也能补救的部分，共七处。

| 缺口 | 行号 | 为什么是规则问题 | 样本是否暴露 |
|---|---|---|---|
| 遍历起点与邻接顺序未定，环路径与成员次序不唯一 | 34 第 961 行判定④；57 第 49 行 | 判据只要求"按遍历顺序回写"，没有给顺序规则，两种实现报不同文本，结论相同 | 样本二、样本三暴露，各只有一解 |
| 多环时报哪一条未定 | 34 第 961 行判定① | 判据只写"检出环即不通过"，没有说多个环时回写哪一条或全部回写 | 未暴露，三个样本各一个环 |
| 节点带版本，跨版本是否算环未定 | 34 第 960 行节点定义 | 节点是 `id@版本`，同一类型两个版本是两个节点，判据没有说跨版本关系算不算环 | 未暴露，样本全为单版本 |
| 轻量节点、待建类型作成员时的出边规则未定 | 34 第 960 行；34 第 767 行字段 1 四类 | R21 只写了外部持证主体是汇点，另两类没有行 22a，判据没说它们的入边出边怎么算 | 未暴露，样本成员全为已登记类型 |
| 两个执行点的先后未定 | 34 第 962 行执行点 | 判据把两处执行点并列，没有定同一批提交里类型注册与组合登记谁先，报错落点随之不同 | 样本三按两种先后各走一遍，都拦得住但位置不同 |
| 22a 的依赖对象是否必须已登记未定 | 34 第 589 行判定② | 判据只要求 22a 的方向、降级与阻塞具体，没有要求对象可解析，悬空端点会让环推迟发现或漏掉 | 未暴露，样本的 22a 对象都已登记 |
| 错误文本模板没有定闭合写法与长环写法 | 57 第 55 行 | 模板只写"环上成员依次为……"且只给两个类型位置，闭合节点是否重复、环长超过二时怎么报都没有规定 | 样本二与样本三暴露，本文按闭合写法报 |

第六行严格说牵涉规则与字段两侧，22a 对象可解析性既可以补进 R21 的判定，也可以做成 22a 的字段校验，本文按"R21 执行点段落没有写"归到规则一侧，如果后续把它做成 22a 的可解析性校验，它就转成字段侧。

### 5.4 字段不够的缺口

字段缺口指字段 3 与 22a 的现有写法承载不了、需要改字段或加子项的部分，共三处。

| 缺口 | 行号 | 为什么是字段问题 | 样本是否暴露 |
|---|---|---|---|
| 字段 3 只写本组合成员之间的边，跨组合依赖没有组合条目的落点 | 34 第 769 行字段 3；34 第 783 行约束 6；57 第 45 行第一步 | 字段 3 的对象域限定在"本组合其他成员"，跨组合的两端分属两个条目，字段 3 写不进去，组合条目读不出跨组合依赖 | 样本三，两个组合都通过一致性比对而全图有环 |
| 字段 3 的"缺失时降级"没有枚举清单 | 34 第 769 行字段 3；34 第 783 行约束 6 | 一致性比对要求比对"降级枚举"，字段 3 只写"挂两个值"，没有取值域，比对没有共同标准 | 样本一至三都暴露，本文取值只能借 53 第 588 行的口径 |

### 5.5 可用性判断

一句话：**R21 在单版本、成员全为已登记类型、字段 3 与 22a 已写全并一致的窄条件下可用**，它拦得住组合内二元环与经 22a 的跨组合二元环，也不误报无环三角；超出这个窄条件以后，跨组合依赖的落点、降级枚举、版本节点、三类特殊成员、报错文本与执行点先后等共十处需要补定义，其中七处属规则本身，三处属字段不够，另有三类情形没有样本覆盖。这条判据现在可以按 §9.5 第 3 项要求的"至少一个必须被拒的环"做验收记录，但不能据此宣布组合循环依赖已经闭环，因为真实组合件仍无样本，纸面样本也没有跑过状态机（34 第 1447 行、53 第 682 行、55 清单第 3 条）。
