# 类型库 · 模拟验证——模板与总览 v1.1

> **版本**：v1.1（2026-11-21）｜由 v1 按 [39-类型库-验证结论-v1](39-类型库-验证结论-v1.md) §6 修订而来；v1 原文保留不动。
> **目的**：用 [31-核心设计原则](31-核心设计原则-智能体类型-v1.md) 的八步创建法批量创建真实类型，验证九要素与创建流程是否"够用、不缺、不冗、可判定"。
> **方法**：不是抽样——覆盖 **12 个领域、78 个类型**，刻意包含不同生命周期、不同复杂度、对抗型与边界型类型。

## 0. 验证假设（先立假设，再逐条打）

| # | 假设 | 判定方式 | 若失败说明 |
|---|---|---|---|
| H1 | 九要素对**任何**领域都够用，不缺失 | 逐类型检查九要素是否都能填满且有意义 | 某要素是空的/无意义的 → 要素设计有问题 |
| H2 | 八步流程顺序可行（先职责后身份，最后生命周期） | 每个类型按八步写，看是否卡住 | 某步无法先于下一步完成 → 顺序要调 |
| H3 | 边界、验收、能力都能"可判定" | 每条边界能写成可程序判定的条件 | 大量类型写不出可判定边界 → 31 的要求过严或不现实 |
| H4 | 类型可派生/组合而不失语义 | 检查清单里标注哪些能派生、哪些不能 | 派生后语义混乱 → 派生规则要收紧 |
| H5 | 生命周期三策略（一次性/短驻/长驻）覆盖真实需求 | 统计 78 个类型的分布 | 某策略几乎用不上 → 可删；或大量类型需要第四种 → 要加 |
| H6 | 不同类型的差异能被九要素区分（不是换皮） | 抽查同域两类型，看九要素是否真的不同 | 大量类型只差"领域词" → 类型抽象层级有问题 |

**实测结论（编号与 39 §2 一致）**：**H1 部分成立**——78/78 能填满，但约 31/78 出现"要素外补丁"，够填不够装；**H2 基本成立**——约 60/78 按序走完，需补"步 0 确认前提"、证据形态前置、3↔6 迭代；**H3 成立但打折**——可判定 ≠ 判得准，边界与验收都要分级；**H4 不成立**——4 条派生里 3 条应改判新建（T008/T025/T031；改判理由是**职责换向/职责不同**，不是"派生不能扩能力"——用户已拍板子类型可扩能力，见 31 v1.1 §4.2）；**H5 不够**——三档都用上，但缺"周期批处理"一档，且长驻还需"有界长驻"、状态外化与续期/退休规则；**H6 基本成立**——同域类型差异真实存在，相邻运维类型（T064/T067）偏弱。

**实测分布**：一次性 **48** / 短驻 **21** / 长驻 **9**（含 1 个有界长驻 T009）。三档之外还有**周期批处理**的真实需求（T061 等）：本表按实测口径计入短驻，并在 §3 的生命周期列单独标注，不另设第四档到计数里。

**覆盖设计**（避免抽样偏差）：

- **生命周期**：一次性 48、短驻 21、长驻 9——三种都覆盖；另有 T009 有界长驻、T061 周期批处理两个"档位边界样本"；
- **交付物类型**：文本、代码、数据、决策、行动、监控——六类全覆盖；
- **风险等级**：低（个人助理）、中（内容/客服）、高（法务/医疗/金融/安全）——三档全覆盖；
- **压力测试**：L 域 6 个（红队、越狱测试、双重身份、超长驻、无边界探索、人机双签）——专门检验九要素的边界；
- **复合型**：若干"一个类型内部有子角色"的类型（如 T008 架构评审兼评审与建议、T075 双重身份兼实现与评审）——检验类型是否会被误用为"团队"。

### 1.1 L 域：压力测试集，不是可实例化类型

L 域（T073–T078）**单列为"压力测试集"**：保留在 78 型清单里用于检验九要素的表达力上限，但**不作为可直接实例化的类型**，也不建议进入类型注册表供业务直接选用。

理由（取自 38 §4 与 §5.6）：这 6 个类型都依赖**类型外前提**，直接照抄九要素表会漏掉这些前提：

| 类型 | 类型外前提 | 漏掉后的后果 |
|---|---|---|
| T073 红队 | 书面授权上下文（目标/时间窗/禁止项/联系人） | "授权内可判、授权本身不可判"，边界失去锚点 |
| T074 越狱测试 | 隔离靶场与配额 | 内容层不可判定，只能靠环境兜底 |
| T075 双重身份 | 互斥角色的组合（阶段状态机） | 一个类型装两个角色，身份/职责/能力/知识四处变形 |
| T076 超长驻记忆 | 共享层的状态外化与续期/退休 | 与"实例可丢弃"正面冲突 |
| T077 无边界探索 | 资源上限与停止条件 | 职责"开放"时无法定义窄职责 |
| T078 人机双签 | 外部人签流程（机器签不是充分条件） | 填出来的是流程签署节点，不是智能体 |

因此：**L 域的类型定义是"压力样本"，不是"实现模板"**；要用其中某个能力，应按 38 §5.3 的建议改为"组合 + 创建前置（授权/预算/隔离环境）"，而不是新建一个 L 域类型。

## 2. 单类型标准格式（模板 v1.1）

> 所有 78 个类型统一按此格式；字段名与 31 v1.1 的属性名逐字一致（职责/能力/知识/边界/接口/生命周期/协作七组子字段）。v1.1 相比 v1 新增：决策权、能力五维、知识读写属性、边界判定方式/粒度/误判方向、验收类型/适用域、生命周期状态外化/交接/续期退休、协作的人与禁止协作。

```markdown
### T0NN 类型名（域 A · 研发工程）

| 要素 | 内容 |
|---|---|
| **类型 id** | `T0NN-type-slug@v1` |
| **一句话职责** | 负责 X，交付 Y，以 Z 验收（Y 可验收、Z 可判定） |
| **1 身份** | 3 句话：它是谁 / 姿态 / 立场（能推出行为） |
| **2 职责** | 只做什么；不做什么；成功标准；**决策权**=建议/共决/执行 |
| **3 能力** | 工具清单，每项标 **影响面**（无副作用/局部/广泛）+ **可逆性**（可回滚/可补偿/不可逆）+ **成本**（低/中/高）+ **作用域**（实例内/项目内/全局）+ **环境**（只读样本/沙箱/预发/生产）；最小必要集 |
| **4 知识** | 读集：每项带 **版本/时效/权威级别/驻留范围**；写域：每项带 **层级/驻留范围/是否禁止写** |
| **5 行为** | 遇到 X 做 Y（规划/歧义/失败/停止各 1–2 条；长驻以"交接条件"替代"停止条件"） |
| **6 边界** | 每条：禁区 + **判定方式**（程序高可信/近似判定/人工/环境化）+ **粒度**（动作级/环境级）+ **误判方向**（漏放/误拦）与代价；必须审批的动作；不可碰数据 |
| **7 接口** | 输入形态；输出交付物；验收证据；**验收类型**（交付时/效果后/过程型）；**适用域**（地区/期间/主体/交易结构/前置条件） |
| **8 生命周期** | **档位**（一次性/短驻/长驻/周期批处理）+ 理由；**状态外化**（位置/保留期/读权限）；**交接条件**；**续期/退休** |
| **9 协作** | 可委派给谁 / 向谁汇报；**人**（需人确认/人机双签）；**禁止协作**（可空） |
| **实例示例** | 任务 A：…；任务 B：…（同一类型两次实例化） |
| **检查** | 职责可验收 ✓ 边界可判定 ✓ 能力最小 ✓ 知识可对应 ✓ 行为可观察 ✓ 生命周期有理由 ✓ |
| **验证发现** | 九要素哪里够用/哪里卡住（1–2 句，供 H1/H2 汇总） |
```

**写法硬要求**：

- 职责必须"负责 X、交付 Y、以 Z 验收"；Y 是名词、Z 可判定；**决策权**必须是建议/共决/执行之一，不能省略；
- 能力必须五维标注（影响面/可逆性/成本/作用域/环境）；"无副作用"要明说，不能空着；没有副作用工具的类型也要写"影响面=无副作用"；
- 知识读集每项带**版本/时效/权威级别/驻留范围**；写域每项带**层级/驻留范围/是否禁止写**；"禁止写"要显式写，不能靠留空表达；
- 边界每条写成"不 + 动作/资源/条件"，并标**判定方式/粒度/误判方向**；近似判定、人工判定、环境化判定必须写明残余风险与补偿手段，不能冒充程序高可信；
- 行为每条写成"遇到 X 做 Y"，禁止"聪明/灵活/专业"这类形容词；长驻类型必须写**交接条件**，不再强求"停止条件"；
- 接口必须标**验收类型**（交付时/效果后/过程型）与**适用域**（地区/期间/主体/交易结构/前置条件；无则写 `—`）；
- 生命周期必须四档之一（一次性/短驻/长驻/周期批处理）+ 理由；长驻/周期批处理必须写**状态外化**（位置/保留期/读权限）与**续期/退休**；
- 协作必须显式写"人"档（需人确认/人机双签）与"禁止协作"（可空；空 ≠ 禁止）；
- 验证发现必须写"哪里卡住了"，不许全写"很顺利"（否则 H1/H2 没被真正检验）。

## 3. 78 个类型清单（按域编号，逐类型实测）

> 三列取值口径：**决策权** = 对交付结果的决定权（建议/共决/执行），不是产出物形态；**验收类型** = 该类型最终的验收时点（交付时/效果后/过程型），取值优先级为 ① 验证发现/检查行对验收时点的声明 → ② Z 中的判据（含效果指标即效果后）→ ③ 接口证据形态（异步证据即效果后；只有过程约束即过程型）；**适用域** = 结论/方案成立所依赖的外部前提范围（有/无/范围），无则记 `—`。逐类型依据见 §7。
>
> 与 39 §2 的差异：39 H3 的示例清单列了 4 个效果后（T062/T065/T068/T071），本表另把 T035/T037/T061 计为效果后，因三者的验证发现/接口明确写了"验收证据在实例结束后才产生""观测窗口未满不给结论""缺货率与周转率不劣化"。39 的清单是示例不是穷举，故总数以本表实测为准（67/7/4）。

## 4. 校验规则（每个类型写完必须过）

> v1.1 保留 v1 的 8 条，并**增补** 2 条（第 9、10 条）；原第 2、5 条各加一句与新增规则衔接的限定，不替换原规则。

1. **职责**：能一句说清"负责 X、交付 Y、以 Z 验收"；Y 是名词；Z 可判定；**决策权**必须为建议/共决/执行之一。
2. **边界**：至少 2 条"可程序判定"的禁区；至少 1 条"必须审批"的动作（低风险类型可为 0，但要明说"无审批动作，理由=低影响"）。v1.1 起这 2 条须为**程序高可信**判定；确无程序判据的，允许退为**环境化**并写明补偿手段，不得用近似判定冒充（见规则 9）。
3. **能力**：每个工具标只读/副作用/审批，并补齐 v1.1 的五维标注：**影响面/可逆性/成本/作用域/环境**；能说"少了哪个就干不了"。
4. **知识**：读集、写域各至少 1 项；读集项带**版本/时效/权威级别/驻留范围**，写域项带**层级/驻留范围/是否禁止写**；越界可判。
5. **行为**：规划/歧义/失败/停止各有至少 1 条"遇到 X 做 Y"。**长驻类型以"交接条件"替代"停止条件"**（见规则 10）；周期批处理写"单次运行边界"。
6. **接口**：输入、输出、证据三样齐全；标**验收类型**（交付时/效果后/过程型）与**适用域**（无则 `—`）。
7. **生命周期**：写理由；**四档**之一（一次性/短驻/长驻/周期批处理）；长驻/周期批处理还须写状态外化、交接条件、续期/退休。
8. **验证发现**：必须写"哪里卡住/哪里不够"，全写"顺利"的不算完成。
9. **边界判定方式（v1.1 新增）**：每条边界须写"**判定方式**（程序高可信/近似判定/人工/环境化）+ **粒度**（动作级/环境级）+ **误判方向**（漏放/误拦）与代价"；近似/人工/环境化判定须写明残余风险与补偿手段（抽检、审批、审计、隔离），不得冒充程序高可信。
10. **长驻状态与交接（v1.1 新增）**：长驻类型**不要求"停止条件"**，须写"**交接条件 + 状态外化**（位置/保留期/读权限）"；周期批处理须写触发节奏与单次运行边界；长驻还须写**续期/退休**条件。

## 8. 无法判定的类型清单

**无。** 78 个类型的决策权、验收类型、适用域三列均能在 35/36/37/38 的 §2/§3/§6/§7（必要时 §8）或 39 §2 找到直接依据，没有靠猜填充的值。

表中 `—` 共 **8 个**，全部出现在"适用域"列（T001、T002、T019、T020、T021、T025、T034、T069），语义是**"无适用域限制"**（确定判断），不是"无法判定"。判定口径：这些类型的交付物在交付后即被下游消费或进入下一环节，类型定义中没有"结论只在某地区/期间/主体/交易结构/前置条件下成立"的声明；其输入里的授权目录/渠道/话题属于实例参数，不构成类型层的适用域。

**需要说明的边界判断（不是无法判定，取值有据但存在两可）**：

- **T009 归"共决"而非"执行"**：发版由人定，守护只按阈值判定继续/暂停/回滚，且全量放行/回滚需值班负责人审批（35 §2、§6）；
- **T017 归"建议"而非"共决"**：批次结论是建议，只有最重的"整批不可用/全量返工"才需审批（35 §2、§6）；
- **T061 归"效果后"而非"交付时"**：Z 含"缺货率与周转率不劣化"，交付时只能验建议的可执行性与资金影响（38 §2、§8）；
- **T054/T056 归"交付时"**：验收证据是模块到能力项映射、判分标准、批改记录；学习效果不在 Z 内（37 §2、§7）；
- **T035/T037 归"效果后"**：T035 的接口证据是"2 个采集周期后的对比（异步证据）"、验证发现写"验收证据在实例结束后才产生"；T037 的证据是"观测窗口对比"、行为写"观测窗口未满不给结论"——Z 字面含交付时判据，但最终判据在观测窗之后（36 §7、验证发现）；
- **T062/T065/T068/T071 归"效果后"**：四者 Z 字面可交付时验，但 38 的验证发现/检查行明确声明"要等执行后才知道/只能验过程"（T062 P1/P3、T068 P3/P4、T071 P3/P11），39 §2 H3 亦将四者列入效果后——按 §3 口径的优先级 ① 采信验证发现的声明。
