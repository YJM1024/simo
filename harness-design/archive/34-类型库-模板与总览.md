# 类型库 · 模拟验证——模板与总览 v1

> **目的**：用 [31-核心设计原则](31-核心设计原则-智能体类型-v1.md) 的**八步创建法**，批量创建真实类型，验证九要素与创建流程是否"够用、不缺、不冗、可判定"。
> **方法**：不是抽样——覆盖 **12 个领域、约 78 个类型**，刻意包含不同生命周期、不同复杂度、对抗型与边界型类型，看八步法是否都成立。
> **产出**：本文（模板+清单+验证假设）+ 四份类型定义（[35 研发与算法](35-类型库-研发与算法.md) / [36 产品与内容](36-类型库-产品与内容.md) / [37 业务与服务](37-类型库-业务与服务.md) / [38 专业与边界案例](38-类型库-专业与边界案例.md)）+ 验证结论。

## 0. 验证假设（先立假设，再逐条打）

| # | 假设 | 判定方式 | 若失败说明 |
|---|---|---|---|
| H1 | 九要素对**任何**领域都够用，不缺失 | 逐类型检查九要素是否都能填满且有意义 | 某要素是空的/无意义的 → 要素设计有问题 |
| H2 | 八步流程顺序可行（先职责后身份，最后生命周期） | 每个类型按八步写，看是否卡住 | 某步无法先于下一步完成 → 顺序要调 |
| H3 | 边界、验收、能力都能"可判定" | 每条边界能写成可程序判定的条件 | 大量类型写不出可判定边界 → 31 的要求过严或不现实 |
| H4 | 类型可派生/组合而不失语义 | 检查清单里标注哪些能派生、哪些不能 | 派生后语义混乱 → 派生规则要收紧 |
| H5 | 生命周期三策略（一次性/短驻/长驻）覆盖真实需求 | 统计 78 个类型的分布 | 某策略几乎用不上 → 可删；或大量类型需要第四种 → 要加 |
| H6 | 不同类型的差异能被九要素区分（不是换皮） | 抽查同域两类型，看九要素是否真的不同 | 大量类型只差"领域词" → 类型抽象层级有问题 |

**覆盖设计**（避免抽样偏差）：

- **生命周期**：一次性（约 25 个）、短驻（约 40 个）、长驻（约 13 个）——三种都覆盖；
- **交付物类型**：文本、代码、数据、决策、行动、监控——六类全覆盖；
- **风险等级**：低（个人助理）、中（内容/客服）、高（法务/医疗/金融/安全）——三档全覆盖；
- **对抗型**：6 个"难定义"类型（红队、越狱测试、双重身份、超长驻、无边界探索、人机双签）——专门检验九要素的边界；
- **复合型**：若干"一个类型内部有子角色"的类型（如架构评审、危机公关）——检验类型是否会被误用为"团队"。

## 2. 单类型标准格式（模板）

> 所有 78 个类型统一按此格式；字段含义与 [31](31-核心设计原则-智能体类型-v1.md) §2 一一对应。

```markdown
### T0NN 类型名（域 A · 研发工程）

| 要素 | 内容 |
|---|---|
| **类型 id** | `T0NN-type-slug@v1` |
| **一句话职责** | 负责 X，交付 Y，以 Z 验收（Y 可验收、Z 可判定） |
| **1 身份** | 3 句话：它是谁 / 姿态 / 立场（能推出行为） |
| **2 职责** | 只做什么；不做什么；成功标准 |
| **3 能力** | 工具清单 + 标注（只读/副作用/审批）；最小必要集 |
| **4 知识** | 读集：…；写域：…（对应共享层范围） |
| **5 行为** | 遇到 X 做 Y（规划/歧义/失败/停止各 1–2 条） |
| **6 边界** | 禁区 + 必须审批的动作 + 不可碰数据（每条可判定） |
| **7 接口** | 输入形态；输出交付物；验收证据 |
| **8 生命周期** | 一次性/短驻/长驻 + 理由（与职责匹配） |
| **9 协作** | 可委派给谁 / 向谁汇报（可空，空=不协作） |
| **实例示例** | 任务 A：…；任务 B：…（同一类型两次实例化） |
| **检查** | 职责可验收 ✓ 边界可判定 ✓ 能力最小 ✓ 知识可对应 ✓ 行为可观察 ✓ 生命周期有理由 ✓ |
| **验证发现** | 九要素哪里够用/哪里卡住（1–2 句，供 H1/H2 汇总） |
```

**写法硬要求**：

- 职责必须"负责 X、交付 Y、以 Z 验收"，Y 是名词、Z 可判定；
- 能力必须标"只读/副作用/审批"；没有副作用工具的类型要明说；
- 边界每条写成"不 + 动作/资源/条件"，能被程序判定；
- 行为每条写成"遇到 X 做 Y"，禁止"聪明/灵活/专业"这类形容词；
- 生命周期必须给理由，不能只写"短驻"；
- 验证发现必须写"哪里卡住了"，不许全写"很顺利"（否则 H1/H2 没被真正检验）。

## 4. 校验规则（每个类型写完必须过）

1. **职责**：能一句说清"负责 X、交付 Y、以 Z 验收"；Y 是名词；Z 可判定。
2. **边界**：至少 2 条"可程序判定"的禁区；至少 1 条"必须审批"的动作（低风险类型可为 0，但要明说"无审批动作，理由=低影响"）。
3. **能力**：每个工具标只读/副作用/审批；能说"少了哪个就干不了"。
4. **知识**：读集、写域各至少 1 项；越界可判。
5. **行为**：规划/歧义/失败/停止各有至少 1 条"遇到 X 做 Y"。
6. **接口**：输入、输出、证据三样齐全。
7. **生命周期**：写理由；三种策略之一。
8. **验证发现**：必须写"哪里卡住/哪里不够"，全写"顺利"的不算完成。
