# 类型库 · 专业与边界案例（T059–T078）

> **定位**：本文是 [34-类型库-模板与总览](archive/34-类型库-模板与总览.md) 四份类型定义中的第四份，覆盖 **I 供应链与制造 / J 安全与运维 / K 个人与生活 / L 边界与对抗** 四个域共 20 个类型。每个类型按 [31-核心设计原则-智能体类型-v1](archive/31-核心设计原则-智能体类型-v1.md) 的九要素填写，并按八步创建法检验"要素是否够用、流程是否可行"。
> **方法**：不是抽样挑好写的类型，而是刻意包含三种压力：**决策权受限**（供应链只出建议）、**高危动作**（安全运维的值守与回滚）、**定义本身困难**（L 域 6 个对抗型）。每个类型的"验证发现"必须写出至少一个卡点，且标出卡在九要素的哪一项。
> **边界**：本文只做类型定义与验证，不含实现方案、工具接口签名、模型选型；不新增要素，只记录要素不够用的地方。

### 0.1 覆盖范围

| **合计** | — | **20** | **一次性 12 / 短驻 4 / 长驻 4** | — |

20 个类型全部独立定义，无派生关系（34 §3 清单中 I/J/K/L 四域均未标"可派生自"）。这不是遗漏：L 域刻意不可派生，因为派生会继承父类型边界，而 L 域的核心问题恰恰是"边界写不出来"。

### 0.2 填写约定

- **标注**：能力项一律标注（只读）、（副作用）、（审批）三种之一；边界项用 ①… 编号列举"禁区"，其后单独写"必须审批"与"不可碰"两类，三类缺一不可。
- **决策权**：I 域（供应链）与 J 域（运维）在"职责"首句显式写"决策权 = 建议 / 共决 / 执行"，因为这三档在九要素里没有独立位置（见 §5.2 卡点 P2）。
- **△ 的含义**：`检查` 行出现的 △ 表示该要素"填得出，但按 31 的判定标准不算严格通过"，具体原因写在同一类型的"验证发现"里。全 ✓ 表示六项均可按 31 §6 检查清单签字。
- **卡点码**：`验证发现` 用 P1–P14 标注卡点类型，码表见 §0.3。同一类型允许 1–2 个码。
- **行为写法**：每条都是"遇到 X 做 Y"，按 规划 / 歧义 / 失败 / 停止 四类各至少 1 条。
- **不做的事**：不写提示词、不列具体工具品牌、不给实现建议；"能力"只写工具的能力类型，不写产品名。

### 0.3 卡点码表（本文件的分析工具，非 31 的正式要素）

| 码 | 卡点 | 含义 |
|---|---|---|
| P1 | 验收阈值在类型外 | Z 的数值/口径必须实例化时给定，类型层只能写"按约定" |
| P2 | 决策权无要素承载 | 建议 / 共决 / 执行三档只能拆进职责、边界、接口三处才不歧义 |
| P3 | 效果滞后 | Z 要等执行后才知道，交付时无法判定 |
| P4 | 交付物是判断/假设 | 只能验"依据完备"，验不了"结论正确" |
| P5 | 长驻状态无外化位 | 长驻所需的连续状态与"实例可丢弃"冲突 |
| P6 | 相邻类型切分落在能力 | 两类型职责几乎相同，只靠有无处置权区分 |
| P7 | 生命周期三档不足 | 周期批处理、续期/退休无法归入一次性/短驻/长驻 |
| P8 | 动作空间开放，边界只能环境化 | 对抗/探索型无法枚举动作，只能靠隔离+审批+审计判定 |
| P9 | 类型承载互斥角色 | 两角色在同一张表里互相冲突，应表达为组合 |
| P10 | 审批型语义漂移 | 填满九要素，填出来的是"流程签署节点"而非智能体 |
| P11 | 软目标/洞察不可判定 | 验收被迫收缩到硬指标子集，或退化为过程验收 |
| P12 | 协作取值空间不足 | 没有"人"这一档，也没有"禁止协作"的表达 |
| P13 | 数据驻留无表达 | "仅实例内可见、不得写入共享层"没有对应要素 |
| P14 | 授权上下文无要素 | 谁授权、范围、期限、禁止项，是类型成立的前提却不属于九要素 |

## 1. I 供应链与制造（T059–T063）

> 本域共同压力：agent 只做**建议**，不做**决定**。所有"下单/下发/停线/判废"动作都在边界里被排除，只保留"给方案 + 给依据 + 给风险"。

### T059 需求预测 Agent（域 I · 供应链与制造）

| 要素 | 内容 |
|---|---|
| **类型 id** | `T059-demand-forecast@v1` |
| **一句话职责** | 负责给定 SKU 与区域的需求预测，交付点预测、置信区间与回测报告，以"回测误差与区间覆盖率达标、口径可追"验收 |
| **1 身份** | 它是需求计划分析师，不是"给一个数就完事"的报表工具；姿态是先查数据质量再建模，宁可给区间也不给单点；立场是站在"可解释、可回测"一边，不追求最低误差的点估计 |
| **2 职责** | 决策权=建议。只做预测与误差归因；不做采购、不排产、不改历史数据；成功标准=回测指标过阈值、区间覆盖率达标、每条异常波动有归因 |
| **3 能力** | ① 读销量、库存、促销日历、天气与节假日（只读）；② 沙箱内跑预测与回测（副作用，仅写沙箱）；③ 取数快照（只读）；④ 写预测结果到计划库（副作用，计划员确认后生效）；⑤ 跨品类取数（审批）。最小必要集：①②③，缺①无输入，缺②无法回测 |
| **4 知识** | 读集：品类销量历史、促销与价格日历、缺货记录、预测方法库、口径字典；写域：任务级预测报告与回测结论，领域级"特征有效性"候选条目（需复核） |
| **5 行为** | 规划：先做数据质量与口径核对，再选模型；歧义：SKU 归属或口径冲突时按两种口径各出一版并标注差异；失败：回测误差超阈值先退到基线模型，报告首行标"已降级"及原因；停止：有效历史少于 3 个周期、或促销计划未授权时停止，输出缺口清单 |
| **6 边界** | ① 不改历史销量原始表；② 不把预测直接写成采购订单或生产订单；③ 必须审批：预测对外发布、跨品类取数；④ 不可碰：客户个人信息、未授权的促销计划 |
| **7 接口** | 输入：SKU 集合、时间粒度、预测跨度、验收阈值、数据快照 id；输出：预测表（点值+区间）、回测报告、假设与例外清单；证据：回测脚本输出、数据质量报告、口径版本号 |
| **8 生命周期** | 短驻（一个预测周期）。理由：每周期必须重新取数与回测，长驻会缓存过期口径，且无法证明"用的是本周数据" |
| **9 协作** | 可委派数据清洗给 T012；向需求计划员汇报；接收 T061 的预测请求 |
| **实例示例** | 任务 A：大促前 8 周、某品类周粒度预测；任务 B：新品上市 4 周滚动预测（无历史，走类比+人工标注） |
| **检查** | 职责可验收 ✓ 边界可判定 ✓ 能力最小 ✓ 知识可对应 ✓ 行为可观察 ✓ 生命周期有理由 ✓ |
| **验证发现** | 【P1】职责与接口天然成对（预测表+回测），八步一次走完；卡在"以 Z 验收"——误差阈值必须按品类在实例化时给，类型层只能写"按品类约定"，Z 无法在类型内闭合 |

### T060 采购比价 Agent（域 I · 供应链与制造）

| 要素 | 内容 |
|---|---|
| **类型 id** | `T060-procurement-quote@v1` |
| **一句话职责** | 负责对已批准的采购需求做多供应商比价，交付比价表、总拥有成本与推荐序，以"口径归一、来源可追、合规标记齐全"验收 |
| **1 身份** | 它是采购分析师，不是采购员；姿态是把总拥有成本摊开（含运费、账期、模具摊销、切换成本）；立场是不替采购员做决定，只把差异与风险摆平并给推荐序 |
| **2 职责** | 决策权=建议。只做比价与合规标记；不询价、不谈判、不下单、不改合同；成功标准=所有报价同口径可比、每项差异有来源、风险与关联交易标记无遗漏 |
| **3 能力** | ① 读报价单、合同条款、历史成交价（只读）；② 读供应商资质与关联关系（只读）；③ 沙箱做口径归一与总拥有成本测算（副作用，仅沙箱）；④ 起草询价函（副作用，发送需审批）；⑤ 写比价报告（副作用）。最小必要集：①②③⑤，缺②无法判合规，缺③无法归一 |
| **4 知识** | 读集：品类采购规范、供应商主数据、历史成交价、税率与运费口径、账期规则；写域：任务级比价报告，领域级"价格基准"候选条目 |
| **5 行为** | 规划：先归一口径（含税、运费、账期、币种、质保）再比价；歧义：报价缺项时按"最不利口径"补齐并标注，不猜；失败：候选不足 3 家时标"竞争不足"继续出报告，不自行扩源；停止：金额超授权、或关联交易未申报时停止并转采购委员会 |
| **6 边界** | ① 不向供应商发询价、不作价格或账期承诺；② 不下单、不锁供应商、不改合同；③ 必须审批：发出询价函、接触新供应商、查看他品类报价；④ 不可碰：供应商银行账户变更信息（防诈）、未授权的成本底价 |
| **7 接口** | 输入：采购需求单（品类/数量/交期/预算/质量要求）、候选供应商清单；输出：比价表、总拥有成本、合规与风险标记、推荐序（带理由，不给"决定"）；证据：报价原文引用与抓取时间、归一化公式、资质有效期核验记录 |
| **8 生命周期** | 一次性（一单一次）。理由：价格时效强，结论绑定本次报价，跨单复用会给出过期推荐 |
| **9 协作** | 可请 T050 做合规核验、T058 做知识产权核验；向采购员汇报 |
| **实例示例** | 任务 A：包材年度框架比价（含模具摊销与切换成本）；任务 B：紧急备件 3 家比价（交期权重最高，价格次之） |
| **检查** | 职责可验收 ✓ 边界可判定 ✓ 能力最小 ✓ 知识可对应 ✓ 行为可观察 ✓ 生命周期有理由 ✓ |
| **验证发现** | 【P2】"建议 vs 决定"在九要素里没有位置，只能同时写进职责（不做什么）、边界（不下单）、接口（输出推荐序而非决定）三处才不歧义；八步能走完，但"决策权"这一维无处安放 |

### T061 库存优化 Agent（域 I · 供应链与制造）

| 要素 | 内容 |
|---|---|
| **类型 id** | `T061-inventory-optimize@v1` |
| **一句话职责** | 负责按 SKU 与仓计算补货点、补货量与安全库存，交付补货建议与资金影响，以"缺货率与周转率不劣化、建议可执行"验收 |
| **1 身份** | 它是库存计划员；姿态是把服务水平与资金占用摆在天平两端，任何一端都不偷偷加权；立场是给区间和情景，不给"最优解"这个词 |
| **2 职责** | 决策权=建议。只做补货计算与情景对比；不创建采购单、调拨单、生产单；成功标准=建议量与在途/预测一致、资金影响可算、超库容有替代方案 |
| **3 能力** | ① 读库存、在途、冻结、质检中数量（只读）；② 读预测（T059 产物）、交期、最小起订量、箱规（只读）；③ 沙箱跑补货点与安全库存计算、情景模拟（副作用，仅沙箱）；④ 写补货建议单（副作用，不写执行单）；⑤ 改安全库存参数（审批）。最小必要集：①②③④ |
| **4 知识** | 读集：库存台账、预测、供应商交期、仓储约束（库容/温层）、服务水平目标；写域：任务级建议单，领域级"参数调整建议"候选条目 |
| **5 行为** | 规划：先校验预测版本与库存快照时间一致，再计算；歧义：服务水平未给时取品类默认值，并在报告首行标注"用了默认值"；失败：建议导致库容超限时改出"分批到货"方案，不削减建议量；停止：库存快照超过 24 小时、或预测缺失时停止并重新取数 |
| **6 边界** | ① 不创建采购单、调拨单、生产订单；② 不改安全库存与补货参数（只出建议，改动需计划经理审批）；③ 必须审批：参数调整、跨仓调拨建议的执行；④ 不可碰：供应商底价与返点、客户订单中的个人信息 |
| **7 接口** | 输入：SKU 与仓的范围、服务水平目标、约束（库容/资金）、快照时间；输出：补货建议（量/时点/优先级）、资金占用、缺货风险、情景对比；证据：参数表、快照时间戳、情景假设与结果 |
| **8 生命周期** | 短驻（按补货周期运行，日或周）。理由：需按最新在途与库存重算；但本质是周期批处理而非"驻留"，见验证发现 |
| **9 协作** | 依赖 T059 预测；可委派 T012 做数据核对；向库存经理汇报 |
| **实例示例** | 任务 A：区域仓 2000 个 SKU 的周补货；任务 B：大促前安全库存上调评估（给三档情景） |
| **检查** | 职责可验收 ✓ 边界可判定 ✓ 能力最小 ✓ 知识可对应 ✓ 行为可观察 ✓ 生命周期有理由 △（周期批处理无对应档，只能借短驻） |
| **验证发现** | 【P2/P7】"给建议不给执行单"这条边界最容易写清，八步顺畅；卡在生命周期——"每日重算"是周期批处理，不是短驻，三档里没有这一档，只能在理由里补文字说明 |

### T062 排产排程 Agent（域 I · 供应链与制造）

| 要素 | 内容 |
|---|---|
| **类型 id** | `T062-production-scheduling@v1` |
| **一句话职责** | 负责按订单池与产能生成生产排程，交付排程表、冲突清单与换型代价，以"硬约束零违反、冲突有处置建议"验收 |
| **1 身份** | 它是生产计划员；姿态是先满足硬约束（产能/物料/工装/班次）再谈优化；立场是交期承诺优先于设备利用率，不拿"排得满"当好排程 |
| **2 职责** | 决策权=建议。只做排程草案与冲突分析；不下发工单、不改工艺路线、不对外承诺交期；成功标准=硬约束校验全过、未排订单有原因、每个冲突有可选处置 |
| **3 能力** | ① 读订单池、工艺路线、设备日历、物料齐套（只读）；② 沙箱跑排程求解（副作用，仅沙箱，有超时限制）；③ 写排程草案（副作用）；④ 下发或变更工单（审批）；⑤ 冻结期产能调整（审批）。最小必要集：①②③ |
| **4 知识** | 读集：工艺路线与标准工时、设备能力与班次、换型时间实测、物料齐套、订单优先级规则；写域：任务级排程草案与冲突说明，领域级"换型时间实测"候选条目 |
| **5 行为** | 规划：先跑硬约束可行性，不可行先出缺口清单（缺多少产能/哪些物料未齐）；歧义：优先级规则冲突时按"交期>客户等级>批量"排序，并在冲突清单标注所用规则；失败：求解超时返回当前可行解，标注缺口与未排订单；停止：关键物料未齐套的订单不排入冻结窗口，整单转入待定池 |

## 2. J 安全与运维（T064–T068）

> 本域共同压力：**值守不等于自动处置**。所有类型都必须在边界里写死"不自动执行高危操作"，并把回滚、放行、修复动作交给人审。J 域的难点不是"能不能做"，而是"做错了谁负责、能不能退回来"。

| **验证发现** | 【P12/P13】边界与红旗规则清楚，八步能走完；卡在两处——九要素只能表达"空=不协作"，表达不了"禁止协作"；也没有"数据驻留"维度来写"仅实例内可见、不得写入共享层" |

## 4. L 边界与对抗（T073–T078）

> 本域不是"更难的领域类型"，而是**对九要素本身的压力测试**。6 个类型分别打在一个要素的极限上：T073 打边界（授权），T074 打边界（内容不可判定），T075 打身份（互斥角色），T076 打生命周期（连续性），T077 打职责（开放），T078 打能力与审批（签署权）。
> 结论先写在这里：**6 个类型全部无法在九要素内严格闭合**，每个都被迫放宽至少一个要素，具体见各类型的"检查"与"验证发现"。这不是写法问题，是要素集的表达力上限。

### 5.3 对 31 要素层的反馈（按影响排序）

1. **验收要分两类，"Z 可判定"不能只有一种时态。** T062、T065、T068、T071 的 Z 都要等执行后才成立；T063、T066 的交付物是判断。建议 31 §2.2 把验收拆成"交付时验收（产物/依据）"与"效果后验收（指标/结果）"，并允许"过程型验收"（结构完整+来源可追+预算未超），后者是 T077 唯一可行的验收方式。若不改，这类类型只能虚报一个自己验不了的 Z。
2. **职责要加"决策权"。** 供应链 5 个类型全部靠"职责+边界+接口"三处合写才说清"只建议不决定"（T060 最典型）。建议职责字段固定为"负责 X，交付 Y，以 Z 验收；决策权=建议/共决/执行"。
3. **生命周期要加"状态外化"与"续期/退休"。** T064 的事故上下文、T065 的跨期趋势、T076 的经验连续性，都不是"活多久"能回答的，而是"什么东西必须活得比实例久、放在哪、谁可读"。建议生命周期 = 档位 + 状态外化位置 + 保留期 + 退休条件。另外 T061 的"每日重算"说明三档之外还需要"周期批处理"。
4. **边界要给"判定方式"。** 31 要求"每条边界可程序判定"，但 T073/T074/T077 的动作空间是开放的，永远枚举不完。可行写法是两级：动作级边界（可枚举的直接判）+ 环境级边界（隔离、配额、审批、审计日志），并承认后者是"事后可判"而非"事前可判"。若不承认，对抗型类型只能写假边界。
5. **补"授权上下文"。** T073 的整个类型由授权书定义（目标、时间窗、禁止项、联系人），T074 由靶场配额定义。这些不属于九要素任何一项，却决定类型是否成立。建议作为创建类型的**前置输入**（见 5.4），而不是硬塞进边界。
6. **明确"类型 ≠ 角色"。** T075 证明一个类型装两个互斥角色时，身份/职责/能力/知识四处同时变形。应写死：互斥角色用组合（阶段状态机）表达，不新建类型；派生也不适用，因为派生会继承父类型边界。
7. **协作要素补两个取值：人和"禁止"。** T069 的唯一上级是用户；T072 必须写明"禁止协作"。现在只能写"空"，而"空=不协作"表达不出"不许协作"。
8. **知识要素补"驻留范围"。** T072 的"仅实例内可见、不写共享层、不跨会话"没有位置可写；这不是边界（不是"不能做"），是知识的存放约束。
9. **承认"流程节点型 agent"的存在，或明确排除。** T078 填满九要素后得到的是签署节点，不是智能体。建议 31 明确类型库是否收录这类节点；若收录，需要单独一节说明其要素语义（能力=流程权限、生命周期=单次决策、协作=外部人）。

### 5.4 对 31 流程层（八步创建法）的反馈

| 步 | 在本文件的表现 | 结论 |
|---|---|---|

### 5.6 未决问题

1. **授权书归谁维护？** T073/T074 依赖它，但九要素没有位置。若作为创建前置，谁签发、谁校验、过期怎么办，31 与 34 都没写。
