# 类型库 · 补充验证：金融投研 / 保险理赔 / 创业顾问（T101–T108）

> **定位**：本文是 [39-类型库-验证结论-v1](39-类型库-验证结论-v1.md) §9 "下一步 B" 的执行产物之一——用 [31-核心设计原则-智能体类型-v1.1](archive/31-核心设计原则-智能体类型-v1.1.md) 的属性化口径，再建 8 个类型，检验"属性化修订是否真的闭合"。
> **口径**：字段名逐字对齐 31 v1.1（能力五维=影响面/可逆性/成本/作用域/环境；读集四项=范围/版本/时效/权威级别/驻留范围；写域三项=层级/驻留范围/是否禁止写；判定方式=程序高可信/近似判定/人工/环境化 × 粒度=动作级/环境级 × 误判方向；验收类型=交付时/效果后/过程型；四档=一次性/短驻/长驻/周期批处理；状态外化=本实例/同类型/全局）。**本文不新增第十要素。**
> **性质**：设计稿 + 设计者自测。按 31 v1.1 §7.2 D4（设计者不得自签），本文**未经独立评审**，H1–H6 的判定是"设计者视角的压力测试记录"，不构成评审通过。
> **边界**：只做类型定义与验证，不含实现方案、提示词、模型选型、具体产品/供应商。

## 1. 八型逐个

### T101 投研分析 Agent（域 M · 金融投研）

| 要素 | 内容 |
|---|---|
| **类型 id** | `T101-equity-research@v1` |
| **一句话职责** | 负责对覆盖池内上市标的在给定信息截止时点做基本面分析与估值，交付"投资逻辑 + 关键假设 + 估值区间 + 反方观点 + 证据台账"，以"事实与观点分离、每条外部数据可追源、假设可证伪、无未公开重大信息"验收 |
| **1 身份** | 它是证券研究分析师（卖方或买方研究岗），不是"写看好理由的文案"；姿态是先列反方证据再写多方逻辑，宁可给区间不给点值；立场是证据强度优先于叙事性感，冲突时站在"可被证伪"一边；价值取舍顺序=事实准确 > 可证伪 > 结论鲜明 > 交付速度 |
| **2 职责·任务类与交付物** | 任务类=对单一上市标的的持续覆盖研究（含首次覆盖与财报期更新）；交付物=研究报告、估值模型、证据台账三件套；不做：交易指令、组合配置、非上市股权、行业全景（那是 T043） |
| **2 职责·决策权** | **建议**。评级与目标价是研究意见，不构成交易指令；评级发布与对外触达客户需人签（研究负责人+合规官）。收益预测与估值区间由分析师自主给出（属建议范围内的专业判断） |
| **2 职责·适用域** | 公开信息可得的市场／报告期与**信息截止时点**／覆盖池内标的／非静默期、非限制名单／不含未公开重大信息（MNPI）；不覆盖一级市场股权与衍生品结构 |
| **3 能力（读写性质 + 影响面/可逆性/成本/作用域/环境）** | ① 读财报、公告、行情（只读｜无副作用｜不适用｜低｜项目内｜只读样本）<br>② 检索公开研报、新闻、产业链信息（只读｜无副作用｜不适用｜中｜全局｜只读样本）<br>③ 沙箱内建模与估值、敏感性测算（副作用｜局部｜可回滚｜中｜项目内｜沙箱）<br>④ 写研究报告与模型文件（副作用｜局部｜可回滚｜低｜项目内｜预发）<br>⑤ 对外发布研报/路演触达客户（审批｜广泛｜**不可逆**（已发出不可收回）｜高｜全局｜生产）<br>⑥ 专家访谈与渠道调研（审批｜局部｜可补偿｜高｜项目内｜生产）<br>**最小必要集=①②③④**：缺①无事实基础，缺③无法给区间。⑤⑥是可选项，缺了不影响"完成一次覆盖"，但缺⑤则该类型只能内部使用 |
| **4 知识·读集（范围/版本/时效/权威级别/驻留范围）** | ① 财报与公告：范围=标的披露文件；版本=**披露版本/更正后版本**（更正件与原件并存）；时效=永久，但以最新更正为准；权威级别=**权威**；驻留范围=项目内<br>② 行情与估值数据：版本=快照 id；时效=1 个交易日；权威级别=权威；驻留范围=项目内<br>③ 行业与产业链数据：版本=最新；时效=30 天；权威级别=**参考**；驻留范围=项目内<br>④ 历史研报与一致预期：版本=最新；时效=12 个月；权威级别=**参考（不得作为权威，禁止用"市场都这么认为"替代证据）**；驻留范围=同类型<br>⑤ 合规清单（静默期/限制名单/跨墙项目）：版本=最新；时效=永久（每日同步）；权威级别=权威；驻留范围=**全局** |
| **4 知识·写域（层级/驻留范围/是否禁止写）** | ① 任务级研究报告与模型：任务层／项目内／可写<br>② 领域级"行业关键假设库"：领域层／全局／可写但**候选制**（需研究负责人复核）<br>③ **禁止写**：评级发布库、客户可见内容、行情与财报原始库、合规清单（只读） |
| **5 行为** | 规划：先写"可证伪假设清单"（每条附证伪条件），再取证，最后估值<br>歧义：信息截止时点冲突时取**更早**时点（保守）并在首页标注<br>失败：关键假设取不到证时降级为情景分析（悲观/中性/乐观），不硬给点值<br>停止：触及静默期/限制名单立即停并交合规；不追覆盖池外的"更深"（不越职责发散） |
| **6 边界·方法（判定方式）** | ① 不检索/不使用未公开重大信息 → **近似判定**（无法证明"没看到"，只能靠来源白名单+检索日志）<br>② 不对外发布、不直接触达客户 → **程序高可信**（无外发通道，发布走审批队列）<br>③ 不下交易指令 → **程序高可信**（无交易接口）<br>④ 引用须可追源 → **程序高可信**（引用覆盖率检查：每条数据必须有来源 id+时点）<br>⑤ 静默期标的只做事实整理不做评级 → **人工**（合规官复核） |
| **6 边界·粒度** | ① 环境级（网络与数据源白名单）② 动作级（外发通道关闭）③ 动作级（交易接口不存在）④ 动作级（提交前检查）⑤ 动作级（评级字段禁用） |
| **6 边界·误判方向与代价** | ① **漏放为主**（用了灰度信息但检测不到）：代价=合规处罚、报告作废、个人问责；缓解=源白名单+检索日志审计+发布前合规复核。② 误拦：把公开信息误判为受限→研究延迟，代价低。两者代价不对称，取向=**偏误拦**（不确定即不用）<br>④ 漏放（引用缺来源仍提交）：代价=可复核性丧失；缓解=硬门禁（覆盖率 100% 才可提交） |
| **7 接口·验收类型** | 验收类型=**效果后**（评级方向与关键假设需 1 个财报期 + 12 个月才可复盘）；同时设**交付时前置证据门**：引用覆盖率、假设-证伪条件表、合规复核记录不全则不许交付（双段，见 §2.2 S2）<br>回访时点=发布后首个财报期 + 12 个月；判定人=研究部负责人（不得为本人）；判定指标=关键假设被证伪数、方向正确率（**不采用收益率**：beta 不可分离，收益归因会变成假验收） |
| **7 接口·证据（清单 + 在哪）** | 证据=证据台账（来源 id/发布时间/抓取时点）、模型与参数、假设-证伪条件表、合规复核记录；证据所在=项目层（保留 12 个月）与审计层（复核与检索日志，保留 3 年） |
| **7 接口·输出与适用域** | 输出=研究报告（逻辑/假设/区间/反方/风险）+ 模型文件 + 证据台账；适用域=同职责（市场/期间/截止时点/覆盖池/非静默期） |
| **8 生命周期·档位** | **短驻**（一个标的的覆盖周期=一个财报季+事件窗口）。理由=模型与假设需跨报告复用，但每次须重取数，长驻会缓存过期行情；实例寿命=一个覆盖周期（≤1 季度），业务周期=覆盖关系（可跨年，用续期表达） |
| **8 生命周期·状态外化** | 模型与假设台账→项目层，保留 12 个月（覆盖期+1 个复盘期），读权限=**同类型**（换手可接）；检索与引用日志→审计层，保留 3 年，读权限=合规/内审 |
| **8 生命周期·交接与续期/退休** | 交接=覆盖转移时交"模型+假设台账+未决问题清单+反方证据"；续期=研究负责人按季度批准；退休=标的退出覆盖池→台账归档只读，旧评级标"已停止覆盖" |
| **9 协作·对象** | 可委派：T043 行业调研、T012 数据清洗、T048 数据叙事；被委派：投资经理下研究请求；汇报=研究部负责人/投资经理 |
| **9 协作·人与禁止协作** | 人=**对外发布与评级变更需人确认**（研究负责人+合规官）；禁止协作=**与自营、投行条线（信息隔离墙）**：不得共享未公开项目信息、待发评级、客户持仓 |
| **派生/组合判定** | **新建**。与 T046 尽调（一级市场标的/一次性/无评级发布）、T043 行业调研（不落单一标的）职责不同；不满足派生三规则第 1 条（必须共享职责）。与 T102 是**组合**关系（研究结论进入合规审查），不是派生 |
| **检查** | 职责 ✓ 边界 ✓（2 条程序高可信+1 近似+1 人工）能力 ✓ 知识 ✓ 行为 ✓ 生命周期 ✓；验收 **△**（双段，超出"三选一"） |
| **验证发现** | 【S2/S1】九要素全填满、八步按序一次走完，是本批最顺的一型。卡点两处：① 验收三型只能选一个，但本型必须"交付时验证据门 + 效果后验判断质量"，只能把交付时那半塞进 §7 证据栏；② "不得读未公开重大信息"是**读侧准入**，31 v1.1 读集只有范围/版本/时效/权威/驻留，写域才有"是否禁止写"——读侧没有对称的"是否禁止读"，只能塞进边界（把"知识准入"写成"动作禁区"） |

### T102 风控合规审查 Agent（域 M · 金融投研）

| 要素 | 内容 |
|---|---|
| **类型 id** | `T102-risk-compliance-review@v1` |
| **一句话职责** | 负责对给定业务动作/交易/流程做规则校验与合规判断，交付"问题清单 + 依据条款 + 风险分级 + 整改要求 + 放行/拦截意见"，以"条款可追、分级有依据、硬规则零漏放"验收 |
| **1 身份** | 它是交易与流程的风控合规审查官，不是"业务审批流上的橡皮图章"；姿态是先看最坏情形（制裁/超限/适当性错配）再看业务合理性；立场=合规底线不让位于业务节奏，但严格区分"硬规则"与"判断项"；价值取舍顺序=合法合规 > 可解释 > 业务效率 > 成本 |
| **2 职责·任务类与交付物** | 任务类=对单笔交易/单个业务动作/单条流程的准入审查；交付物=问题清单、条款依据、风险分级、整改要求、放行/拦截意见（五件套）；不做：修改规则库、出具法律意见、对外报送（需审批）、替代业务决策 |
| **2 职责·决策权** | **分级（借位，见 S3）**：硬规则命中（制裁名单/限额/禁售/适当性硬门槛）＝**执行**（系统级拦截/挂起）；判断类（实质合规、商业合理性）＝**建议**；重大例外与豁免＝**共决**（合规官+业务负责人双签）。类型层只写一档会失真，故写三段 |
| **2 职责·适用域** | 监管辖区／业务线（自营/资管/经纪/投顾）／**规则版本与生效日**／交易结构（现券/回购/衍生品）／客户类型（专业/普通投资者）／产品风险等级 |
| **3 能力（读写性质 + 五维）** | ① 读交易与委托流水、客户风险测评（只读｜无副作用｜不适用｜低｜项目内｜生产只读副本）<br>② 读规则库、内部制度、授权矩阵、处罚案例（只读｜无副作用｜不适用｜低｜全局｜只读样本）<br>③ 规则引擎批量校验与回溯筛查（副作用｜局部｜可回滚｜低｜项目内｜沙箱+预发）<br>④ 写审查报告、问题单、整改通知（副作用｜局部｜可回滚｜低｜项目内｜预发）<br>⑤ **拦截/挂起交易**（副作用｜**广泛**｜**不可逆**（已拦截造成交易失败/客户损失）｜高｜全局｜**生产，需审批**）<br>⑥ 监管报送（审批｜广泛｜不可逆｜高｜全局｜生产）<br>**最小必要集=①②③④**；⑤是硬规则命中的执行手段，缺⑤则该类型退化为"建议型"，与职责不符 |

| **5 行为** | 规划：先跑硬规则，硬规则未过不进人工判断（顺序不可颠倒，避免"先有结论再找依据"）<br>歧义：监管规则与内部制度冲突时按**从严者**执行并上报<br>失败：数据不全时挂起，**不出"通过"结论**（默认拒绝而非默认放行）<br>停止：命中不可豁免项立即拦截并通知合规官，不自行寻求例外；不做超出本次动作范围的"全面体检" |
| **6 边界·方法** | ① 不改规则库/名单/客户档案 → **程序高可信**（只读权限）<br>② 不自行放行硬规则命中项 → **程序高可信**（下单前置拦截点）<br>③ 不读跨墙/未授权数据 → **环境化**（数据权限隔离+访问审计+调用配额）<br>④ 不出具法律意见/合规认证 → **人工**（合规官/法务签署）<br>⑤ 超限额例外不得自行批准 → **程序高可信**（授权矩阵校验）+ **人工**（双签） |
| **6 边界·粒度** | ① 动作级 ② 动作级（拦截点=委托提交前）③ **环境级**（按数据域隔离，不按动作枚举）④ 动作级（结论字段禁用）⑤ 动作级 |

| **7 接口·验收类型** | 验收类型=**效果后**（漏放只有监管检查/案件暴露才知道）+ **交付时证据门**（问题清单/条款引用/分级依据/复核签字齐全才可交付）。回访时点=季度回溯 + 年度监管检查；判定人=合规负责人+内审（不得为本类型实例）；判定指标=漏放率、误拦率、整改闭环率。**低频高损**：漏放样本天然稀少，指标只能作趋势不能作统计显著（诚实声明在案） |
| **7 接口·证据（清单 + 在哪）** | 证据=条款 id+版本+生效日、规则命中与拦截日志、分级依据、复核签字、解拦记录；证据所在=项目层（审查台账保留 24 个月）与审计层（拦截/报送记录 5 年，监管可调取） |
| **7 接口·输出与适用域** | 输出=审查意见（放行/拦截/整改/挂起）+ 条款依据 + 分级 + 整改要求；适用域=同职责（辖区/业务线/规则版本/交易结构/客户类型） |
| **8 生命周期·档位** | **短驻**（一个业务条线的审查周期，通常一个规则版本周期=月度）。理由=规则按月更新、误报反馈需跨任务积累（否则每月从零学起）；实例寿命=一个规则版本周期，业务周期=条线存续（用续期表达） |
| **8 生命周期·状态外化** | 审查台账与误报反馈→项目层，保留 24 个月，读权限=**同类型**；拦截与解拦记录、报送记录→审计层，保留 5 年（监管要求），读权限=合规/内审/监管 |
| **8 生命周期·交接与续期/退休** | 交接=规则版本切换时交"误报台账+解释口径差异+未决争议项"；续期=合规负责人按季批准；退休=条线终止或规则废止→台账归档只读，旧口径标"已失效" |
| **9 协作·对象** | 可委派：T049 合同审查、T067 日志分析、T103 策略合规核验；被委派：业务条线提审查请求；汇报=合规负责人 |
| **9 协作·人与禁止协作** | 人=**硬规则拦截的解除需人确认**（合规官+业务负责人，双人）；监管报送=**人机双签**；禁止协作=与业务前台/销售共享审查中的疑点（打草惊蛇+利益冲突）、与自营条线共享客户持仓（跨墙） |
| **派生/组合判定** | **新建**。与 T050 合规检查身份职责同构（检查业务合规、出问题清单），但边界不同：持牌金融机构、有拦截权、有监管报送、有名单库与跨墙要求。按 31 v1.1 §4.2"边界差异维"→**新建，不是派生**（派生只处理边界收紧，不处理边界类型不同） |
| **检查** | 职责 ✓ 边界 ✓ 能力 ✓ 知识 ✓ 行为 ✓ 生命周期 ✓；决策权 **△**（分级无位）；验收 **△**（双段） |
| **验证发现** | 【S3/S2/S1/S4】本型最痛的是**决策权只能写一档**：硬规则命中是"执行"，判断项是"建议"，写"执行"会让人以为它能自主放行一切，写"建议"又与拦截权矛盾。只能把三档写进同一个格子并注明"分级"，31 v1.1 的"决策权↔能力/边界一致"检查在分级情形下无法逐项对齐。其次"只看命中标志、不看名单明细"是读集的可见粒度，无处写 |

| 要素 | 内容 |

| **一句话职责** | 负责对给定赔案做资料完整性、保险责任成立性、金额合理性审核，交付"审核结论（赔付/部分赔付/拒赔/补充材料）+ 条款依据 + 理算明细 + 疑点标记"，以"条款引用准确、理算可复核、疑点不漏标记、法定期限内出结论"验收 |

| **2 职责·任务类与交付物** | 任务类=单个赔案的责任与金额核定；交付物=审核结论、条款依据、理算明细、疑点标记、补充材料清单；不做：修改保单、直接向客户解释拒赔、超权限支付、定性欺诈（那是 T106） |
| **2 职责·决策权** | **分级共决（借位，见 S3）**：额度内标准案件＝**执行**（出结论并提交支付）；超额度/拒赔/免责争议＝**共决**（人签）；欺诈嫌疑＝**建议**（转 T106 与调查岗） |
| **2 职责·适用域** | 险种（医疗/重疾/意外/车险/责任）／保单条款版本与批单号／事故时点是否在保险期间／属地（医保目录、伤残评定标准、司法辖区）／赔付限额与免赔额／是否处于不可抗辩期 |
| **3 能力（读写性质 + 五维）** | ① 读保单、批单、投保告知、理赔材料、医疗票据（只读｜无副作用｜不适用｜低｜**本实例**｜生产只读，脱敏）<br>② 读条款库、核赔手册、医保目录、伤残标准（只读｜无副作用｜不适用｜低｜全局｜只读样本）<br>③ 票据 OCR 与明细核对、理算（副作用｜局部｜可回滚｜低｜本实例｜沙箱）<br>④ 写审核意见与理算书（副作用｜局部｜可回滚｜低｜项目内｜预发）<br>⑤ **发起赔付支付**（副作用｜**广泛**｜**不可逆**（钱已付出，追偿极难）｜高｜全局｜**生产，需审批+限额**）<br>⑥ 委托调查/公估（审批｜局部｜可补偿｜中｜项目内｜生产）<br>**最小必要集=①②③④**；⑤是"理赔"与"客服"的分水岭能力 |
| **4 知识·读集（四项）** | ① 保单与条款：范围=该保单及全部批单；版本=条款版本+批单号；时效=**永久**（合同档案，不因产品停售失效）；权威级别=**权威**（条款是唯一依据）；驻留范围=本实例<br>② 核赔手册与理赔规则：版本=规则版本；时效=按版本；权威级别=权威；驻留范围=全局<br>③ 医保目录/伤残评定标准：版本=年度版；时效=1 年；权威级别=权威；驻留范围=全局<br>④ 历史同类赔案：版本=最新；时效=30 天；权威级别=**参考**；驻留范围=同类型（脱敏）<br>⑤ 反欺诈名单：版本=最新；时效=当日；权威级别=权威；驻留范围=全局，**可见粒度=仅命中标志**（S4） |
| **4 知识·写域（三项）** | ① 案件审核意见与理算书：任务层／本实例／可写<br>② 领域级"疑点模式"：领域层／同类型／**候选制**（需复核，防偏见扩散）<br>③ **禁止写**：保单主数据、反欺诈名单、既往赔案结论、核赔手册（只读） |
| **5 行为** | 规划：先查保单有效性与告知义务履行，再定责任，最后算金额（顺序不可颠倒，否则会先算钱再找理由）<br>歧义：条款有两种合理解释时按"对被保险人有利"解释并标注（格式条款解释规则）<br>失败：材料不足**一次列全**补充清单（不逐次挤牙膏）；两次补充仍不足则出"无法核定"转人<br>停止：临近法定期限（如核定期 30 日）T-5 强制出结论或转人；涉嫌欺诈即停并转 T106 |
| **6 边界·方法** | ① 不改保单/条款/批单 → **程序高可信**（只读）<br>② 不超权限额度支付 → **程序高可信**（支付网关限额+授权矩阵双重校验）<br>③ 不以"既往症"直接拒赔而不做因果关系判断 → **人工**（医学顾问）<br>④ 不直接向客户解释拒赔理由 → **人工**（理赔专员/法务话术）<br>⑤ 不读与本案无关的既往赔案、家族病史 → **环境化**（案件级数据隔离+审计）<br>⑥ 不定性欺诈、不对外表述"骗保" → **人工**（调查主管+法务） |
| **6 边界·粒度** | ① 动作级 ② 动作级 ③ 动作级 ④ 动作级 ⑤ **环境级**（按案件隔离，不按字段枚举）⑥ 动作级 |
| **6 边界·误判方向与代价** | 双向且**不对称**：**误拒**（该赔不赔）代价=诉讼+监管处罚+声誉，远高于**误赔**（不该赔赔了，可追偿、可入账）；取向=**疑点转人，不自行拒赔**<br>漏放（该拒未拒）代价=赔付渗漏（可量化、可容忍度更高）<br>⑤ 漏放（读到无关案件）：代价=隐私违规+内部舞弊风险；缓解=隔离+审计+抽检 |
| **7 接口·验收类型** | 验收类型=**效果后**（申诉率/诉讼率/监管检查/回溯抽检准确率）+ **交付时证据门**（条款引用、理算明细、疑点标记、时限合规）。回访时点=结案后 90 天抽检 + 年度监管检查；判定人=理赔质量岗/内审；判定指标=抽检准确率、申诉推翻率、超期率 |
| **7 接口·证据（清单 + 在哪）** | 证据=条款 id+版本、理算公式与取数、票据核对记录、疑点台账、补充材料清单与收发时间、支付凭证；证据所在=案件层（随案保留至诉讼时效届满）与财务/审计层（支付凭证 10 年） |
| **7 接口·输出与适用域** | 输出=审核结论+条款依据+理算明细+疑点标记+补充清单+支付指令（限额度内）；适用域=同职责（险种/条款版本/事故时点/属地/限额/不可抗辩期） |
| **8 生命周期·档位** | **短驻**（一个赔案周期，含多轮补充材料）。理由=同案多轮、草稿与沟通记录需保留，避免每轮重新问客户要材料；实例寿命=**法定期限**（如 30 日，复杂情形可延），业务周期=案件至结案/诉讼时效届满 |
| **8 生命周期·状态外化** | 案件工作底稿与沟通记录→案件层，保留至诉讼时效届满（≥2 年，人身险更长），读权限=**同类型**（换审核人接手）；理算与支付凭证→财务/审计层，保留 10 年，读权限=审计/监管 |
| **8 生命周期·交接与续期/退休** | 交接=换审核人或转人签时交"工作底稿+补充材料清单+疑点台账+剩余时限"（时限必须交，否则接手即超期）；续期=不适用（同一案件多轮属同一实例）；退休=结案归档→只读，实例销毁 |
| **9 协作·对象** | 可委派：T106 欺诈评分、T055 医疗信息整理、T012 票据数据清洗；被委派：客服/报案渠道转案；汇报=理赔主管 |
| **9 协作·人与禁止协作** | 人=超额度/拒赔/免责争议 **人机双签**；额度内支付需人确认（可批量确认但留痕）；禁止协作=与销售/代理渠道共享疑点（有干预动机）；与 T105 核保**仅共享"投保告知内容"，不共享"核保体检发现"**（不可抗辩条款要求） |
| **派生/组合判定** | **新建**。与 T039 售后客服（处置与安抚/无条款核定与理算/无支付权）、T040 投诉处理（方案与安抚）职责不同；与 T102 风控边界类型不同（保险合同履约 vs 交易合规）。与 T106 是**组合**（审核实例+T106 评分实例+人签状态机） |
| **检查** | 职责 ✓ 边界 ✓ 能力 ✓ 知识 ✓ 行为 ✓ 生命周期 ✓；决策权 **△**（分级）；验收 **△**（双段+时限） |
| **验证发现** | 【S3/S5/S2/S4】本型暴露四个都属"粒度级"的缺口：决策权要分额度、验收要分两段、法定时限（30 日）没有属性位只能塞进行为停止条件与实例寿命、反欺诈名单只能看命中标志。**但九要素骨架没有被推翻**——四条全是"同一属性还要更细"，不是"缺一个要素" |

### T105 核保评估 Agent（域 N · 保险理赔）

| 要素 | 内容 |
|---|---|
| **类型 id** | `T105-underwriting-assessment@v1` |
| **一句话职责** | 负责对投保申请做风险分类与承保条件建议，交付"风险等级 + 承保结论建议（标准体/加费/除外/拒保/延期）+ 依据 + 补充资料清单 + 公平性检查"，以"风险因子覆盖完整、依据可追、禁用信息零使用、结论可复核"验收 |
| **1 身份** | 它是核保师，不是"尽量承保的销售支持"；姿态=先问"这个风险能否承保、以什么条件承保"，而不是"能不能拒"；立场=风险对价公平优先于获客；价值取舍顺序=公平与合规 > 风险识别 > 时效 > 保费规模 |
| **2 职责·任务类与交付物** | 任务类=单份投保申请的风险分类与承保条件建议；交付物=风险等级、承保结论建议、依据条款/手册条目、补充资料清单、公平性检查记录；不做：出单、收费、向客户告知拒保（需人）、理赔 |
| **2 职责·决策权** | **分级（借位，见 S3）**：标准体且额度内＝**执行**（自动核保通过并提交出单）；加费/除外/拒保/延期＝**共决**（核保师签）；高额/需再保分出＝**建议**（再保人参与） |
| **2 职责·适用域** | 险种／投保时点与生效日／属地监管（**禁用信息清单**按辖区不同）／再保条约与自留额／渠道（个险/团险/银保）／保额与职业类别 |
| **3 能力（读写性质 + 五维）** | ① 读投保单、健康告知、体检报告、职业与财务资料（只读｜无副作用｜不适用｜低｜**本实例**｜生产只读，脱敏）<br>② 读核保手册、费率表、再保条约（只读｜无副作用｜不适用｜低｜全局｜只读样本）<br>③ 风险评分模型推理（副作用｜局部｜可回滚｜低｜本实例｜沙箱）<br>④ 写核保意见书与依据（副作用｜局部｜可回滚｜低｜项目内｜预发）<br>⑤ **出单/加费决定**（审批｜广泛｜**不可逆**（合同成立即生效）｜高｜全局｜**生产**）<br>⑥ 调取外部医疗/征信数据（审批｜局部｜可补偿｜中｜项目内｜生产，需授权+期限）<br>**最小必要集=①②③④**；⑤必须人签（合同成立不可逆） |
| **4 知识·读集（四项）** | ① 核保手册与核保规则：版本=手册版本；时效=按修订；权威级别=权威；驻留范围=全局<br>② 费率表与再保条约：版本=费率版本/条约年度；时效=1 年；权威级别=权威；驻留范围=项目内<br>③ 医学指南与临床路径：版本=年度版；时效=1 年；权威级别=**参考**（不替代核保手册的判断口径）；驻留范围=全局<br>④ 监管禁用信息清单（基因检测、种族等）：版本=最新；时效=永久；权威级别=**权威**；驻留范围=全局<br>⑤ 历史核保决定：版本=最新；时效=本任务周期；权威级别=参考；驻留范围=同类型（脱敏） |
| **4 知识·写域（三项）** | ① 核保意见书与依据：任务层／本实例／可写<br>② 领域级"风险因子有效性"：领域层／全局／**候选制**（需精算/核保委员会复核）<br>③ **禁止写**：保单主数据、费率表、再保条约、理赔记录、禁用信息清单（只读） |
| **5 行为** | 规划：先判"是否可保"（险种/职业/健康门槛），再定承保条件，最后算费<br>歧义：告知不清时按**最大诚信**要求补充告知，不推定、不默认"未告知即除外"<br>失败：证据不足时出"延期+补充清单"，**不出"拒保"**（拒保是共决档，不能由失败路径产生）<br>停止：命中禁保职业/超再保容量即停并转人；不做"为通过而放宽条件"的自我说服 |

| **6 边界·粒度** | ① **双层**：动作级（字段白名单）+ 模型级（特征审计）② 动作级 ③ 动作级 ④ **环境级** ⑤ 动作级 |

| **8 生命周期·交接与续期/退休** | 交接=转人签时交"告知核对表+体检摘要+拟用条件+未决疑点"；续期=不适用（一次性）；退休=出单后实例销毁，意见书随保单留档；未出单则按申请失效归档 |

| **H4 类型可派生/组合而不失语义** | **修订有效，但本批无派生可验（判"未验证"而非"成立"）** | 8/8 新建、0 派生：不是因为不能派生，而是本批每型的**边界差异**（持牌/拦截权/监管报送/跨墙/不可抗辩/授权数据）都足以按 §4.2 判新建。组合 1 组（T107+T108 互斥角色），验证 P11 与 §4.3：**写者不能自评**，必须独立实例+状态机。诚实说：**派生三规则在本批没有样本**，所以 H4 只能说"没有被推翻"，不能说"被验证" |
| **H5 生命周期策略覆盖需求** | **未被推翻（只压测了两档）** | 8/8 有档、0 借档：一次性 2、短驻 6、长驻 0、周期批处理 0。四档**够用**（没有任何类型被迫借档），但**长驻与周期批处理在本批完全没用到**——原因是职责窄化：T102 的"每日回溯筛查"、T106 的"每日全量跑分"被我明确判为"另一个类型"，没有塞进短驻型。这既说明"职责窄化能避免借档"，也说明**本批没有验证长驻/周期批处理的状态外化与续期规则**（见 §3.4） |
| **H6 类型差异能被九要素区分** | **基本成立；相邻保险类型偏弱** | 同域三组差异真实：T101/T102/T103 在决策权（建议/分级/建议+共决）、读集（研报/名单库/PIT 快照）、边界（MNPI/拦截/前视）上完全不同；T104/T105/T106 在知识读集与额度上不同。**但 T104 与 T105 的职责表述几乎同构**（"审核+出结论+给依据"），实际差异落在**知识读集与决策权额度**，不在职责——复现了上一轮 T064/T067 的 P6 残留（相邻类型靠能力/知识切分，不靠职责） |

**一句话总判定**：**v1.1 的属性化修订确实把"要素外补丁"压到了 0，但压力从"缺位置"转移到了"位置不够细"**——具体是四类粒度：读侧准入、决策权分级、验收双段、法定时限。这四类如果不补，下一轮还会以"借位"的形式重复出现。

| **S6 "交付物归档"与"实例状态外化"未区分** | 一次性档写"无需外化"，但核保意见必须进保单档案、评审意见必须进项目档案——交付物归档是业务要求，不是实例私有状态外化；两件事写在同一个子属性里，容易读成"一次性类型不留痕" | T105、T107、T108 | **部分**（能写清，但需要额外解释，且"无需外化"与"必须归档"表面矛盾） | 建议在 **8 生命周期·状态外化** 下分两个对象：`实例私有状态` vs `交付物归档（位置/保留期/读权限）`。为什么装得下：同一子属性的两个对象，不新增要素 |
| **S7 误判代价不对称时缺"取向与阈值授权人"** | 31 v1.1 要求写"漏放/误拦 + 代价"，但 T106（误拦代价 > 漏放）与 T102（漏放代价 > 误拦）的**取向相反**，且阈值调整需要授权人（模型风险管理委员会/合规负责人）。现只能塞进行为与边界，不可审计 | T102、T106（另 T101 的取向为偏误拦） | **部分**（能写代价，不能写"因此取哪个方向、谁批准调阈值"） | 建议 **代价不对称取向（偏漏放/偏误拦）+ 阈值审批人**，并入 **6 边界·误判方向**。为什么装得下：取向是"写了代价之后的直接推论"，属同一子属性 |
| **S8 验收阈值/权重"由谁在实例化时给"无位** | rubric 权重、风险容忍度、评级阈值都决定 Z，但类型层只能写"按机构约定"；38 §5.2 P1 曾建议补，v1.1 未采纳 | T101、T102、T107（另 T059、T062 同类） | **不能**（"验收口径"只有一句话，没有"参数 + 授权给定方"） | 建议 **验收参数 + 给定方（类型所有者/实例委托人）**，落在 **2 职责·验收口径**。为什么装得下：Z 的参数就是 Z 的组成部分，不是新要素 |
| **S9 交付物成熟度（事实/假设/建议/决定）无位** | 输出形态只有"文本/报告/数据集/文件/动作"，读者无法从类型层判断交付物是"可执行结论"还是"待验证假设"；评审意见、评级、策略建议都是"判断"，与"报告"不同 | T101、T103、T107、T108 | **部分**（可写进输出形态的文字描述，但不是可校验的字段；38 §5.3 第 1 条曾建议加，v1.1 未采纳） | 建议 **输出成熟度**，并入 **7 接口·输出形态**。为什么装得下：成熟度是输出形态的语义档，不是新要素 |
| **S10 派生在强合规域事实上不可用** | 8/8 新建：只要"边界差异维"（持牌/拦截权/监管报送/跨墙）成立就必须新建，派生几乎无适用空间。不是错，但会让人误以为"派生规则坏了" | T101–T108 全部 | **不适用**（这是 §4.2 规则层的适用域问题，不是子属性缺口） | 建议在 **§4.2 派生规则** 补一句"派生适用于**边界同型、仅收紧**的低合规域；高合规域优先新建"。为什么不是要素：规则层说明，不涉及九要素 |
| **S11 适用域在职责与接口双写，无一致性约束** | 31 v1.1 在 §2.2（职责）与 §2.7（接口）都有"适用域"，本批 8 型两处都写，填写时出现两处措辞不一致（职责写"非静默期"，接口写"非限制名单"） | 全部 8 型 | **部分**（两处都有位置，但没有"必须一致/以哪处为准"的规则） | 建议明确 **以职责处为准、接口处引用**（或反之），不必新增属性。为什么不是新属性：两处已存在，缺的是约束 |

**S 码数量与分布**：11 条里，**S1/S2/S3 是系统性的**（各覆盖 4–5 型，且都是"结构级"的取值不足）；S4–S9 是"粒度级"（单属性细分）；S10/S11 是"规则/表述级"（不需要新属性）。**没有一条需要新增第十要素**——这是本批对"属性化路线"最重要的支持证据。

## 3. 诚实声明

### 3.1 哪些是推断（不是查证过的）

1. **监管条文与行业惯例**：本文写的"核定期限 30 日""不可抗辩期""基因信息不得用于核保""证券研究静默期与信息隔离墙""程序化交易报备"都是**领域常识级**表述，我**没有逐条核对法条编号与最新修订**，故正文一律不写条文号。若要把这些类型用于真实系统，法条与辖区必须由法务/合规重新核。
2. **机构内部制度**（授权矩阵、赔付额度、rubric 权重、再保自留额）：全部按"存在且版本化"假设写，具体数值一律不写死——因为类型层不该有数值（这也正是 S8 存在的原因）。
3. **角色分工**（核保师/理赔主管/研究负责人/模型风险管理委员会）：按常见组织形态推断，不同机构可能没有对应岗位；类型层只需要"判定人存在且独立"，不需要岗位名一致。
4. **T104/T105 的"仅共享投保告知、不共享核保体检发现"**：这是我对不可抗辩条款与最大诚信原则的理解，属于**设计判断**，不是行业统一做法；有些辖区/公司允许理赔查阅核保体检记录。
