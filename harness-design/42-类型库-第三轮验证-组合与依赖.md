# 42 类型库 · 第三轮验证 C：组合与依赖

> 范围：只压「组合与依赖」——v1.2 里最晚补、样本最少的一块（31 §4.3 提名四件但「移交契约」无字段定义；41 §9 第 4 条把它列为未解；34 §6.2 把「依赖降级缺枚举」与「组合内部禁止协作只有反例」列为三处最弱之二）。
> 边界：只新建本文件，不改 31/34/35–38/41；不新增第十要素；成员类型的 20 行登记仍在 35–38，本文件只写「进组合后覆盖的行」。
> 结论摘要：四件里 1 件可声明（多类型）、2 件半可（状态机、依赖）、1 件不可（移交契约）；依赖降级三档确认不足（还需「范围降级」与「节奏降级」）；组合件当前只有「组合 owner 签字」一个责任人，没有登记位。
> 日期：2026-11-21｜性质：第三轮 C 线验证记录（不是设计稿）

## 0. 范围与口径

### 0.1 本轮验什么

二轮 41 的结论是「补属性解决了写不下，没有解决判不了」。本轮顺着这条线只问三件事：

1. 31 §4.3 的「组合形态四件」（多类型 / 状态机 / 依赖声明 / 移交契约）在 v1.2 的字段集里，到底能不能真的写出来——能写到什么粒度。
2. 组合层缺哪些**登记位**（不是缺哪个要素；九要素不动）。缺位一律给新卡点 S 码，并逐条对照 41 的 U 码。
3. 依赖降级能不能枚举；L 域（红队 / 越狱 / 无边界）能不能作为组合成员。各做一个小样本。

### 0.3 写法口径

- **成员类型不重写 20 行**：T0NN 的 20 行在 35–38，本文件只写「组合内覆盖的模板行」与「P11 判定」。理由：避免第二份事实来源（34 §7.3 硬约束）。
- **每个组合件 = 成员与席位表（≤7 行）+ 组合声明（10 项）+ 依赖降级实测 + 签批实测 + 卡点**，控制在 30–40 行。
- **组合件编号 T217–T222 沿用任务给定**，只作验证编号；正式登记建议另立命名空间（S01），因为 T 编号空间已用到 T122。
- **卡点必须写清**：卡在哪个字段 / 缺哪个登记位；不写「不适用」了事。
- **判定一律引条款号**，不引二手转述；组合声明里的每个值都能回到 31 §2.x 或 34 §4 的某一行。

### 0.4 缩写与判据

- **U 码** = 41 §4 的 22 条二轮卡点；**P 码** = 38 §5.2 的卡点；**S 码** = 本轮新卡点（S01–S10）；**G 码** = 34 §0.2 的六组改动。
- **「四件」** = 多类型 / 状态机 / 依赖声明 / 移交契约（31 §4.3）。
- **「三档」** = 34 §6.2 提到的「不出结论 / 只出建议 / 人工接管」。
- **P11 三问速记**：交付物（有独立交付物？）/ 边界（有独立边界？）/ 委派（可被单独委派？）。三问全 ✓ = 类型；只签署 / 排序 / 转发 = 流程节点（31 P11、U22）。表中记作 `✓✓✓`。
- **行号**指 34 §4.1 的 20 行模板行号（行 4 职责、行 9 输出、行 10 验收、行 14 档位、行 18 协作）。

### 0.5 不做

1. 不新增第十要素（41 §4 已 22/22 在九要素内找到落点，34 §6.3 推算三原则已定）。
2. 不改 35–38 的成员 20 行，不重排 T101–T122，不重算三列。
3. 不给组合件建 20 行模板——组合件不是类型（D8 / P11），给它建模板就等于把组合件偷渡进类型库。

## 1. 六个组合件

### T217 生产事故处置组合（J 域）

**成员与席位**（4 席 / 3 类型）

| 席位 | 成员类型 | 组合内职责与交付物（覆盖行 2/9） | 决策权与边界（行 4/6） | P11 | 判定 |
|---|---|---|---|---|---|
| A1 发现者 | `T067-log-analysis@v1` | 告警聚类 + 事件初判（定级 / 影响面 / 首条证据） | 建议；只读日志、不删日志 | ✓✓✓ | 类型 |
| A2 取证者 | `T067-log-analysis@v1`（第二实例） | 证据固化包：时间线、可重跑查询、脱敏样本 | 建议；行 18 覆盖=人只被告知 | ✓✓✓（席位独立） | 类型 |
| B 指挥 | `T064-incident-response@v1` | 处置方案 + 处置记录 + 复盘输入 | 共决（低危执行 / 高危只提议）；回滚须审批 | ✓✓✓ | 类型 |
| C 取证 / 隔离审批 | `T068-change-review@v1` | 变更相关性结论 + 隔离动作放行意见 | 建议（不执行）；不批自己起草的变更 | ✓✓✓ | 类型 |

**组合声明**（10 项）

1. **多类型**：3 类型 4 席；A1/A2 同类型两实例，只靠席位区分目的（发现 vs 取证）——这也是「禁止协作」唯一能落地的方式（S03）。
2. **状态机**：P1 报警（告警到达且影响面定级完成）→ P2 隔离（判为用户可见或资损）→ P3 处置（隔离完成且时间线冻结）→ P4 复盘（证据包封存）。迁移判据可写；超时迁移的执行主体无位（S07）。
3. **依赖声明**：B→A1（缺 A1：B 只出建议不出处置记录，阻塞启动）；C→B（缺 B 的事故上下文：C 只出「无法判定」，降级为不出结论）；A2→原始日志源（对象不是类型，S04）。三档不够，实测还用了「挂起」（S05）。
4. **移交契约**：A1→B/C 交「初判报告」（每条结论追到日志行、定级附影响面口径；缺依据退回）；A2→人 交「证据包」（时间线每点有查询 id、脱敏检查通过；含 PII 拒收）；C→B 交「变更相关性三值结论」（是 / 否 / 不确定 + 待查项；缺回滚评估退回）；B→人 交「处置记录 + 复盘」（每动作有审批人、改进项有责任人；缺审批人拒收）。
5. **组合内禁止协作**：① A2 不得读 A1 的初判结论，只读原始日志——理由=取证独立性，否则发现者兼取证者，证据链自证；② C 不得引用 B 的自评分或自评复盘作为放行依据——理由=审核实例不得与执行实例共享分数（T104/T106 同型）；③ B 不得自评复盘（写者不得自评，D4 延伸到组合）。
6. **人机双签**：P2 隔离=人机双签（执行档 + 不可逆，值班主管签）；P4 复盘=人确认（共决档）；P1/P3=人只被告知（A1 建议档、B 低危执行档）。与决策权档位一致；但「隔离动作」的档位写成员行 4 还是组合声明，两处都能写（S06）。
7. **适用域与前置条件**：生产环境、值班期内；前置=可执行回滚脚本 + 告警通道可用；前置缺失时的行为（不启动还是降级）无字段。
8. **登记与版本**：组合声明不入类型库（D8），写独立组合登记处（§2.5），记 comboId@v、成员 id@版本区间、状态机、依赖、移交、禁止协作、owner。
9. **复核触发**：T064 升版改「低危」定义、或 T068 放开「不批自己起草」→ 组合必须重评；当前无触发器（S09）。
10. **卡点**：S03（席位≠类型）、S05（降级档不足）、S06（档位落点冲突）、S08（「不得共享分数」用「禁止调用」表达不了）。

**依赖降级实测**（缺什么 → 落到哪一档）

- 缺 A1 初判 → 只出建议 + 阻塞启动：两个字段同时填，语义重叠（S05：不够）。
- 缺原始日志源 → 不出结论（A2 只交「无法取证」）：够。
- 缺 C 的变更结论 → 人工接管（隔离审批转值班主管）：够。
- 缺回滚脚本 → 挂起（进不了 P3）：挂起不是档，是「阻塞启动=true」的后果（S05：不够）。

**签批实测**（哪阶段必须人、哪阶段只需告知；与档位是否一致）

- P1 报警 / P3 处置 = 人只被告知：A1 建议档、B 低危执行档，一致。
- P2 隔离 = 人机双签：B 共决档 + 不可逆，一致。
- P4 复盘 = 人确认：B 共决档，一致；但「阶段级档位写成员还是组合」无位（S06）。

### T218 并购尽调组合（G + H 域）

**成员与席位**（4 席：3 类型 + 1 缺位）

| 席位 | 成员类型 | 组合内职责与交付物（覆盖行 2/9） | 决策权与边界（行 4/6） | P11 | 判定 |
|---|---|---|---|---|---|
| L1 法务 | `T049-contract-review@v1` | 条款风险清单 + 可替换文本 + 律师介入问题 | 建议；不出法律意见、不代签、对外发送须审批 | ✓✓✓ | 类型 |
| L2 财务 | `T051-financial-analysis@v1` | 分析结论 + 异常项 + 口径说明 | 建议；不出审计意见、不改账 | ✓✓✓ | 类型 |
| L3 业务 | `T043-industry-research@v1` | 行业 / 业务报告 + 来源清单（含证据强度列） | 建议；不给投资建议、不预测股价 | ✓✓✓ | 类型 |
| 汇总 | 库内无此类型（T046 兼任会犯写者自评） | 风险清单六类 + 信息缺口表 + 红旗项 | 库内无边界可引 | 交付物✓ 边界✓ 委派✓，但无类型可落 | 类型缺位（S04） |

**组合声明**（10 项）

1. **多类型**：3 类型 + 1 缺位；缺位不得用 T046 顶替（T046 自己也出风险清单，等于写者自评），也不得由 L1–L3 任一兼任（34 §3.1 已说组合的决策权应在组合声明，同理汇总权也不在成员上）。
2. **状态机**：立项（目的 / 深度 / 授权材料清单确认）→ 三线尽调（可并行）→ 交叉质询（每线对另两线的关键假设提 1–3 个质询）→ 汇总（缺口表 + 风险分级）→ 投决（人）。迁移判据：质询「每条有答复或标未答复」；汇总「每类风险有结论或入缺口」；投决「缺口表经人确认」。
3. **依赖声明**：三线互不依赖（可并行）；汇总→三线全交（缺→阻塞启动）；投决→汇总 + 缺口表（缺→阻塞）；L2→L3 的业务口径（缺 L3：L2 只出财务事实不出经营结论=只出建议）。缺 L1：不出投资结论、只出财务/业务建议；缺 L2：范围降级为只出法务 + 业务（S05）。
4. **移交契约**：每线交「底稿 + 证据清单（来源 / 日期 / 口径）+ 置信度 + 未获取项」；验收=每条风险有「事实-依据-等级-影响」；拒收=无来源的事实、把媒体转载当已证实。汇总交「六类风险清单 + 缺口表 + 红旗项」；验收=缺口有未获取原因与替代核验路径；投决材料验收=每条建议标成熟度（事实 / 假设 / 建议 / 决定，行 9）。
5. **组合内禁止协作**：① L2 与 L3 不得互相打分——理由=业务规模假设与财务收入预测同源，互评即共谋（T104/T106 同型）；② 汇总席位不得由 L1–L3 兼任——理由=写者不得自评；③ 三线不得互读对方的置信度自评分作为加权依据——理由=审核实例不得与评分实例共享分数。
6. **人机双签**：投决=人决定（组合决策权在人）；交叉质询=人只被告知；三线结论进投委会材料=人确认（T049/T051 的「对外发送须审批」在此升级为组合级门）。
7. **适用域与前置条件**：标的 + 尽调目的 + 已授权材料清单；前置=授权材料到位。同一标的不同目的算不同组合实例，不得复用结论。
8. **登记与版本**：组合声明绑定「目的 / 深度」；成员 id@版本区间；汇总类型的落点（新建 T2xx 或明确由人承担）必须先定，否则组合不可实例化。
9. **复核触发**：T049 升版若放开结论句、或 T051 改异常阈值口径 → 组合重评；无触发器（S09）。
10. **卡点**：S01（组合声明无载体）、S02（移交契约缺版本与追溯 id）、S04（成员缺位）、S08（交叉质询算不算「调用」无法判）、S10（「汇总」的 P11 判定不唯一）。

**依赖降级实测**（缺什么 → 落到哪一档）

- 缺 L3 业务线 → 只出建议（L2 只出财务事实、不出经营结论）：够。
- 缺 L1 法务线 → 只出建议（不出投资结论，只出财务 / 业务）：够。
- 缺 L2 财务线 → 范围降级（只出法务 + 业务，不出估值区间）：三档没有「范围」这一维（S05：不够）。
- 授权材料未到 → 阻塞启动（三线都不启动，降级档因此无意义）：与 S05 同一处语义重叠。

**签批实测**（哪阶段必须人、哪阶段只需告知；与档位是否一致）

- 立项 / 交叉质询 = 人只被告知：三线都是建议档，一致。
- 投决 = 人决定：组合决策权在人，成员只有建议档，一致。
- 三线结论进投委会材料 = 人确认：T049 / T051 的「对外发送须审批」升级为组合级门，一致。

### T219 临床路径组合（H 域）

**成员与席位**（4 席：1 类型 + 2 缺位 + 1 流程节点）

| 席位 | 成员类型 | 组合内职责与交付物（覆盖行 2/9） | 决策权与边界（行 4/6） | P11 | 判定 |

| 用药审核 | 库内无类型（T050 是通用合规，合规依据换维） | 审核意见 + 相互作用证据 + 替代方案 | 库内无（候选新建） | 交付物✓ 边界✗ | 类型缺位（S04） |
| 随访 | 库内无类型（T041 是续费回访，职责换向 + 对外义务不同） | 随访记录 + 失访原因 + 复诊提醒 | 库内无（候选新建） | 交付物✓ 边界✗ | 类型缺位（S04） |
| 医生签字 | 流程节点（只签署） | 签字回执 + 责任归属 | 法定责任在人 | 交付物△ 边界✓ 委派✓ | 流程节点（S10） |

**组合声明**（10 项）

1. **多类型**：表面 3 类型，实测只有 1 个可直接用；另外 2 个（诊断建议、用药审核）按 31 §4.2 顺序 1（职责换向）与顺序 2（边界换维：合规依据从通用法规换成临床指南 / 说明书）都必须新建，随访同样换向。这是本轮最强的「组合反过来暴露类型库缺位」的样本。
2. **状态机**：入径评估（诊断明确 + 指南版本确认）→ 诊断建议（假设 + 依据 + 待医生判断）→ 用药审核（相互作用证据 + 替代方案）→ 执行（院内，不在 agent 边界内）→ 随访 → 出径。迁移判据：诊断建议「每条假设有依据条目、不确定项列出」；用药审核「每项有相互作用证据与一个替代方案」；出径「随访完成或标失访」。
3. **依赖声明**：用药审核→诊断建议（缺→只出「无法审核」，不出结论）；随访→用药审核（缺→人工接管随访计划）；诊断建议→指南库版本（外部数据源，S04）。缺诊断建议时**阻塞启动**——没有诊断假设就没有可审对象，此时「降级」无意义（S05）。
4. **移交契约**：诊断建议交「假设 + 依据条目 + 不确定性 + 待医生判断项」；验收=每条依据可追到指南条目；拒收=出现确诊或剂量表述。用药审核交「三级意见（通过 / 条件通过 / 阻断）+ 依据 + 替代方案」；验收=阻断有可复核依据；拒收=无证据条目。随访交「随访记录 + 失访原因」；验收=含时间 / 渠道 / 患者原话；拒收=含他人病历或做跨患者关联。
5. **组合内禁止协作**：① 信息整理不得向用药审核提供「整理后的判断」，只交原始材料的结构化结果——理由=同一实例既整理又审核会把自家摘要当证据（写者自评）；② 用药审核实例不得引用诊断建议实例的自评分或置信度——理由=审核不得与评分共享分数；③ 医生签字不得由任何 agent 代签——理由=T078 边界：机器签不是充分条件。
6. **人机双签**：诊断建议=人机双签（共决，医生签）；用药审核=人机双签（执行档，药师 / 医生签）；随访=人只被告知；入径与出径=人确认（属临床决策）。与决策权档位一致。
7. **适用域与前置条件**：适用域必须是「已有明确指南版本的病种 + 中国大陆地区 + 成人」；前置=指南版本、院内路径版本、患者授权。前置缺失时组合不得启用，但无字段承载（S01）。
8. **登记与版本**：组合声明绑定指南版本与路径版本（临床路径本身是版本化文档）；成员新建（诊断建议 / 用药审核 / 随访）落库前，组合只能登记为「待建组合」，不能实例化。
9. **复核触发**：指南更新、路径改版、成员升版 → 组合重评；无触发器（S09）。
10. **卡点**：S04（成员缺位 + 外部指南依赖）、S10（签署判节点，但签署承担法定责任）、S02（移交物必须绑定指南版本，契约无版本字段）。

**依赖降级实测**（缺什么 → 落到哪一档）

- 缺诊断建议 → 阻塞启动（没有诊断假设就没有可审对象，降级无对象可降）：S05 的语义重叠再现。
- 缺用药审核 → 人工接管（药师签字）：够。
- 指南库版本过期 → 不出结论（沿用 T050 的「依据可能过期则暂停出结论」）：够。
- 缺随访 → 范围降级（只出在院路径、不出院外随访）：三档没有这一维（S05：不够）。

**签批实测**（哪阶段必须人、哪阶段只需告知；与档位是否一致）

- 信息整理 = 人只被告知：T055 建议档，一致（且它不做判断，无签批对象）。
- 诊断建议 / 用药审核 = 人机双签：共决 + 执行档，一致；双签的责任方是医生 / 药师，不是 agent。
- 入径 / 出径 = 人确认：属临床决策，一致；随访 = 人只被告知。

**组合声明**（10 项）

3. **依赖声明**：归因→核对（缺→不出结论）；关账→归因（缺→阻塞启动，不允许关账）；归档→关账（缺→挂起）。数据未就绪时实测走「范围降级」（先关已就绪科目、其余延后）——三档没有这一档（S05）。
4. **移交契约**：核对报告交「勾稽项清单 + 未过项金额差 + 取数日志」；验收=每格有查询来源；拒收=用上期值填充（T018 边界）。归因交「差异清单」；验收=每项有金额与方向；拒收=无金额。关账交「关账版本 + 引用版本号」；验收=版本号可对；拒收=引用旧版清单。
5. **组合内禁止协作**：① 核对不得对归因结论做「数据可用性评分」——理由=核对者给归因者打分，会让归因裁剪数据以过审；② 归因不得复核自己提出的差异豁免——理由=写者不得自评；③ 关账签字不得引用核对方的自评「数据质量良好」——理由=签署依据必须是可复核事实，不是自评分。
6. **人机双签**：关账确认=人机双签（法定责任在人）；差异豁免=人确认；核对报告=人只被告知。与档位一致：核对是执行档可仅告知，归因是建议档须人确认。
7. **适用域与前置条件**：月度周期、单一法人主体（多主体合并关账会跨主体读数据，需另判）；前置=账期关闭、数据分区就绪、上期已归档。
8. **登记与版本**：组合声明要写「每月 T+1 触发」与「T+3 硬时限」，但行 14/15 是型级字段，组合层无节奏与硬时限位（S01、S07）。
9. **复核触发**：T018 改模板结构、T051 改异常阈值、关账人变更 → 组合重评；无触发器（S09）。
10. **卡点**：S01（节奏 / 硬时限无位）、S05（范围降级）、S07（超时迁移无执行主体）、S10（签署判节点）。

**依赖降级实测**（缺什么 → 落到哪一档）

- 缺核对报告 → 阻塞启动（无勾稽不能关账）：降级档无意义。
- 缺差异归因 → 只出建议 + 范围降级（只关部分科目）：只出建议够，范围降级不够（S05）。
- 数据分区未就绪 → 范围降级（已就绪科目先关、其余延后）：三档没有这一维（S05：不够）。
- 上期报表未归档 → 挂起（阻塞启动）：与降级档重叠。

**签批实测**（哪阶段必须人、哪阶段只需告知；与档位是否一致）

- 核对 = 人只被告知：T018 执行档，一致。
- 差异豁免 = 人确认：T051 建议档，一致。
- 关账确认 = 人机双签：法定责任在人，一致；但「关账截止」超时后是否强制关账、谁签，无位（S07）。

9. **复核触发**：新增租户、供应商主数据变更、成员升版 → 组合重评；无触发器（S09）。
10. **卡点**：S04（外部系统依赖 + 成员缺位）、S05（范围降级）、S06（催收档位落点）、S08（租户隔离不是「调用禁止」）。

- 缺催收类型 → 人工接管（应收会计线下催收）：够。

7. **适用域与前置条件**：单服务 / 单批次；前置=回滚包、发布单审批、观察窗阈值。前置缺失即阻塞，但「阻塞启动」目前只能写在依赖栏，四件里没有独立的前置字段。

9. **复核触发**：T009 改阈值或放开「无回滚包不发布」、T001 放开授权 paths → 组合重评；无触发器（S09）。
10. **卡点**：S03（回滚双席）、S05（范围降级）、S06（预授权）、S07（超时迁移执行主体）、S09（成员升版不触发复核）。

**依赖降级实测**（缺什么 → 落到哪一档）

- 缺测试红绿证据 → 不出结论（不放行）= 阻塞启动，T009 边界已写死。
- 缺 diff → 阻塞启动（测试无对象）：降级无意义。
- 缺 DB 回滚脚本 → 范围降级（只回滚应用、不回滚 DB）：三档没有这一维（S05：不够），且它是「部分回滚」，比降级更危险。
- 缺回滚包 → 阻塞启动（T009「无回滚包不开始发布」）：降级档无意义。

**签批实测**（哪阶段必须人、哪阶段只需告知；与档位是否一致）

- 灰度 = 人只被告知：T009 执行档，一致。
- 全量放行 / 复盘 = 人确认：共决档，一致。
- 回滚 = 人机双签：执行档 + 不可逆，一致；但「发布单预先批准回滚」是预授权，能力只有「是否审批」二值（S06）。

### 2.2 必须回答的五个问题

**（1）组合形态四件在 v1.2 下是否真的可声明？**
1 件可（多类型：成员 id@版本能引用）、2 件半可（状态机：阶段与迁移条件能写，缺判定人与超时行为；依赖：方向 / 阻塞能写，对象只认类型 id、降级档不足）、1 件不可（移交契约：无字段）。换句话说：**组合形态可以描述，但不可执行**——描述出来的组合无法保证可跑（34 §8.3 的原话）。

**（2）移交契约缺什么？**
① 交付物标识（必须带产出成员的 id@版本，否则复盘追不到「哪一版谁交的」）；② 验收判据的引用方式（引成员行 10，还是另立组合级判据——两者会冲突：T064 的验收是「5 分钟内识别处置」，组合要的是「恢复 SLO」，两个判据同时成立时以谁为准没有规则）；③ 拒收 / 退回规则（谁有权拒收、退回后状态机回哪个阶段、重交次数上限）；④ 责任方与签字（移交物出问题算成员还是组合 owner）；⑤ 跨阶段追溯 id（阶段产物如何串成一条证据链）；⑥ 兼容性（成员升版后旧移交物是否仍被接受，与 S09 同源）。

**（3）依赖降级能否枚举？**
不能。三档只覆盖「结论成熟度」这一维。实测 6 件里出现三种三档装不下的情形：范围降级（T218 缺 L2 只出法务 + 业务；T220 只关已就绪科目；T221 只对已到账单供应商）、节奏降级（T220 周期批处理改按需触发）、回退（T222 全量失败回上一阶段——这已不是降级而是迁移）。另外「挂起」不是第四档，它是「阻塞启动=true」的后果，却被当成降级写。建议：成熟度（结论 / 建议 / 代执行）× 范围（全量 / 局部）× 节奏（周期 / 按需）× 接管（人 / 上游系统）四维 + 一个阻塞布尔，并明确「阻塞启动=true 时降级行为不再填」。

**（4）组合件不进类型库后「谁管它」？**
现状只有 34 §5.3 的「组合件的 R11 另需组合 owner 签字」——这是全套文档里唯一给组合责任人位置的地方。缺的是：登记表（组合声明写在哪）、id 命名空间（T 编号已用到 T122，T217–T222 只是验证编号）、成员版本区间、复核触发器、与类型库的引用完整性检查（成员被弃用 / 归档后组合怎么办）。建议轻量方案：`combos/<comboId>.md` + `C<域>-<slug>@vN` 命名 + 成员版本区间 + 复核状态位，与类型库并列但不混（§2.5）。

**（5）L 域能不能作为组合成员？**
不能直接作成员。小样本见 §2.3：T078 按 P11 是流程节点（只签署），T073 虽有独立交付物但需要「书面授权」这个创建前置，T077 需要「资源上限 / 停止条件」前置。结论：L 域是能力来源，不是成员；要用其能力按 34 §2.4 的「组合 + 创建前置」处理——但「创建前置」在组合声明里没有字段（S04/S10），所以当前只能写在正文备注，不可校验、不可拦。

### 2.3 L 域成员压力测试小样本

**样本**：在 T222 上加一个「发布签字」席，成员填 `T078-人机双签@v1`；再把 T217 的取证席换成 `T073-红队@v1`（攻击面取证）。

| 候选 | P11 三问逐条 | 判定 | 组合层后果 |
|---|---|---|---|
| T078 人机双签 | 交付物：只有签字回执（△）；边界：只在授权范围签（✓）；可单独委派：可委派的是「一个签字动作」而不是交付物（△） | 流程节点 | 不能作成员；若硬塞，组合会得到一个没有交付物的席位，移交契约无法填 |
| T073 红队 | 交付物：攻击面报告（✓）；边界：书面授权内可判、授权本身不可判（✓ 但边界锚点在类型外）；可单独委派：✓ | 类型（带前置） | 可作成员，但前置=授权书（目标 / 时间窗 / 禁止项 / 联系人）；四件无「创建前置」字段，缺授权时组合仍会正常启动 |
| T077 无边界探索 | 交付物：探索报告（✓）；边界：只有资源上限与停止条件（✓ 但在类型外）；可单独委派：✓ | 类型（带前置） | 同上；且「停止条件」本身是组合迁移条件，与状态机重叠 |

**结论**：L 域里只有「有边界锚点 + 有独立交付物」的（T073 / T077）在带前置的前提下可作成员，T078 是流程节点；T074 需要隔离靶场、T075 本身就是组合、T076 需要共享层——三者作为成员会各自把「组合」偷换成「环境」。因此本轮支持 34 §2.4 的处置（按「组合 + 创建前置」用能力），但指出该处置缺字段：**创建前置应当成为组合声明的必填项与阻塞启动条件**，否则「组合 + 创建前置」只是一句建议。

### 2.4 对 31 §4.3 组合章节与 34 §5 规则的修订建议

以下都在九要素之外做「组合件属性」，不是第十要素。

- **A. §4.3 四件 → 组合声明卡（10 字段）**：comboId@v / owner / 成员席位表（成员 id@版本区间、席位名、席位级禁止协作）/ 状态机（阶段、迁移判据、判定人、超时行为）/ 依赖（对象含外部系统与缺位成员、四维降级、阻塞布尔）/ 移交契约（5 + 1 项）/ 创建前置 / 适用域 / 复核触发器 / 与类型库引用完整性。明确一句：**组合声明是组合件属性，不是类型第十要素**。
- **B. 行 18 依赖扩三处**：对象允许「外部系统 / 数据源 / 待新建成员」；降级从三档扩成四维 + 阻塞布尔；禁止协作补两种语义（不得共享分数、不得读对方自评），不只「不得调用」。
- **C. 状态机补「迁移三件」**：判据、判定人（成员 / 人 / 门）、超时行为；与行 15 硬时限对齐，超时的执行主体必须点名。
- **D. P11 补两条**：只签署 / 只排序 / 只转发 = 流程节点（U22 已有）；若签署承担法定责任，须在组合声明里写「签署责任方」，不得靠 P11 判成类型来绕过责任。
- **E. 34 §5 增三条组合规则**（接 41 的 R13–R35）：**R36** 组合声明六字段完整（成员 / 状态机 / 依赖 / 移交 / 禁止协作 / 创建前置）；**R37** 席位唯一，且禁止协作写到席位级；**R38** 成员升版 / 停用 / 归档触发组合复核，未复核不得实例化。
- **F. 证据强度重估（34 §6）**：行 18 依赖档 C → **B**（本轮 6 件，降级行为可判但有维度缺口）；组合内部禁止协作 B → **B+**（6 件都能点名且理由可判，「是否足够治理」仍未验）；移交契约 **D → C**（需求已验证：6 件缺的是同一批 5 项）。

### 2.5 组合件登记位置（可落地的轻量方案）

- **位置**：`harness-design/combos/<comboId>.md`，与类型库分开目录、分开命名空间。
- **命名**：`C<域>-<slug>@vN`，示例 `C-J-incident@v1`、`C-H-close@v1`；本文件的 T217–T222 只作验证编号（理由：T 编号已用到 T122，T2xx 会与未来类型冲突，S01）。
- **每条记录一屏**：成员席位表（id@版本区间）、状态机（含判定人与超时）、依赖（四维 + 阻塞）、移交契约（5 + 1 项）、禁止协作（席位级）、创建前置、owner、复核记录。
- **版本化**：组合声明自身 semver；成员版本区间写 `[min, max)`；成员升版落在区间外 → 组合状态置「需复核」，不得实例化。
- **引用完整性**：成员被弃用 / 归档 → 登记处报「悬空成员」，组合声明保留（31 §4.1 弃用不删除的同理）。

## 3. 诚实声明

1. **本轮样本是构造出来的组合**，不是已落地的生产组合；「能不能跑」只做了可声明性检查，没有做实例化试跑，也没有真实组合的验收证据。
2. **成员类型只读了关键行**（职责 / 能力 / 边界 / 接口 / 协作），未逐条比对 35–38 全文；P11 判定基于各类型行 2/6/9 的自述，未做跨文件一致性核对。
3. **移交契约的 5 项缺口是从 6 件归纳的**，不是穷举；可能的第 7 项是「跨组合移交」（组合 A 的产出喂给组合 B），本轮未压——它与组合内移交不是同一个问题。
4. **依赖降级四维是实测归纳**，未做统计验证（6 件里 3 件出现范围降级、2 件出现「阻塞启动」与降级档重叠）；四维够不够要等真实组合落地。
5. **T219 没有可实例化的组合**：它的结论是「成员缺位」，属需求侧验证，不是运行侧验证；把它计入 6 件组合样本会高估本轮覆盖面。
6. **L 域只压了 T078 与 T073**，T074 / T075 / T076 / T077 未过；「L 域不可作成员」的结论对这 4 个是外推。
7. **未新增第十要素**：所有卡点都落在九要素的已有字段，或「组合件属性缺位」上；组合声明不是要素，它与 `typeId@version` 同级，属登记物。
8. **每件都留了卡点**：6 件没有一件用「一切正常」收尾，其中 T219 / T222 的卡点会让组合直接不可实例化——这不是措辞问题，是结构问题。
