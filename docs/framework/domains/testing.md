## 1 适用范围与位置

本文件规定测试与验收域怎么接判据、怎么选用例层、怎么执行、怎么判不稳定、怎么分级缺陷、怎么留证、怎么交验收。适用对象是 `specs/test/`、`scripts/ac/`、`build/report.json`、`build/evidence/`、`docs/testing/flaky.md` 以及验收记录中的测试结论。产品行为与实现质量分别由产品设计域与对应实现域判定，本文件只判测试产出是否足以支撑结论。

测试域处在契约冻结与验收签字之间。输入是冻结的 AC、变更范围、风险矩阵与实现改动；输出是 test-plan 增量、断言脚本、可复跑的测试输出、缺陷记录与交接四件。测试域不定义产品行为，也不代替验收员签字。

## 2 四层职责边界

四层指单元、集成、端到端与真机，分别回答逻辑对不对、接口与持久化通不通、用户路径走得通不通、真实设备与真实模型上能不能用。每层只判自己那一问，低层能判的行为不升到高层，高层通过不能补低层缺失。写的人与跑的人按角色分离，实现者不判定自己的产出。

### MXV2-QA-05 单元层由撰写员写、撰写员跑

- 规则：单元层用例由改动所属的撰写员编写并在点级运行，判定员只复核断言与结果，不替撰写员补用例。
- 判据：每条单元 TC 的作者是撰写员，点级运行记录的执行人也是撰写员；判定员作为作者或执行人的单元 TC 条数为 0；命令退出码 0。
- 执行：`ai-review:每条单元 TC 的作者是撰写员，点级运行记录的执行人也是撰写员`；谁判：验收员；误放行：未逐项核对“单元层由撰写员写、撰写员跑”即判通过；误拦截：证据已齐仍判不通过
- 层级：L2
- 依据：MXV2-7-03、MXV2-8-06；S-065
- 适用：纯函数、状态机、解析与校验改动。

### MXV2-QA-06 集成层由后端撰写员写、判定员变更级复跑

- 规则：接口与集成用例由后端撰写员编写并在点级跑通，判定员在变更级用同一命令复跑，复跑不通过退回原点。
- 判据：每条集成 TC 有撰写员点级运行记录与判定员变更级复跑记录各一份；只有一份的按 `missing` 计。
- 执行：`ai-review:每条集成 TC 有撰写员点级运行记录与判定员变更级复跑记录各一份`；谁判：验收员；误放行：未逐项核对“集成层由后端撰写员写、判定员变更级复跑”即判通过；误拦截：证据已齐仍判不通过
- 层级：L2
- 依据：MXV2-7-03、MXV2-8-01、MXV2-8-07；S-065

### MXV2-QA-07 端到端层由判定员写、验收员跑

- 规则：端到端用例由判定员编写，验收员在变更级与出口级运行，撰写员只提供登录态、夹具与选择器，不写端到端断言。

### MXV2-QA-08 真机层由判定员发起、验收员或用户判定

- 规则：真机与真实模型用例由判定员发起并写步骤，验收员执行与判定；用户只在出口级抽检前端效果，Lead 不执行真机与截图。

### MXV2-QA-09 层按最低可判定层选择

- 规则：一条 TC 只写一个判定层，先选能判定该行为的最低层，低层判不了才升层，禁止用高层通过替代低层缺失。
- 判据：每条 TC 的判定层唯一；纯逻辑改动的 TC 判定层为单元；用集成或端到端替代单元缺失的条数为 0。
- 执行：`ai-review:逐条核对 TC 判定层与改动路径；谁判：判定员；误放行：纯逻辑改动只写端到端用例并判通过；误拦截：改动同时含纯逻辑与界面，按主要行为选层后仍保留另一层补充观察。`
- 层级：L2
- 依据：MXV2-7-03、MXV2-7-04；S-065、S-073
- 适用：用例设计评审时。

### MXV2-QA-10 替身只用于低层，不代替集成

- 规则：桩、模拟与伪实现只允许出现在单元与组件层，接口与集成层必须打真 handler 或真后端；端到端层的 `page.route()` 注入只证明前端错误态。
- 判据：接口与集成 TC 使用替身的条数为 0；端到端 TC 的证据写明注入方式；用注入结果证明真实后端 413、403 或 500 的条数为 0。

- 层级：L2
- 依据：MXV2-7-03；S-066

### MXV2-QA-11 四层结果不互相抵扣

- 规则：单元、集成、端到端、真机四层各自记结果，任何一层失败都不得用另一层通过抵消；补充层失败按缺陷登记，不改判定层状态。
- 判据：`build/report.json` 的 layers 数组四层状态分别记录；存在“单元失败但集成通过即判 pass”的 TC 条数为 0；补充层失败有缺陷编号。

- 层级：L2
- 依据：MXV2-7-03、MXV2-8-10；S-065

## 3 判据接收与用例设计

## 6 不稳定用例
