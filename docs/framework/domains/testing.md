## 1 适用范围与位置

本文件规定测试与验收域怎么接判据、怎么选用例层、怎么执行、怎么判不稳定、怎么分级缺陷、怎么留证、怎么交验收。适用对象是 `specs/test/`、`scripts/ac/`、`build/report.json`、`build/evidence/`、`docs/testing/flaky.md` 以及验收记录中的测试结论。产品行为与实现质量分别由产品设计域与对应实现域判定，本文件只判测试产出是否足以支撑结论。

测试域处在契约冻结与验收签字之间。输入是冻结的 AC、变更范围、风险矩阵与实现改动；输出是 test-plan 增量、断言脚本、可复跑的测试输出、缺陷记录与交接四件。测试域不定义产品行为，也不代替验收员签字。

### MXV2-QA-01 只判定测试与验收产出

- 规则：本文件只判定 `specs/test/`、`scripts/ac/`、`build/report.json`、`build/evidence/` 与验收记录中的测试产出，不判定产品行为与实现质量。
- 判据：判定记录引用的路径全部落在上述位置；引用 `specs/product/` 或 `frontend/src/` 作为通过依据的条数为 0。
- 执行：`ai-review:核对判定记录引用的路径是否只落在测试产出位置；谁判：验收员；误放行：把实现文件当作测试结论，没跑用例就签通过；误拦截：引用实现文件只为定位缺陷，结论仍由测试输出支撑。`
- 层级：L2
- 依据：MXV2-7-03、MXV2-8-05；S-065
- 适用：测试评审与收口核对时。

- 规则：测试投入按单元 70%、集成 20%、端到端与真机 10% 作规划建议，只在复盘里对照实际层分布，不设门禁，不因比例偏差退回变更。
- 判据：复盘有实际层分布与建议值的对照；偏差有原因说明；以比例不达标退回变更的条数为 0。

- 依据：MXV2-9-12；S-068

## 2 四层职责边界

四层指单元、集成、端到端与真机，分别回答逻辑对不对、接口与持久化通不通、用户路径走得通不通、真实设备与真实模型上能不能用。每层只判自己那一问，低层能判的行为不升到高层，高层通过不能补低层缺失。写的人与跑的人按角色分离，实现者不判定自己的产出。

### MXV2-QA-07 端到端层由判定员写、验收员跑

- 规则：端到端用例由判定员编写，验收员在变更级与出口级运行，撰写员只提供登录态、夹具与选择器，不写端到端断言。
- 判据：端到端 TC 作者是判定员；运行记录的执行人是验收员；撰写员作为端到端 TC 作者的条数为 0。
- 执行：`ai-review:端到端 TC 作者是判定员`；谁判：验收员；误放行：未逐项核对“端到端层由判定员写、验收员跑”即判通过；误拦截：证据已齐仍判不通过
- 层级：L2
- 依据：MXV2-7-03、MXV2-8-05、MXV2-8-06；S-074
- 适用：用户路径、像素几何、遮挡与真实点击。

### MXV2-QA-10 替身只用于低层，不代替集成

- 规则：桩、模拟与伪实现只允许出现在单元与组件层，接口与集成层必须打真 handler 或真后端；端到端层的 `page.route()` 注入只证明前端错误态。
- 判据：接口与集成 TC 使用替身的条数为 0；端到端 TC 的证据写明注入方式；用注入结果证明真实后端 413、403 或 500 的条数为 0。
- 执行：`ai-review:核对替身使用位置与证据类型；谁判：判定员；误放行：用 page.route() 造 500 后写“后端 500 已验证”；误拦截：组件层用 MSW 覆盖错误态，证据类型已写明替身。`
- 层级：L2
- 依据：MXV2-7-03；S-066
- 适用：涉及错误态与外部依赖的用例。

## 3 判据接收与用例设计

测试接到的是冻结的 AC 与变更范围，不重新定义产品行为。设计阶段先把 AC 翻成可观察判据，再选层、编号、划分支、写表驱动，最后确认断言能在目标缺失时失败。判据与执行手段分开写，判据写不出可观察条件时退回契约，不在测试侧补数值。

### MXV2-QA-15 用例覆盖真实用户路径

- 规则：每条用户故事至少一条端到端路径，路径写起点、关键动作与终点，覆盖用户从进入到完成的真实操作，不用接口调用序列代替有界面的用户路径。
- 判据：每条用户故事有路径清单；端到端 TC 覆盖路径起点与终点；只有接口与组件拼接、没有完整路径的条数为 0。
- 执行：`ai-review:核对路径清单与端到端 TC 是否走真实入口与真实点击；谁判：判定员；误放行：接口全绿就认为用户路径可用；误拦截：纯后端或无界面变更，路径由接口调用序列覆盖并注明理由。`
- 层级：L2
- 依据：MXV2-7-03、MXV2-8-10；S-074
- 适用：用户故事验收前。

### MXV2-QA-16 四类分支逐条落位

- 规则：每条 AC 的用例至少覆盖正常、边界、错误、权限四类分支，任一类不适用时写 `N/A：<理由>` 与批准人。
- 判据：四类分支各有 TC 或 N/A 理由；缺类且无理由的 AC 条数为 0；只测主路径的 AC 不得判 `pass`。
- 执行：`script:node scripts/check-trace.mjs --rule MXV2-7-05` 期望退出码 0
- 层级：L2
- 依据：MXV2-7-05、MXV2-7-04；S-073
- 适用：用例设计评审时。

## 4 流水线与执行

变更级与出口级只认 `verify-all.mjs` 一次真跑的结果，点级按改动范围用 `run-ac.mjs` 跑增量。执行前先自检断言框架，执行后按退出码记状态，非 0 不得写通过。端到端用仓库内的 Playwright 依赖，不另起一套运行器。

### MXV2-QA-21 变更级只用 verify-all 单一入口

- 规则：变更级与出口级测试统一用 `node scripts/verify-all.mjs` 一次跑完构建、清单、四层验证、变异抽查与汇总，不另写串联脚本。
- 判据：命令退出码 0；生成 `build/report.json` 与 `build/manifest.json`；六层状态都在 report 的 layers 里；另写串联脚本的份数为 0。
- 执行：`ai-review:命令退出码 0`；谁判：验收员；误放行：未逐项核对“变更级只用 verify-all 单一入口”即判通过；误拦截：证据已齐仍判不通过
- 层级：L3
- 依据：MXV2-7-12、MXV2-8-03；S-067
- 适用：变更级全量回归与出口级验收前。

### MXV2-QA-22 分层跑用 --only、--skip 与 --no-build

- 规则：点级只跑改动涉及的层，用 `--only` 限定；排除某层用 `--skip`；复用已有产物用 `--no-build`；`verify-all.mjs` 不接受 `--scope`，不得把 `--scope` 写进命令。
- 判据：点级命令只含改动层；`--only` 与 `--skip` 指向同层的条数为 0；带 `--scope` 的命令条数为 0；`--no-build` 时 `build/manifest.json` 存在且校验通过。
- 执行：`ai-review:点级命令只含改动层`；谁判：验收员；误放行：未逐项核对“分层跑用 --only、--skip 与 --no-build”即判通过；误拦截：证据已齐仍判不通过
- 层级：L2
- 依据：MXV2-7-04、MXV2-7-15；S-073
- 适用：点级增量验证时。

- 判据：自检末行为 `SELF-TEST PASS`；退出码 0；自检失败后仍跑用例的轮次为 0。
- 执行：`ai-review:自检末行为 SELF-TEST PASS`；谁判：验收员；误放行：未逐项核对“跑断言前先自检断言框架”即判通过；误拦截：证据已齐仍判不通过

- 依据：MXV2-7-11、MXV2-7-12；S-076

## 5 变异抽查

变异抽查回答的是断言能不能抓住改动，不回答覆盖率高不高。每次变更只抽少量高风险纯逻辑目标，改坏目标后测试必须变红，跑完必须还原。抽查结果进复盘，存活体不直接阻断交付，但连续两轮存活同一处要登记。

### MXV2-QA-29 每次变更至少 3 条变异

- 规则：每次变更级运行从 `specs/features/<域>.yaml` 的 `mutations:` 段取前 3 条执行变异抽查，少于 3 条时阻止运行并补映射；变异由 `verify-all.mjs` 承担，`npx stryker run` 未安装。
- 判据：`build/report.json` 的 `mutations` 数组长度不小于 3；映射不足 3 条时 `verify-all.mjs` 退出非 0；本次变异条数写入报告。
- 执行：`ai-review:build/report.json 的 mutations 数组长度不小于 3`；谁判：验收员；误放行：未逐项核对“每次变更至少 3 条变异”即判通过；误拦截：证据已齐仍判不通过
- 层级：L3
- 依据：MXV2-7-15、MXV2-8-03；S-072
- 适用：变更级回归与高风险模块。

### MXV2-QA-30 变异必须变红并还原

- 规则：每个变异体改坏目标代码后对应测试必须失败，测试仍通过即判该测试是假测试，整轮变异失败；运行后目标文件必须还原到改动前字节一致。
- 判据：每条变异 `status` 为 `red`；`restored` 为 `true`；出现 `green` 或未还原时整轮退出非 0。
- 执行：`ai-review:每条变异 status 为 red`；谁判：验收员；误放行：未逐项核对“变异必须变红并还原”即判通过；误拦截：证据已齐仍判不通过
- 层级：L1
- 依据：MXV2-7-15；S-072
- 适用：变异抽查结果判定时。

### MXV2-QA-31 变异只抽纯逻辑高风险模块

- 规则：变异目标只取纯函数、状态机、金额与权限判定，不覆盖界面渲染、网络与整文件；每季度复核一次目标清单并写复核日期与复核人。
