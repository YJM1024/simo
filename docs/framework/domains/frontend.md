版本：v2.0.0，日期 2026-11-27。状态：active。位置：`docs/framework/domains/frontend.md`。

上游：`docs/framework/MOXIAN.md` 第 5 章至第 8 章；`docs/framework/v2/SOURCES.md` 的 S-050 至 S-056 与 S-074、S-075；`docs/framework/v2/RESEARCH.md` 第三章 3.5 节与 1.6 节的测试组；`docs/framework/domains/product-design.md` 第 7 节的可访问性七项。

编号口径：本文件规则编号为 `MXV2-FE-<两位序号>`，从 01 起连续，不跳号不复用；总册章级规则写作 `MXV2-<章>-<NN>`，域规则与章级规则不互相占号。

执行口径：`script:` 只写本仓库现有且可原样执行的单条命令，期望退出码 0，命令在仓库根执行。域规则的执行方式由首条依据决定：首条依据落在总册 45 条 script 规则之一时，写该脚本的 `--rule <总册编号>` 命令；首条依据是 ai-review 时写判据要点、谁判、误放行、误拦截四要素，四要素缺一不得冻结。`npm`、`go.ps1`、Playwright 等工程命令是真实可跑的单条检查，保留 `script:`，不计入总册 45 条规则集合。本文件 script 10 条、ai-review 20 条，其中复用总册单条规则 5 条不同编号、工程命令 10 条。总册 45 条 script 规则是全册的单条可跑集合，域规则是它的下位细化，一条总册规则可支撑多条域规则；四份域文件合计 script 28 条、ai-review 82 条，与总册条数不是同一集合，域文件不重复统计总册条数。

增量覆盖率没有基线时，`scripts/check-incremental-coverage.mjs` 退出码 2 属待补，不算失败；先补 `frontend/coverage/coverage-final.json` 与 `backend/coverage.out` 基线，补出后按退出码 0 判，补基线路径见 `docs/framework/v2/BACKLOG.md` 的 B-16。

可访问性的项名与阈值不在本文件重复定义，统一引用 `docs/framework/domains/product-design.md` 第 7 节的七项；本文件只写前端怎么取到证据。

## 1 适用范围与位置

本文件规定前端域怎么接契约、怎么设计组件与状态、怎么写代码、怎么自测、怎么交证据。适用对象是 `frontend/` 下的界面、组件、样式、状态与交互改动，以及 `specs/frontend/` 下的长期 spec 与变更增量。后端接口实现与产品行为定义分别由后端域与产品设计域判定。

前端处在设计契约与验收之间。输入是冻结的 AC、设计列的选择器与几何、组件 spec 与后端接口形状；输出是前端 spec 增量、组件状态矩阵、可复跑的测试证据与交给测试域的夹具。前端不定产品行为，也不代替验收作结论。

### MXV2-FE-01 只判定 frontend/ 与 specs/frontend/ 下的产出

- 规则：本文件只判定 `frontend/` 下的代码与截图证据、`specs/frontend/<域>/spec.md` 增量，以及前端提交的测试证据；产品行为按产品设计域判定，接口形状按后端域判定。
- 判据：判定记录指向的路径属于上述两类之一；指向 `specs/product/` 或 `specs/backend/` 的判定记录条数为 0。
- 执行：`ai-review:判定记录指向的路径属于上述两类之一`；谁判：验收员；误放行：未逐项核对“只判定 frontend/ 与 specs/frontend/ 下的产出”即判通过；误拦截：证据已齐仍判不通过
- 层级：L2
- 依据：MXV2-5-12、MXV2-3-08
- 适用：评审前端产出与收口核对时。

## 3 实现约定

实现只改任务卡 scope 内的文件，组件走公开出口，样式取令牌。三条约束的目的都是让改动可回滚：越界改动无法归因，绕过出口的导入拆不动组件，硬编码字面量改不了主题。

### MXV2-FE-12 样式只取令牌，硬编码字面量为 0 处

- 规则：颜色、间距、字号、圆角与阴影只从令牌取值，组件样式里不得出现字面量；确无对应令牌时先补令牌再使用，不在组件里就近写值。
- 判据：组件样式中的颜色、间距、字号字面量数为 0；新增令牌有六字段登记。
- 执行：`ai-review:扫描组件样式里的颜色、间距与字号字面量，逐个核对是否走令牌`；谁判：验收员；误放行：组件里写死 `#333`，换主题时漏改；误拦截：把令牌名里的十六进制值判为字面量。
- 层级：L2
- 依据：MXV2-5-17；S-045
- 适用：写样式与改令牌时。

### MXV2-FE-13 组件只从公开出口导入

- 规则：跨目录引用组件一律经过组件公开出口文件，页面不得引用组件内部文件，也不得维护第二份同形实现。
- 判据：绕过出口的导入数为 0；同一组件在库内实现文件数为 1。
- 执行：`ai-review:检索导入路径，确认跨目录引用都经公开出口`；谁判：判定员；误放行：页面直接引内部文件，组件拆分时整片报错；误拦截：同目录内相对引用被判为绕过出口。
- 层级：L2
- 依据：MXV2-5-11、MXV2-5-09
- 适用：写组件与重构时。

### MXV2-FE-14 不新增未批准依赖

- 规则：新增运行时依赖先写变更包并经架构师批准，批准记录写依赖名、版本、用途与替代方案；未批准的依赖不得进入 `package.json`。
- 判据：依赖变化都有变更包登记；无登记的依赖变化数为 0；批准记录四项齐全。
- 执行：`ai-review:比对 package.json 差异与变更包登记，确认每个新依赖有批准`；谁判：架构师；误放行：为一个小功能引入整套状态库，包体与维护成本失控；误拦截：把已有依赖的补丁版本升级判为新依赖。
- 层级：L2
- 依据：MXV2-4-21
- 适用：改依赖时。

### MXV2-FE-15 严格模式下双渲染结论一致

- 规则：组件在严格模式下双渲染时，同一用例的结论与单渲染一致；依赖渲染次数或副作用顺序的用例不算通过，须改写为幂等断言。

## 6 端到端

端到端只验证用户可见行为：从入口进去，用用户能用的方式操作，断言用户能看到的结果。用例自带数据、互不依赖、默认不重试；选择器与断言写法决定失败时能不能定位。

- 执行：`script:npm --prefix frontend run test:e2e` 期望退出码 0

- 依据：MXV2-7-03；S-053
