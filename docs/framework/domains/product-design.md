## 1 适用范围与位置

本文件规定产品列与设计列在墨线框架内怎么受理、怎么写需求、怎么写验收场景、怎么定设计契约、怎么定可访问性阈值，以及这些产出由谁判。前端实现、后端接口与测试执行按各自域文件判定，本文件只写它们要接住的输入。

本文件处在受理与契约之间。输入是用户请求、`docs/product/TREE.md` 的功能点与 `SOURCES.md` 的来源判定；输出是可冻结的判据、可核对的场景与可执行设计契约。判定单位是需求点：一个点的判据齐全才允许开工，缺一件按未冻结处理。

## 2 受理与立项

受理阶段把用户请求变成可判级的变更包，立项阶段把目标、范围与非目标写死。两阶段的产出不合格时后续所有判据都会失真，因此本节规则全部前移到开工之前执行，冻结后只允许按 MXV2-4-08 迁移状态。

本节对应 SOURCES 的 S-037 与 S-038 两条改造后采纳来源：故事地图给骨架与切片，INVEST 给需求点拆分自检。S-039 Job Stories 与 S-041 WSJF 不采纳，理由分别是与立项三句重复且无可核对判据、公开材料缺评分推导，两条只在文末承接表登记。

### MXV2-PD-08 优先级用 RICE 四因子算，得分不作门禁

- 规则：优先级按触达、影响、信心与工作量四个因子各写一行取值与口径，排序结论写进立项字段；得分只用于排序，不得以得分低否决需求，也不得用工作量换算成档位。
- 判据：四个因子各有一行取值与口径；排序结论在立项字段内；以得分直接否决需求的记录条数为 0。
- 执行：`script:node scripts/check-mapping.mjs --rule MXV2-4-05` 期望退出码 0
- 层级：L3
- 依据：MXV2-4-05；S-040
- 适用：排优先级时。

### MXV2-PD-09 用户活动主干先骨排再切片

- 规则：先把用户活动排成主干，再按价值切发布批次；每个切片至少含一个需求点编号，主干之外不得新增需求点。
- 判据：主干行数与切片数可数；每个切片至少含一个需求点编号；不属于任何主干的点数为 0。
- 执行：`ai-review:核对主干与切片，确认每个点能挂到主干且切片有交付物`；谁判：需求方；误放行：切片只写名称不写点编号，发布范围无法核对；误拦截：把主干内的支撑活动判为不属于主干。
- 层级：L2
- 依据：MXV2-4-06、MXV2-4-10；S-037
- 适用：规划发布批次时。

### MXV2-PD-10 需求点按 INVEST 六条自检

- 规则：每个需求点按独立、可协商、有价值、可估算、小、可测六条自检，规模上限为数人周；六条中任一条不成立时先拆点，拆完再立项。
- 判据：六条各有结论；规模超过数人周的点有拆分记录；未自检的点数为 0。
- 执行：`script:node scripts/check-points.mjs --rule MXV2-4-10` 期望退出码 0
- 层级：L2
- 依据：MXV2-4-10；S-038
- 适用：拆需求点与立项时。

## 3 需求句写法

需求句按 EARS 五句式分槽写，前置条件、触发与响应各占一槽。分槽的目的是让句子能被判真假：同一句话里出现两个响应、一个实现手段或一个没有数值的形容词，判据就无法冻结。

本节引用 S-035 EARS（采纳）与 S-025 29148 的九条需求特性（改造后采纳，只取清单作评审项）。两份来源共用的判据是句子可判，不引入第二套句式。

### MXV2-PD-13 需求句按 EARS 五句式分槽写

- 规则：每条需求句写成五种句式之一：普遍式写系统做什么，事件式写当某个触发发生时系统如何响应，状态式写处于某状态期间系统如何表现，可选式写带某特性时如何表现，不期望式写出现某情况时系统如何拒绝；前置条件、触发与响应三槽各出现一次。
- 判据：每条需求句能归入五句式之一；三槽各出现一次；归不进的句子数为 0。
- 执行：`ai-review:每条需求句能归入五句式之一`；谁判：判定员；误放行：未逐项核对“需求句按 EARS 五句式分槽写”即判通过；误拦截：证据已齐仍判不通过
- 层级：L1
- 依据：MXV2-6-05；S-035
- 适用：写需求句时；契约门评审需求句时。

### MXV2-PD-15 需求句不写实现手段

- 规则：需求句只写用户可观察的行为与结果，不写组件名、库名、表名、接口路径与内部状态字段；实现手段写进设计列或技术方案，不写进产品需求。
- 判据：句内出现组件名、库名、表名或接口路径的条数为 0。
- 执行：`ai-review:逐句检索技术名词，确认只剩可观察行为`；谁判：撰写员；误放行：需求写成“用对话框组件弹出”，换实现即失效；误拦截：把用户可见的“下载文件”判为实现手段。
- 层级：L2
- 依据：MXV2-6-05；S-025
- 适用：写需求句与评审时。

## 4 验收场景写法

场景用给定、当、那么三段写，那么段只放可观察结果。场景是 AC 的可执行形态：一条 AC 至少一个场景，一个场景只挂一条 AC，场景之间互不依赖。

本节引用 S-036 Gherkin 6（采纳，声明式场景与可观察结果）。判定五段与 Criterion 六项由总册 MXV2-7-02 定义，本节只写场景这一层，不重复定义判据字段。

### MXV2-PD-22 场景声明式，不写多点操作序列

- 规则：场景用声明式句子写状态与事件，不写“先点 A 再点 B 再输入 C”的操作脚本；单个“当”段只允许一个界面动作或一个领域事件。
- 判据：单个“当”段含两个及以上界面动作的场景数为 0。
- 执行：`ai-review:数“当”段里的动作个数，超过一个的判为不合格`；谁判：撰写员；误放行：把整条操作路径塞进一个场景，失败时无法定位；误拦截：把一个动作带两个参数判为两个动作。
- 层级：L2
- 依据：MXV2-6-05；S-036
- 适用：写场景时。

### MXV2-PD-23 一条 AC 至少一个场景，一个场景只挂一条 AC

- 规则：AC 与场景双向一一对应，一条 AC 至少有一个场景，一个场景只挂一条 AC；场景跨 AC 复用时拆成两条场景，不共享编号。
- 判据：AC 与场景双向可查且一一对应；无场景的 AC 数为 0；挂两条及以上 AC 的场景数为 0。
- 执行：`ai-review:AC 与场景双向可查且一一对应`；谁判：判定员；误放行：未逐项核对“一条 AC 至少一个场景，一个场景只挂一条 AC”即判通过；误拦截：证据已齐仍判不通过
- 层级：L2
- 依据：MXV2-7-01、MXV2-2-04
- 适用：写场景与冻结判据时。

### MXV2-PD-24 适用路径全覆盖：正常、边界、错误

- 规则：每条 AC 按正常、边界、错误三类判定适用路径，适用的每类至少一条场景，不适用写 `N/A` 加理由；错误路径至少覆盖一个可失败操作。
- 判据：正常、边界、错误三类中各适用类别至少一条场景；不适用类别有 `N/A` 加理由；缺类别的 AC 数为 0。
- 执行：`ai-review:正常、边界、错误三类中各适用类别至少一条场景`；谁判：判定员；误放行：未逐项核对“适用路径全覆盖：正常、边界、错误”即判通过；误拦截：证据已齐仍判不通过
- 层级：L2
- 依据：MXV2-7-04、MXV2-7-05；S-036
- 适用：写场景与测试计划时。

## 5 AC 与判据冻结

AC 是判定的最小单位。本节规定 AC 的编号、六段句式、Criterion 六项、判定轨道与冻结动作。判据在点开工前冻结，冻结后改动走修订登记，同一变更内同一判据只能修订一次。

## 6 设计契约

设计列的可执行内容分五类：组件状态、令牌、架构视图、决策记录与界面几何。本节把五类落到可核对的字段，字段缺一不得冻结；冻结后改动走契约变更单，一张单只改一项。

本节引用 S-043 M3 状态、S-045 DTCG、S-046 C4、S-047 ADR 四条采纳或改造后采纳来源。四条来源共同的落地方式是字段化：有值的字段能核对，原则性表述不能。

### MXV2-PD-35 组件八态矩阵覆盖八态

- 规则：组件状态矩阵覆盖默认、悬停、聚焦、按下、禁用、加载、空、错误八态，每态写触发条件、可见结果与断言；缺态写 `N/A` 加理由，不得留空。
- 判据：八态各一行且各有可见结果与断言；缺态有 `N/A` 加理由；缺项合计为 0。
- 执行：`ai-review:八态各一行且各有可见结果与断言`；谁判：判定员；误放行：未逐项核对“组件八态矩阵覆盖八态”即判通过；误拦截：证据已齐仍判不通过
- 层级：L2
- 依据：MXV2-5-17；S-043
- 适用：写组件 spec 与状态矩阵时。

### MXV2-PD-36 状态层与目标尺寸按 40dp 与 48dp 取值

- 规则：状态层高度取 40dp、交互目标取 48dp，两项写进契约表几何列；禁用态不参与对比度判定，作为例外登记并写批准人。
- 判据：状态层 40dp 与目标 48dp 各出现在几何列；禁用态例外有批准人；两项缺一的数量为 0。
- 执行：`ai-review:核对几何列两个数值与禁用态例外登记`；谁判：架构师；误放行：状态层与目标尺寸只写在设计稿里，实现按另一套数值；误拦截：把同组件在密集列表里的 24dp 例外判为违规。
- 层级：L3
- 依据：MXV2-5-17；S-043
- 适用：写组件几何与验收组件时。

### MXV2-PD-38 令牌值与类型必填，命名禁用字符

- 规则：每个令牌必须有值（value）与类型（type），类型可继承但继承链写进文件；令牌名不得含空格、不得以点号开头、不得用花括号包裹，工具不得猜类型。
- 判据：每个令牌有 value 与 type；名称含空格、点号开头或花括号的令牌数为 0。
- 执行：`ai-review:逐个读令牌文件，确认值与类型成对、名称合规`；谁判：架构师；误放行：令牌只有值没有类型，生成器按字符串处理，单位丢失；误拦截：把类型继承自父组的令牌判为缺类型。
- 层级：L2
- 依据：MXV2-6-05；S-045
- 适用：写令牌文件时；令牌评审时。

### MXV2-PD-39 C4 只画上下文与容器两级

- 规则：架构图只画系统上下文与容器两级，组件级与代码级不画；确需下探时在图上写明理由与登记人，不新增第三张图。
- 判据：上下文与容器两级图各一张；出现组件级或代码级图时写理由与登记人。
- 执行：`ai-review:核对图的数量与层级标注，确认下探有理由`；谁判：架构师；误放行：直接画组件图，读图人看不到系统边界；误拦截：容器图里画了组件方框但未标层级的情形被判为第三张图。
- 层级：L3
- 依据：MXV2-5-17；S-046
- 适用：画架构图时。

### MXV2-PD-40 ADR 五节与状态四值

- 规则：架构决策记录写标题、背景、决策、状态与后果五节，状态取提议、接受、作废、被替代四值，编号按创建顺序连续；被替代的记录保留并指向新记录。
- 判据：五节齐全；状态属于四值；编号连续；被替代记录有新记录编号。
- 执行：`ai-review:逐份读五节与状态行，核对编号连续性`；谁判：架构师；误放行：决策只写在变更描述里，半年后无法追溯取舍；误拦截：一份记录同时记两条决策被判为缺节。
- 层级：L2
- 依据：MXV2-5-17；S-047
- 适用：写 ADR 时。

### MXV2-PD-42 界面几何写选择器与断点

- 规则：每个几何项写选择器、属性、数值、单位与断点五项，选择器用稳定锚点不用类名与结构位置；同一元素在不同断点取值不同时逐档写一行。
- 判据：每个几何项五项齐全；缺项数为 0；选择器不含类名与 `nth-child`。
- 执行：`ai-review:每个几何项五项齐全`；谁判：判定员；误放行：未逐项核对“界面几何写选择器与断点”即判通过；误拦截：证据已齐仍判不通过
- 层级：L2
- 依据：MXV2-5-17、MXV2-7-08
- 适用：写界面几何与视觉验收时。

## 7 可访问性与设计准则

可访问性的七项检查以本节为唯一定义处，其它文件只引用项名与阈值，不另列一套。七项之外不新增检查项：确需新增时先改本节并登记，再由前端与验收引用。

七项与 WCAG 2.2 准则的对应关系固定如下，准则编号以 S-048 合并的十一条为限，发布日期 2024-12-12。

| 项 | WCAG 2.2 准则 | 阈值 |
|---|---|---|
| 键盘操作 | 2.1.1、2.1.2、2.4.3 | 主路径只需 Tab、Shift+Tab、Enter、Space、Esc |
| 焦点可见 | 2.4.7、2.4.11 | 轮廓 ≥2px、偏移 ≥2px、对比 ≥3:1、可见面积 ≥90% |
| 可访问名称 | 4.1.2 | 每个交互元素名称非空 |
| 对比度 | 1.4.3、1.4.11 | 正文 ≥4.5:1、大字号 ≥3:1、非文本 ≥3:1 |
| 错误识别 | 3.3.1、3.3.3 | 原因与改法齐全，不只靠颜色 |
| 减少动效 | 2.3.3 | reduce 下非必要动画 0s |
| 目标尺寸 | 2.5.8 | ≥24×24 CSS px，主操作与触控 ≥44×44 |

### MXV2-PD-43 可访问性七项为唯一集合

- 规则：可访问性检查只认键盘操作、焦点可见、可访问名称、对比度、错误识别、减少动效、目标尺寸七项，各项结论按四值写并附证据行；整块不适用时写 `N/A` 加理由并由验收确认。
- 判据：七项各有结论与证据行；出现第八项时已登记并改齐；缺项数为 0。
- 执行：`ai-review:七项各有结论与证据行`；谁判：判定员；误放行：未逐项核对“可访问性七项为唯一集合”即判通过；误拦截：证据已齐仍判不通过
- 层级：L3
- 依据：MXV2-7-14；S-048、S-049
- 适用：界面调整与新功能含界面时；出口抽检时。

### MXV2-PD-46 键盘可达，无焦点陷阱（WCAG 2.1.1、2.1.2）

- 规则：主路径只用 Tab、Shift+Tab、Enter、Space、Esc 即可完成，浮层打开后焦点进入浮层、Esc 可退出并把焦点还给触发元素；不得出现焦点被困在区域内的情形。
- 判据：主路径五键可完成；Esc 可退出浮层；焦点陷阱数为 0；焦点返回触发元素。
- 执行：`ai-review:只用键盘走一遍主路径，记录焦点序列与退出动作`；谁判：验收员；误放行：浮层只能点关闭按钮，键盘用户出不去；误拦截：把需要按住修饰键的快捷键缺失判为键盘不可达。
- 层级：L3
- 依据：MXV2-6-05；S-048、S-049
- 适用：写交互与验收界面时。

### MXV2-PD-49 错误识别给出原因与改法（WCAG 3.3.1、3.3.3）

- 层级：L3
- 依据：MXV2-6-05；S-048

### MXV2-PD-50 文本放大 200% 不丢内容（WCAG 1.4.4）

### MXV2-PD-53 Nielsen 十项作人工检查表

- 执行：`ai-review:逐项读结论与证据，确认没有把检查表当评分表`；谁判：判定员；误放行：只写“整体符合十项原则”，无法定位问题；误拦截：把某一项判为不适用的说明判为空结论。

### MXV2-PD-54 文案与术语表登记

- 层级：L3
- 依据：MXV2-5-17；S-044
- 适用：写界面文案与本地化时。
