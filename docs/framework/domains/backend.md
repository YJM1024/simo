本文件把后端域在墨线框架中的执行口径固定下来，覆盖适用范围、阶段步骤、必产出、判据写法、门禁、常见错误、对外接口、缺口补充条款与采纳落点。规则编号从 `MX-BE-01` 起连续编排，规则正文与总册第 6 章、第 8 章、第 9 章、第 10 章以及 [`TASK-MATRIX.md`](../TASK-MATRIX.md) 的八类任务配套使用。本文件的定位是后端域的作业规范，产品目标由产品 spec 定义，交互与视觉由设计 spec 定义，任务判级与门禁名称以任务矩阵为准。规则之间出现冲突时，先按任务矩阵的门禁名册执行，再把冲突登记到变更记录的未决点，不自行改口径。

## 1 适用范围与位置

后端域在五列契约表中处于第四列，向上承接产品与设计冻结的目标，向下给前端与测试提供可执行契约。任务是否适用本文件，取决于它是否改动后端代码、HTTP 或 WS 契约、数据库结构与迁移、运行时配置或错误码，任一项成立就按本文件执行。后端列写 N/A 的任务不进入本文件的阶段步骤，契约表仍保留该列与理由。

MX-BE-01 任务受理时在后端适用栏写判定结果，改动后端代码、HTTP 或 WS 契约、数据库结构与迁移、运行时配置、错误码中的任一项即标“适用”，五项都不改即标“N/A”并写理由。

MX-BE-02 接口形状开工前收齐产品 AC、设计说明中的状态与交互、当前长期 spec、相关实现与测试四类输入，缺 AC 或判据未冻结时停在契约阶段，不进入实现。

MX-BE-03 后端列填写方法、路径、鉴权要求、请求字段、成功响应、错误状态与错误码、幂等与分页语义，并在契约门接受设计、测试与 Lead 的复核，冻结由契约门 owner 执行。

MX-BE-04 后端列的产出同时交付前端与测试，前端取字段、错误码与事件载荷，测试取夹具、假上游与证据锚点，只写内部实现说明的条目不进入契约表。

MX-BE-05 长期 spec 只记录已实现或明确标注未实现的对外行为，不写前端视觉、产品文案与未裁决冲突；与产品要求不一致时登记冲突清单并交 Lead 裁决。

MX-BE-06 后端无改动的任务在契约表后端列写 N/A 与理由，后端只做内部重构且对外契约不变时仍写行为等价判据，不按 N/A 处理。

## 2 阶段步骤

后端按六个步骤推进，每一步的产出是下一步的输入，步骤之间不跳序。接口形状先于数据模型，数据模型先于实现，单测先于接口测试，自测在最后汇总证据。涉及存量数据改写时，数据模型步骤同时产出迁移计划，迁移计划未写完不开工实现。

下表给出六步的输入、动作、产出与判定人，每一步的完成以产出写入文件为准，不以口头说明为准。

| 步骤 | 输入 | 动作 | 产出 | 判定人 |
|---|---|---|---|---|
| 接口形状 | 产品 AC、设计状态、现有路由与 spec | 定方法、路径、字段、状态码、错误码、幂等与分页、事件帧 | 接口契约表与 spec 的 HTTP、WS 节 | 后端 owner 自检，设计或 Lead 复核 |
| 数据模型与迁移 | 接口形状、现有表与迁移版本、数据量 | 定表列约束索引、迁移版本、回填与切换、备份与恢复 | 数据模型节、迁移表、迁移计划 | 后端 owner 自检，设计复核 |
| 实现 | 冻结的接口与数据模型 | 按契约改代码，缺口先回写 spec | 代码与变更记录 | 实现者 |
| 单测 | 实现与失败路径清单 | 纯逻辑、迁移、权限边界先写失败用例 | 包内测试与运行输出 | 实现者 |
| 接口测试 | 单测通过、真实 Handler | 用 httptest 断言状态、错误码、字段与落库结果 | 接口测试与日志 | 实现者 |
| 自测 | 全部改动、门禁命令 | 跑 vet、包级测试、定向接口测试并记录 | 自测记录与证据索引 | 验收复核 |

MX-BE-07 接口形状、数据模型与迁移、实现、单测、接口测试、自测六步按序执行，前一步产出未写入 spec 时后一步不得开工。

MX-BE-08 接口形状产出必须写方法、路径、鉴权要求、请求字段与类型、成功状态与响应体、错误状态与错误码、分页与幂等语义、WS 帧类型，缺任一项不得进入数据模型步骤。文件下载、导出与附件类接口另写 Content-Type、Content-Disposition（含文件名编码 `filename*=UTF-8''`）、体积上限与超时四项，体积与超时写比较符与单位，四项缺一不得冻结。

MX-BE-09 数据模型与迁移步骤先写表名、列名、类型、默认值、约束、索引、迁移模块与版本、回填方式、备份与恢复方式，再写实现代码。

MX-BE-10 实现只覆盖 spec 已写明的行为，实现中发现契约缺口时先回写 spec 并重过契约门，再继续改代码。

MX-BE-11 纯逻辑、迁移与权限边界三类改动先写能失败的测试，再写实现；普通文案与前端展示改动不强制先写失败测试。

MX-BE-12 接口测试必须经真实 Handler 或 httptest 启动服务，断言状态码、错误码、响应字段与落库结果，不以服务层函数调用替代。

MX-BE-13 自测记录写命令、退出码、耗时、日志路径与未跑项，未跑项写 missing 与原因，不写“通过”。

MX-BE-14 每步预计不超过 20 分钟，某步超过 20 分钟没有进展时停止，报告卡点、已试内容与所需输入，不用继续等待代替判断。

MX-BE-15 接口形状与数据模型由后端 owner 自检后交设计或 Lead 复核，单测与接口测试由实现者执行，自测结论由验收复核，实现者不签自己的验收结论。

## 3 必产出文件与字段

后端每个需求点至少留下六类产物，产物写在长期 spec、变更包与 `scripts/ac/` 三处，位置固定。产物的字段以本节表格为准，模板未建立的先用 spec 内等价表格承载。产物之间要能互相引用，接口契约的每个错误码在错误码表有定义，每个事件在事件载荷节有字段说明，每个迁移版本在迁移表与迁移计划中各出现一次。

| 产物 | 位置 | 必填字段 | 判定 |
|---|---|---|---|
| 后端 spec 增量 | `specs/backend/<域>/spec.md` | 头部表、§0 索引、HTTP 与 WS 契约、数据模型、不变量与并发、可复现证据、涉及文件、未实现项 | 缺节或证据锚点为空即不合格 |
| 接口契约 | `specs/backend/openapi.yaml` 或 spec 内字段表 | 方法、路径、鉴权、请求、成功、错误码、幂等、分页、并发 | 路由覆盖差一条即不合格 |
| 状态机与迁移表 | spec 的数据模型节与 `migration-plan.md` | 状态、迁移、触发、副作用、事件、错误码；模块、版本、Up、前置、备份、回滚、基线哈希 | 有状态无迁移图或有版本无回滚方式即不合格 |
| 错误码表 | spec 的错误码总表 | code、HTTP 状态、触发条件、信封形状、前端动作、WS 适用性 | 同一 code 两个状态即不合格 |
| 事件与载荷 | spec 的 WS 契约节与审计事件表 | WS 帧的 type、方向、data 字段、顺序、重放、抑制、幂等；审计事件的操作者、时间、动作、对象、结果、请求 ID | 只写事件名即不合格 |
| 迁移计划 | `specs/changes/<CHG>/migration-plan.md` | 范围、版本序列、双写、回填、切换、收缩、备份、演练、回滚 | 无备份或无演练记录即不合格 |

长期 spec 的头部、索引与分节字段按下表核对，表格同时约束 spec 增量与既有 spec 的回写。

| 节 | 必填字段 | 判定 |
|---|---|---|
| 头部 | 域、状态、版本、最后更新、owner、产品输入、变更输入、运行时基线、代码基线、本文范围 | 缺一项不合格 |
| §0 索引 | 需求点、覆盖状态、承载接口、证据锚点 | 无证据锚点不合格 |
| HTTP 契约 | 方法、路径、入参、成功、错误 | 缺错误码不合格 |
| WS 契约 | 帧、data、顺序、重放、抑制 | 只写帧名不合格 |
| 数据模型 | 表、列、类型、约束、索引、迁移版本 | 无迁移版本不合格 |
| 不变量与并发 | 不变量、事务边界、并发结果、幂等 | 只写“线程安全”不合格 |
| 证据与文件 | 测试文件与行号、涉及文件 | 行号失效不合格 |
| 未实现项 | 差距、出口、负责人 | 缺出口不合格 |

MX-BE-16 每个需求点在长期 spec 内至少写 HTTP 契约、WS 契约、数据模型、不变量与并发、可复现证据、涉及文件、未实现项七节，不适用节写 N/A 与理由。

MX-BE-17 长期 spec 头部表写域、状态、版本、最后更新、owner、产品输入、变更输入、运行时基线、代码基线与本文范围，§0 索引按需求点列出覆盖状态与证据锚点。

MX-BE-18 接口以 `specs/backend/openapi.yaml` 为唯一事实来源，文件建立前用 spec 内字段表等价承载，字段表至少含方法、路径、鉴权、请求字段、成功状态与响应、错误状态与 code、幂等、分页、并发九列。JSON Schema 组件的复用与配置校验按 MX-BE-64 执行。

MX-BE-19 有两个及以上状态的实体必须列出状态集合、合法迁移、触发动作、副作用、投递事件与失败错误码，非法迁移写明返回码。

MX-BE-20 每个模块按版本列出模块名、版本号、迁移名、Up 内容、前置条件、备份位置、回滚方式、是否已发布与发布基线哈希，已发布版本的 Up 不得改写。

MX-BE-21 每个错误码写 HTTP 状态、触发条件、响应信封形状、前端处理动作与是否用于 WS 错误帧，一个 code 只对应一个 HTTP 状态。

MX-BE-22 每个 WS 帧写 type、方向、data 字段与类型、发送顺序、重放规则、抑制规则与幂等行为，审计事件写操作者、时间、动作、对象、结果与请求 ID，载荷字段增删按破坏性变更处理。客户端重连的续传水位取最后一条已确认消息的序号，补拉窗口写条数上限与重叠丢弃规则，两项写入 WS 契约节；未写续传水位或补拉窗口时，重连后重复投递按契约缺失处理，不按前端去重掩盖。trace_id 的生成、写入与传播按 MX-BE-67 执行。

MX-BE-23 涉及删列、改类型、拆表或存量数据回填时写迁移计划，含范围、版本序列、双写与回填、读切换、收缩前置条件、备份路径、演练记录与回滚触发条件。迁移计划按 `docs/framework/templates/migration-plan.md` 填批次大小、单批失败重试次数、续跑起点与中断判定四组字段；批次大小写每批行数与提交方式，重试写次数与退避，续跑写从最后提交批次的下一批开始，中断判定写断点表字段与已处理范围的判定方式。四组缺任一项时迁移演练门判不通过，不得按行数估算或按时间推断已处理范围。迁移计划的就绪核对按 MX-BE-62 第三项执行。

MX-BE-24 spec 每次修订追加日期、版本、变更内容与依据，不覆盖旧行，版本号与最后更新日期在同一次提交内同步。

MX-BE-25 新模板先登记到总册附录 A 再使用，模板未建立时在 spec 内用同字段的等价表格承载，不新建未登记模板。

## 4 判据写法

判据的最小单位是一条能独立运行的断言，断言必须能回答返回了什么、字段是什么值、数据库留下了什么。判据写在 AC 冻结之前，写入任务卡与 test-plan，实现完成后只补实现细节，不改判据语义。下面先给六类判据的写法对照，再给三组正例与三组反例。

| 类型 | 合格写法 | 不合格写法 |
|---|---|---|
| 状态码 | 精确状态码、错误码与信封字段三者同时断言 | 只写 4xx 或只写状态码 |
| 字段 | 响应路径、字段名、类型与取值 | 整段 JSON 文本包含 |
| 边界 | 下界减一、下界、上界、上界加一 | 只测中间值 |
| 并发 | 真实并发发起，断言一成一败或幂等收敛 | 顺序调用两次 |
| 幂等 | 同一键只落一行并返回同一 id | 只断言两次 2xx |
| 事件 | 顺序、载荷、最终正文拼接 | 只断言收到任意帧 |

MX-BE-26 每条后端 AC 至少映射一条可执行断言，断言落在 Go 测试或 `scripts/ac/` 脚本，无法自动化的写人工判据、判定人与操作步骤。

MX-BE-27 断言写精确 HTTP 状态、错误码字符串与信封字段，只断言状态区间或只断言状态码不算通过。

MX-BE-28 字段断言写响应路径、字段名、类型与取值，不用整段 JSON 文本包含代替字段断言，不用中文提示文案代替 `code`。

MX-BE-29 数值参数覆盖下界减一、下界、上界、上界加一，字符串覆盖空串、纯空白、最大长度与最大长度加一，缺参、非法类型与未知枚举各一条。

MX-BE-30 并发用例真实并发发起请求，断言一成一败或双方幂等收敛，SQLite 写冲突要声明 `busy_timeout` 与重试次数。

MX-BE-31 同一幂等键重复提交断言返回同一资源 id、重复响应带 `idempotent:true`、库里只有一行，不同键断言产生两行，失败重试断言占位被释放。

MX-BE-32 WS 用例断言事件顺序、载荷字段与最终正文拼接结果，只断言收到任意一帧不算通过。

MX-BE-33 每条证据写命令、退出码、关键输出、执行时间与环境，截图与日志片段只作附件，不能替代命令。

MX-BE-34 判据评审按下面三组正例与三组反例对照，出现任一反例特征即退回重写。

| 正例 | 断言内容 | 合格原因 |
|---|---|---|
| 正例一 | `POST /api/chat` 带同一 `clientMutationId` 连发两次，断言两次 202、`messageId` 相同、第二次 `idempotent=true`、user 消息行数为 1 | 状态、字段、幂等与落库结果写在同一条断言里 |
| 正例二 | `POST /api/sessions/main/archive` 断言 409、`ok=false`、`code=main_session_protected`、`sessions.archived` 仍为 0 | 同时钉住状态码、错误码与数据不变 |
| 正例三 | 注入 `HealthReport{Ready:false,DB:"error"}` 后 `GET /api/health` 断言 503、`ok=false`、`ready=false`、`checks.db=error` | 覆盖依赖失败分支，不依赖真实故障 |

| 反例 | 错法 | 退回原因 |
|---|---|---|
| 反例一 | 只断言创建会话返回 200，不校验 `session.id` 前缀、`draft` 与 `messageCount` | 状态码通过但字段契约可能已经损坏 |
| 反例二 | 断言响应正文包含“主会话不可归档”，不断言 `code=main_session_protected` | 文案改动即误报，前端按 code 分支 |
| 反例三 | 并发用例顺序发两次请求，或只断言“没有 500”就算通过 | 没有制造并发，也没有断言幂等收敛与行数 |

三组正例取自本仓 P1-CONV 的已落地用例，测试位置分别是 `backend/cmd/simo/p1_conv_chat_idempotency_test.go:58`、`backend/cmd/simo/p1_conv_sessions_http_test.go:557`、`backend/internal/platform/httpserver/server_test.go:41`；三组反例是按本节要求构造的错法，只用于对照，不作为证据。

## 5 门禁

后端门禁在自验门与证据门上执行，Go 命令从 `backend` 目录发起并统一经 `toolchain/go.ps1` 设置工具链环境，契约一致性一行从工作区根目录发起。每道门禁的通过标准以退出码、失败数与断言覆盖三项判定，退出码为 0 但断言不足仍算不通过。门禁失败时停在该步，修完重跑同一命令，不用“同批次其他包通过”替代。

| 门禁 | 命令 | 通过标准 | 不通过处理 |
|---|---|---|---|
| go vet | `..\toolchain\go.ps1 vet ./...` | 退出码 0，无诊断输出 | 修到无输出再继续 |
| 包级单测 | `..\toolchain\go.ps1 test ./internal/modules/<pkg> -count=1` | 改动包与直接依赖包退出码 0，0 FAIL，新增 skip 已登记理由 | 缺一个包不算通过 |
| 全量回归 | `..\toolchain\go.ps1 test ./... -count=1` | 退出码 0，0 FAIL，报告包数、通过数与新增 skip | 失败包修完重跑全量 |
| 接口层测试 | `..\toolchain\go.ps1 test ./cmd/simo -run '<用例名>' -count=1 -v` | 目标用例全部 PASS，且覆盖 §4 的状态、字段、边界与落库断言 | 用例不足先补断言 |

## 7 与其它域的接口

后端与前端、测试、验收三方只通过契约与证据交接，三方都不直接读后端代码推断行为。交给前端的部分是可消费字段、错误码与事件载荷，交给测试的部分是可重复搭建的夹具与可替换的假上游，交给验收的部分是可复跑的命令与结果。三份交接物在契约门冻结一次，后续变化按变更流程通知。

**给前端的字段与错误码。** 后端交付给前端的是一组稳定字段、错误码与事件载荷，前端不读后端数据库，也不解析后端日志。字段名与类型以 spec 为准，空集合返回空数组，时间统一为 Unix 毫秒。错误处理按 `code` 分支，提示文案由前端映射，后端改文案不影响前端逻辑。

| 项目 | 约定 | 示例 |
|---|---|---|
| 时间 | Unix 毫秒，0 表示未发生 | `createdAt: 1763000000000` |
| 会话 ID | `main` 为主会话，新会话为 `sess-<16 hex>` | `sess-9f2c41a7b3d84e10` |
| 空集合 | 返回 `[]`，不返回 `null` | `{"sessions":[]}` |
| 错误信封 | `{"ok":false,"error":"...","code":"..."}`，附加字段在 spec 登记 | `{"ok":false,"error":"会话不存在","code":"not_found"}` |
| 条件请求 | 304 表示内容未变，保留现有数据 | `spec-projection` 的 ETag |
| 幂等响应 | 重复提交返回同一 id 并带 `idempotent:true` | `POST /api/chat` |

| code | HTTP | 前端动作 |
|---|---|---|
| `bad_request` | 400 | 提示可修正的原因，保留用户输入 |
| `not_found` | 404 | 刷新列表或回到主会话，不做乐观删除 |
| `conflict` | 409 | 提示当前状态冲突，刷新后重试 |
| `session_archived` | 409 或 WS `error` 帧 | 切只读态，先恢复会话 |
| `mutation_in_progress` | 409 | 稍后重试，不换幂等键重发 |
| `internal` | 500 | 展示错误并允许重试，不伪造成功 |

MX-BE-49 前端只依赖 spec 写明的字段名、类型、可空性与取值，后端新增字段默认可忽略，删除字段或改类型按破坏性变更提前一个变更包通知。

MX-BE-50 前端按 `code` 分支处理失败，不解析 `error` 文案，错误响应至少含 `ok=false`、`error`、`code`，附加字段以 spec 登记为准。

MX-BE-51 事件载荷的字段名与类型在 spec 的 WS 契约节冻结，前端不得依赖帧顺序以外的实现细节，后端不得在未通知的情况下改变顺序或字段含义。

**给测试的夹具与假上游。** 测试拿到的是可重复搭建的环境与可替换的上游，同一用例重复运行得到同一结论。夹具使用临时数据根与固定种子，假上游覆盖正常、错误、超时与取消四条路径。测试通过真实 HTTP 与 WS 入口驱动，结束后关闭服务并释放数据库锁。

| 项目 | 做法 | 位置 |
|---|---|---|
| 临时数据根 | `t.Setenv("SIMO_HOME", t.TempDir())` | 包内测试 |
| HTTP 服务 | `httptest.NewServer(handler)` 或仓库内的测试应用构造器 | `backend/cmd/simo/*_test.go` |
| 模型假上游 | `SIMO_LLM=mock`，覆盖正常、错误、超时与取消 | `backend/internal/platform/llm/mock.go` |
| 固定种子 | 固定会话 ID、消息 ID 与时间戳，不用随机值做断言 | 各测试文件 |
| 收尾 | 关闭服务、释放数据库锁、临时目录随测试回收 | `t.Cleanup` |

MX-BE-52 测试夹具使用临时 `SIMO_HOME` 与 `t.TempDir()`，固定种子数据写清 ID、时间与状态，用例之间不共享数据库文件。

MX-BE-53 模型调用使用 `SIMO_LLM=mock` 或仓库内的假上游，覆盖正常流、错误、超时与取消四种路径，假上游的请求与响应写进测试说明。

MX-BE-54 测试从真实 HTTP 与 WS 入口驱动，断言事件顺序与落库结果，测试结束关闭服务并释放锁，不留下占用端口的进程。

**给验收的证据。** 验收拿到的是按 AC 分组的证据索引，每条证据能照着命令重跑。证据包写明命令、退出码、关键输出、环境与未验证项，缺一项按 missing 处理。证据只追加不覆盖，修正时保留旧版本并在复盘注明。

| 项 | 内容 |
|---|---|
| 命令 | 写清工作目录的完整命令，含 `-run` 与 `-count=1` |
| 退出码 | 0；非 0 写失败原因与处理动作 |
| 输出 | 关键断言、通过数、失败数与日志路径 |
| 环境 | 执行日期、Go 版本、`SIMO_HOME` 隔离方式与端口 |
| 未验证 | 写 missing 与原因，不写“基本通过” |

MX-BE-55 每个需求点提交证据索引，含命令、退出码、日志路径、执行时间、环境与未验证项，路径写相对工作区的路径。

MX-BE-56 证据按 AC 编号分组，一条 AC 对应一条主证据，补充证据另列，没有证据的 AC 记 missing，不记 pass。

### 8.2 契约与配置校验

MX-BE-64 `specs/backend/openapi.yaml` 的请求体与响应体使用 JSON Schema 2020-12，同一实体只在 `components.schemas` 定义一个条目，多个端点通过 `$ref` 引用，同一实体出现两份及以上内联 schema 即不合格。配置 schema 写在 `specs/backend/config.schema.json`，顶层 `$schema` 取 `https://json-schema.org/draft/2020-12/schema`，字段与 `config.Config` 的 JSON 标签一一对应，必填项、类型、枚举、默认值与取值范围齐全。配置 schema 建立后，启动时按该 schema 校验 `SIMO_HOME/config.local.json`，必填缺失、类型不符或枚举越界时以非零码退出并输出字段路径，校验用代码内逐字段检查实现，不引入通用校验中间件。字段增删或类型变化与 schema 更新在同一次提交内完成。schema 文件建立前在长期 spec 的运行时配置节用同字段表格承载，契约门人工核对字段数与代码一致。（候选 11）

### 8.3 运行约束与可观测

MX-BE-65 六条运行约束按下表核对，`docs/process/RELEASE-CHECKLIST.md` 的对应条目与 `scripts/check-runtime-config.mjs` 未建立前，由自验门人工执行并记录命令与输出。（候选 6）

| 约束 | 要求 | 核对方式 |
|---|---|---|
| 密钥来源 | 密钥只从环境变量或 `config.local.json` 读取，日志、错误响应与长期 spec 不出现明文，启动日志只写密钥字段名 | 检索启动日志与错误响应，确认无密钥值 |
| 日志去向 | 日志写标准输出或标准错误，由宿主重定向到文件，进程不自行创建日志文件 | 代码检索日志文件创建调用，结果为空 |
| 地址与数据根 | 监听地址经 `SIMO_ADDR` 或 `-addr` 覆盖，数据根经 `SIMO_HOME` 覆盖，默认值写在启动帮助里 | `simo serve -h` 输出含两项说明 |
| 依赖锁定 | 依赖版本由 `go.mod` 与 `go.sum` 锁定 | 提交前 `go mod tidy` 后工作区无差异 |
| 优雅退出 | 收到 `SIGTERM` 或中断信号后在 10 秒内完成关闭、释放数据库锁并以退出码 0 结束 | 启动后发终止信号，核对退出码与关闭日志 |
| 写入范围 | 进程与工具只写 `SIMO_HOME` 下的 workspace、artifacts、数据库文件与系统临时目录 | 路径策略测试与越界用例，越界返回 403 或 404 |

MX-BE-66 结构化日志的每条记录输出一个 JSON 对象，七个必填字段与取值按下表核对。日志不得写入 `apiKey`、`Authorization`、`Cookie`、`Set-Cookie` 的值，不得写入模型原始输入输出与用户消息正文，需要定位时写长度或哈希前 8 位。测试断言一次请求的全部日志行含七个字段，禁用字段的值不出现在序列化结果中。当前 `log.go` 使用 `TextHandler`，切换 `JSONHandler` 前按本节字段人工核对，`scripts/check-log-fields.mjs` 未建立时由自验门执行同一断言并记录。（候选 18）

| 字段 | 取值 | 说明 |
|---|---|---|
| `time` | RFC3339 带毫秒 | 记录产生时间 |
| `level` | `debug`、`info`、`warn`、`error` | 与 `slog` 级别一致 |
| `service` | `simo` | 固定值，用于多进程日志归并 |
| `trace_id` | 32 位小写十六进制 | 同一请求保持一致，按 MX-BE-67 生成 |
| `request_id` | 非空字符串 | 同一请求保持一致，无请求头时生成 |
| `event` | `<域>.<动作>` | 点分小写，例如 `chat.turn_start` |
| 业务字段 | 至少一个 | HTTP 请求写 `method`、`path`、`status`、`duration_ms`；迁移写 `module`、`from_version`、`to_version` |

MX-BE-67 HTTP 入口为每个请求确定一个 `trace_id`，请求头带合法 `traceparent` 时沿用其中的 trace-id，缺失或不合法的按 32 位小写十六进制新生成。合法指版本为 `00`、trace-id 为 32 位非零小写十六进制、span-id 为 16 位非零小写十六进制、flags 为两位十六进制；`traceparent` 非法时另记布尔字段 `trace_invalid=true`。该值写入同一请求的全部 slog 记录，WS 事件帧在顶层增加 `traceId` 字段并取同一值，字段名与格式写进长期 spec 的 WS 契约节。调用模型服务或其他进程时按 W3C traceparent 格式发送 `00-<trace-id>-<span-id>-<flags>`，span-id 每次调用新生成 16 位小写十六进制，flags 取 `01` 或 `00`。本节在批三启用，启用前只生成与记录 trace_id，不做出站传播；不引入 OpenTelemetry SDK、Collector 与后端存储。测试断言同一请求的 HTTP 日志、WS 帧与出站请求头三处 trace_id 一致，非法 `traceparent` 用例断言新生成且 `trace_invalid=true`。（候选 19）

### 8.5 度量与交付检查

MX-BE-70 上线检查单按下表补可靠性、安全与成本三类可判定项，三类全部勾选才算通过。日志超限时告警并滚动归档，不自动删除；请求体上限与超时上限沿用代码常量，调高任一项需要写理由与批准人。批三启用前只登记，不阻断发布。（候选 7）

| 类别 | 项目 | 判定 |
|---|---|---|
| 可靠性 | 数据备份 | 迁移前自动备份，每日一份，保留 7 天 |
| 可靠性 | 恢复演练 | 每季度一次，恢复耗时不超过 30 分钟，记录数据完整性核对结果 |
| 可靠性 | 单点依赖 | 模型服务、SQLite 与文件系统各写故障表现、检测方式、降级动作与恢复步骤 |
| 安全 | 错误响应 | 不含堆栈、绝对路径、SQL 语句与密钥 |
| 安全 | 依赖清单 | 记录名称、版本、许可证与已知高危漏洞的处理结论 |
| 安全 | 发布检查 | 跑 `go vet ./...` 与依赖漏洞检查，工具未定时人工核对依赖公告并记录 |
| 成本 | 日志上限 | 单文件 50 MB，目录总量 500 MB，保留 7 天，超限告警并滚动归档，不自动删除 |
| 成本 | 请求体上限 | 保持 `MaxRequestBodyBytes` 的 1 MiB，超限返回 413 与 `body_too_large` |
| 成本 | 超时上限 | 模型流空闲 120 秒、整轮 10 分钟，调高任一项需写理由与批准人 |

MX-BE-71 三条 SLI 与内部目标按下表记录，统计周期为自然月。三项指标按 `docs/process/templates/slo.md` 的字段记录，模板未建立前在长期 spec 的运行时基线节用同字段表格承载，模板建立后按模板字段填写实例，目标值在首批真实流量采集后校准一次并记录校准依据。每月人工复盘一次，单项样本少于 30 条时记样本不足，不计达标或未达标。错误预算按成功率目标折算当月允许失败数，批三取得连续两个月各不少于 1000 条样本前不执行发布冻结，达到条件后超出预算暂停发布并在复盘写处置。（候选 21）

| SLI | 定义 | 内部目标 |
|---|---|---|
| 请求成功率 | 自然月内非 5xx 响应数除以总请求数，排除 `/api/health` 与 WS 握手 | 不低于 99.5% |
| 首帧延迟 | `POST /api/chat` 返回 202 到首个 `delta` 帧到达，取自然月 p95 | 不高于 3000 毫秒 |
| 写请求延迟 | 非 GET 请求从收到请求到响应头写出，取自然月 p95，流式响应不计入 | 不高于 800 毫秒 |

### 8.7 命令行程序与发布产物

独立工具类交付的命令行程序按本节执行，与 HTTP 服务共用 Go 工具链、依赖锁定与退出码口径，不新增角色。发布产物的签名、验签、时间戳与可复现构建按本节 MX-BE-77 与 MX-BE-78 执行，两份规则适用于安装包、更新清单与命令行产物。工具目录取 `tools/<工具名>/`，owner 与可写范围按 `ROLES.md` 第 6 节 MX-R-32 执行，本节只写命令行程序的技术规则，不另定 scope，也不占用前端、设计与文档目录。

MX-BE-74 命令行契约字段七项在契约表的命令行契约类逐项填写，一个契约项对应一个子命令，七项不得全部写 N/A。七项为子命令、参数与选项、环境变量、退出码、stdout 与 stderr 约定、产物路径与版本输出。子命令写命令名与子命令名，与 `--help` 输出一致；参数与选项写位置参数、长短选项、默认值与是否必填；环境变量写变量名、用途、默认值与是否必填；退出码逐类写含义，成功取 `0`，参数或环境错误取 `2`；stdout 只写结果，stderr 写错误与进度；产物路径写文件路径、命名规则与哈希计算命令；版本输出写 `--version` 的格式与版本号来源。缺任一项时契约门判不通过，契约项全部写 N/A 时按 CLI 任务没有契约项处理。

MX-BE-75 命令行实现按下列规则执行。参数解析用 Go 标准库 `flag` 加子命令分发，不引入第三方命令行框架；配置取默认值、环境变量与命令行参数三层，命令行参数优先，冲突时以命令行参数为准并把生效值写进 `--help`。stdout 与 stderr 分开写，正常结果只进 stdout，错误、警告与进度只进 stderr。退出码按 MX-BE-74 的契约返回，`main` 函数不直接调用 `os.Exit`，由顶层统一返回。依赖由 `go.mod` 与 `go.sum` 锁定，不引入 cgo 依赖。构建用 `go build -trimpath` 产出单个二进制，产物名带版本号，版本号在构建时注入变量。路径处理用 `filepath`，Windows 与类 Unix 各跑一次启动检查，不假设分隔符与主目录位置。安装说明写清解压位置、环境变量与首次运行命令，安装步骤与命令行契约一并冻结。

MX-BE-76 命令行自验写三条命令与三条结果：构建命令与产物路径、测试命令与退出码、产物校验命令与哈希值。产物校验核对 `--version` 输出、文件哈希与构筑产物名三处一致，三处不一致时自验门判不通过。安装验证在隔离目录复制产物后运行 `--version` 与一个真实子命令，两步的退出码与 stderr 输出写入证据。组件登记门对独立工具写 `N/A：<理由>`，理由写明本次没有界面组件，由验收确认；证据索引另登记产物哈希与版本号两项。

MX-BE-77 发布产物签名按下列字段与命令执行，字段缺任一项时自验门与收口门判不通过。签名对象取安装包与更新清单两份文件，构建完成后先算哈希再签名，哈希值与签名结果同时写进发布记录。Windows 平台的签名命令为 `signtool sign /fd SHA256 /tr <时间戳服务地址> /td SHA256 /a <产物路径>`，其他平台为 `openssl dgst -sha256 -sign <私钥路径> -out <签名文件> <产物路径>`；私钥与证书只从证书存储或受控环境变量读取，不写进仓库、构建脚本明文与日志。验签命令分别为 `signtool verify /pa /all <产物路径>` 与 `openssl dgst -sha256 -verify <公钥路径> -signature <签名文件> <产物路径>`，验签退出码非 0 时产物不得进入更新清单。时间戳取 RFC 3161 时间戳服务返回值，服务不可达时本次签名无效，不得用本机时间替代。发布记录逐项写产物名、版本号、构建命令、哈希算法与哈希值、签名算法、证书主体、证书有效期、时间戳服务地址、时间戳值、验签命令、验签退出码与可复现构建结论十二项，十二项写进契约表发布与签名类的同一行，填写模板见 `docs/framework/templates/release-signing-checklist.md`。下表按字段组合并，逐项写法如下。

| 字段组 | 写法 | 判定 |
|---|---|---|
| 产物名 | 文件名含版本号，与更新清单一致 | 名称不一致按缺失计 |
| 哈希算法与值 | `SHA-256` 加 64 位小写十六进制 | 长度不符或含大写字母按缺失计 |
| 签名算法 | `RSA-PSS-SHA256`、`ECDSA-P256-SHA256` 或 `Authenticode` 三值之一 | 三值之外按未签名处理 |
| 证书主体 | 证书 `CN` 与颁发者名称 | 与发布主体不一致按缺失计 |
| 证书有效期 | 起止日期，覆盖发布日 | 发布日不在有效期内时不得发布 |
| 时间戳 | 服务地址、时间值与校验结果 | 缺时间戳的签名按无效处理 |
| 更新清单 | 文件路径、格式版本、包含的产物与哈希 | 清单缺产物或哈希按缺失计 |
| 灰度与回滚点 | 分桶键、放量档位、观察窗口、回滚阈值 | 缺任一项时更新不得放量 |

MX-BE-78 可复现构建在隔离目录执行一次，取同一提交号、同一工具链版本与同一构建参数，比对产物哈希与文件清单两项，两项一致才算可复现。构建命令固定使用 `go build -trimpath -buildvcs=false`，时间相关变量取 `SOURCE_DATE_EPOCH` 的固定值，压缩参数与文件顺序写进构建脚本。哈希不一致时列出差异文件与差异原因，差异来自构建路径、时间戳或依赖缓存时逐项消除后重跑一次，重跑仍不一致时按不可复现登记并写明阻塞原因，不得只在发布记录写构建成功。可复现构建结论写进发布记录与证据索引，验收在放行时核对两次构建的命令、环境与哈希。

### 8.8 多租户、授权与数据分布

本节的规则在引入远程访问、多用户、分库分表或外部依赖时生效。四项都不成立的变更在契约表对应类写 `N/A：<理由>` 与重开条件，由契约门核对；四项任一成立时以下字段与判据不得留空。

MX-BE-79 租户上下文与配额按下列字段登记，缺任一项时契约门判不通过。租户标识来源取认证令牌的 tenant 声明，令牌未携带时取请求头 `X-Tenant-Id`，两个来源同时存在且不一致时返回 400 与 `tenant_mismatch`，不按其中一个来源覆盖。租户标识在全部业务端点必填，健康检查、版本查询与静态资源三类端点除外，缺失时返回 400 与 `tenant_required`。隔离不变量固定为四条：查询条件必须带 `tenant_id`，写入行的 `tenant_id` 取自上下文且不接受请求体覆盖，导出范围按 `tenant_id` 过滤，跨租户读取统一返回 404 与 `not_found`，不返回 403，也不在响应中区分资源不存在与无权访问。配额计量单位取请求数与存储字节两项，配额上限与重置周期写进 `specs/backend/config.schema.json` 与契约表，运行时不接受按请求临时调整。请求数超限返回 429 与 `tenant_quota_exceeded` 并带 `Retry-After` 秒数，存储字节超限返回 413 与 `tenant_storage_quota_exceeded`。审计事件写租户标识、操作者、动作、对象与结果五项，租户标识不得只写在日志正文。检查记录按 `docs/framework/templates/tenant-isolation-checklist.md` 填写。

| 字段 | 写法 | 判定 |
|---|---|---|
| 租户标识来源 | 令牌声明与请求头两个来源，写优先级 | 未写来源或优先级按缺失计 |
| 必填范围 | 业务端点清单与三类例外端点 | 例外未列名按缺失计 |
| 上下文载体 | 请求头、路径参数或令牌声明三值之一 | 同一接口两种载体按冲突计 |
| 隔离不变量 | 四条：查询带租户、写入盖租户、导出按租户过滤、跨租户返回 404 | 缺一条按缺失计 |
| 配额计量单位 | 请求数与存储字节两项 | 只写其中一项按缺失计 |
| 配额上限 | 数值加单位与统计周期 | 未写周期按缺失计 |
| 重置周期 | 自然月、自然日或固定秒数 | 与上限统计周期不一致按冲突计 |
| 超限动作 | 状态码、错误码、`Retry-After` 与前端动作 | 缺错误码按缺失计 |

MX-BE-80 授权策略按主体、资源、动作、环境属性、求值顺序、默认拒绝与拒绝优先、旧角色映射七项登记，七项缺一不得冻结。主体属性写用户标识、角色与租户三项；资源属性写资源类型、归属者与租户三项；动作取读取、创建、修改、删除、导出五值；环境属性写请求时间、网络区域与设备标识三项，不适用写 `N/A：<理由>`。求值顺序固定为租户匹配、主体与动作匹配、资源归属匹配、环境条件匹配、默认拒绝五步，前四步任一不通过即进入拒绝，不继续求值。拒绝优先于允许，同一请求同时命中允许规则与拒绝规则时按拒绝处理，拒绝结论写命中的策略编号。旧角色映射逐行写旧角色、新属性集合与迁移等价判据，旧角色到新属性的映射必须覆盖全部存量角色，缺一个角色时契约门判不通过。策略求值只在服务端完成，客户端不缓存允许结论；策略变更写审计事件，字段为策略编号、变更人、变更前后摘要与批准人。拒绝响应返回 403 与 `forbidden`，响应字段含 `policyId`，不含资源是否存在的信息。策略矩阵按 `docs/framework/templates/permission-policy-matrix.md` 填写。

MX-BE-81 分片路由按分片键、路由函数与版本、库标识、全局唯一 ID 生成口径、跨库一致性判据五项登记，五项缺一不得冻结。分片键取租户标识与业务主键两级，两级都写进契约表，只写租户标识的按缺失计。路由函数写函数名、输入、输出与版本号，版本变更时旧路由保留一个变更周期用于读取旧数据。库标识写逻辑库名与物理连接名，连接串不写明文密码。全局唯一 ID 取 64 位整数，高 8 位为库标识、中间 40 位为毫秒时间、低 16 位为库内序列，同一毫秒内序列溢出时等待下一毫秒，不使用数据库自增主键充当全局唯一 ID。跨库一致性判据取同一事务、最终一致与补偿三种口径之一并写对账字段。选择补偿口径时，跨库读取走接口聚合，跨库写入用 outbox 表加补偿任务，补偿任务的观测窗口与重试次数写进配置；同一事务口径只适用于同一物理库内的分表。查询缺少分片键时返回 400 与 `shard_key_required`，不执行全库扫描。重分布写源库、目标库、双写窗口、按分片键回填、逐库计数核对与切换时点六项，计数核对按分片键分组，不按全表行数比对。

MX-BE-82 外部依赖的限流、退避与熔断参数按下列字段登记在 `specs/backend/config.schema.json` 与接口契约的外部依赖策略节，字段缺任一项时契约门判不通过。参数取整数或字符串类型，运行时可读，不允许写死在代码常量里；需要按环境覆盖时在配置文件写覆盖值与批准人。限流窗口取秒数，阈值取窗口内允许请求数，突发额度取窗口内允许的额外请求数。重试次数取 0 至 3，退避序列写基数、倍数、上限与抖动比例，抖动比例取 20%。熔断阈值写连续失败次数与窗口内失败比例两项，两项任一命中即打开；半开状态允许的探测请求数取 3，探测全部成功才关闭。降级动作取返回缓存值、返回 503 与 `dependency_unavailable`、进入排队三种，选择依据写在字段旁。观测窗口取 60 秒，窗口内的成功数、失败数、熔断次数与降级次数写进证据文件。假上游的自检按 MX-QA-65 执行，注入条件与判定值与本条参数一致。

| 字段 | 取值示例 | 判定 |
|---|---|---|
| 依赖名 | 模型服务或第三方接口名 | 与契约表外部依赖策略行一致 |
| 限流窗口 | `60` 秒 | 未写单位按缺失计 |
| 限流阈值 | `600` 次每窗口 | 与提供方配额一致 |
| 突发额度 | `60` 次 | 不超过提供方上限 |
| 重试次数 | `3` | 超过 3 按违规计 |
| 退避序列 | 基数 `200` 毫秒、倍数 `2`、上限 `5000` 毫秒、抖动 `20%` | 缺抖动按缺失计 |
| 熔断阈值 | 连续 `5` 次失败或 `30` 秒内失败比例 `50%` | 缺一项按缺失计 |
| 半开探测 | `3` 次 | 未写按缺失计 |
| 降级动作 | 缓存值、503 或排队三值之一 | 未写按缺失计 |
| 观测窗口 | `60` 秒 | 未写按缺失计 |

### 8.9 数据合规处置

MX-BE-83 合规删除按请求核验、范围清单、级联执行、完成证明四步执行，四步缺一不得进入执行。请求核验写法规依据、请求人身份核验方式、请求范围与受理时点四项，法规依据写具体条款，身份核验写凭证类型与核对人，核验不通过时拒绝执行并登记理由。保留例外逐条写数据类型、保留依据、保留期限、批准人与到期处置，常见例外为法定保存期限、未结争议与审计日志保留 180 天三类，例外之外的数据一律纳入删除范围。完成时限取受理后 30 日内，身份核验与范围确认在 3 个工作日内完成，逾期未完成时登记原因与新的到期日。

范围清单逐项写库内表与行数、备份副本、导出文件、缓存与第三方已共享副本五类，五类缺一按范围不完整处理。级联执行按库内行、缓存、导出文件、备份副本、第三方副本的顺序执行，库内行先删子表再删主表，同一事务提交；备份副本按保留期轮转删除，删除后保留删除记录；第三方副本由对接方在 5 个工作日内通知、15 个工作日内回执，回执未到时按 blocked 登记并升级，不把未回执写成已删除。完成证明写四类证据：库内计数归零的查询输出、备份删除记录、第三方回执、独立抽检记录。独立抽检按 MX-QA-68 的抽样规则从删除清单中抽取，任一项仍可读出时删除判失败并回到级联执行。删除清单与对账口径写进变更包与证据索引，删除清单至少含请求号、主体标识、数据类型、各存储的删除行数、删除时间与执行人六项。处置记录按 `docs/framework/templates/compliance-disposal-record.md` 填写。
