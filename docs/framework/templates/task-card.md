# 任务卡模板（task-card）

版本：v0.3，2026-11-24。
定位：本文件是派单卡的完整模板，任务卡按这里的字段逐项填写，字段缺项或留空的卡不派发。
依据：`docs/framework/MOXIAN.md` 表 3-3、表 7-4 与第 7 章、`docs/framework/ROLES.md` 第 11 节与第 12 节、`docs/framework/EFFORT.md` 第 7 节的档位粘贴行、`docs/framework/TASK-MATRIX.md` 第 2 节的派单门。

## 1 基本信息

基本信息表由派单方在过派单门前填写，执行方不代填。表内十八项字段与 `MOXIAN.md` 表 7-4 一一对应，字段留空按缺失计。

表 1 基本信息字段

| 字段 | 填写内容 | 填写要求 |
|---|---|---|
| 卡号 | `TASK-<CHG-ID>-<NN>` | 与 `specs/changes/<CHG-ID>/tasks.md` 的卡行一一对应，编号连续且不复用。 |
| 所属变更 | `CHG-<主域代码>-<三位序号>` | 与变更包首部一致；独立小改也先有变更包，没有编号的卡不派。 |
| owner 角色 | 八个角色名之一 | 取 `ROLES.md` 第 1 节的 Lead、产品、设计、前端、后端、测试、验收、复盘之一。 |
| 执行人 | 会话名或子智能体名 | 与 owner 角色分列填写，一列一个承接人，两列都填，缺任一项不派。 |
| Change | `CHG-<主域代码>-<三位序号>` | 与所属变更同值；空值不得派发。 |
| REQ | `REQ-x.y`，多个用顿号分隔 | 至少一项；空值不得派发。 |
| AC | AC 编号逐条列，一条一行 | 只写编号并指向 `specs/product/<域>/spec.md` 的原文，不复制判据。 |
| CT | 契约项编号逐条列 | 无契约项时写 `N/A：<理由>`，理由不少于 8 个字符，并由派单方与复核人签字。 |
| scope 允许段 | 逐行列文件路径或目录 | 写可写的文件与目录；写目录时末尾加 `/`，表示该目录及其子目录可写。 |
| 禁止项 | 逐条写路径、命令或动作 | 至少一条，覆盖 `.git`、构建产物与 scope 外文件；不写无法判定的说法。 |
| 验收标准 | AC 编号与判据 | 判据取 `scripts/ac/<AC-ID>.mjs` 或 `人工:<动作>`；没有判据不得派发。 |
| 证据 | 命令、截图与落盘路径 | 每条 AC 对应生成命令、路径、判定结果与轮次，不写「跑过测试」这类说法。 |
| 推理档位 | `<档位名>（<阶段>）｜升档理由：—` | 照 `EFFORT.md` 第 7 节粘贴，阶段名取主表六个列名；升档时替换理由。 |
| 步骤 | 每步动作、预计分钟、产出与汇报对象 | 单步预计不超过 20 分钟，超过时先拆步。 |
| 并行或串行 | `并行 <卡号>` 或 `串行 <卡号>` | 写依赖卡号；同一文件同一时间只允许一张卡修改。 |
| 省略项 | 省略项、理由与批准人三格 | 无省略时写「无省略」。 |
| 状态 | 按 `MOXIAN.md` 表 3-3 的任务卡状态五值填写 | 由派单方更新，执行方不改；取值与含义以表 3-3 为准，本表不另列定义。 |
| 验收签字人 | 独立验收人标识 | 写验收或用户，不得与执行人同人；用户只签前端效果。 |

填写说明：

- 卡号、变更号与契约项编号按 `MOXIAN.md` 表 3-2 的格式分配，模板不再保留占位写法。
- scope 允许段与禁止项分两段写，两项逐条对应，交集为空才可派发。
- AC 编号必须能在 spec 里查到，查不到的编号按未填处理；AC 缺判据时先回契约阶段补判据。
- 证据写每条 AC 要交什么，完成判据写谁来看、看完放哪，两节不重复。
- 推理档位由派单方填写，执行方不得改动该行；执行方发现取值与 `EFFORT.md` 主表不符时停手报派单方改档。
- 并行或串行必须写依赖卡号，前置卡未完成时本卡排在其后，不并行开工。
- 验收签字人在派单时写清，验收前不得由 owner 临时指定，避免自签。

## 2 步骤与汇报点

步骤表把任务拆成每步不超过 20 分钟的步骤，每步写清产出与汇报对象，一张卡只覆盖一个验收单元。步骤表的行与基本信息表的步骤字段内容一致。

表 2 步骤与汇报点

| 步骤号 | 内容 | 预计分钟 | 产出 | 汇报对象 |
|---|---|---|---|---|
| S1 | | ≤20 | | |
| S2 | | ≤20 | | |
| S3 | | ≤20 | | |

填写口径：

- 一步估算超过 20 分钟时拆成两步再填，不把两步合并成一步。
- 某一步超过 20 分钟仍无进展时，执行方停下并报告卡点：卡在哪一步、已试过什么、需要什么支持。
- 每完成一步向该步的汇报对象发一次汇报，不超过 3 行：做完什么、证据在哪、下一步是什么。
- 一步覆盖多个阶段时，在该步内容里写实际档位与理由，基本信息表仍只填一个档位。

## 3 完成判据

完成判据回答谁判、看什么、证据放哪三个问题。五项判据全部成立时，任务卡由派单方改为 `待验收`；验收通过改为 `已通过`，验收不通过改为 `打回`，并在 `tasks.md` 写退回原因与下一轮动作。

表 3 完成判据

| 判据项 | 谁判 | 看什么 | 证据放哪 |
|---|---|---|---|
| AC 全部通过 | 测试跑断言，验收复核 | 每条 AC 的判定状态为 pass，未跑项写 missing 与原因 | `specs/changes/<CHG-ID>/evidence.md` 的本人任务节 |
| 证据可复跑 | 验收 | 命令、参数、路径与轮次齐全，按路径重跑得到同一结论 | 证据文件的同一节，附命令原文 |
| scope 无越界 | 验收 | 交付文件集合与卡内 scope 逐条对照，无 scope 外写入 | 检查点与 `tasks.md` 的越界记录 |
| 步骤与检查点齐全 | 派单方 | 每步有汇报记录，检查点字段齐全且时间戳连续 | `.tmp/<task-id>/checkpoint.md` |
| 签字非自签 | 派单方 | 签字人与 owner、执行人、用例作者均不同人 | 任务卡签字行或验收报告 |

状态与交付记录由派单方在验收签字后更新，执行方不改任务卡状态字段。

## 4 交接信息

交接以文件为准，对话里的口头结论不作交接；同一父会话把本节内嵌进派单 prompt，跨会话与换人时写 `HANDOFF.md`。

表 4 交接信息

| 字段 | 填写内容 |
|---|---|
| 检查点路径 | `.tmp/<task-id>/checkpoint.md`，每步完成与停下时更新，字段按 `MOXIAN.md` 表 8-1 的七项。 |
| 已完成 | 已完成的步骤号、产出与证据路径，逐条列。 |
| 未完成 | 尚未开始的步骤与卡住的原因，写清已试过的动作。 |
| 下一步 | 接手人第一步要做什么，写到文件与命令一级。 |
| 接收方与日期 | 接手人标识与接收日期；退回时写清缺哪一项。 |

跨会话交接按 `MOXIAN.md` 表 8-1 的检查点七项展开，正文压到 8,000 token 以内。
