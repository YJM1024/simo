# 依赖升级检查清单（dependency-upgrade）

版本：v1.0，2026-11-25。状态：active。本模板服务 `GATES.md` 第 3.4 节 MX-G-63、`MOXIAN.md` 表 5-2「依赖」字段与 `TASK-MATRIX.md` 第 2.1 节「依赖升级与回滚可用性」行，落点 `docs/framework/templates/dependency-upgrade.md`。

## 1 用途与何时用

升级或替换框架、运行时、数据库驱动、第三方 SDK 与构建工具时，在契约冻结前逐项填一次。只升补丁号且锁文件不变的可写「不适用」并写理由；跨主版本、改行为或带安全修复的升级必须填全。清单未附回滚可用性证据时，兼容门与证据门都不通过。

## 2 字段表

| 列名 | 必填 | 取值口径 |
|---|---|---|
| 依赖名 | 是 | 包名或组件名，与锁文件一致 |
| 当前版本与目标版本 | 是 | 语义化版本号，跨主版本时加写 `MAJOR` 标记 |
| 升级类型 | 是 | 补丁、次版本、主版本、替换四值之一 |
| 变更范围 | 是 | 影响模块、调用点数量与涉及目录 |
| 破坏性变更 | 是 | 逐条写变更说明链接、受影响调用点与适配方式；无则写「无」并写核对来源 |
| 适配点 | 是 | 文件路径加函数名或配置键，一行一处 |
| 验证命令 | 是 | 构建、类型检查与增量测试命令，写退出码要求 |
| 回滚方式 | 是 | 回滚版本号、回滚命令与数据兼容结论；回滚后需清缓存时写清 |
| 观察窗口 | 是 | 上线后观察时长与指标，写阈值 |
| 许可与安全 | 是 | 许可证名，扫描工具与退出码，命中处置结论 |
| 判定人 | 是 | 兼容性与回滚可用性由后端判定，测试复核 |

## 3 填写示例

| 字段 | 示例 |
|---|---|
| 依赖名 | `go1.23` 运行时 |
| 当前版本与目标版本 | `1.22.7` → `1.23.4` |
| 升级类型 | 次版本 |
| 破坏性变更 | 无，核对来源为该版本发行说明「兼容性」节 |
| 适配点 | `backend/go.mod` 的 `go` 指令；`backend/internal/...` 无调用点变化 |
| 验证命令 | `go build ./...`、`go test ./internal/chat/...`，退出码均为 0 |
| 回滚方式 | 回退 `go.mod` 到 `1.22.7` 并重建，数据无结构变化；回滚后清 `dist/` 缓存 |
| 观察窗口 | 上线后 24 小时，错误率与 p95 与基线比较，阈值 1% 与 2 倍 |
| 判定人 | 后端判定，测试复核 |

## 4 与条款、门禁的引用

- 条款：MX-G-63 核依赖升级类安全修复的契约四项，为 API 变化清单、受影响调用点清单、锁文件更新与回滚点；本清单把这四项落到字段，另补升级类型、变更范围、适配点、验证命令、观察窗口与许可安全。
- 门禁：外部依赖门核配额与降级方案，兼容门核破坏性变更与验证命令，证据门核回滚实测记录；`TASK-MATRIX.md` 第 2.1 节「依赖升级与回滚可用性」行按本表判定。
- 模板列写法：矩阵格模板列按 `proposal`、`spec`、`tasks`、`task-card`、`evidence`、`RETRO` 登记，本清单作为 evidence 的附件引用，不新增模板名。
