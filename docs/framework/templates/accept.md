# 验收记录模板（accept）

版本：v0.1，2026-11-27。状态：active，随 CHG-FW-002 补齐矩阵引用。
定位：本文件记录一次收口验收的对象、三层结论、分域签字、放行与归档，是 `TASK-MATRIX.md` 验收与收口阶段引用的验收记录。缺字段、缺签字或缺证据索引的记录不计入收口门。
依据：`docs/framework/MOXIAN.md` 第 8 章（验收与放行）、表 9-2（证据字段）与第 7 章门禁条目；`docs/framework/TASK-MATRIX.md` 第 3 节与第 6 节的验收与收口列；`docs/framework/templates/evidence-index.md` 的登记表。

## 1 基本信息

验收开始前填对象与依据，验收结束后补结论、签字与放行。记录缺一项即按缺字段处理，不补写、不追认。

| 字段 | 填写内容 | 填写要求 |
|---|---|---|
| 变更号与任务卡 | `CHG-<域>-<NN>` 与任务卡号 | 一项记录只对应一个变更包；跨包验收拆成多条记录。 |
| 验收层级 | 点级、变更级、出口级之一 | 一次记录只写一层；点级按增量、变更级做一次全量回归与重建、出口级补真机与安装路径。 |
| 验收对象与版本 | 文件、构建或提交号 | 代码写提交号或构建号，文档写路径与行数；对象在验收后又有改动时另开一条记录。 |
| 验收依据 | AC 编号、契约项编号、规则位 | 每条结论都能回指到具体编号，不写“按规范”“按矩阵”。 |
| 验收人与角色 | 姓名或子智能体名与角色 | 功能、视觉、安全、合规、性能、迁移、文档、设计、发布按第 3 节分列；同一人兼任多角色时写全，签字关系按 `ROLES.md` 第 13 节。 |
| 验收时间 | 日期与起止时刻 | 写时区，精确到分钟；跨日验收分行记录。 |
| 记录落点 | 变更包 `spec.md` 验收节或独立文件 | 独立成文时路径写进任务卡 scope，并在证据索引登记。 |

## 2 三层结论

三层各写一行，结论只取 `pass`、`fail`、`pending` 三值。`pending` 必须写未验证原因码与解除条件，不得当作通过。

| 层级 | 范围 | 证据索引 | 结论 | 未验证原因码 |
|---|---|---|---|---|
| 点级 | 本轮变化的点与 AC | `evidence.md` 对应轮次 | pass/fail/pending | 不适用或七类原因码之一 |
| 变更级 | 全量回归与一次重建 | 同上，另附全量报告路径 | pass/fail/pending | 同上 |
| 出口级 | 真机与安装路径 | 同上，另附真机记录路径 | pass/fail/pending | 同上 |

变化项重验写进第二行，只重验本轮变化的 AC；未变化的 AC 沿用上一轮证据并注明轮次，不重复判定。回滚点复验另起一行，写复验时间与结论。

## 3 分域签字

按任务类型取用本节各行，未涉及的域写 `N/A` 与理由，不留空行。

| 域 | 判定内容 | 判定人 | 结论与依据 |
|---|---|---|---|
| 功能 | 三层验收结论与证据索引一致 | 验收员 | 写 AC 编号与证据路径 |
| 视觉 | 四档验收（像素、几何、角色文本、弱网）；需求方另签前端效果 | 验收员与需求方 | 写截图档位与几何观测路径 |
| 安全 | 复现与越权用例结果、扫描证据脱敏、结论与合规分开签 | 验收员与安全评审人 | 写扫描路径与结论 |
| 合规 | 数据处置、删除证明、窗口与审批 | 验收员 | 写处置记录路径 |
| 性能 | 基线与目标对照、p95 与固定测量命令 | 验收员 | 写命令与原始数据路径 |
| 数据迁移 | 迁移前审批、执行后复验、回写受理、契约、测试与证据四处 | 验收员与发布员 | 写审批记录与复验输出 |
| 文档 | 链接、示例复跑、术语与章节结构；读者签字 | 撰写员与读者 | 写核对命令与读者结论 |
| 设计 | 令牌差异、组件清单、可访问性判据 | 设计评审人 | 写设计说明路径与评审记录 |
| 独立工具发布 | 发布清单、签名、灰度或回滚方案 | 发布员 | 写放行单路径 |

## 4 放行与归档

放行结论只写“放行”或“退回”。退回写清退回项、责任人与重验方式；放行写清放行范围、生效时间与放行人，附证据索引与复盘链接。

| 字段 | 填写内容 |
|---|---|
| 放行结论 | 放行或退回 |
| 退回项与责任人 | 退回时逐条写，放行时写“不适用” |
| 放行范围与生效时间 | 写环境、批次与时刻 |
| 放行人 | 发布员或需求方，按 `ROLES.md` 取 |
| 归档位置 | 变更包与证据归档路径 |
| 复盘链接 | `docs/plan/RETRO-<YYYYMMDD>-<需求点ID>.md` 或 `RETRO-CHG-<CHG-ID>.md` |

归档后不再改写记录正文；补验与重验另开记录，并在原记录落点写明后继记录路径。

## 5 未验证项清单

未验证项逐条写编号、原因码、解除条件与责任人，条数写入放行结论前的核对。清单为空时写“无”，不写“基本完成”。

## 6 判定口径

- 三层结论、分域签字、放行与归档四节齐全，且每条结论可回指证据，才计入收口门。
- 验收人不得给自己的产物签字；功能签字与视觉签字分别由验收员与需求方完成，发布员只签放行，不代签功能与视觉。
- 证据缺失写 `missing` 与原因码，不写“通过”；`skipped` 不算通过。
- 记录与证据索引冲突时，以证据索引与原始输出为准，先修记录再放行。
