# 发布与签名清单（release-signing）

版本：v1.0，2026-11-24。状态：active。
定位：本文件是一次发布产物签名与放行的检查记录，一次发布填一份，覆盖构建、签名、验签、时间戳、可复现构建、更新清单与回滚点七类。
依据：`docs/framework/domains/backend.md` MX-BE-77、MX-BE-78，`docs/framework/templates/contract-table.md` 类 11，`docs/framework/templates/cli-release-checklist.md` 第 1 至 9 节。
落点：`specs/changes/<CHG-ID>/release-signing.md`，证据另存 `specs/changes/<CHG-ID>/evidence.md` 的发布节。

## 1 使用条件
交付安装包、更新清单、命令行产物或桌面更新任一项时必填。四项都不成立时在变更包写 `N/A：<理由>` 与重开条件。填写人取发布执行人，复核人取验收，密钥保管人按 `ROLES.md` 的证书与密钥写作用域规则执行。

## 2 构建与产物
| 字段 | 填写内容 | 判定 |
|---|---|---|
| 版本号 | 语义化版本，与变更包一致 | 与更新清单不一致按缺失计 |
| 提交号 | 完整提交哈希 | 与构建记录不一致按缺失计 |
| 工具链 | Go 或其他工具链版本 | 未写版本按缺失计 |
| 构建命令 | 完整命令行，含工作目录与参数 | 不可复跑按缺失计 |
| 产物名 | 文件名含版本号 | 与更新清单不一致按缺失计 |
| 哈希算法与值 | `SHA-256` 加 64 位小写十六进制 | 长度或大小写不符按缺失计 |
| 文件清单 | 产物内的文件列表与各自哈希 | 缺清单按缺失计 |

## 3 签名检查
| 检查项 | 通过条件 | 结果 | 证据 |
|---|---|---|---|
| 签名对象 | 安装包与更新清单两份文件都已签名 | 待填 | 待填 |
| 签名算法 | `RSA-PSS-SHA256`、`ECDSA-P256-SHA256` 或 `Authenticode` 三值之一 | 待填 | 待填 |
| 证书主体 | 证书 `CN` 与发布主体一致 | 待填 | 待填 |
| 证书有效期 | 发布日落在证书起止日期内 | 待填 | 待填 |
| 密钥来源 | 证书存储或受控环境变量，仓库与日志无明文 | 待填 | 待填 |
| 签名命令 | 完整命令行，含时间戳服务地址 | 待填 | 待填 |
| 签名结果 | 退出码 0，签名文件已生成 | 待填 | 待填 |

## 4 验签与时间戳
| 检查项 | 通过条件 | 结果 | 证据 |
|---|---|---|---|
| 验签命令 | 完整命令行，与签名对象一致 | 待填 | 待填 |
| 验签退出码 | `0` | 待填 | 待填 |
| 时间戳服务 | RFC 3161 服务地址可达，返回时间有效 | 待填 | 待填 |
| 时间戳校验 | 时间戳值与签名对象哈希匹配 | 待填 | 待填 |
| 失败处理 | 验签失败时产物不得进入更新清单 | 待填 | 待填 |

时间戳服务不可达时本次签名无效，不得用本机时间替代。验签失败的产物保留原文件并登记失败原因，修复后重新签名与验签。

## 5 可复现构建
| 检查项 | 通过条件 | 结果 | 证据 |
|---|---|---|---|
| 构建参数 | `go build -trimpath -buildvcs=false`，时间变量取 `SOURCE_DATE_EPOCH` | 待填 | 待填 |
| 第二次构建 | 在隔离目录用同一提交与工具链重跑一次 | 待填 | 待填 |
| 哈希一致 | 两次构建的产物哈希相同 | 待填 | 待填 |
| 文件清单一致 | 两次构建的文件列表与各自哈希相同 | 待填 | 待填 |
| 差异说明 | 不一致时列出差异文件与原因，重跑后仍不一致按不可复现登记 | 待填 | 待填 |

## 6 更新清单与灰度
| 字段 | 填写内容 | 判定 |
|---|---|---|
| 更新清单格式 | 文件名、格式版本与字段清单 | 缺字段按缺失计 |
| 清单内容 | 产物名、版本号、哈希与发布日期 | 与产物不一致按缺失计 |
| 分桶键 | 键名与哈希或取模方式 | 未写按缺失计 |
| 放量档位 | 1%、10%、50%、100% 四档 | 缺档位按缺失计 |
| 观察窗口 | 每档时长与单位 | 未写按缺失计 |
| 回滚阈值 | 指标、比较符、数值与连续命中次数 | 缺连续次数按缺失计 |

## 7 回滚点
| 字段 | 填写内容 |
|---|---|
| 上一版本 | 版本号、产物路径与哈希 |
| 回滚触发条件 | 错误率超过 1% 或 p95 超过基线 2 倍并连续命中 3 个窗口 |
| 回滚命令 | 完整命令行与工作目录 |
| 回滚后验证 | 健康检查、版本号与一次关键业务命令 |
| 不可回滚点 | 已提交的数据迁移批次与已发送通知 |

回滚点缺任一项时不得放量。回滚后验证不通过时保持回滚状态并登记异常，不继续放量。

## 8 证据与判定
| 字段 | 填写内容 |
|---|---|
| 结论 | `pass`、`partial`、`failed` 三值之一 |
| 证据 | 签名记录、验签输出、哈希值、可复现构建结论、更新清单与回滚记录六类 |
| 填写人 | 发布执行人角色名与日期 |
| 复核人 | 验收角色名与日期 |
| 放量结论 | 全量生效或已回滚两值之一，写最终档位与结束时间 |

## 9 检查清单
- [ ] 使用条件已判定，版本号、提交号与工具链三项齐全。
- [ ] 产物名、哈希与文件清单齐全，哈希为小写 64 位，签名对象两份、算法、证书主体与有效期齐全。
- [ ] 验签退出码为 0，时间戳已校验，可复现构建两次哈希与文件清单一致。
- [ ] 更新清单格式与内容齐全，四档放量与观察窗口已写。
- [ ] 回滚五项齐全，不可回滚点已写明。
- [ ] 六类证据齐全，结论只取三值，放量结论只取两值。
