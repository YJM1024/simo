# 架构决策记录模板（ADR）

版本：v1.0，2026-11-25。状态：active。本模板服务 `MOXIAN.md` 第 6 章与第 8 章、`docs/framework/domains/product-design.md` MX-PD-62，落点 `docs/framework/templates/adr.md`，条目正文写进 `docs/plan/DECISIONS.md`。

## 1 用途与何时用

重构、跨模块接口变更、数据模型与路由变更、引入或替换外部依赖时，用一个可复核的决策记录固定「为什么这样选」。开工前写，冻结时定稿，实施后只追加后果，不回改决定。一次决策一条记录，编号 `ADR-<三位序号>` 域内唯一、删除不复用；被取代的旧记录状态改为「已取代」并写新编号。

## 2 字段表

| 列名 | 必填 | 取值口径 |
|---|---|---|
| ADR 编号 | 是 | `ADR-<三位序号>`，与 `DECISIONS.md` 的 DEC 编号互相引用，不合并编号 |
| 标题 | 是 | 一句话写决策对象，不写方案名 |
| 日期 | 是 | `YYYY-MM-DD`，写决定日期 |
| 状态 | 是 | 提议、已接受、已拒绝、已取代四值之一；已取代须写取代它的 ADR 编号 |
| 决策人 | 是 | 角色名加签字日期；重构类决策人不得为实现者本人 |
| 背景与约束 | 是 | 三至五句，写现状、必须满足的约束与不成立的假设 |
| 备选方案 | 是 | 至少两个，每个写做法、代价与放弃理由；只写一个方案按缺失计 |
| 决定 | 是 | 选定方案与一句话理由，理由指向具体约束，不写「更合理」 |
| 后果 | 是 | 正面、负面与待观察各一条，负面后果写触发条件 |
| 影响范围 | 是 | 涉及的需求点、契约项编号、目录与组件编号 |
| 关联变更与任务卡 | 是 | `CHG-<域>-<NNN>` 与任务卡号；无卡时写 `N/A：<理由>` |
| 复核人 | 是 | 与决策人不同的角色，按 `ROLES.md` 第 13 节不得自签 |
| 回滚方式 | 是 | 撤销该决定需要改动的文件与数据，写一步可执行动作 |

## 3 填写示例

| 字段 | 示例 |
|---|---|
| ADR 编号 | `ADR-017` |
| 标题 | 任务轨迹改用追加写入的事件日志 |
| 状态 | 已接受 |
| 决策人 | 后端，2026-11-25 |
| 背景与约束 | 轨迹当前按整表更新，并发写入丢轨迹；前端按 `traceSeq` 去重，序号必须严格递增；不引入消息中间件。 |
| 备选方案 | 一、整表加乐观锁，代价是冲突重试放大写放大；二、追加事件日志加序号分配，代价是多一张表与一次查询。 |
| 决定 | 选二，序号由数据库序列分配，满足严格递增且不引入中间件。 |
| 后果 | 正面是并发写入不丢轨迹；负面是查询需要按任务聚合，触发条件为单任务轨迹超过 2000 条；待观察读放大。 |
| 回滚方式 | 停写事件表，按任务重算快照回填轨迹表，删事件表。 |

## 4 与条款、门禁的引用

- 条款：MX-PD-62 规定五节结构与编号唯一；`MOXIAN.md` 第 6 章要求重构类变更在契约表类 1、类 2 引用本记录编号。
- 门禁：契约门（MX-G-26 至 MX-G-31）核契约表引用；重构等价性判定按 `TASK-MATRIX.md` 第 2.1 节验收对象表执行；矩阵重构格的模板列写「design、ADR」。
- 证据：本记录路径与行号写进 `templates/evidence-index.md` 的「设计证据」组，判定人写复核人角色。
