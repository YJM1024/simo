# 独立工具发布检查清单（cli-release-checklist）

版本：v0.1，2026-11-24。状态：active，随第二批压测补缺建立。
定位：本文件是独立工具类交付物的发布、升级与回滚检查清单，一次发布填一份，逐项留证据。
依据：`docs/framework/TASK-MATRIX.md` 第 8 节独立工具行与第 2.1 节验收对象表，`docs/framework/domains/backend.md` MX-BE-74 至 MX-BE-76，`docs/framework/MOXIAN.md` MX-11-12。
落点：`specs/changes/<CHG-ID>/cli-release.md`，发布记录另在 `docs/testing/ACCEPT-<CHG-ID>-<YYYYMMDD>.md` 留一行。

## 1 基本信息

| 字段 | 填写内容 | 要求 |
|---|---|---|
| 变更号 | `CHG-TOOL-<NNN>` | 与变更包首部一致 |
| 工具名 | 命令名，与 `--version` 输出一致 | 不写内部代号 |
| 版本号 | 语义化版本，主版本、次版本、修订号三段 | 与产物文件名、`--version` 输出三处一致 |
| 目标平台 | Windows、Linux、macOS 中的一个或多个 | 逐个平台填安装与启动结果 |
| 产物路径 | 二进制文件路径与哈希值 | 哈希用 `Get-FileHash` 或 `sha256sum` 计算 |
| 安装方式 | 解压位置、环境变量与首次运行命令 | 三步按顺序写 |
| 判定人 | 验收与抽检用户 | 工具实现者不得签本人产物 |

## 2 发布前检查

八项全过才允许发布，一项不过停在自验门。

| 编号 | 检查项 | 通过标准 | 证据 |
|---|---|---|---|
| P-01 | 版本号一致 | 变更包、产物文件名、`--version` 三处一致 | 三处截图或输出 |
| P-02 | 依赖锁定 | `go.mod` 与 `go.sum` 已提交，`go mod tidy` 后无差异 | 命令退出码 0 与空差异 |
| P-03 | 构建可复现 | `go build -trimpath` 运行两次产物哈希相同 | 两次哈希值 |
| P-04 | 命令契约齐全 | 子命令、参数、环境变量、退出码、stdout 与 stderr、产物路径、版本输出七项齐全 | 契约表行号 |
| P-05 | 退出码符合契约 | 成功为 `0`，参数或环境错误为 `2`，错误走 stderr | 三条实测命令输出 |
| P-06 | 产物哈希与清单一致 | 产物哈希写进证据索引并与清单一致 | 哈希对照表 |
| P-07 | 文档齐全 | 安装说明、版本说明与回滚步骤三段齐全 | 文档路径 |
| P-08 | 组件登记 N/A | 无界面组件时写 `N/A：<理由>` 并由验收确认 | 证据文件对应行 |

## 3 安装验证

安装验证在隔离目录执行，不污染开发环境。四步按顺序做：复制产物到隔离目录、设置环境变量、运行 `--version`、运行一个真实子命令。四步各记退出码与 stderr 输出，任一步非零按发布失败处理。

## 4 升级检查

升级前读旧版本号与旧配置，升级后核对四件事：新版本号、配置兼容、数据目录兼容与旧命令行为不变。配置项改名或删除时写迁移说明与默认值；数据目录结构变化时写备份路径与回滚方式。升级验证以旧版本生成的产物或数据为输入，只用空数据验证升级不算通过。

## 5 回滚检查

回滚写清回滚触发条件、回滚命令、回滚后验证三处。触发条件取安装失败、启动失败、子命令退出码与契约不符、产物哈希不一致四类之一。回滚命令写具体路径与参数，回滚后运行 `--version` 与一个真实子命令，核对版本号回到旧版本且数据目录可用。旧版本产物保留到下一个版本发布成功，保留位置写进清单。

## 6 验收层级与判定人

独立工具按出口级验收，三层内容为契约测试、构建、安装验证与产物抽检四项。用户抽检可用性，验收签命令行契约与产物；工具实现者不得签本人产物。发布检查清单缺项时收口门判不通过，版本号、产物哈希与安装结果三项缺一不得标记已发布。

## 7 发布记录

一次发布一行，字段为版本号、发布日期、产物哈希、目标平台、安装结果、升级结果与回滚演练结果。发布后把本文件路径写进变更包证据索引与表 11-1 的签字类。

## 8 未通过处理

任一项未通过时停在自验门，修完重跑全部检查项，不跳过失败项只跑其余项。同一检查项连续两轮不过是停在该步报告卡点，写已试内容与所需输入，不以继续打包代替判断。

## 9 清单自身的核对

清单每项必须有证据路径，没有证据路径的项按未检查计。同一变更两次发布时各填一份，第二份引用第一份的编号，不覆盖旧记录。清单项与 `TASK-MATRIX.md` 第 8 节的独立工具行冲突时以任务矩阵为准，并回写本文件后重新核对。发布记录缺版本号、产物哈希或安装结果其中一项时，收口门按交付物缺失登记。
