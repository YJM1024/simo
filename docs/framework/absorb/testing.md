# 墨线框架测试与验收候选吸收决策表

本文把调研报告中 26 个测试与验收候选整理成采纳决策，供墨线框架第一批落地使用。表中「落点」一列写该候选落到总册的章号或模板名，章号按 `docs/framework/MOXIAN.md` 的十三章结构写，其中 9 章为测试与证据。判定分采纳、改造后采纳与不采纳三类，每条给出理由、落地批次与自动化方式。

判定依据来自仓库现状与已生效的约束。`docs/framework/MOXIAN.md` 第 9.4 节的 MX-9-20 已定门禁分阻断、告警与夜间三档，MX-9-21 已定覆盖率只做趋势、不设硬指标；GWT 只作验收用例格式见 `docs/framework/domains/testing.md` 第 4 节的 MX-QA-25，不引入 Pact 的登记见总册附录 C 与 `docs/framework/domains/backend.md` 第 8.6 节。`docs/process/SPEC-STANDARD.md` 第 2 节把判定人与脚本路径设为每条 AC 的必填字段，第 3 节定了断言脚本契约。工具面已有 `run-ac.mjs`、`ac-coverage.mjs`、`check-spec-language.mjs`、`check-trace.mjs`、`capture-visual.mjs` 与 `check-visual-baseline.mjs`，`scripts/ac` 下有 41 个断言脚本；frontend 装了 Vitest 5.1 与 Playwright 1.65，后端 `go.mod` 未装 testify，107 个测试文件共 314 个测试函数，表驱动写法只出现在 7 个文件里。

采纳、改造后采纳与不采纳的条目都进总册附录 C 的采纳清单索引，不采纳的条目写清重新评估的条件。新建的模板同时登记进附录 A 模板清单，门禁类条目同时登记进附录 B 门禁清单。本表判定列只取采纳、改造后采纳与不采纳三值，不写同义变体。

## 统计

四组计数分别按判定、类型、落地批次与自动化方式统计，合计与候选总数 26 条一致。

- 按判定：采纳 10 条，改造后采纳 13 条，不采纳 3 条。
- 按类型：策略 7 条（采纳 2、改造后采纳 5）、验收方法 5 条（采纳 1、改造后采纳 4）、自动化 7 条（采纳 4、改造后采纳 1、不采纳 2）、门禁 4 条（采纳 2、改造后采纳 2）、技能 3 条（采纳 1、改造后采纳 1、不采纳 1）。
- 按落地批次：批一 16 条，批二 7 条，不落地 3 条。
- 按自动化方式：脚本 13 条，模板 8 条，人工 2 条，不适用 3 条（对应三条不采纳）。

批一在本轮落地，产物限于模板字段、总册条文与现有脚本的参数调整。批二依赖批一冻结的字段或新增工具。不落地的条目只登记不引入。

## 批一可落地条目

以下十条从批一的 16 条判定里挑出，都能在本轮写成模板字段或脚本参数，不依赖新增工具链。

1. 每条 AC 补判定人、脚本路径与证据路径三个字段，判定人写自动或人工加动作，缺失时不允许开工。落到 spec 模板的 AC 字段与 `check-spec-language.mjs` 的第三条规则（无脚本且未写人工即 error）。
2. AC 文本保留 Given、When、Then 句式，断言按触发、观察点、判据、脚本、判定人五段写。落到 spec 模板的 AC 字段，检查由 `check-spec-language.mjs` 的七条规则承担。
3. 测试层归属表列单元、集成、契约、界面、人工五层，每层写运行命令与目录约定，按改动路径选层。落到 test-plan 第 2 节的层列与总册 9 章的层归属表。
4. 风险矩阵在 test-plan 第 1 节补可能性与影响两列，按三档打分，高风险点增加测试深度与回归频率。落到 test-plan 第 1 节。
5. 等价类表与边界值表从字段类型、数据库约束与 schema 推导，用例按表驱动写，每行一个代表值与一个越界值。落到 test-plan 第 2 节用例列与新建的表驱动用例模板。
6. 门禁按阻断、告警、夜间三档挂载，阻断档只留 error 级规则，夜间档跑覆盖率趋势与视觉基线。落到 `check-sdd.mjs`、`check-spec-language.mjs`、`run-ac.mjs` 与 `ac-coverage.mjs` 的串行命令。
7. 不稳定用例连续三次结果不一致时移入隔离清单，写责任人与到期日，隔离集不参与发布判定。落到新建的 flaky 清单模板与 `run-ac.mjs` 的复跑参数。
8. 覆盖率按行、分支、函数三类统计并列出未覆盖行，阈值只进夜间告警。落到 `npm run test:coverage` 与 `go test` 的 cover 参数，结果写 evidence 第 3 节。
9. 视觉基线只在 3 至 5 个关键页建立，差异容差与遮罩写进脚本参数，基线更新需要人工审查。落到 `capture-visual.mjs` 与 `check-visual-baseline.mjs`，截图路径写 evidence 第 4 节。
10. 核心纯逻辑、迁移与权限路径先写失败测试并保留运行日志，日志时间要早于实现提交。落到 evidence 第 2 节的命令输出与 task-card 的自验项。

## 未决项

1. 增量覆盖率是否升为阻断。当前按告警运行，升为阻断需要修改 `docs/framework/MOXIAN.md` 第 9.4 节的覆盖率条款（MX-9-22），等用户裁决。
2. 契约唯一源。仓库内未找到 OpenAPI 文件，契约测试的提供者侧校验缺少输入，需要后端确认契约文件的生成方式与存放位置。
3. 视觉回归阈值。不同系统与字体渲染的差异没有公开可复用的数值，需要在本机 Windows 环境对 3 至 5 个页面实测后确定容差。
4. 变异抽检工具。Go 侧与前端均未装变异工具，Stryker 只覆盖 JavaScript 与 TypeScript，抽检方式与工具选型留到批二评估。
5. 属性测试范围。金额、解析、状态机三类核心逻辑的具体清单需要架构确认，确认前只做固定种子样例。
6. 新建模板的维护人。flaky 清单、变异抽检记录与表驱动用例模板需要登记进附录 A，总册附录 D 已把附录 A 至 C 的维护人列为未决点，需在第二批开工前确定。
7. 智能体独立验收的准确率与误判率没有公开对照数据，先用已有 33 条 AC 的人工结论做回放校准，再决定门禁强度。
