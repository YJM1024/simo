# 产品需求与产品设计候选采纳决策（product-design）

候选 18 条，采纳 3 条，改造后采纳 11 条，不采纳 4 条，批一可落地 8 条。
落点覆盖总册第 2、3、5、6、7、8、10、11、13 章共 9 章，另有 3 条不采纳项的落点记总册附录 C 采纳清单索引，第 1、4、9、12 章没有对应候选。

本文逐条处理 `docs/research/product-design-survey.md`（2026-11-24，18 个候选）的结论，每条给出判定、理由、落点、批次与自动化方式。判定按任务给定口径执行：采纳指候选的产物形态可以直接写成规则、模板字段或脚本检查；改造后采纳指保留核心思想但改变产物形态或范围，改法写在理由列；不采纳必须写出一条可核对的理由，并给出取舍记录的位置。编号沿用调研文件的分节编号，回查时按编号定位原节。调研文件第四节对多数候选只给出宽口径结论，本表把它拆到单条并落到具体章号，两者不一致处以本表为准。

## 批一可落地清单（8 条）

下面八条按依赖顺序排列，前两条决定需求点能否被脚本核验，第三与第四条作用于受理阶段的提案，后四条在实现与验收阶段生效。可复用的现成文件有模板 `docs/process/templates/spec.md`、`proposal.md`、`design.md`、`test-plan.md`，脚本 `scripts/check-spec-language.mjs` 与 `scripts/probe-cdp.mjs`，样式文件 `frontend/src/styles/tokens.css` 与组件清单 `frontend/src/components/manifest.json`。需要新建的模板两份、脚本五个，另加一条样例页路由。

1. AC 句式统一为中文 EARS（1.2）：改模板 `docs/process/templates/spec.md` 的 AC 段写法，在脚本 `scripts/check-spec-language.mjs` 现有七条规则上增加句式解析规则，解析失败的行报 error 并计入缺口。
2. delta 三标记与归档合并（1.3）：新建模板 `docs/process/templates/delta.md` 定义 ADDED、MODIFIED、REMOVED 三段的写法和必填字段，新建脚本 `scripts/merge-delta.mjs` 做基线冲突检测，冲突时以退出码阻断归档。
3. 受理澄清上限五问（1.1）：改模板 `docs/process/templates/proposal.md` 的待确认项节，规定每次最多五问、每问一问一句，新建脚本 `scripts/check-proposal.mjs` 检查字段齐全与冻结前待确认项清零。
4. 提案动机三行（2.1）：改模板 `docs/process/templates/proposal.md` 的背景与问题节，固定期望结果、受影响角色、当前替代方案三行，期望结果必须带度量指标，缺失由同一条 `scripts/check-proposal.mjs` 报错。
5. RICE 排序表（2.5）：新建模板 `docs/process/templates/priority.md` 与脚本 `scripts/rice.mjs`，四个因子缺任一项时拒绝计算并列出缺项，算出的分值只用于同一待办池内的相对排序。
6. 设计令牌单一来源（3.1）：以 `frontend/src/styles/tokens.css` 为唯一取值来源，把 token 清单写进模板 `docs/process/templates/design.md`，新建脚本 `scripts/check-tokens.mjs` 扫描组件样式里的硬编码颜色与间距，命中数量不为零时判不通过。
7. 可访问性自动子集（3.5）：新建脚本 `scripts/check-a11y.mjs`，覆盖对比度、表单标签、页面语言、焦点顺序与目标尺寸五项，由各条 AC 脚本调用；其余准则写进模板 `docs/process/templates/test-plan.md` 的人工检查列，每条带签字人与证据路径。
8. 组件样例与截图基线（3.7）：按 `frontend/src/components/manifest.json` 的 variants 与 states 生成应用内样例页路由，每个状态一个可访问地址，截图复用 `scripts/probe-cdp.mjs`，基线目录与命名规则写进模板 `docs/process/templates/design.md`。
