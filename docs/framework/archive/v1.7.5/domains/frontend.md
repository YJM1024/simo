## 1 适用范围与位置

本文件规定前端域在墨线框架内如何接收契约、设计组件与状态、实现、自测和提交验收，并把每个阶段的产出物、判据与门禁写到可判定。适用对象是 `frontend/` 下的界面、组件、样式、状态与交互改动，以及 `specs/frontend/` 下的长期 spec 与变更增量。后端接口实现、产品行为定义和验收签字分别由后端域、产品域和验收角色承担，前端不代替它们作结论。

前端域处在设计契约与测试验收之间。输入是产品 spec 中与界面有关的 AC、设计列的选择器与几何、组件 spec 和后端接口形状；输出是前端 spec 增量、五份设计与状态产物、可复跑的自验证据，以及交给测试的选择器与夹具。测试域据此写用例，验收角色据此复核，用户只签视觉与交互效果。

表 1-1 给出八类任务在前端的必做项。主类型决定必做集，附加类型只叠加特有门禁，不改变主类型的取值；任务判级由受理阶段完成，前端在契约门之前只核对，不自行改判。

| 任务类型 | 前端必做项 | 可省或不适用 | 特有门禁 |
|---|---|---|---|
| 新功能 | 前端列六字段、组件 spec 增量（涉及组件时）、八态矩阵、错误态、组件登记、关键档位截图 | 无可省项 | 组件登记门、可访问性门 |
| 界面调整 | 视觉与交互设计说明落成前端增量、八态与档位、复用组件判定、关键档位截图 | 无可省项 | 组件登记门、可访问性门 |
| 缺陷修复 | 失败用例先行、相邻路径回归、修复前后输出 | 契约与拆分可省；根因不明、跨模块或涉契约变更时契约升级为必做 | 无 |
| 重构 | 行为等价判据、同一组组件测试前后通过、组件公开 API 与 DOM 锚点不变 | 无可省项 | 兼容门 |
| 数据迁移 | 读取新结构的兼容展示、旧数据渲染用例、回滚期 N/A 说明 | 无可省项 | 兼容门 |
| 性能优化 | 首屏与交互基线、同条件三次取中位数、正确性回归 | 拆分可省 | 性能基线门 |
| 安全修复 | 攻击用例先行、修复后攻击用例失效、相邻入口扫描 | 无可省项 | 安全评审门 |
| 纯文档 | 语言检查、链接检查、示例命令复跑 | 前端代码测试与状态矩阵不适用，写 N/A 加理由 | 文档校验门 |

前端契约只有一处事实来源，即 `specs/frontend/<域>/spec.md`。变更增量写在同一文件的对应功能点节内，变更包只登记范围、状态与证据索引。组件 spec 属于设计列的子产物，按 `specs/COMP-<NNN>-<slug>/spec.md` 建，前端不另建第二份组件契约。

本节的规则如下。

- MX-FE-01 前端域的适用对象是 `frontend/` 下的界面、组件、样式、状态与交互改动，以及 `specs/frontend/` 下的长期 spec 与变更增量，本文件之外的代码与文档不按本文件判定。
- MX-FE-02 每条与界面有关的产品 AC 必须在前端 spec 增量或任务卡中有判据载体，判据载体的字段按第 3.1 节填写，缺字段即判契约不完整。
- MX-FE-03 前端契约的事实来源只有 `specs/frontend/<域>/spec.md`，同一事实不得在变更包、任务卡或组件画廊中另写一份可执行口径。
- MX-FE-04 八类任务的前端必做项按表 1-1 执行，主类型决定必做集，附加类型只叠加门禁与证据项。
- MX-FE-05 前端在契约阶段接收设计列与后端接口形状，实现完成后向测试域交付选择器与夹具，向验收角色交付可复跑证据，交接顺序不得颠倒。
- MX-FE-06 前端实现者不得给自己的功能或视觉签字，功能签字由验收完成，视觉签字由用户完成。

## 2 阶段步骤

前端工作按契约接收、组件与状态设计、实现、自测、提交验收五步推进。每步写清输入、动作、产出与判定人，前一步产出是后一步输入；任一步判定不通过时停在该步，不进入下一步。五步与 `TASK-MATRIX.md` 的六阶段对应如下：契约接收与组件状态设计落在契约与设计，实现落在执行，自测覆盖执行阶段的自验与测试与证据阶段的取证，提交验收落在验收与收口。

### 2.1 契约接收

- 输入：产品 spec 的 AC 与优先级、设计列的选择器与几何、适用的组件 spec、后端接口形状（method、path、请求与响应字段、错误码）。
- 动作：逐条把 AC 映射到组件、状态与锚点；核对六字段是否齐全；缺字段的条目列入缺口清单并退回设计或后端补齐；冻结判据，写清脚本或人工判据；不适用的字段写 N/A 加理由。
- 产出：前端 spec 增量的功能点节、判据冻结记录、缺口清单。
- 判定人：前端 owner 提交，设计与测试复核，契约门由 `TASK-MATRIX.md` 列出的复核角色确认。

### 2.2 组件与状态设计

- 输入：冻结的契约、组件库 `manifest.json`、`tokens.css`、既有组件测试。
- 动作：按复用现有组件、扩展变体、新建组件的顺序选型；新建组件先归入原子、分子、有机体、模板、页面五层中的一层并在 `manifest.json` 登记层级字段；写八态矩阵与键盘路径；写事件到状态映射，含非法事件的处理；确定锚点与查询方式；为几何与视觉判据选定采样点、档位与容差；逐请求列错误态与重试入口。
- 产出：组件状态矩阵、DOM 锚点与选择器清单、事件到状态映射、错误态清单，以及新建或变更组件时的组件 spec 增量。
- 判定人：设计评审组件语义与几何，前端 owner 对可实现性负责，测试复核可测性。

### 2.3 实现

- 输入：组件与状态设计产物、冻结判据、任务卡的 scope 与禁止项。
- 动作：只在 scope 内改动；组件只从 `src/components/index.ts` 导入；样式只使用 `tokens.css` 与组件样式；不写页面级 CSS、不写内联 style、不引入未批准依赖；按事件映射实现状态；错误态使用 `role="alert"` 或 `role="status"`；可访问名称与键盘路径落地；新建或修改组件时同批更新 `manifest.json` 与画廊截图。
- 产出：代码改动、manifest 更新、关键档位截图、执行记录。
- 判定人：同域实现者自验，组件登记门由前端 owner 提交、验收核对。

### 2.4 自测

- 输入：实现、判据、第 5 节的门禁命令。
- 动作：先跑改动目标的测试文件，再跑受影响组件测试全量；跑类型检查；对几何与时延判据在固定视口采样；失败时修到通过，不改判据；记录命令、退出码、通过数与跳过数；取不到的证据写 missing 与原因。
- 产出：自验记录、命令输出、截图、missing 清单。
- 判定人：实现者自验，测试域复核可复跑性，验收独立重跑。

### 2.5 提交验收

- 输入：自验记录、证据索引、变更包、前端 spec 增量。
- 动作：按需求点提交，附复跑命令与环境；验收复跑增量并抽查关键 AC；用户签视觉与交互；通过后回写 spec 状态、组件签字与复盘；不通过退回原实现者，连续两轮不过再换人或拆分。
- 产出：验收记录、签字、spec 与变更包状态、复盘。
- 判定人：验收功能签字，用户视觉签字，Lead 在收口门确认。

本节的规则如下。

- MX-FE-07 契约接收以判据冻结为出口，AC 的组件、状态、锚点、错误态与无障碍判据缺任一项且未写 N/A 加理由时退回补齐，前端不得自行补设计数值或后端字段。
- MX-FE-08 组件选型按复用现有组件、扩展变体、新建组件的顺序进行，Radix 依赖落地后浮层类组件只允许包装 Radix 的 Dialog、Menu、Popover、Tooltip 与 Select，新建组件必须先登记 `manifest.json` 并由组件登记门确认后才允许页面使用。
- MX-FE-09 组件与状态设计必须产出八态矩阵与键盘路径，八态为默认（`default`）、悬停（`hover`）、聚焦（`focus`）、按下（`active`）、禁用（`disabled`）、加载（`loading`）、空（`empty`）、错误（`error`），与 `GATES.md` 的 MX-G-28 取同一集合，缺一态须写 N/A 加理由。
- MX-FE-10 实现只改任务卡 scope 内的文件，组件只从 `src/components/index.ts` 导出与导入，页面不得新建组件或维护第二份组件实现。
- MX-FE-11 样式只使用 `tokens.css` 的 token 与组件自身样式，不得新增硬编码字面量；DTCG 生成链落地后 token 以 DTCG JSON 为唯一来源，生成物不手改，组件内硬编码字面量扫描为 0 处、token 构建前后 diff 为空；页面不得出现 `<style>`、内联 style 或页面级 CSS 文件，新增依赖须先经变更包批准。
- MX-FE-12 新建组件、修改组件 API 或修改视觉与交互时，`manifest.json` 的组件、变体、状态与 owner 字段同批更新，新建组件同时登记原子、分子、有机体、模板、页面五层中的一层，截图证据按组件登记门提交，缺任一项不得合入。
- MX-FE-13 自测顺序为目标测试、受影响组件测试全量、类型检查，前一步失败不得跳到下一步，全部通过后才允许提交验收。
- MX-FE-14 自测记录必须写出通过数、失败数与跳过数，跳过项逐条写原因与替代证据，取不到的证据写 missing，不得写成通过。
- MX-FE-15 自测失败时修改实现或补测试，不得删减、放宽或改写已冻结的判据来换取通过。
- MX-FE-16 提交验收的材料包含复跑命令、环境、证据路径与未验证项清单，缺少未验证项清单时验收不得开始复核。
- MX-FE-17 验收不通过时退回原实现者，同一需求点连续两轮不通过后由 Lead 决定换人或拆分，换人前原实现者把已完成部分写回文件。
- MX-FE-18 验收通过后同批回写前端 spec 状态、组件签字、变更包与单点复盘，回写缺失时该需求点不得标记完成。
- MX-FE-51 前端实现按 `docs/process/skills/frontend-implementation/SKILL.md` 执行，该文件至少写全触发条件、输入、步骤、产物、完成判据与反模式六节，步骤与第 2 节的五步一一对应；每步的完成判据写第 5 节的门禁命令与退出码，写不出命令的步骤写人工判据、判定人与证据路径；文件缺节、步骤与五步不对应或完成判据没有命令与退出码时该文件不算落地，实现按第 2 节五步人工执行并在证据里注明，文件修订后同批更新第 8 节表 8-1 的第 24 行。（对应候选 24）

## 3 必产出文件与字段

五份产物是新功能、界面调整、重构、数据迁移、性能优化与安全修复的最小集合，缺一份不得进入提交验收。缺陷修复按表 1-1 取最小形态，五份产物写在任务卡与失败用例里，字段仍按本节填写。每份产物有固定字段与落点，字段留空按缺失计，不适用写 N/A 加理由；前端 spec 增量是主文档，其余四份可以写在它的功能点节内，同一事实只保留一处。

### 3.1 前端 spec 增量

- 落点：`specs/frontend/<域>/spec.md`；新功能与界面调整写完整功能点节，缺陷修复写失败用例与修复记录，重构写行为等价判据。
- 结构：组件边界、状态归属、错误呈现、尺寸与断点四类共用口径在一个文件里只写一次；每个功能点按组件与页面结构、状态与数据流、接口调用、交互细节、可测断言、涉及文件行号六节写。
- 字段：按表 3-1 的六字段填写，字段分布在六节中且能被检索到。
- 任务卡：前端任务卡在通用字段上补组件、状态矩阵、截图档位与门禁命令四字段，缺任一项不得派单。

| 字段 | 必填 | 写法 |
|---|---|---|
| 组件与 props | 是 | 组件名、props 名称、类型、默认值、是否必填、数据来源 |
| 状态转移 | 是 | 状态 A 经事件 E 到状态 B，列出全部转移，非法事件写明保持原状态 |
| 事件到状态 | 是 | 事件名、派发者、前置状态、目标状态、副作用 |
| DOM 锚点 | 是 | `data-*` 属性与取值、role 与可访问名称，供断言定位 |
| 错误态 | 是 | 每个请求失败的可见反馈、role、文案、重试入口与数据不变量 |
| 无障碍 | 是 | role、可访问名称、焦点顺序、键盘路径；不适用写 N/A 加理由 |

### 3.2 组件状态矩阵

- 落点：组件 spec 的“状态矩阵”节；没有独立组件 spec 时写在前端 spec 增量的对应功能点节。
- 字段：状态、触发条件、可见结果、断言、截图档位。
- 覆盖：至少包含默认（`default`）、悬停（`hover`）、聚焦（`focus`）、按下（`active`）、禁用（`disabled`）、加载（`loading`）、空（`empty`）、错误（`error`）八态，另列键盘路径；每个状态对应一条用例，每格写值或 N/A 加理由。

### 3.3 DOM 锚点与选择器清单

- 字段：锚点、查询方式、所属 AC、采样点、稳定性说明、替代查询方式。
- 优先级：组件测试按 role 与可访问名称、label 与文本、`data-*` 的顺序查询；设计列与跨进程的 CDP 断言使用 `data-*` 稳定锚点；同一判据只选一种查询方式。
- 禁止项：类名、`nth-child`、结构位置与数组下标不得作为判据；`getByTestId` 仅在角色与文本都不可用时使用，并在用例内注释理由。

### 3.4 事件到状态映射

- 字段：事件、派发者、前置状态、目标状态、副作用、非法事件处理、断言。
- 事件源：指针事件、键盘事件、WebSocket 帧、BroadcastChannel 消息与定时器分别列出，键盘事件写清按键与修饰键。
- 非法事件：未定义转移的事件必须保持原状态，并有对应用例证明状态与界面都未变化。

### 3.5 错误态清单

- 字段：操作或请求、失败条件、可见反馈、role、文案、重试入口、数据不变量、证据。
- 层级：字段或卡片内联、页面级、全局提示三级沿用会话域的既有口径，同一失败不得同时出现在两级。
- 不变量：失败时不得显示假 0 或假成功，未知数值显示破折号，失败请求不得在本地追加消息或把草稿标记为已发送。

### 3.6 文案资源与本地化

文案与格式资源按本节登记，词条文件、格式选项与回退顺序只有一处来源。词条键名格式为 `<域>.<页面或组件>.<语义>`，段内只用小写字母、数字与下划线，键名不写中文、不写序号。一个键只对应一个语义，同一语义在多个页面复用时引用同一键，不复用键承载第二个含义；废弃键在词条文件标记 `deprecated` 并写替代键名，替代完成后删除。

词条字段按下表填写，缺任一项时前端 spec 的文案节不完整。

| 字段 | 写法 | 判定 |
|---|---|---|
| 词条键 | 点分三段，段内小写 | 含中文或序号按不合格计 |
| 默认语言文本 | `zh-CN` 文本，占位符用 `{name}` | 占位符与参数名不一致按缺失计 |
| 复数与占位符规则 | ICU MessageFormat，写 `one` 与 `other` 分支 | 只写一种分支按缺失计 |
| 其他语言文本 | 逐语言一行，键集合与默认语言一致 | 缺键按缺失计 |
| 缺键回退链 | `zh-CN` 到 `zh` 到 `en`，最后显示默认语言 | 回退链缺一级按缺失计 |
| 术语表条目 | 术语、译法与裁定人 | 术语未进表按缺失计 |

格式统一由 `Intl` 构造，不手写拼接。日期与时间用 `Intl.DateTimeFormat(locale, { timeZone, dateStyle, timeStyle })`，时区取用户设置，用户未设置时取产品指定的默认时区，不取浏览器本地时区；数字与货币用 `Intl.NumberFormat(locale, { style, currency })`；相对时间用 `Intl.RelativeTimeFormat(locale, { numeric: 'auto' })`。同一页面内同一类数据只取一种格式，日期格式来源写进契约表类 1 的本地化列，前端不另存一份格式表。

伪本地化在一轮构建内执行一次，把所有 ASCII 字母替换为带重音字符并把文本长度扩展 30% 至 40%，检查溢出、截断与换行点三项，三项各留截图或 DOM 测量。缺键时界面向用户显示回退语言文本，同时上报 `i18n_missing` 计数与键名，不把原始键名显示给用户。语言清单、默认语言与回退顺序取产品设计域 MX-PD-29 的本地化范围，前端不自行增删语言。清单按 `docs/framework/templates/localization-checklist.md` 填写。

### 3.7 离线队列与同步

离线队列存 IndexedDB，一条待发操作一行，字段固定为 `opId`、`entity`、`method`、`payload`、`idempotencyKey`、`baseVersion`、`createdAt`、`attempts`、`state` 九项。`opId` 用 UUID v4，`idempotencyKey` 由 `opId` 与实体标识拼接，重试时复用同一个键。`state` 取 `pending`、`inflight`、`done`、`failed`、`conflict` 五值，`done` 的行保留 24 小时后清理，`failed` 的行保留到用户处理。

同一实体的操作串行发送，顺序按 `createdAt` 升序，跨实体可以并行；同一时刻只允许一个发送器持有队列锁，锁超时取 10 秒。队列上限取 200 行，超出时停止入队并提示用户，不静默丢弃。页面刷新与重新打开后从 IndexedDB 恢复队列，恢复时把 `inflight` 行改回 `pending` 并重发。

缓存按实体分键，键格式为 `<实体>:<标识>`，值含 `version`、`updatedAt`、`payload` 三项。列表缓存 TTL 取 5 分钟，详情缓存 TTL 取 1 小时，过期后先返回旧值再后台刷新。缓存结构版本从 1 起，结构变更时写迁移函数，旧版本数据在首次读取时迁移，迁移失败时清空该键并重新拉取，不清空整个库。

重试只对网络错误、408、429 与 5xx 生效，退避序列取 1 秒、2 秒、4 秒、8 秒，最多 4 次，抖动比例取 20%；4xx 中的其余状态不重试，直接转 `failed`。冲突检测用 `baseVersion` 与服务端当前版本比对，不一致时进入 `conflict`，界面提供保留本地、放弃本地与重新加载三个动作，用户选择前不覆盖服务端数据。合并只按字段进行，服务端已改字段以服务端为准，本地新改字段写回时带上新的 `baseVersion`，合并结果写一条审计记录。冲突解决后重放顺序为合并后的操作再拉取增量，不按时间戳强行覆盖。

## 4 判据写法

判据必须由第三人在同一环境复算。选择器写稳定锚点，aria 写角色与可访问名称，像素写属性、数值、单位、采样点与容差，时延写起始事件、采样点与阈值。四类写法共同要求一句一断言，主语用 AC 编号或选择器，不用“该按钮”“这个列表”这类指代。

选择器判据写查询方式与唯一性，例如按角色与名称查询后断言命中数量；aria 判据写 role、可访问名称与状态属性；像素判据写 `getBoundingClientRect()` 的属性、比较符、数值、单位与容差；时延判据写计时起点、终点与阈值，起点取事件派发或响应完成时刻。

表 4-1 是三条正例，表 4-2 是三条反例与改写。样例中的数值与视口只示范写法，落地时以设计列与产品 AC 的取值为准。

| 编号 | 正例 |
|---|---|
| 正例 1 | 点击可访问名称为「收起右栏」的按钮后 500ms 采样，该按钮的 `aria-expanded` 为 `false`，采样点为按钮元素，容差 0，视口 1280×800。 |
| 正例 2 | 视口 1280×800 下，`#insp-panel` 的 `getBoundingClientRect().width` 不大于 1px，采样点为面板元素，容差 1px。 |
| 正例 3 | agent 消息落库后 500ms 内，该会话行出现 `data-unread="true"`，采样点为 DOM 变更完成时刻，容差 0。 |

| 编号 | 反例 | 问题 | 改写 |
|---|---|---|---|
| 反例 1 | 按钮要好点。 | 缺选择器、属性、数值、采样点与容差。 | 视口 375×812 下，可访问名称为「新建会话」的按钮的 `getBoundingClientRect().width` 不小于 44px，采样点为按钮元素，容差 0。 |
| 反例 2 | 1280 宽下布局正常。 | “正常”不可测，缺属性、数值与容差。 | 视口 1280×800 下，`aside.sidebar` 的 `getBoundingClientRect().width` 等于 240px，采样点为左栏根元素，容差 1px。 |
| 反例 3 | 未读要及时出现，加载要快。 | 两条断言合写，缺起始事件与阈值。 | 拆成两条判据：判据一为 agent 消息落库后 500ms 内该会话行出现 `data-unread="true"`，判据二为消息接口响应后 300ms 内 `role="status"` 的加载态消失，两条采样点分别为 DOM 变更完成时刻与响应完成时刻。 |

本节的规则如下。

- MX-FE-25 每条判据只写一个断言，复合条件拆成多条，主语使用 AC 编号、选择器或角色名称。
- MX-FE-26 选择器判据写明查询方式、唯一性条件与命中数量，不使用类名、结构位置与数组下标。
- MX-FE-27 aria 判据写明 role、可访问名称与状态属性，名称按完整文本或明确正则匹配，空名称判失败。
- MX-FE-28 像素判据写明元素、`getBoundingClientRect()` 属性、比较符、数值、单位、采样点、档位与容差，容差取 0 或明确的像素值。排版类判据按 MX-FE-52 写换行点、行数与文本块几何，不按整页截图人工目视。
- MX-FE-29 时延判据写明起始事件、采样点、阈值与单位，阈值取毫秒数，起点与终点都能由脚本记录时间戳。
- MX-FE-30 判据定义不得出现 `docs/process/SPEC-STANDARD.md` 第 2.2 节禁用词表中的词，出现任一词即判不合格。
- MX-FE-52 排版判据写明元素、观测属性、比较符、数值、单位、视口档位、采样点与容差八项。观测属性取 `Range.getClientRects().length`（换行点）、`getClientRects()` 行数、`getBoundingClientRect().width`（文本块宽度）与 `scrollHeight`（文本块高度）四项；容差取 0 像素，采样在字体加载完成后执行。文本内容差异不参与比对，换行点或行数变化记失败，禁用整页截图人工目视替代断言。

## 6 常见错误与拦截点

本节列前端最常见的十一类错误与对应拦截点。命中任一条的产出退回，退回原因写入证据文件；同一错误在同一任务出现两次，按流程异常上报 Lead。清单不替代第 5 节的门禁，只说明门禁在什么位置拦住它们。

| 编号 | 错误 | 拦截点 | 判定方式 |
|---|---|---|---|
| E1 | 改共享组件只跑目标用例，不跑基线 | G3 全量与 G5 基线 | 全量 failed 0，四档基线 diff 0 |
| E2 | 实现用的选择器与 spec 清单不一致 | 3.3 节清单与 spec 同批评审 | 清单外选择器 0 处，锚点变更有回写记录 |
| E3 | 测试中存在 skip | G3 跳过计数 | 新增 skip 0，存量 skip 有替代证据 |
| E4 | 状态矩阵缺错误态 | 3.2 节八态核对与 3.5 节请求比对 | 每个请求至少一条错误态 |
| E5 | 只测正常路径，边界与错误路径缺用例 | 测试 spec 的正常、边界、错误、权限四类路径 | 每个 AC 的适用路径均有用例 |
| E6 | 页面写一次性样式或组件未登记 | 组件登记门与构建检查 | 页面目录 CSS 0 个，`<style>` 0 处，manifest 缺项 0 处 |
| E7 | 用假 0 或假成功掩盖失败 | 3.5 节数据不变量与错误用例 | 失败后无新增消息，未知数值显示破折号，出现 `role="alert"` |
| E8 | 无障碍只写 aria-label，缺键盘与焦点 | 可访问性门 | 七项均有结论，键盘与焦点有断言 |
| E9 | 用开发机截图代替固定档位截图 | G5 档位清单 | 截图文件名含宽度，脚本四档与验收三档均有结论，缺档写 N/A 理由 |
| E10 | 时延判据缺起始事件 | 第 4 节语言检查 | 每条时延判据含起始事件与阈值 |
| E11 | 实现者自签验收 | 收口门 | 签字人与实现人不同 |

本节的规则如下。

- MX-FE-40 命中第 6 节表内任一条的产出退回原实现者，退回时写明错误编号、证据路径与需重跑的门禁。
- MX-FE-41 每条退回记录写入证据文件，修复后从对应拦截点重跑，不用其他门禁的通过结果替代。
- MX-FE-42 同一错误在同一任务出现两次时按流程异常上报 Lead，由 Lead 决定重新派单或调整判据，不得由实现者自行豁免。

## 7 与其它域的接口

前端向测试域与验收角色交付可复用的判据材料，向后端域索取可实现的接口形状。交付物必须让对方在不读实现的情况下写出用例或接口契约，索取物必须让前端在不猜字段的情况下实现错误态。接口在契约门冻结，冻结后变更走变更包。

### 7.1 向测试域交付

1. 选择器清单：每条 AC 的锚点、查询方式、采样点、档位与容差。
2. 夹具：`frontend/src/test/fixtures.ts` 的工厂函数、`App.test-utils.tsx` 的快照构造、MSW handler 或接口响应样例，覆盖成功、空、错误与慢响应。
3. 断言映射：AC 到测试文件与用例名，未建的写 missing。
4. 环境：base URL、浏览器版本、构建号、视口与时区。
5. 复跑命令与证据路径。

### 7.2 向后端索取

- 接口字段：method 与 path、鉴权、请求字段（名称、类型、必填、边界）、响应字段（名称、类型、示例值）、错误码（HTTP 状态与 code 成对）、并发与幂等、存储不变量。
- 边界 schema：Zod 依赖落地后，接口响应、URL 参数与本地存储由 schema 校验并从 `z.infer` 导出类型，不保留手写同形类型，非法样本必须失败的用例随 schema 同批提交。
- 错误码：前端按 `code` 分支，不按 message 文本分支，每个错误码在 3.5 节清单中有对应错误态与重试入口。
- 变更：字段增删改或错误码变更时同批更新 MSW handler 与错误态清单，接口形状未定时前端只搭骨架，不猜字段。

本节的规则如下。

- MX-FE-43 向测试域交付选择器清单、夹具、断言映射、环境与复跑命令五件，缺任一件时测试域不得开工。
- MX-FE-44 向后端索取 method 与 path、鉴权、请求字段、响应字段、错误码、并发与幂等、存储不变量七项，字段边界以 schema 表达，缺任一项时前端只搭骨架。
- MX-FE-45 前端按错误码的 code 字段分支，不按 message 文本分支，每个错误码对应一条错误态与一个重试入口。
- MX-FE-46 接口字段或错误码变更时，同批更新 MSW handler、错误态清单与相关用例，漂移未处理时不得提交验收。
- MX-FE-47 前端与后端、测试域对契约理解不一致时提交契约门裁决，裁决结论写入变更包，任一方不得自行解释。
