# 适配层

位置：`docs/framework/adapters/`。适配层把「墨线」框架与具体模型、具体命令行工具隔开，框架主体保持通用，当前环境的实现参数放在本目录。换模型或换命令行工具时只新增一条分支文件，不改框架主体。

## 一、适配层管什么

适配层登记框架无法自行决定、又必须固定下来的五类实现参数。判断一份内容该不该写进适配层，看它是否只影响执行方式、不影响判定结论；只影响执行方式的内容归入本层，影响判定结论的内容留在总册。五类之外的环境差异写进覆盖表或未决点，不另开一节。

1. 推理档位映射。写明路由提供的档位名称、每档适合的任务形态、判定依据与例外，以及派单卡的「推理档位」字段取哪个值。
2. 上下文预算与压缩策略。写明窗口大小、自动压缩触发点、压缩后保留量、摘要长度上限、压缩后必须保留的信息，以及压缩造成细节损失后的补写方式。
3. 工具调用与并行派单方式。写明当前可用的派单工具、同一批的并行上限、派单必须显式携带的字段，以及中断与重试的处理方式。
4. 成本计量口径。写明请求数、输入 token、缓存命中与输出 token 的计数口径、取数位置，以及按什么时点的价格折算费用。
5. 已知失败模式与绕行办法。写明当前模型与工具下反复出现的失败现象、识别方式、可执行的绕行做法，以及无法绕行时的上报条件。

## 二、适配层不管什么

适配层不写规则条文，门槛、判级与不得开工的条件由总册规定，本层只登记实现参数。适配层不写门禁，触发时机、检查动作与失败处理由总册第 7 章、`GATES.md` 与 `scripts/ac/` 下的脚本承担。适配层不定义产物格式，任务卡、契约表、证据登记表与复盘模板沿用附录 A 的模板。适配层不分配角色职责，谁实现、谁验收、谁裁决以及各自的签字权写在总册第 3 章。

适配层与总册冲突时以总册为准，冲突事实写进覆盖表的影响范围列或分支文件末尾的未决点。适配层与门禁脚本冲突时先核对脚本版本与输入，再判定是脚本缺陷还是适配文件过期。两类冲突都不得靠修改 main 解决。

## 三、适配文件的六节

每份适配文件固定六节，节名与顺序不改。缺少任何一节，该文件不能作为派单依据。分支文件按模型名或工具名命名，一条分支只对应一个模型或一种命令行工具。

| 节 | 必写内容 |
|---|---|
| 版本与适用范围 | 模型或命令行工具的名称与版本、版本绑定、路由提供的档位、默认档、生效日期、适用与不适用的任务类型 |
| 推理档位映射 | 档位清单、每档对应的任务形态与判定依据、例外、与派单卡「推理档位」字段的对应、漏标时的缺省值 |
| 上下文与压缩 | 窗口上限、压缩触发点、压缩后保留量、摘要长度上限、压缩后保留的字段、检查点与交接摘要的补损路径 |
| 工具与派单 | 可用工具与用途、并行上限、派单必填字段、每步的汇报节奏、超时与中断的处理方式 |
| 成本计量 | 请求数口径、未命中输入与缓存命中的分列口径、缓存命中率的算法、取数位置、计价时点与单价来源 |
| 已知失败模式与绕行 | 失败现象、识别方式、绕行做法、上报条件、无法绕行时的替代路径 |

六节之后固定附一份覆盖表，覆盖表不计入六节，用于登记分支对 main 的覆盖，没有覆盖时写「无」，只补充不覆盖的条目单列在补充项。四列依次为 main 原文、分支写法、覆盖理由、影响范围。覆盖表的条数与版本绑定一起登记在总册附录 C。

## 四、分支模型

框架主体是 main，适配文件是从 main 切出的分支。分支大部分继承 main，只在自己的分支上做定制，换模型或换命令行工具就是新开一条分支，main 不动。分支只登记当前环境的参数，通用规则仍回 main 维护。

1. 分支只能新增或覆盖，不得删除或改写 main 的规则。main 的章节、规则编号与条文在分支里原样保留，分支写法与 main 写法并列出现。
2. 凡覆盖必须进覆盖表，逐条写 main 原文、分支写法、覆盖理由、影响范围四列。覆盖理由要给出可复核的事实，影响范围要写到受影响的章节、脚本或角色。
3. 分支不得引入 main 里没有的强制门禁，只能放宽或细化 main 的门禁。确需新增门禁时先回 main 提案，提案通过后由 main 发布，分支只引用新门禁。

分支文件必须写版本绑定，格式为 `main <main 版本> + <分支序号>`，例如 `main v2.0.0 + ds.1`。main 升级后，各分支先核对覆盖表是否仍成立，再递增分支序号。覆盖不再成立时删除该覆盖并在覆盖表登记理由。

当前分支文件是 `deepseek.md`，对应 DeepSeek Harness 与模型 `deepseek-flash`，版本绑定 `main v2.0.0 + ds.1`。该文件的覆盖 2 条、补充 6 条，条目内容以文件内的覆盖表为准。

## 五、通用性判据

换模型或换命令行工具时，只新增适配文件，文件名换成新的模型名或工具名，六节内容按新环境重写。总册的章节、规则编号与条文零改动，门禁脚本的入口、参数与退出码语义零改动。判据用三个检查验证，三项都通过才算适配完成。

1. 静态检查：检索总册正文与 `scripts/ac/` 目录，模型名、命令行工具名与档位名的命中数为 0；有命中说明环境细节漏进了通用层。
2. 空跑检查：取一张只读任务卡，按新适配文件走一遍派单、压缩与取数，记录的档位、触发点与取数路径与适配文件一致。
3. 回退检查：切回旧分支，同一张任务卡仍能按旧参数执行；旧分支无法执行说明两条分支之间存在隐式依赖。

新模型缺少某一档位时，在第二节写降级规则并注明降级后的观测指标，不改总册与脚本。新工具没有子智能体时，在第四节写串行派单方式与单步时长上限，不改第 4 章的拆分粒度。两项处理都不改 main 与门禁脚本。

## 六、与总册的引用关系

总册第 3 章在角色职责处引用适配层第二节与第四节，说明执行者以什么档位、什么工具承担角色，角色边界与签字权仍以第 3 章为准。总册第 4 章在派单卡字段处引用适配层第二节与第四节，说明「推理档位」字段的取值、并行上限与汇报节奏，卡片字段集合仍以第 4 章为准。总册第 9 章在度量口径处引用适配层第五节，说明请求数、输入 token 与缓存命中占比的取数与折算，指标定义仍以第 9 章为准。

引用只写位置，不整章复制条文；覆盖表为逐条对照引用 main 原文，引用范围限于被覆盖的条目。总册写「见适配文件第 X 节」，适配文件写「见总册第 N 章」，两边各自维护自己的内容。新增或替换适配文件后，在总册附录 C 登记文件名、版本绑定、生效日期与覆盖表条数；覆盖关系不变时只登记文件名与日期。
