## 4 四项检查能力的判据与自检断言

### 4.1 字段类型一致性

契约表的字段列由 `specFieldColumnIndex` 识别，表头匹配“字段”“字段名”“查询参数”“参数”“列”“props”，存在“类型”列时也识别“名称”，以及“关键字段”。字段与类型同时存在时，`extractSpecFieldTypes` 逐行收集字段名、原始类型、声明行号与标题行号。实现位置在 `scripts/check-contract.mjs` 第 554 至 626 行。

类型先做归一。`normalizeSpecType` 转小写后按竖线、斜线、逗号、分号或空白分隔取首段，去掉括号注释，再按别名表折叠为七类。`text`、`varchar`、`char`、`uuid`、`timestamp`、`datetime` 与“时间戳”归入 `string`；`int`、`integer`、`bigint`、`real`、`float`、`double` 归入 `number`；`bool` 与 `boolean` 归入 `bool`；`json`、`object`、`map` 归入 `object`；`array` 与 `list` 归入 `array`；`string[]`、`array<string>` 与“string数组”归入 `string[]`；`object[]`、`array<object>` 与“object数组”归入 `object[]`。

比对按来源作用域执行。`sourceRefs` 取契约表字段行里的 `§N` 与 `N1`，`declarationMatchesSource` 按列文件标题行匹配；作用域内没有候选时回退到全部候选。两侧归一后的类型不相等，就在第 1318 行判定，error 记录在 1321 至 1331 行（第 1330 行为消息模板），消息给出契约表侧类型与行号、列文件侧类型与行号。字段缺失记 error，字段多出记 warning。契约表没有“类型”列，或列文件没有声明类型时，类型比对没有输入，不产生类型不一致记录。

自检覆盖三类情形：前端字段与类型一致的样例 `MX-G-27` error 为 0；前端字段类型不一致的样例产生 1 条 error，消息同时含“契约 number”“声明 string”与两侧行号；前端字段缺失的样例报前端 spec 缺字段。`gap-type` 夹具专用于第二类。

### 4.2 契约表缺格

`MX-G-26` 把契约表分成六类，每类有固定的必须有值列。扫描按行执行，逐列取单元格，去掉行内标记与空白后为空就记 error，消息写明第几行缺哪一列，例如“第 N 行缺「类型」”。整张表为空时另记 error。实现位置在第 983 至 1073 行。

扫描只覆盖六类契约表的固定列，自由文本列与说明列不在范围内。单元格里写“无”“—”“N/A”等占位文字时不为空，不触发缺格。这个边界与本轮之前一致，没有放宽。

自检覆盖两类情形：契约表缺格的样例报缺“类型”；失败样例同时覆盖两列缺格，记录数为 2。`gap-missing-cell` 夹具专用于缺格。

### 4.3 中文状态映射

契约表类 2 的状态取值写成中文时，`runMxG28` 先按 `CONTRACT_STATE_MAP` 把中文名映射成存储态与展示态。映射表在第 89 至 98 行，八组取值见第 2.1 节。状态迁移的“从状态”与“到状态”按同一张表映射，前端在映射后把展示态相同的迁移合并成一条。

非界面对象、且契约表出现中文状态时，判定进入任务状态机模式。后端 spec 的状态集合与迁移按存储态比对，前端 spec 按展示态比对。列文件缺失记 warning；缺失状态记 error；多出状态记 warning，可被 `N/A：前端状态` 或 `N/A：设计状态` 压掉；有迁移表时缺失迁移记 error，无迁移表时报迁移表为空。界面对象仍按八个英文 UI 状态 `default`、`hover`、`focus`、`active`、`disabled`、`loading`、`empty`、`error` 判定，出现表外英文状态记 error。实现位置在第 1337 至 1540 行（任务状态机分支），设计分支在 1521 至 1539 行，分支返回在 1540 行。
