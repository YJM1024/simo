# 司墨产品规划：对齐 DSH 的产品能力面

> 2026-11-07。产品名 **司墨（Simo）**（语音识别曾把"司墨"误识别为"思默"，以司墨为准）。本文从产品视角盘点 DeepSeek Harness（DSH）的能力面，给出司墨的复用清单、智能体团队设计草图、以及"还缺哪些基本智能体产品功能"。
> **已定修订**：不引入独立工作区——**会话树即工作区**；会话内可含多个任务，由智能体自主编排（DAG/工作流），**每个任务完成都汇报**；定时任务/自动化排 M13。
> 技术决策由 Lead 负责；本文只谈产品。

## 1. DSH 产品能力面（产品视角）

### 1.1 会话与任务
- **会话树即工作区**（不引入独立 workspace）；会话列表：分组、搜索、置顶、归档、复制会话 ID、fork；
- 会话内 **任务/工作流**：拆解、依赖（DAG）、自动推进、逐任务汇报、暂停/恢复/取消、任务面板；
- 会话轨迹视图（Trajectory）：完整执行轨迹与聊天视图切换；
- 上下文压缩（compaction）、token/上下文占用显示、模型重试记录；
- 会话级权限选择器（composer 内）、计划模式（Plan mode）。

### 1.2 对话与输入
- Markdown 富文本渲染、代码块、表格、推理过程折叠；
- 输入增强：文件/文件夹/会话/技能/命令/密钥等 **chips**、`@` 引用、斜杠命令、命令面板；
- 附件：图片/文件拖拽、预览、附件 rail；
- 审批对话（approval）、计划审阅（plan review）、提问式交互（ask_user_question）；
- 模型选择器、思考强度、快捷键与 IME 处理。

### 1.3 文件与交付物
- 文件工具：read / write / edit / glob / grep / read_image；
- **交付物（deliverables）**：会话内生成的文件在消息尾部以卡片呈现，可一键打开；
- 文件打开方式：内置预览（Markdown/代码/图片/PDF）、通过会话事件坐标打开文件、交给系统默认应用；
- 图片查看、diff 视图（工具调用卡片内）、文件搜索。

### 1.4 执行与自动化
- `pwsh` / `bash`、持久终端（6 个终端工具）、后台作业（jobs）；
- 定时任务（schedule_create/update/list）、长期目标（goals）、工作流（workflow/ralph）、待办（todo）；
- 执行治理：超时、输出上限、spill 落盘、环境变量重建、审计。

### 1.5 多智能体
- 子代理（subagent / fork / fresh）、Agent Team（团队 roster、成员消息、共享任务板、等待）；
- Agent Preset：人格 + 工具集 + 模型路由；
- 子代理产物交接、双裁决、修复环；
- 团队任务：创建/认领/依赖/写作用域/完成。

### 1.6 扩展与设置
- 插件（plugins/bundles）、插件市场、官方插件；
- 技能（skills）、MCP、自定义工具；
- 设置中心：通用（语言、外观、Enter 行为）、模型与 Provider、插件、外观主题（亮/暗 token）、快捷键、关于。

### 1.7 安全与治理
- 沙盒三模式（read-only / workspace-write / danger-full-access）+ 审批策略（ask/never，fail-closed）；
- 单次提权（`sandbox_permissions` + `justification`）；
- 路径守卫、读前写守卫、环境清理、输出 spill、审计事件。

### 1.8 其他产品细节
- 会话/事件检索、trace、通知/toast、quota 提示、onboarding、快捷键。
- 图片/附件在用户消息与助手消息两侧独立渲染。

## 3. 智能体团队设计草图（待讨论，不实现）

### 3.1 角色
- **Lead（秘书/调度）**：与用户对话、拆任务、分派、汇总、对用户负责；
- **专家 Worker**：每人有 persona、工具子集、模型档位、上下文；可并行。

### 3.2 数据模型
- `team_agents(id, name, role, persona, tools[], model, status)`
- `team_tasks(id, title, description, owner, status, depends_on[], write_scopes[], session_id)`
- `team_messages(id, from, to, kind, content, created_at)`（或复用 core 事件总线）
- 记忆作用域：`team` 共享 + `agent:<id>` 私有。

### 3.3 流程
1. 用户 → Lead；
2. Lead 判断"自己做 / 派给谁 / 拆几步"；
3. 创建任务（写作用域 + 依赖）→ 认领 → 执行 → 汇报；
4. Lead 汇总给用户；失败升级/重试；用户随时可插话（不打断后台）。

### 3.4 关键决策（先想清楚再实现）
- 固定团队 vs 动态 spawn（建议：固定 3–5 个角色 + 允许临时 spawn）；
- 共享记忆的写回规则（单写者/冲突）；
- 并发上限与预算（每任务 token 上限）；
- 产物交接（文件路径/摘要，不复制）；
- 冲突：写作用域重叠时串行，不重叠并行。

### 3.5 UI
- 团队面板：成员卡片（状态/当前任务/模型）；
- 任务板：待办/进行中/完成/阻塞；
- 消息流：仅展示用户关心的节点（派发、完成、失败），细节折叠。

## 4. 司墨还缺的基本产品功能（清单）

6. **交付物面板**：本会话生成/上传的文件集中查看（你提的"文件"选项卡）；
7. **历史导航**：消息迷你时间轴、点击跳转（你提的第 2 点）；
8. **会话概览**：目标/约束/现状/已完成/待办/备注/时间线，汇报体（你提的第 3 点）；
9. **错误恢复**：断线重连、模型失败重试、任务中断恢复提示；
