# 已裁决事实

新任务开工前读这里，不读前一个 Agent 的对话。每条一句结论加一句依据，追加只写在末尾并带日期。

## 会话域

- **置顶进本轮验收面**：会话行菜单对非主、非草稿、非归档会话提供置顶/取消置顶，排序以后端返回为准，前端不重排。依据 m00913 期间裁决与 `AC-CONV-001-04`。
- **置顶只影响同级顺序**：同父兄弟间按 `pinned DESC, created_at DESC, id DESC` 排，不改变父子归属、不提升到顶层（跨层级不上浮，子会话始终在父会话之下）；同级唯一子会话无兄弟可比时行序不变属预期。依据 `backend/internal/modules/sessions/service.go` 的 `sortSessions` 与产品裁决（2026-11-21）。
- **归档会话不可置顶**：后端返回 409 `session_archived` 并带 `blockers`，前端菜单不渲染该项。依据 `AC-CONV-001-04`。
- **未读持久化**：游标存后端，刷新与重启后保留；进入会话即标记已读；侧栏只显示无数字红点，不做全站汇总。依据 m00747 四条口径。
- **主会话不可归档，其他会话可归档**：归档主会话返回 409 `main_session_protected`。依据 m00747。
- **不提供删除入口**：产品只允许归档，后端 `DELETE /api/sessions/{id}` 保留但不暴露。依据 m00747。
- **子会话暂不可移动**：显式非目标，写成边界而不是缺口。依据 m00768。
- **搜索以标题搜索为主**：走 `GET /api/sessions?q=`；消息搜索保留代码但无入口。依据 m00747。
- **草稿会话语义**：`POST /api/sessions` 返回 201 `draft=true`，草稿是服务端内存态，不出现于 `GET /api/sessions` 与 `/tree`，首条消息物化后才进列表；刷新后草稿行消失属预期，`Session.draft` 是前端本地标记。草稿不发 `spec-projection`，右栏显示「发送第一条消息后生成目标与执行态」。依据 2026-11-21 裁决。
- **行内消息数按会话自身计**：会话行内数字只表示该会话自身消息数，不含子会话与其他会话；底部汇总继续报全局（全部 N 会话、归档 M、全局消息 X），主会话行不因含子会话而变大。依据 2026-11-22 Lead 裁决与 `AC-CONV-001-05`。
- **右栏任务组展开必须补取**：状态组 `total` 大于首屏 3 条时，展开须取到剩余条目并使显示计数与可见条目一致，不得出现总数大于条目却无法继续获取的状态。依据 2026-11-22 Lead 裁决与 `AC-CONV-008-05`。
- **时间轴整列命中与最近刻度映射**：时间轴以整条轨道（宽 44px）为连续命中面，轨道内任意点映射到纵向最近的刻度，刻度视觉条可小于 44×44；点击后目标消息进入视口且 active 等于被点击刻度，能置顶时顶部即目标消息，受滚动到底限制的最后若干条只要求进入视口且 active 正确。依据 2026-11-22 Lead 裁决与 `AC-CONV-007-02`（6px 间距下逐条 44×44 必然重叠）。

## 文档与流程

- **两层 Spec**：长期 Spec 按域一个文件、常驻仓库；变更 Spec 一次需求一包、做完归档。功能点靠 ID 区分，一个文件可含多个功能点 ID。依据 m00470。
- **长期 Spec 五列**：产品 / 设计 / 前端 / 后端 / 测试，没有长期验收 spec。依据 m00506。
- **60 内容项落在多个文件里**：12 功能点乘五列，每域每列一个文件、每个 12 节，空节写 `N/A：理由`。依据 m00549。
- **变更包粒度**：一个 CHG 可覆盖多个功能点与场景，按需求提出视角分类，不按功能点拆包。依据 m00307。
- **门禁五条**：治理类 `Implements: N/A：理由` 合法且不打前缀白名单；只跳过 `archived`，不跳 `historical`；`design.md` 按需；新增变更级 AC 编号 `AC-<CHG-ID>-<NN>`；CI 先 `continue-on-error`。依据 `CHG-SYS-001/spec.md` 与 m00265 区裁决。
- **LEGACY 变更包不归档**：0 covered 不算完结，归档会藏缺口。依据 m00265 区裁决。

## 质量

- **实现者不自签**：视觉与功能签字由独立验收角色完成，Lead 只抽查关键证据。依据 `AGENTS.md` 与 m00224。
- **skipped 不算通过**：浏览器组缺 CDP、docker smoke 未跑，都写 `未验证`，不写 `pass`。依据 m00265 区裁决与多轮验收记录。
- **部分覆盖不写 covered**：状态只用 `pass/partial/missing/blocked`，`covered` 由验收签字后统一改。依据 `docs/product/TRACEABILITY.md` 与多轮回填记录。

## 团队与成本

- **按功能分类派任务**：派发单元叫任务，粒度是一个功能分类（L2 组或并列的一组功能点）；一个分类派一个设计 Agent、一个前端 Agent、一个后端 Agent，把该分类所有功能点一次做完，不再按功能点或修复点拆。依据 2026-11-22 用户裁决（60 元、54 个 Agent 的复盘，要求少派、降本、缩短工期）。
- **分类数量 5–10**：一个域控制在 5–10 个分类，超过就是拆细了。会话域参照：会话管理、消息与渲染、输入与发送、多标签与同步、右栏投影。依据同一次裁决。
- **顺序是设计→前后端并行→测试验收→更新 spec**：实现侧自测通过才交测试 Agent 独立验收，验收通过才更新该分类 spec 与状态。依据用户对分类流程的描述。
- **验收不过交回原实现 Agent**：同一分类内连续两轮不过才换人；换人前先让其把已完成部分写回文件。依据 2026-11-22 用户裁决。
- **推理档位跟着分类走**：分类级开发默认 `high`，契约设计与整线验收用 `max`；`off` 只给抄录，`low` 只给闭集核对，不允许低档兜底把任务切碎。依据 2026-11-22 用户裁决。
- **跨分类复用先压缩**：默认新开；沿用同一 Agent 前先压成不超过 8,000 token 的交接摘要，压缩后前缀仍超门槛则新开。依据 `rules/cost-efficiency.md` 分档表。
- **卡住即处置**：30 分钟未交付主动查一次，60 分钟未落盘令其停下先落盘；任何验证超过 10 分钟拿不到证据就记未取到。依据时间轴任务挂起 8.5 小时的事故。
- **每轮验收最多重建一次二进制**：缺陷攒齐、一次改、一次构建、一次启动、一次取证。依据 2026-11-21 至 22 共 9 次构建的时间线。
- **常驻服务由 Lead 持有**：子会话启动的进程随其结束退出，8787 由主会话后台 job 常驻。依据 deploy-conv6 交回后端口无人监听的事实。
- **验收只复核变化项**：只重验本轮变化的 AC，其余沿用上一轮证据并注明轮次，全量重验留到整线出口。依据五轮验收重复取证的耗时。
- **验收不省**：可以省重复读取与重复全量，不省独立验收。依据 2026-11-21 至 22 的缺陷捕获记录（树排序未消费 `pinned`、归档会话可置顶、`read_cursor` 无决胜）。
- 任务硬超时 30 分钟：任何任务（含前后端实现）到点未交付即查原因，卡环境则落盘换路，任务过大则当场拆分；派单须写明该条并要求 30 分钟节点回报。

## 建域与变更 spec（2026-11-22）

- **已有实现时反推契约建四列**：某域已有代码与测试、但没有设计、前端、后端、测试四列长期 spec 时，读代码与测试反推契约、判据与产品差异裁决，不先写设计推演再实现；四列指设计、前端、后端、测试，产品列沿用已有 spec，同域约 30–40 分钟。依据是会话域 743 行设计 spec 等于重述已实现方案，避免重述已知、避免大 spec 开销，见 `docs/process/SPEC-STANDARD.md` 第 4.1 节与 `docs/plan/RETRO-20261122.md` 的「五份 spec」段。
- **变更 spec 先增量后补丁**：先写变更增量，只写这次改什么、影响哪些功能点、验收判据，再改代码，最后用 10–20 行补丁按文件、节、原文、新文、理由回写长期 spec；第一次建域先按 4.1 写一次全量四列，第二次起才适用。依据是避免重述已知与大 spec 开销，见 `docs/process/SPEC-STANDARD.md` 第 4.2 节与 `docs/plan/RETRO-20261122.md` 的「下一轮 runbook」第二步。
- **长期 spec 按主题分节 + PRD→节号索引**：设计/前端长期 spec 不按 12 个 PRD 逐节，而按主题分节并在开头维护 PRD→节号索引；tasks 卡 08/09 的「按功能点 ID 分节」按内容覆盖解释，理由是逐 PRD 逐节会让同一组件、同一状态、同一错误口径在多个 PRD 下重复，产生大量重复段落。见 `docs/plan/BACKLOG.md` 第 2 节 REQ-010-04/05 与 `docs/plan/RETRO-20261122.md` 的「五份 spec」段。

## 流程总纲与语言标准（2026-11-22）

本节编号从 B1-10 往后接，用 `DEC-` 前缀区分于功能裁决。

- **DEC-11 变更 spec 是唯一入口，建域型变更同走变更包**：任何需求先开 `specs/changes/<CHG-ID>/spec.md`。长期 spec 与变更只有两种关系：域已存在时读它写增量，域不存在时在同一次变更里把四列建出来；两种关系可以在同一个变更里并存。建域型变更的需求点包含两类内容，一类是建四列的长期 spec，一类是补实现缺口与补证据。理由：入口收敛到一个位置，状态与证据才有一个可追溯的来源；会话域这一轮的准确定性就是建域型变更。生效范围：全部域与后续变更包；`docs/process/SPEC-STANDARD.md` 第 4.1、4.2 节的变更 spec 定义不变，本次只补“建域型变更”这种用法。
- **DEC-12 交付单元收缩到需求点**：一个点做完、增量测试过、自验过即交付，不等整线。派单粒度仍是功能分类，不因交付单元变小而切碎。理由：整线交付把等待时间摊到每个点上，RETRO P11 记录五次全量重验约 3 小时。生效范围：全部派单与验收；`PROCESS.md` 第 4 节、项目 `AGENTS.md` 的流程投影同步。
