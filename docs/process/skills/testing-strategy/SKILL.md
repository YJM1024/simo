# SKILL · testing-strategy

## 何时使用

- spec/AC 已写，需要决定测什么、测到哪、怎么证明；
- 新功能/迁移/权限/并发/发布前的风险判断；
- 需要把 AC 映射到可执行断言与证据。

不用于：替产品定义 AC；替组件做视觉审美判断（仍需人工走查）。

## 输入

- AC/非目标/风险清单；
- 变更范围（模块/数据/API/UI）；
- 现有测试/evals/CI 能力与缺口；
- 生产/真实环境限制。

## 步骤

1. **风险清单**：数据丢失、权限、迁移、并发、外部依赖、回归、可用性、性能；
2. **分层**：单元（纯逻辑/校验）、集成（API/DB/迁移）、契约（OpenAPI/evals）、UI（交互/截图）、手工走查；
3. **AC→断言**：每条 AC 至少一条可执行断言/可复现证据；
4. **测试数据**：正常/边界/空/错误/无权限；隔离临时目录；
5. **自动化取舍**：能稳定跑进 CI 的自动化；不稳定的降级为 scripted/manual，但需证据；
6. **门禁**：blocking / warning / nightly；未过阻断发布；
7. **回归**：已过项抽查 + 旧路径兼容；记录通过/失败/未跑。

## 产物

- `test-plan.md`：风险矩阵、层、用例、AC 映射、截图矩阵；
- `evidence.md`：命令/日志/截图/报告路径；
- 自动化用例/脚本（实现阶段）；
- 门禁清单与豁免记录（谁批/为什么）。

## 检查表

- [ ] AC 100% 有断言/证据；
- [ ] 正常/边界/错误/权限/回滚覆盖；
- [ ] 迁移/并发/幂等按风险覆盖；
- [ ] 测试数据隔离，不碰真实用户数据/固定端口；
- [ ] 失败可复现；未跑项明确标注；
- [ ] 截图/DOM 证据可复查。

## 反模式

- 只测 happy path；用覆盖率数字代替风险覆盖；
- 测试依赖真实外部服务/固定数据，导致 flaky；
- 未跑项写“通过”；失败重跑掩盖；
- 只做手工截图，无断言/无路径；
- 为了让测试绿而删断言。

## 示例

> 时间轴组件：单元测分组顺序/gap/角色映射；组件测 hover/focus/键盘/edge；截图 1600/1920/1180/375；DOM 断言 44px rail 无文字、无 `title`；AC A1–A10 逐条映射。
