# 场景流程 · SCENARIOS

状态：v0（草案；只定义流程，不写代码）
定位：把 `FRAMEWORK.md` 的通用门禁落成 6 条可执行路径；每条路径都写：触发、必产物、门禁、角色、验收、升级/降级、反模式。
配套：技能细节见 [`skills/`](skills/)，通用 SDD 见 [`FRAMEWORK.md`](FRAMEWORK.md)。本文件不复制技能全文。

## 0. 使用方式

1. 先判定场景（不确定时按**更重**的场景走，例如“新功能 + 数据变更”按迁移处理）；
2. 只取本场景**必产物**，小改可精简，但 **AC 与证据不可省**；
3. 门禁表里 **Blocking** 未过不得进入下一阶段；Warning 可记录后放行；
4. 角色按场景最小集合分配，不要求每个角色全程在线，但签字/证据必须留；
5. 升级条件一旦命中，停止当前路径，转对应场景并补产物。

### 0.1 门禁自动化边界（总表）

| 门禁 | 可自动 | 仍需人工 |
|---|---|---|
| Spec 结构/字段/链接 | 脚本 lint（文件存在、章节、链接） | 需求边界、非目标、价值判断 |
| AC 映射 | 脚本检查每条 AC 是否有断言/证据 | AC 是否真的覆盖用户意图 |
| tsc/build/test/evals | CI/本地命令全自动 | 失败原因归因、是否可接受 |
| 组件登记/截图存在 | manifest + 文件检查可自动 | 视觉质量、状态齐全、设计取舍 |
| API/契约字段 | OpenAPI/schema diff 可自动 | 兼容性策略、迁移风险 |
| 迁移演练/hash 对账 | 脚本可自动 | 是否可切换、数据语义是否正确 |
| 发布包/哈希/健康检查 | 脚本可自动 | 发布窗口、回滚决策 |
| 事故分级/复盘 | 只自动收集时间线/日志 | 定级、根因、责任与改进决策 |

> 原则：**机器能证明“有没有/跑没跑/对不对齐”，人证明“该不该/够不够/能不能接受”。**

## 1. 新功能（Feature）

### 触发

- 用户/产品提出新的可感知能力，或现有能力需要新行为；
- 跨 ≥2 个模块，或需要新的 API/数据/交互；
- 无法用现有组件/契约的小改动覆盖。

### 必产物

- `specs/<CHANGE-ID>/proposal.md`（问题、范围、非目标、替代方案）；
- `spec.md`（R/MUST-SHOULD + A/GWT，AC 可验证）；
- `design.md`（方案、接口、数据、权衡、回滚）；
- `tasks.md`（owner/scope/依赖/验收）；
- `test-plan.md` + `evidence.md`（命令/截图/测试）；
- 涉及 UI：组件登记/画廊；涉及 API：契约/ADR。

### 门禁

| 门禁 | 类型 | 通过条件 |
|---|---|---|
| Spec Ready | Blocking | 边界/非目标/AC 可验证；产品确认 |
| Spec Approved | Blocking | 产品 + 技术共同确认 |
| Design Ready | Blocking | 方案/接口/数据/风险/回滚齐全 |
| Tasks Ready | Blocking | 每任务 owner/scope/依赖/验收 |
| Verify | Blocking | tsc/build/测试/截图/AC 全过 |
| Regression | Blocking | 已过项抽查无回归 |
| Archive | Warning | spec/证据归档，不删 |

### 角色

产品（问题/范围/AC）、前端/后端（设计/实现）、测试（策略/证据）、验收（独立走查）、Lead（拆解/最终裁决）。

### 验收

- 每条 AC 至少一条可执行断言；用户路径可走通；
- 无回归；失败路径/空态/权限路径有覆盖；
- 证据可复现（命令/截图/DOM/测试报告）。

### 升级 / 降级

- **升级**：涉及数据迁移→场景 4；涉及发布→场景 5；发现线上事故→场景 6；跨团队/架构变化→补 design/ADR 并重评审。
- **降级**：只改文案/样式且无契约变→可精简为轻量 spec；但仍需 AC + 证据 + 回归。

### 反模式

- 先写代码后补 spec；AC 写成“体验好/正常”；没有非目标导致范围膨胀；
- 只测 happy path；把“没时间”作为跳过 Design/Tasks 的理由。

## 2. 组件（Component）

### 触发

- 新增组件、修改组件 API/变体/视觉/交互；
- 页面需要现有组件无法表达的展示；
- 组件库/画廊变更。

### 必产物

- `specs/COMP-<NNN>-<slug>/` 最小集：`proposal/spec/design/tasks/test-plan/evidence`（小改可合并）；
- 组件画廊条目：名称、variant/state、tokens、截图、owner、验收状态；
- 页面引用证据（只有登记后才允许）。

### 门禁

| 门禁 | 类型 | 通过条件 |
|---|---|---|
| Component Spec Ready | Blocking | 语义/API/状态/tokens/使用场景齐全 |
| API Approved | Blocking | 命名/变体/兼容性确认 |
| Implement | Blocking | 组件 + 画廊 + 截图 |
| Page Adoption | Blocking | 只使用已登记组件 |
| Verify | Blocking | 状态矩阵/回归/三档截图/无定制 CSS |
| Archive | Warning | 版本与变更原因归档 |

### 角色

前端（实现/画廊）、产品（语义/验收）、设计/验收（视觉/状态）、Lead（API/兼容裁决）。

### 验收

- 状态矩阵完整；可访问性（键盘/焦点/名称/对比度）；
- 页面无定制 CSS/内联样式；旧用法迁移无回归；
- 截图覆盖要求档位；token 无硬编码。

### 升级 / 降级

- **升级**：API 破坏性变更→迁移任务 + 版本号；影响 ≥2 页面→页面回归；新 token→设计系统评审。
- **降级**：只加 variant 不改 API→可走轻量 COMP spec；仅修样式→仍需截图与画廊更新。

### 反模式

- 页面内写一次性组件；未登记先用；用 `!important`/页面 CSS 覆盖组件；
- 只截默认态；改组件不更新画廊/旧页面回归。

## 3. Bugfix

### 触发

- 缺陷/回归/用户报告；线上或验收失败；
- 行为与 spec/AC 不一致。

### 必产物

- 复现步骤 + 失败证据（日志/截图/测试）；
- 根因说明（不是“改了就好了”）；
- 失败测试（先红后绿）或可重复的验证脚本；
- 修复 patch + 回归证据；涉及发布走场景 5，涉及数据/安全走升级。

### 门禁

| 门禁 | 类型 | 通过条件 |
|---|---|---|
| Repro | Blocking | 可稳定复现，有证据 |
| Diagnosis | Blocking | 根因与影响面清楚 |
| Test Ready | Blocking | 失败用例可自动化/可复跑 |
| Fix Verified | Blocking | 失败→通过；无新增失败 |
| Regression | Blocking | 相邻路径抽查通过 |
| Archive | Warning | 关联 issue/spec 证据 |

### 角色

报告者、模块 owner（前端/后端）、测试/验收、Lead（定级/是否升级）。

### 验收

- 修复前失败、修复后通过；根因被覆盖；
- 无回归；错误态/边界态不退化；
- 若无法自动化，至少提供可复跑的命令/截图。

### 升级 / 降级

- **升级**：数据丢失/安全/线上不可用→事故（场景 6）；需要 schema/接口变更→迁移（场景 4）。
- **降级**：纯文案/样式→轻量修复，但必须截图证据；不得跳过复现。

### 反模式

- 直接改代码不写失败测试；只修表象不找根因；
- “无法复现”就关闭；修完不做回归。

## 4. 数据迁移（Migration）

### 触发

- schema/表结构/索引/路径/ID 语义变化；
- 旧数据需要搬迁、重算、回填、清理；
- 备份/恢复/容器升级涉及数据目录。

### 必产物

- 迁移 spec：源/目标、字段映射、兼容策略、非目标；
- 迁移 design：单事务/分批、幂等键、回滚/重试、停服窗口；
- 备份与恢复演练记录；迁移前后对账/hash；
- 迁移脚本/dry-run 计划（实现阶段）；monitoring/日志。

### 门禁

| 门禁 | 类型 | 通过条件 |
|---|---|---|
| Migration Spec Ready | Blocking | 映射/范围/非目标/回滚明确 |
| Dry Run | Blocking | 影子库/副本演练通过，差异可解释 |
| Backup Verified | Blocking | 可恢复，hash/清单校验 |
| Apply | Blocking | 单事务/幂等/失败 fail-closed |
| Verify | Blocking | 行数/抽样/hash/关键查询对账 |
| Regression | Blocking | 旧路径/兼容读不破 |
| Archive | Warning | 迁移记录/回滚点归档 |

### 角色

后端/数据 owner、产品（语义/可接受丢失）、运维/发布、验收。

### 验收

- 迁移前后记录数/抽样/关键字段一致（或差异有清单）；
- 重复执行幂等；失败可回滚；不删旧数据直到确认；
- 旧版本兼容/回滚路径可用。

### 升级 / 降级

- **升级**：不可逆/跨版本/大数据量→停服窗口 + 双人复核；涉及用户交付物→先备份。
- **降级**：仅新增可空字段→可在线增量，但仍需 dry-run/回滚；不得省略备份。

### 反模式

- 无备份直接删/改；用“脚本一次过”代替 dry-run；
- 迁移与业务上线混在一个不可回滚步骤；只对账总数不对账内容。

## 5. 发布（Release）

### 触发

- 一批变更通过 Verify，准备出包/上线（含 8787/容器/便携包）；
- 版本号/发布说明/迁移需要公开。

### 必产物

- Release checklist：范围/版本/变更说明/已知问题；
- 全量验证证据：tsc/build/test/evals/截图/健康检查；
- 迁移备份/回滚计划；包/镜像/SHA256；
- 发布后 smoke 与监控记录。

### 门禁

| 门禁 | 类型 | 通过条件 |
|---|---|---|
| Release Ready | Blocking | 范围/版本/说明/已知问题齐全 |
| Verify | Blocking | 全量门禁通过，无 blocking 缺陷 |
| Package | Blocking | 包可复现、hash 记录、无密钥 |
| Smoke | Blocking | 目标环境启动/健康/关键路径通过 |
| Rollback Ready | Blocking | 旧版/备份可回退 |
| Archive | Warning | 发布证据归档 |

### 角色

Release owner/Lead、模块 owner、测试/验收、运维（部署/监控）。

### 验收

- 目标环境真实路径走通；健康检查/关键 API/UI 通过；
- 包 hash/版本/说明一致；无密钥/敏感文件；
- 回滚演练或回滚命令可用。

### 升级 / 降级

- **升级**：阻塞缺陷/数据风险→停止发布；线上事故→场景 6。
- **降级**：仅文档/无运行时变更→可走轻量发布，但仍需 hash/说明；不得跳过 smoke。

### 反模式

- “本地过了”直接上线；无回滚包；发布说明只写“优化”；
- 带密钥/临时文件打包；发布后不看监控。

## 6. 事故（Incident）

### 触发

- 线上不可用、数据损坏/丢失、安全事件、严重回归；
- 用户无法完成核心路径；SLO/健康检查持续失败。

### 必产物

- 事故记录：时间线、影响面、严重级别、当前状态；
- 立即缓解证据（回滚/限流/停服/恢复）；
- 根因分析（5 Whys/因果链，不先归咎个人）；
- 修复与验证；复盘与 follow-up（owner/deadline）。

### 门禁

| 门禁 | 类型 | 通过条件 |
|---|---|---|
| Detect/Declare | Blocking | 有明确 owner/级别/频道 |
| Contain | Blocking | 先止血，保留现场证据 |
| Recover | Blocking | 核心路径恢复，数据完整性确认 |
| Verify | Blocking | 修复验证 + 关键回归 |
| Postmortem | Blocking | 时间线/根因/影响/follow-up 完成 |
| Archive | Warning | 证据与事故记录归档 |

### 角色

事故指挥（Lead/oncall）、模块 owner、运维/数据、沟通人、复盘主持人。

### 验收

- 服务恢复且可观测；数据无二次损坏；
- 根因可解释，修复有测试/证据；
- follow-up 有 owner/期限；同类监控/门禁补齐。

### 升级 / 降级

- **升级**：数据丢失/安全/持续不可用→最高级别；跨团队/需停服→指挥升级。
- **降级**：单用户/可绕过/无数据影响→普通 bugfix，但仍保留记录；不得删除事故证据。

### 反模式

- 先找责任人再止血；删日志/覆盖现场；
- 只恢复不写复盘；follow-up 无 owner/期限；
- 用“偶发”结案，不补门禁。

## 7. 场景矩阵

| 场景 | 主 skill | 必产物最小集 | 自动门禁 | 人工门禁 |
|---|---|---|---|---|
| 新功能 | `spec-driven` + `product-discovery` | proposal/spec/design/tasks/test/evidence | spec lint、AC 映射、tests/build | 范围/价值/AC 意图 |
| 组件 | `component-gallery` + `frontend-implementation` | COMP spec、画廊、截图 | manifest/截图存在、tsc/build | 视觉/状态/API 取舍 |
| Bugfix | `testing-strategy` | 复现、根因、失败测试、回归 | 失败→通过、回归套件 | 定级/是否升级 |
| 数据迁移 | `backend-contract` + `testing-strategy` | 迁移 spec/design/备份/对账 | dry-run、hash/行数、回滚脚本 | 语义/可接受丢失/切换决策 |
| 发布 | `release-checklist` | checklist、包/hash、smoke、回滚 | 全量门禁、hash、健康检查 | 发布窗口/回滚决策 |
| 事故 | `testing-strategy` + `backend-contract` | 时间线、缓解、根因、follow-up | 日志/监控收集、回归 | 定级/根因/改进决策 |

> 场景不是互斥的：升级即切换主场景并补齐产物；不得用“已经在修”绕过升级。
