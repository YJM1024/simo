## 4. A3 内部滚动（1180 与 375）

研究员会话（38 条，3 个围栏代码块）：

| --- | --- | --- |
| 真实 pre 矩形宽 | 462 | 299 |

| `.conversation-scroll` | 568 / 568，overflow auto | 359 / 359，overflow auto |
| 页面 scrollWidth / innerWidth | 1180 / 1180 | 375 / 375 |

代码块子句成立：`.msg-text pre` 有 `max-width:100%; overflow-x:auto`，长行在 pre 内部横滚，卡片与页面都不溢出（`code-longline-1180.png`、`code-longline-375.png`）。

表格子句不成立。`library.tsx:236-243 renderMessageText` 只处理围栏代码与行内 code，不解析 Markdown 表格；全项目也没有 `.msg-text table` 规则。真实会话 `tableCount=0`。用真实渲染结构注入 `min-width:1200px` 的表格后：

| 档位 | 表格宽 | 卡片 scrollWidth / clientWidth | `.conversation-scroll` scrollWidth / clientWidth | 页面 scrollWidth / innerWidth |
| --- | --- | --- | --- | --- |
| 1180 | 1200（右缘 1480） | 1250 / 526 | 1271 / 568 | 1180 / 1180 |
| 375 | 1200 | 1246 / 357 | 1247 / 359 | 375 / 375 |

卡片自身宽 526/357，装不下 1200 的表格，内容溢出卡框；横向滚动由整个消息列表承担，而不是表格或表格包裹层内部。页面级没有横向溢出，但“表格内部滚动”在字面上不成立。若契约方把“内部”解释为“会话列内部”，则该项可通过；本报告按“表格自身内部滚动”判定，故计入拒绝理由。

## 拒绝理由

COMP-conversation-panel 的唯一实质拒绝项是 A3 的表格子句（spec 第 174 行“代码块/表格超宽时内部滚动”、第 246 行 A3）。实现没有表格渲染路径，也没有表格级横向滚动容器；在真实渲染结构里注入宽 1200 的表格后，卡片内容溢出卡框，滚动落到整个 `.conversation-scroll`，而不是表格内部。代码块子句已通过，因此这是单点缺口，不是整体回退。

如果产品确认消息渲染不支持 Markdown 表格并修订 A3 的文字，或在 `.msg-text` 增加表格包裹层（例如 `display:block; overflow-x:auto; max-width:100%`），本组件其余判据本轮全部通过，可转 accepted。本报告不代签、不改 spec 状态。

## 未验证项

1. `density`/`ariaLabel` 的非默认值没有运行时实例：app 调用点与画廊都不传这两个 prop，只有源码路径与 `.is-compact` 的样式路径取证。
2. `node build.mjs` 本体在验收沙箱因管道被拒（EPERM）未能直接执行；两阶段等价复跑、tsc、vitest 均通过。`build.mjs` 在 frontend cwd 下复跑得到的 CSS 是 73122 bytes，与线上 78803 不同源，字节级复现依赖 tailwind 的扫描基址。
3. A3 的表格用例是注入 DOM 合成的；真实消息里没有 table（渲染器不产 table），因此没有真实数据路径可验证。
4. COMP-composer-send-mode 的 A1–A4、A6、A7 持久化与迁移本轮未复测（上一轮已通过），本轮只覆盖 A5 的七态与提示槽，以及 375 档页面 `scrollWidth` 375（无横向溢出）。
5. 静态原型 `gallery.html` 依赖 `/prototype/*.css`，8787 不服务该路径，只能以静态资源方式渲染取证。
