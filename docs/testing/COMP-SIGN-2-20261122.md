## 1. 结论

`COMP-conversation-panel` 判为 **rejected**。五条修复中的视觉项全部实测通过：卡内第二层白底与第二道边已消失，1180 标签左基线差由 37px 降到 1px，右栏首块与消息列顶部差由 51px 降到 0px，1180 消息卡与 Composer 均左对齐到 300px、宽 528px。拒绝原因是 spec 自己的 API 门禁仍未通过：`specs/COMP-conversation-panel/spec.md:120-123` 要求 `density`/`ariaLabel` 等 API 与实现一致，并写明“补齐前本组件的 API 门禁不成立”；当前 `frontend/src/components/library.tsx:764-780` 仍是 `{ timeline, children, state, empty, error, onRetry, scrollRef, onScroll }`，没有 `density` 和 `ariaLabel`，`aria-label` 仍硬编码为“当前会话消息”。另有 A3 的 CodeBlock/表格内部滚动、A11/A12 的 1920 档、A10 的 build 复跑三项未取证，不能按全通过签字。

`COMP-composer-send-mode` 判为 **rejected**。A8 的发送失败清空输入已修复：注入 500 后 textarea 值 `验收失败保留-1795283047126` 与发送前完全一致，错误文案为“请求失败（500），请稍后重试”，假成功重试后输入清空、错误消失，高度回到 150.05。A5 仍有缺口：空输入时默认、悬停、聚焦、失焦四种状态分别为 opacity 0/1/1/0，但**输入非空后失焦仍为 opacity 1**（class 含 `is-visible`）。`specs/COMP-composer-send-mode/spec.md:117` 要求“hover/focus 显示，移出/失焦消失”，没有“非空例外”；`frontend/src/components/library.tsx:681` 按 `text.trim()` 无条件加 `is-visible`，`components.css:1045` 的注释写的是“输入非空时出现”，实现与 spec 文字不一致。

本轮没有把任何 spec 的状态改为 `accepted`。两个 spec 的 `status` 行保持原值：panel 仍是 `approved`，composer 仍是 `spec ready`。

## 7. 缺陷与观察项

1. **API 门禁未过（阻塞）**：panel 缺 `density`/`ariaLabel`，`aria-label` 不可定制。spec 已明确该门禁不成立，不能判 accepted。
2. **A5 非空失焦仍显示（阻塞）**：composer 的 `is-visible` 只看 `text.trim()`，不看 hover/focus 与鼠标位置；spec A5 要求移出/失焦消失。其余 A5 子项均已通过，修复面很小。
3. **加载错误被同时显示到 Composer（观察）**：`app.tsx:906` 将全局 `error` 作为 `sendError` 传入 Composer，消息加载 500 时面板和输入区各出现一次“请求失败（500）”，Composer 高度从 150.05 增到 168.19，面板高度相应从 662.95 减到 644.81。外层列宽与中心不变，A7 仍按通过记，但这条重复提示建议另开卡处理。
4. **加载错误下时间轴消失（观察）**：非 ready 态不渲染 `.conversation-panel > .timeline`，空态、加载态、错误态均无时间轴；ready 恢复。spec 没有要求非 ready 保留时间轴，本轮不计失败。
