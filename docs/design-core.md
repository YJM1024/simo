# 司墨核心设计（会话 / Spec / 记忆 / 智能体）

> **2026-11-08 用户确认（v0.2）**：在 2026-11-07 总体模型上，补齐近期确认的五组决策——Spec 的内部定位、本体 vs 产品抽象、记忆类型与召回、视图等价、对话即操作与启动汇报、长程运行时能力。本文是总纲；实现契约见 `docs/m*.md`。

## 0. 本体与产品抽象：一切皆记忆，会话是交互视图

### 0.1 本体层（只有两样东西）

1. **记忆（Memory）**：唯一的事实/经验载体。实体、关系、事件、观点、规范、程序、工作状态都以记忆记录存在；原文（raw）不可变，canonical 是处理入口。
2. **动作（Action）**：对世界或记忆的受控变更。每个动作有参数、权限、审计、结果；工具/CLI/API/UI 都只是动作的调用方或呈现层。

> **一切皆记忆**：会话、任务、项目、文件、团队、智能体身份，都是记忆中的记录或记录视图；不为它们另起一套"独立真相"。

### 0.2 产品层（都是投影，不是新本体）

| 产品抽象 | 本体上的真实形态 |
|---|---|
| 会话 | 一段消息流 + 相关记忆的交互视图；有负责人、有内部 Spec |
| 子会话 / 项目 / 团队 | 会话树上的组织关系 + 记忆中的实体关系 |
| 任务 / 工作流 | 记忆里的目标/步骤/状态 + 动作序列；可由对话重建 |
| 文件 / 产物 | 记忆中的文件实体 + 存储引用 |
| 智能体 | 记忆中的身份定义（人格/工具/模型/记忆视图） |
| 视图 / 面板 / 自定义工作流 | 同一套会话消息与动作的**呈现/编排**，不是第二真相 |

**判定规则**：新增一个"顶级产品概念"前，先问它能不能落到「记忆记录 + 关系 + 动作」；不能就不要新增，只做视图。**Spec 也遵守这条规则**（见 §2）。

## 1. 会话

- **只有一个主会话**（会话树根节点），默认负责人是司墨；
- 其余节点都只是**会话**；不存在"项目会话/子会话/任务"这类特殊类型；
- **项目是映射概念**：把某些会话当作一个项目，是会话树的视图能力，不是独立实体；
- **会话 = 交互视图**：同一套消息/记忆在某个组织节点上的呈现；换视图不改变事实；
- 子会话负责人可在对话中切换；
- **继承边界**：上级会话只继承**任务/需求/背景**，**不传人格**；智能体只能用自己的人格执行任务。

## 2. Spec（会话内部的实现手段，不是顶级实体）

> **定位（用户 2026-11-08 再次确认）**：Spec 不是与"会话/记忆/智能体"并列的顶级设计实体；**它属于会话**，是会话实现目标的手段/规范层。**没有会话，就没有 Spec**。

- **默认 1 会话 = 1 Spec**：目标、约束、完成条件、状态、证据、待办；轻量/探索性会话允许"极简 Spec"（只保留目标与概览），不强制完整结构；
- 执行循环：读 Spec → 决策 → 执行 → 更新 Spec；
- **对用户不可见**：用户只看到「概览」/汇报/结果；所有 Spec 操作投影成自然对话（见 §7、§8）；
- 子任务挂 completion/acceptance 键，完成写 evidence；归档走 canArchive；
- Spec 是内部实现细节，**不占用产品层的一等实体位置**（不新增"Spec 页面/Spec 导航"）。

## 3. 记忆（全局唯一库）

- **只有一个记忆库**；不存在"每个会话一套记忆"；
- 会话/智能体都是**视图**：按关联实体、作用域、类型过滤，只取相关部分；
- 记忆绑定**实体**（含域、项目、会话、任务等，它们本身也是实体），实体间有关系；
- **五种类型**：
  - **场景**（发生了什么：episode/事件）；
  - **语义**（事实：稳定的世界/用户/领域知识）；
  - **规范**（目标/约束/决定/偏好）；
  - **程序**（怎么做：流程/技能/工具用法）；
  - **工作**（当前状态：进行中的任务/进度/待办）；
- **金字塔**：记忆内部由抽象到具体的组织与召回结构（高层摘要/实体卡 → 事实/事件 → 原始片段），可多视角、可压缩；
- **写入**：用户消息原文永久保存；处理前必须做**意图识别 + 系统化改写**，得到 canonical；记忆写的是 canonical（保留 raw 溯源）；
- **事实唯一、观点归属**：客观事实要求一致；不同立场/观点带归属，允许并存；
- **冲突保留**：不合并、不覆盖，标 `disputed`；可询问用户，也可保留待后处理；
- **多路召回 + 融合 + agentic**：先理解查询的实体与关系 → 多路召回（关键词/向量/图谱邻域/时间/作用域）→ 融合评分（如 RRF）→ 关系下钻 → 取相关记忆；召回全程可由智能体多步、工具化、追问；
- **不隔离**：智能体之间可只读彼此的人格/记忆（写入仍受域约束）。

## 4. 智能体

- 智能体是身份定义（人格/行为模式/工具/模型/记忆视图），本身也是记忆中的实体；
- 多个智能体本质是司墨的不同人格/场景化行为模式；
- **防人格混乱**：身份锁定、他者内容打标、只能写自己的记忆域、行为校验；
- 消息头像即身份标识；会话树显示负责人头像。

## 5. 团队

- **V0（当前）**：子任务 = 子智能体；互不对话；只向 Lead 汇报；并发上限，超出排队；
- **V1**：角色之间可直接对话、保留记忆；
- **V2**：每个会话可定义团队模板（向下继承）；成员 = 下级会话；可进入成员会话直接聊；复用司墨主模板；会话内部 Spec 驱动。

## 6. 视图等价原则（用户 2026-11-08 确认）

> **任何自定义视图/工作流，都必须等价于"同一套会话消息 + 动作"，并且能用默认对话复现。**

- **同一真相**：自定义视图、面板、工作流画布不产生第二套数据；底层仍是会话消息/记忆/动作；
- **可复现**：视图里能做的事，必须能用默认聊天里的自然语言指令完成；不能复现的视图是无效视图；
- **可降级**：视图损坏/不可用时，默认对话仍可完成同一任务；
- **可迁移**：视图/工作流可导出为一段对话/动作序列，换界面仍能复现；
- **不锁定**：不因为用了某个视图就产生"只能在视图里操作"的能力；
- **布局/偏好例外**：纯展示状态（滚动位置、折叠、宽度）可以只存在视图层，不要求对话复现；但它们不是"能力"。

**检验方式**：为每个自定义视图写一条"默认对话等价路径"；写不出来就不发布。

## 7. 一切操作可通过对话完成（API → 动作层 → CLI/工具）

> **用户 2026-11-08 确认**：UI 只是便捷入口；**任何能力都必须能通过对话完成**。

```
用户对话 / UI / CLI / 外部调用
        ↓（同一个入口）
   动作层（Action Layer）
   - 动作定义：id、参数、权限、审计、证据、结果
   - 单一实现：不按 UI/CLI 各写一套
        ↓
工具 / 存储 / 外部系统（实现细节）
```

- **动作层是唯一能力层**：API/HTTP/WS 是传输，CLI/工具是调用方，UI 是调用方 + 呈现层；四者不各自实现业务；
- **对话等价**：每个 UI 操作都要有对应的自然语言意图/指令；每个指令都落到同一动作；不存在"只能在 UI 做"的操作；
- **可审计**：动作统一记录（谁、何时、参数摘要、权限、结果），UI 操作与对话操作同一账本；
- **可组合**：动作可由工作流/定时任务/其他智能体调用，不依赖界面；
- **新增功能门槛**：设计评审必须回答"对话怎么说、落到哪个动作、权限是什么、如何审计"；
- **例外**：纯展示/布局偏好不是能力，可不入动作层；但改变状态的操作一律入动作层。

## 8. 启动汇报（kickoff）规则（用户 2026-11-08 确认）

> 司墨在**开始一件事**时要主动汇报，避免用户不知道它在干什么；但不要每轮都汇报。

**触发时机**：

1. 会话开场/用户提出新目标；
2. 长任务/工作流开始；
3. 中断后恢复、重连、换负责人；
4. 计划发生实质变化（范围/顺序/关键约束变）。

**汇报内容（模板）**：

1. **我理解的目标**（一句话）+ 明确的非目标/边界；
2. **计划**：阶段/任务（3–5 条以内，带依赖）；
3. **第一步**现在做什么；
4. **需要你确认的**（最多 1 个真歧义/风险问题；没有就说明"我先按默认做"）；
5. **预期产出**与完成判断。

**风格**：

- 简短、自然、先讲结论；不堆关键词、不出现内部术语；
- 不假装进度：没开始就说没开始；有阻塞就说阻塞；
- 计划变化时更新 kickoff，而不是重复播报；
- 用户明确说"直接做/别汇报"时，尊重用户（只保留必要风险确认）。

## 9. 长程任务需要的运行时能力清单

> 长程任务 = 跨多步/多工具/多阶段、可能中断、需要恢复和预算控制的任务。运行时必须提供：

| # | 能力 | 要求 |
|---|---|---|
| 1 | **持久化状态** | 计划/任务/阶段/进度/产物指针落库；重启不丢 |
| 2 | **检查点与恢复** | 关键步骤前写检查点；中断后从最近一致点继续；恢复先拿写所有权 |
| 3 | **任务图与依赖** | DAG/依赖/就绪判定；并行上限；阻塞传播 |
| 4 | **暂停/取消/重试** | 暂停只停新启动；取消保留已完成；重试不重复副作用 |
| 5 | **预算与超时** | token/费用/步数/wall-clock 上限；到限暂停并汇报；headroom 诚实 |
| 6 | **权限与审批** | 工具/写/执行/联网统一动作层审批；无人应答 fail-closed |
| 7 | **产物与文件** | 产物登记/存储/预览/下载；路径安全；不复制真相 |
| 8 | **事件日志与幂等** | 事件先落库再推进；幂等键；崩溃重放不重算副作用 |
| 9 | **上下文管理** | 压缩/裁剪/记忆召回；长任务不爆上下文；关键约束不丢 |
| 10 | **进度与汇报** | 阶段/任务完成汇报；进度可观测；不刷屏 |
| 11 | **调度与触发** | 定时/事件触发；错过只补最近一次；失败重试上限 |
| 12 | **可观测性** | 运行状态/耗时/成本/错误可查；错误可归因 |
| 13 | **并发与隔离** | 多任务/多智能体并发；写作用域冲突检查；单写者事务 |
| 14 | **可恢复的委派** | 子智能体失败/卡死可检测、可接管、可汇总；不丢结果 |

> 当前实现（M13）已覆盖大部分：事件日志/检查点、任务与工作流、取消/重试、权限审批、产物、定时任务、预算基础。**待补强**：跨重启的强一致恢复、长任务 wall-clock/费用硬上限、进度上报节流、失败接管与对账。

## 10. 原则

1. **事实唯一、观点归属**；
2. **统一存储、按需取用**（视图，不是分库）；
3. **原文不可变、canonical 是唯一处理入口**；
4. **Spec 是会话内部手段**：对用户不可见，用户看概览/汇报；修改通过对话/动作完成；
5. **会话树传"事"不传"人"**；
6. **冲突是正常数据，保留而非覆盖**；
7. **一切皆记忆**：不轻易新增顶级实体；新增前先落成记忆/关系/动作；
8. **视图等价**：自定义视图/工作流必须能由默认对话复现；
9. **一切操作可通过对话完成**：对话/UI/CLI 共用动作层，无隐藏路径；
10. **开始先汇报（kickoff）**：目标、计划、第一步、待确认、预期产出；计划变化时更新。
