# 墨斗元模型 v0.2

## 1. 定位与不变量

元框架固定五类流程点、六槽槽名、允许边集与具体化规程。角色、步骤、产物数量与判据内容由填槽决定。固定处可逐条比对，放开处按填槽验收（DESIGN.md:18）。

## 2. 五类流程点

五点是坐标，不是流程。每点回答一个问题，产出一类对象。顺序由第 4 节的边给出。

| 流程点 | 回答的问题 | 产出的对象 |
|---|---|---|
| 需求点 | 要产出什么，边界与验收取值是什么 | 需求陈述 |
| 来源点 | 依据哪份材料、哪个版本、凭什么适用 | 来源引用 |
| 判定点 | 多个做法或来源冲突时选哪个，为什么 | 裁决记录 |
| 规则点 | 这一层必须成立什么，违反了拦在哪 | 规则条目 |
| 验收点 | 凭什么判合格，谁签 | 验收结论 |

## 4. 点间连接

允许边共十组，线性链只是其中一条全序特例。需求直连规则与需求直连验收两条的成立条件见表。偏序五条，禁止边三类。

| 起点 | 终点 | 用途 | 成立条件 |
|---|---|---|---|
| 需求点 | 来源点 | 声明依据 | 需求点无前驱 |
| 需求点 | 判定点 | 需求自带取舍 | 取舍写进需求陈述 |
| 需求点 | 规则点 | 需求直连规则 | 规则点已填满 |
| 需求点 | 验收点 | 需求直连验收 | 判据已冻结 |
| 来源点 | 判定点 | 依据冲突进裁决 | 无 |
| 来源点 | 规则点 | 依据沉淀为规则 | 无 |
| 来源点 | 验收点 | 证据直达验收 | 无 |
| 判定点 | 规则点 | 裁决结果固化 | 无 |
| 判定点 | 验收点 | 裁决作验收条件 | 无 |
| 规则点 | 验收点 | 按规则判合格 | 无 |

| 类别 | 规则 | 内容 |
|---|---|---|
| 偏序 | 需求点无前驱 | 入边为空，先于其余点 |
| 偏序 | 验收点无后继 | 出边为空，是终点 |
| 偏序 | 规则点先于验收点 | 验收按已冻结的规则判 |
| 偏序 | 除退回外不回冻结点 | 已冻结的点不再作为边的终点 |
| 偏序 | 无环 | 边集构成偏序，退回不记边 |
| 禁止 | 来源点到需求点 | 需求边界会由可用材料决定 |
| 禁止 | 验收点到规则点 | 等于用结果放宽机制（DESIGN.md:82） |
| 禁止 | 验收点到需求点 | 退回只记在验收点，不构成边，避免环 |

## 5. 具体化规程

六步各有判据，不过就停在该步。四元组缺项退回专家（DESIGN.md:115）。步骤见表。

| 步 | 动作 | 判据 |
|---|---|---|
| 1 | 读领域四元组 | 参与者角色、交付物类型、判据来源、约束条件四项有取值（DESIGN.md:32） |
| 2 | 定流程集 | 每条流程有输入与可命名的交付物（DESIGN.md:33、35） |
| 3 | 填五点六槽 | 六槽非空，强制槽按第 3 节判据逐条过 |
| 4 | 连边成偏序 | 边在第 4 节表内，无环，需求点无前驱，验收点无后继 |
| 5 | 冻结判据与证据 | 每条判据能由第三人按证据复算（DESIGN.md:18） |
| 6 | 独立签署并登记版本 | 签署人不是第 3 步填槽人；版本记入领域节点（DESIGN.md:76） |

## 6. 多级

具体化一个框架的操作者不必是元框架，也可以是其他类型的操作框架。节点是框架及其类型，边是某类框架对另一类框架的具体化或生成。约束是操作者与被产出的领域框架不同型，或操作者本身属于某一特殊领域。

同一套五点在每层重复，点集不变，变的是槽位填充。上层槽值作下层默认值，下层只写增量（DESIGN.md:68）。默认值可收紧不可放宽，末端是任务（DESIGN.md:74、82）。

## 7. 点集准入

v0.1 把点集定为封闭五元集，只约束元框架这一类操作者。加点要两条同时成立：产出物、完成判据、签署者归不进现有点，且在两个以上不同领域重复出现。新点自带五项：问题、六槽划分、入边出边、偏序位置、样本回放。加点按版本事件升版重验证据（DESIGN.md:76）。隐性知识与纯审美不设点（DESIGN.md:117）。

## 8. 六部件关系

六部件是六槽的汇总：单元对产出物，判据对完成判据，证据对证据形式，角色对产出者与签署者，状态机对产出物的状态与转移（DESIGN.md:36）。门禁由完成判据与冻结解冻合成，管开工与放行。取法已定为正文版（DESIGN.md:129）。

## 10. 自检

可判定：第 3 节判据可逐条比对，第 4 节边表穷举。可复算：证据含来源、版本与签署时点（DESIGN.md:92）。不自兼：签署者强制不同于产出者与填槽人。全覆盖与门禁样例不在自检范围（DESIGN.md:18）。

## 附录 A 七角色参考实例

七角色是参考实例，不是规则。它们是具体化操作框架的一组角色分工，产出者、判定者、签署者分开。每个角色落在若干槽上，名称与数量随领域改，模型只固定槽。

| 角色 | 落在哪些槽 |
|---|---|
| 需求提出方 | 需求点的产出者，签署由所属层负责人另任 |
| 领域专家 | 需求点、规则点的产出者 |
| 框架设计者 | 第 5 节各步的填槽人 |
| 产出执行者 | 来源点、判定点的产出者 |
| 判定者 | 判定点的签署者 |
| 签署者 | 验收点的签署者 |
| 维护者 | 规则点的产出者与签署者 |
