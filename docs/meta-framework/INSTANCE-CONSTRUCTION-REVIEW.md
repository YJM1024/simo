# 建筑施工图审查：墨斗元模型 v0.2 的一次领域具体化

本文用墨斗元模型 v0.2 在建筑施工图审查领域走一遍第 5 节的六步规程，检验五点六槽在软件之外的覆盖度，并记录缺口。施工图审查指建设单位把施工图送第三方审查机构，对照公开的工程建设标准核对是否合格，合格后才能开工；强制条文指必须执行、不得协商的条文。文中的领域事实全部是假设，法规一律用占位名处理，不引条款编号与内容。

## 1. 为什么选这个领域

它与软件开发的差别在交付物形态：软件交付代码与运行系统，合格与否靠测试与评审判；施工图审查交付图纸与审查文书，图纸会被退回修改，同一份图纸在整改前后被判两次，而审查机构只出意见、不生产图纸，产出者与验收者从一开始就是两拨人。它的判据有明确来源：判据来自公开的工程建设标准与地方审查管理办法，第三人可以调取原文复算，不需要依赖团队内部约定。它有可命名的交付物：委托审查范围、施工图、审查意见书、整改回复、复审记录、审查合格书，每一件都能命名、能判合格、能留证，符合元模型对交付物的三条要求。

## 2. 领域四元组

四项取值都按假设填写，未与从业者核对。

| 元 | 取值 | 状态 |
|---|---|---|
| 参与者角色 | 建设单位（委托方）、设计单位（图纸产出方）、审查机构（第三方审查）、建筑与结构、给排水、电气、暖通五专业审查人、审查机构技术负责人、授权签字人、施工图审查主管部门、勘察单位 | 假设，待领域专家确认 |
| 交付物类型 | 文书类：委托审查范围、审查意见书、整改回复、复审记录、审查合格书。图纸类：各专业施工图、结构计算书、地勘报告。文书只增版本不回改，图纸整份换版 | 假设，待领域专家确认 |
| 判据来源 | 当地施工图审查管理办法（条款待专家填）、现行工程建设标准（名称与版本待专家填）、项目立项与规划批复（文号待专家填）、经审查合格的勘察报告 | 假设，待领域专家确认 |
| 约束条件 | 审查时限（法定工作日，天数待专家填）、审查范围不得小于强制条文覆盖范围、审查机构与设计单位不得为同一主体、意见须逐条对应图号与专业、整改须由原设计单位完成并签章 | 假设，待领域专家确认 |

## 3. 五类点的填法

五点是坐标，不是步骤。下面逐点填六槽，每点配一件具体物件，槽名取自元模型第 3 节，槽值是本次领域填充。

需求点，物件是委托审查范围。

- 产出物：委托审查范围，含项目概况、审查专业清单、送审图纸清单、审查依据清单、时限约定。
- 产出者：建设单位项目负责人。
- 完成判据：目标（取得审查合格书）、范围（专业与图纸清单可逐张核对）、验收取值（合格与不合格二分，不合格须逐条列整改项）、约束（范围不小于强制条文覆盖范围）四项齐全。
- 证据形式：委托书加送审清单，逐项列图号与版本。
- 签署者：审查机构项目负责人，与产出者不同人。
- 冻结与解冻：受理时冻结；追加专业或补图记版本事件，已出意见的条目重验。

来源点，物件是送审施工图与地勘报告。

- 产出物：来源引用，含标准名称与版本、批复文号、地勘报告版本、适用理由。
- 产出者：审查机构接件人。
- 完成判据：规范名、版本、适用理由三项齐全，且每条依据能指到具体专业与图纸。
- 证据形式：补料留痕条目，一条依据一条记录，含来源文件、版本与引入时点。
- 签署者：审查机构技术负责人。
- 冻结与解冻：依据版本随受理冻结；换版或新增地方文件记版本事件，重验已出意见。

判定点，物件是专业间冲突与范围冲突的裁决。

- 产出物：裁决记录，含冲突双方、优先级、证据合并方式、复审范围。
- 产出者：审查机构技术负责人。
- 完成判据：冲突双方（如建筑专业的疏散宽度要求与结构专业的梁位限制）、优先级（强制条文优先于一般条文，地方办法优先于机构内部惯例）、证据合并方式（两专业意见并列保留，按优先级取一条作为整改要求）三项齐全。
- 证据形式：裁决记录随冲突意见所在边登记，一条冲突一条记录。
- 签署者：专业总工或机构负责人，不得为裁决人。
- 冻结与解冻：随边冻结；改判记版本事件，重出受影响意见。

规则点，物件是审查作业规则。

- 产出物：规则条目，覆盖意见格式、强制条文处置、复审范围、时限起算。
- 产出者：审查机构技术负责人，兼该层规则维护人。
- 完成判据：每条规则能落到一条可核对的意见判据或一个受理、出证门禁，且不放宽上位标准与管理办<!-- -->法。
- 证据形式：规则条目加核对方式，核对方式写明核对人与留痕位置，人工逐条核对或审查系统校验均可。
- 签署者：审查机构负责人。
- 冻结与解冻：判据冻结；解冻只能收紧或增证，例如把提示性条文的「宜」改为必须回复。

验收点，物件是审查意见书与审查合格书。

- 产出物：验收结论，初审出一份带整改项的不合格结论，复审出一份合格结论，两份都是可命名交付物。
- 产出者：各专业审查人出专业意见，复审人做复核。
- 完成判据：结论逐条对应证据，第三人可按图号、依据、整改回复三项复算；每条意见有图号、有依据、有整改对应。
- 证据形式：意见书加复审记录，逐条闭环，签署时点记到日。
- 签署者：授权签字人，不得为出意见的审查人。
- 冻结与解冻：签署后冻结；复审不通过另出一份结论，不回改已签发的意见书。

## 4. 由此长出的流程

流程由上面五个点的槽值与边连出来，元模型不规定步骤的数量与名称。这条流程的七步、八个角色、六个状态都是本次填充的结果。

1. 送审：建设单位提交委托书、施工图、批复与地勘报告，产出委托审查范围与送审清单，执行者是建设单位项目负责人与审查机构接件人。
2. 受理：接件人核对范围与材料完整性，冻结需求点与来源点，产出受理记录，机构项目负责人签署。
3. 初审：五专业审查人按依据逐张审图，各出专业意见，产出专业审查意见，执行者是建筑、结构、给排水、电气、暖通审查人。
4. 提意见：技术负责人合并专业意见并裁专业间冲突，出审查意见书，授权签字人签发。
5. 整改：设计单位按意见修改图纸并出整改回复，建设单位组织提交，产出修改图与整改回复。
6. 复审：复审人核整改项与受影响项，出复审记录，执行者可以不是原审查人。
7. 出证：复审通过出审查合格书，不通过退回第 5 步或终止并出具书面结论，授权签字人签发。

状态依次为待受理、审查中、已提意见（待整改）、已回复（待复审）、复审通过（已出证）、复审不通过（回整改或终止）。回整改不回到审查中，只重开验收点；终止是关闭，不再转移。

元模型不规定步数，七步是范围槽与复审规则共同定出来的。委托范围只含消防专项时，第 3 步的专业数降到一至两个，第 4 步的合并动作消失；地方办法允许告知承诺制时，第 5、6 步并成一次抽查。角色数量也随之变化，五个专业审查人可能只剩一个。

## 5. 五点够不够

逐环节检查的结论是五点在对象层面够用，缺口落在槽的约束与第六个部件上，不在点集。

整改回复与复审的循环放得进。元模型第 4 节把退回排除在边集之外，退回只记在验收点，不构成环；复审因此是验收点的第二次执行，两次执行之间的差别由需求点的版本事件承载，范围收窄为整改项与受影响项。缺口在槽：退回之后动手的是设计单位，不是原产出者，验收点的产出者槽只写了一个角色，装不下「退回对象」。建议在该点增加槽值「退回对象与退回范围」，不新增点。

多主体会签只放得进一半。专业间冲突由判定点裁，合并格式与责任标注由规则点定，这两处没有障碍。写不进去的是人和签：验收点的产出者槽写作「验收执行者，单一角色」，五个专业各出意见违反这一条；签署者槽写作「独立验收角色」，没写集合。建议把这两个槽从单数改为「角色集合，集合与产出者不相交，集合内注明主签与签署顺序」。这是槽约束的修订，代价是所有已填的验收点要重填一遍。

时限管理放得进一半。时限写在四元组的约束条件里，超时的处置写成规则条目，状态转移以时限为守卫。六槽没有时间字段，起算点、中止、顺延只能写在规则条目的正文里，无法作为独立可复算的证据。缺口在第六个部件的状态机，要把时间写成转移的必备属性。时限不产出独立对象，按第 7 节的准入条件不构成新点。

复审不通过的回退放得进。两个出口都是状态转移，回退不记边，不构成环。缺口在终止态的区分：六部件把状态机写作「从起草到关闭」，没有区分合格关闭与不合格关闭，而不合格关闭要出具一份可命名的书面结论，这份结论同样要能留证、能被第三人复算。

候选新点「合议点」在本领域不成立，记录理由备查。它要回答多个平行产出如何合并为一份对外有效的结论、由谁负责，产出物是带责任专业标注的会签件，入边是多个产出点到它，出边是它到验收点。不立项的原因是合并件与不合格结论在本领域是同一份文书、同一批人签，产出物、完成判据、签署者都归得进验收点，第 7 节的第一条不成立；这类合并动作只有在某个领域把会签意见与合格判定拆成两份文书、两个签署人时才需要独立成点。

## 6. 与墨线对照

同一套点在不同领域长出的步骤不同，差别来自槽值，不来自点集。

验收次数。墨线一次验收即关闭，需求、来源、判定、规则、验收串成一条链。施工图审查长出两步验收，因为验收对象是可修改的图纸，整改由机构之外的设计单位完成，第一次结论必然是不合格。

角色数量。墨线用实现者不自签、验收 Agent 独立签字两个角色解决签署。施工图审查要五专业分签、技术负责人核签、授权签字人签发三层，原因是交付物按专业切分，一个专业判不了另一个专业的合格。

来源点的执行次数。墨线的来源点一次补料留痕，记依据文件与版本。施工图审查的补料跨受理与复审两个时点，现场核查记录与主管部门批复在复审中才出现，来源点因此要执行两次。

## 7. 未验证项

四元组四项取值全部是假设，需领域专家逐项确认，其中审查机构与主管部门的职责边界最影响边集。审查时限的天数、起算日、中止与顺延规则未验证，它直接决定状态机守卫怎么写。强制条文的范围与「应」「宜」类条文的处置口径未验证，它决定规则点能否收紧到必须回复。复审范围是只核整改项与受影响项，还是全图复核，未验证；这一条决定复审是同一个验收点的第二次执行，还是一个新的验收点，本文按前者写，属假设。各专业分签的责任划分、主签归属、电子签章的法律效力未验证。地方管理办法的名称、文号与条款内容全部按占位处理，需专家填入后方可复算。

本文只做具体化演示，不产出可执行的审查作业规程。按元模型第 8 节，领域知识由专家提供，元模型只负责组织与生成，判断交付物是否合格仍然由审查人承担。
