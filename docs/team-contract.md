## 1. 术语与边界

### 1.1 术语（只此一套）

| 术语 | 定义 |
|---|---|
| **会话树** | 唯一的组织结构；**主会话是根**，所有节点都叫「会话」；本文统一称上级/下级会话 |
| **Lead（负责人）** | 当前会话的 `owner_agent_id`；主会话默认是司墨；Lead 对上级汇报、对下级汇总 |
| **团队成员** | **下级会话**；不是新实体；成员 = 一个会话 + 其负责人 agent |
| **团队** | 一个会话下的成员集合（V0 只是虚拟集合；V1/V2 有显式团队记录） |
| **团队模板** | 角色清单 + 继承关系；实例化后生成下级会话（V2） |
| **角色** | 团队模板中的职责定义；实例化后由 agent 承担 |
| **agent** | 身份（人格/工具/模型/记忆域）；司墨是 agent，模板角色实例也是 agent |
| **任务（Task）** | 会话内最小执行单元（M10）；V0 的子任务由子智能体执行 |
| **Spec** | 会话内部规范层（M18）；**每个会话一个**，对用户不可见 |
| **交付物** | 成员产出的文件/产物/结论；跨会话时按引用传递，不复制 |

> 本文统一使用「会话 / 下级会话」两词，不再使用其他旧称；团队不是新的一层实体，只是会话树上的组织关系 + 负责人 + 模板。

### 1.2 边界

- **成员 = 下级会话**，不新增独立“团队成员”对象；
- **Spec 仍属于各自会话**；团队页/Lead 只读状态/概览/交付物，不读其他会话的 Spec 正文；
- **不做** V1/V2 之外的扩张：不做多人协作、跨设备、外部 A2A；
- V0 是现有 M10 语义：**子任务 = 子智能体，互不对话，只向 Lead 汇报，并发上限 + 排队**；
- V1 才允许角色间直接对话；V2 才引入团队模板与只读团队页；
- **用户不感知 Spec/团队内部术语**：UI 只有会话树、团队页（V2）、概览、任务。

## 2. 三阶段模型

### 2.1 V0：当前形态（已有 M10）

| 维度 | 规则 |
|---|---|
| 结构 | 不创建下级会话；会话内任务由**子智能体**执行 |
| 通信 | 成员之间**不对话**；子智能体只向 Lead（当前会话负责人）汇报 |
| 汇报 | 每个任务完成由 Lead 在会话里发一条汇报（M10 逐任务汇报） |
| 并发 | 默认并发 3（可配），超出排队；失败重试 ≤2；预算/步数上限 |
| 记忆 | 子智能体只拿任务 brief + Spec 切片；不回写用户可见记忆 |
| 用户 | 只跟 Lead 对话；看不到子智能体 |

> V0 的“团队”只是 Lead + 任务执行者，**没有团队记录/团队页**；不要为 V0 造团队表。
> 子智能体的底层执行者复用 M18：默认 `agent:task-npc`（空人格任务智能体），也可配置 `agent:simo`；它不是团队成员会话。

### 2.2 V1：角色间可直接对话（会话间消息路由）

| 维度 | 规则 |
|---|---|
| 结构 | 团队 = 下级会话集合；每成员一个会话 + 一个负责人 agent |
| 通信 | 成员之间**可直接对话**（内部消息路由）；Lead 也可发消息；**用户不参与内部对话** |
| 记忆 | 每个成员保留自己的会话记忆；通用角色可跨会话共享（见 §4） |
| 汇报 | 不刷屏用户：内部消息不进用户主窗口；Lead 在会话里汇总/转述（必要时引用交付物） |
| 用户 | 用户只跟当前会话负责人说话；可进入成员会话查看/对话（V2 团队页提供入口，V1 可用会话树直接进入） |
| 边界 | 不做团队模板/继承（那是 V2）；不做自动建整队（V1 成员由动作创建） |

**消息路由**：只允许团队内、有关系的成员之间；消息是**内部事件**，不是用户消息；Lead 决定哪些内容以自然语言汇报给用户。

### 2.3 V2：团队模板 + 只读团队页 + 可进入成员聊天

| 维度 | 规则 |
|---|---|
| 模板 | 每个会话可定义团队模板；**向下继承、可覆盖**；模板 = 角色清单 |
| 人格 | 角色基础人格**复用司墨主模板**；可覆盖职责/工具/模型，**不可覆盖安全底线/身份锁定** |
| 实例化 | 模板实例化 → 生成下级会话（成员），各挂负责人 agent |
| 团队页 | **只读**团队页：团队/模板/成员/角色/状态/进度/交付物；无编辑控件 |
| 进入聊天 | 用户可进入某成员会话直接聊；回来后 Lead 汇总；不复制消息 |
| 编排 | 成员会话内部仍由各自 Spec 驱动（M18）；Lead 读概览/状态，不读 Spec 正文 |
| 继承 | 子团队可继承父模板；覆盖只增不减安全约束；禁止继承环 |

## 3. 角色模型

### 3.1 两类角色

| 类型 | 实例化 | 记忆 | 生命周期 | 标识 |
|---|---|---|---|---|
| **模板角色** | **每次实例化新建** | **独立**（`agent:<template>-<instance>`） | 随团队实例存在 | 新 agent 实体 |
| **通用角色** | 同一 agent 跨团队/会话复用 | **共享**（`agent:<role>`） | 长期存在 | 稳定 agent 实体 |

规则：
- 模板中每个角色声明 `role_type: template|generic`；
- 模板角色每次实例化产生**新 agent 身份**（人格版本固定）；不共享私有记忆；
- 通用角色跨会话复用，**共享通用记忆**；不可被单个团队修改人格（只能读）；
- 两类角色都能承担负责人；切换负责人 = 改会话 `owner_agent_id`，不改成员结构。

### 3.2 模板角色字段（建议）

| 字段 | 说明 |
|---|---|
| `role_key` | 模板内唯一（如 `researcher`） |
| `title` | 展示名（团队页） |
| `role_type` | `template` / `generic` |
| `persona_base` | 默认 `simo`（复用主模板） |
| `persona_override` | 职责/风格覆盖（不含安全底线） |
| `tools` / `model` | 可覆盖工具白名单/模型（不能越过模板上限） |
| `responsibilities` | 职责描述（自然语言） |
| `inputs` / `outputs` | 交付物契约（可选） |
| `inherits_from` | V2 继承：模板/角色级覆盖 |

### 3.3 负责人切换

- 通过对话表达“这个会话由 X 负责/换成 X”；
- 动作层校验：目标 agent 必须属于当前团队/模板；权限足够；写审计；
- 切换后：历史消息不改归属；新消息归属新负责人；Spec 归属会话不变；
- V0 不切换负责人（Lead 固定）；V1 允许 Lead 指定成员负责人；V2 支持从模板角色选。

## 4. 记忆边界

### 4.1 三层记忆

| 层 | 归属 | 写法 | 读法 |
|---|---|---|---|
| **团队共享记忆** | `team:<id>`（团队实体） | Lead 直写；成员提交候选，由单写者/Lead 合并 | 团队成员可读 |
| **会话/任务记忆** | `session:<id>` / `task:<id>` | 该会话负责人写；成员只能提交候选 | 会话参与者；Lead 读概览/交付物，不读正文全文 |
| **智能体通用记忆** | `agent:<id>` | 仅该 agent 写 | 其他 agent 只读（design-core 不隔离） |

### 4.2 Spec 边界（关键）

- **每个会话一个 Spec（M18）**；Spec 属于会话，不是团队/记忆的公共数据；
- **Lead 不读成员 Spec 正文**：只读成员状态、概览摘要、交付物、必要 handoff；
- **成员之间不共享 Spec**：通过交付物/消息（V1）/Lead 转述协调；
- 用户始终看不到任何 Spec；团队页只展示状态/概览摘要。

### 4.3 人格隔离

- 人格 = 角色模板（基础司墨 + 角色覆盖）；上级只继承任务/需求/背景，**不继承人格**；
- 每轮注入 `persona@persona_version`；他者内容打标 `[agent:<id> 的观点]`；
- 只能写自己的记忆域；跨域只读或提交候选；
- 通用角色共享记忆 ≠ 共享人格写入权；人格版本不可被单个会话改写。

## 5. 跨会话触发（V1/V2）

> 目标：成员步骤完成 → 依赖满足 → **自动启动下一会话动作**；交付物作为输入；幂等、可重试、可暂停。

### 5.1 触发模型

```
成员 A 步骤/任务 done
  → 产出交付物（artifact/摘要/结论）并登记 deliverable
  → 依赖图/触发器检查（目标成员 B 的前置是否满足）
  → 触发 B 的动作（start_task / start_workflow / send_message）
  → B 的会话内由 Spec 驱动执行；A 的交付物作为输入引用
  → B 完成 → 继续下游；Lead 收到汇总
```

### 5.2 规则

- **依赖**：触发器只在依赖满足（前置成员/步骤 done）时启动；
- **输入**：只传交付物引用（artifact id/路径/摘要），不复制文件；接收方按权限读取；
- **幂等**：`triggerId + fromMember + sourceEventSeq` 唯一；重复投递不重复启动；
- **重试**：失败 ≤2 次，指数退避；仍失败 → 标记 failed 并向 Lead 汇报；不无限重试；
- **暂停**：团队/成员暂停 → 不启动新动作，运行中按暂停语义跑完即停；恢复继续；
- **取消**：终止 future 触发；已完成不回滚；
- **并发/预算**：受团队并发上限、每成员 token/步数预算约束；超出排队或暂停；
- **安全**：触发动作仍走权限/审批；无人应答 fail-closed；
- **可见性**：触发器事件不直接推用户；Lead 在会话中汇总。

### 5.3 V0 的对应关系

- V0 不跨会话：任务 DAG 在**同一会话**内自动推进（M10）；没有成员会话可触发。
- V1 支持定向成员消息（direct message），但不强依赖模板；跨会话触发可在 V1 手工配置。
- V2 由团队模板/成员关系生成触发器，默认“上游交付物就绪 → 下游启动”。

## 7. API / 事件增量

### 7.1 公开 API（用户可见）

| 方法 | 路径 | 阶段 | 说明 |
|---|---|---|---|
| GET | `/api/sessions/{id}/team` | V1/V2 | 当前会话的团队摘要（只读；V2 团队页数据源） |

### 7.3 事件（内部事件日志）

| 事件 | 阶段 | 说明 |
|---|---|---|
| `team.created` / `team.archived` | V1/V2 | 团队生命周期 |
| `team.template.applied` | V2 | 模板实例化 |
| `team.member.added` / `member.status_changed` | V1/V2 | 成员会话创建/状态 |
| `team.owner.changed` | V1/V2 | 负责人切换 |
| `team.message.queued` / `delivered` / `failed` | V1 | 内部消息路由 |
| `team.trigger.fired` / `trigger.failed` | V1/V2 | 跨会话触发 |
| `team.deliverable.ready` | V1/V2 | 交付物就绪（触发下游输入） |

- **M31 起**：`team.*` 已加入用户 WS 允许表，团队页实时刷新；事件只投影状态/摘要，不显示成员内部消息正文；Lead 仍按需汇总；
- 团队页只读展示投影（状态/成员/交付物），不展示事件原文。

### 7.4 与 M18 的关系

- 每个成员会话各自拥有 Spec（M18）；团队不共享 Spec；
- 成员执行由各自 Spec 驱动；Lead 只读成员概览/状态；
- 跨会话触发启动的是“成员会话内的动作/任务”，仍走该会话的 Spec 状态机与权限。

## 8. 验收标准

### 8.1 V0

1. 一个需求 → 任务由子智能体执行；子智能体之间无消息；
2. 每个任务完成 Lead 在会话里汇报；用户看不到子智能体；
3. 并发上限生效（默认 3），超出排队；失败重试 ≤2；
4. 暂停/恢复/取消/重启语义与 M10 一致；
5. 无团队表/团队页也能工作（V0 不造团队记录）。

### 8.2 V1

1. 团队成员 = 下级会话；各有负责人 agent；
2. 角色间可直接发内部消息；消息不出现在用户主窗口；
3. Lead 汇总为自然语言汇报；不刷屏；
4. 各成员保留自己的记忆；通用角色跨会话共享记忆；
5. 用户可进入成员会话查看/对话；返回后 Lead 汇总；
6. 权限/审批仍 fail-closed；无跨团队越权。

### 8.3 V2

1. 每个会话可定义团队模板；向下继承、可覆盖；禁止环；
2. 模板实例化生成下级会话；成员负责人按角色挂载；
3. 团队页只读（模板/成员/角色/状态/交付物）；无编辑控件；
4. 可进入成员会话聊天；不复制消息；
5. 模板角色实例化新建、记忆独立；通用角色复用、共享记忆；
6. 换负责人通过对话完成并审计；
7. 团队共享记忆/会话 Spec/智能体记忆三层边界正确；Lead 不读成员 Spec 正文；
8. 跨会话触发：上游交付物就绪 → 下游自动启动；幂等/重试/暂停生效；
9. 用户侧不出现 Spec/内部团队术语。

## 10. 风险与待拍板

### 10.1 风险

| # | 风险 | 应对 |
|---|---|---|
| 1 | 团队页泄漏 Spec/内部术语 | API schema 白名单；UI 扫描；只读投影 |
| 2 | V1 内部消息刷屏用户 | 内部消息不进用户主窗口；Lead 汇总；频率限制 |
| 3 | 模板继承导致人格/权限越权 | 安全底线不可覆盖；继承环检测；工具/模型上限校验 |
| 4 | 跨会话触发重复启动/风暴 | 幂等键 + 依赖检查 + 并发/重试上限 + 暂停 |
| 5 | Lead 读成员 Spec 破坏边界 | 只暴露概览/状态/交付物接口；Spec 正文不跨会话 |
| 6 | 通用角色共享记忆污染 | 写域隔离；通用角色人格只读；候选合并 |
| 7 | V2 团队页/成员过多导致性能问题 | 分页/摘要；懒加载；只读缓存 |
| 8 | V0/V1/V2 代码分叉 | 同一 team 服务分阶段启用，V0 不建团队表；特性开关 |

### 10.2 待拍板（≤5）

| # | 问题 | 建议默认 |
|---|---|---|
| 1 | **V1 消息路由范围**：所有成员可互发，还是只允许模板声明的通信边？ | 默认**只允许声明的通信边**（模板/触发关系）；自由互发 P1 |
| 2 | **通用角色记忆共享范围**：共享全部通用记忆，还是仅白名单类型（规范/程序）？ | 默认共享**规范+程序**；场景/工作记忆不跨会话共享 |
| 3 | **V2 模板继承深度**：允许几层？ | 默认**≤3 层**，超过拒绝；环检测 |
| 4 | **团队页可见性**：所有用户可见，还是仅 Lead 会话可见？ | 默认**仅当前团队/Lead 会话可见**；跨团队不可见 |
| 5 | **换负责人权限**：Lead 可换任意成员，还是仅上级负责人可换下级？ | 默认**只能换直接下级**；跨级需用户确认 |

## 11. 与既有文档的差异

- **design/10 §47**：定义了 V0/V1/V2 模型；本契约补充术语（会话树/下级会话）、表/API/事件/验收/测试/风险。
- **M10**：V0 直接复用其任务/工作流/逐任务汇报/并发/重试语义，不重复实现。
- **M18**：每个成员会话各自有 Spec；团队不共享 Spec；Lead 只读概览/状态。
- **design/24**：团队共享记忆/会话记忆/智能体记忆的分层沿用；Spec 不属于记忆类型。
- **design-core**：一切皆记忆、会话是交互视图；团队是会话树组织关系，不是新本体。
