# TaskStack 悬浮任务概览 · 组件设计

> 状态：设计完成，排在前端重构之后实现。
> 归属：会话页（Chat）输入框上方；长程任务状态视图，不产生聊天消息。

## 1. 结构

```
TaskStack
├─ 折叠态（默认）
│   ├─ TaskCard × 1–3          // 主标题 + 副标题 + 状态/耗时
│   └─ "还有 N 个任务"          // 超出 3 条时的折叠行
└─ 展开态（点击某个任务）
    ├─ TaskCard（高亮当前）
    └─ TaskSteps
        ├─ 已完成步骤（从上到下）
        ├─ 进行中步骤（高亮、带旋转/脉冲状态）
        └─ 未完成步骤（弱化）
```

## 2. 卡片

- 主标题：任务名（≤ 1 行，超出省略）
- 副标题：当前步骤 + 一句解释（≤ 2 行）
- 右侧：状态（执行中 / 已暂停 / 等待确认 / 已完成 / 失败）+ 耗时
- 点击：展开该任务步骤；再次点击收起；同组多任务可逐个展开
- 进行中卡片左侧 2px 靛蓝指示条；完成/失败后从栈中移除

## 3. 步骤列表（展开态）

- 顶部：已完成（check 图标、灰/绿、按完成顺序）
- 中部：进行中（靛蓝高亮、进度、当前动作说明）
- 底部：未完成（空心圆、弱化文字、预计动作）
- 每步：步骤名 + 说明 + 状态 + 耗时；长列表内部滚动（max-height ~40vh）
- 分组标题：已完成 / 进行中 / 未完成，小号灰字
- 展开时卡片保持可见；不覆盖输入框；不把最后几条消息完全遮住

## 4. 堆叠与克制

- 默认最多 3 条卡片；超过显示「还有 N 个任务」；
- 展开只展开一个任务的步骤（手风琴），避免多层叠加；
- 任务结束/取消后自动移除；无活跃任务时整个组件隐藏；
- 快速任务不进入栈，直接结束消息。

## 5. 状态与数据

- 数据来源：任务/工作流运行时 API + WS 事件（不新增聊天消息）
- 字段：taskId、title、currentStep、steps[{id,name,status,detail,duration}]、status、updatedAt
- 状态：running / paused / waiting_confirm / done / failed / canceled
- 仅在「有活跃长任务」时渲染；刷新后从服务端恢复

## 6. 视觉

- 位置：消息列表底部、Composer 上方，居中列宽（与 780 列一致）
- 背景 surface、1px line、圆角 10、轻阴影；无渐变/重阴影
- 字号：标题 12.5/600、副标题 11.5/灰、步骤 11.5、分组 10.5
- 动效：展开 150–200ms；状态切换不闪烁；尊重 reduced-motion

## 7. 验收与防退化

- 前端 check：`check-task-stack`（出现/隐藏）、`content`、`limit`（≤3）、`expand`、`steps-order`（完成→进行→未完成）、`live`、`detail`、`quick`、`order`
- 截图基线：1600/1180，折叠/展开/多任务/空态 各一张，纳入组件画廊
- 设计门禁：新组件只能使用 tokens；禁止页面内写 hex/圆角/字号
- 组件必须登记到 design gallery；未登记不得在页面使用
