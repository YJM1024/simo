# 任务复杂度分级（Task Complexity C0–C4）

状态：**唯一事实源（2026-11-15 修订；只文档，未实现）**
定位：统一“做多小的动作、要不要建任务/会话、要不要方案消息、要不要确认”的口径；替代旧 K2“所有任务都必须先描述方案”的绝对表述。
关联：[`session-core-spec.md`](session-core-spec.md) K/C 规则、[`tasks/product.md`](tasks/product.md) P4/P5、[`tasks/backend.md`](tasks/backend.md) B3。

> **旧 K2 冲突已解决**：旧 K2 写“所有任务执行前都必须先描述方案”，与 C0/C1 冲突。本修订把 K2 改为按 C 级：**C0 无方案消息；C1 先复述（不等待确认）；C2+ 先方案、C2+ 确认后执行**。任何仍引用“所有任务必须先方案”的旧文案，以本文件为准。

## 1. 分级总表

| 级别 | 名称 | 时长/复杂度 | 父级动作 | 会话/Worker | 消息要求 | 确认 | 执行循环 |
|---|---|---|---|---|---|---|---|
| **C0** | 即时 | 1–2 分钟，单步/无需追踪 | 不建任务 | 不建会话；直接做 | **不复述** | 不需要 | 交互内直接完成 |
| **C1** | 轻任务 | 轻量、可一次完成，但仍需让用户知道在做什么 | 不建正式任务 | 不建正式会话；**fork 临时 Worker** 直接做 | **先发一条复述消息（不等待确认）** | 不需要确认 | 交互内/短异步，结果直接回 |
| **C2** | 任务执行 | 多步/需要追踪/后台执行 | **在当前会话建 1 个正式 Task** | 不建子会话 | **方案消息** | **方案确认后执行** | 执行循环异步，交互循环可继续 |
| **C3** | 子会话任务 | 需要隔离上下文/多轮迭代 | **父级自动建 1 个子会话（不建父级 Task）**；子会话内部可按需建 Task | 子会话可继续增加 | 方案消息 | 父级方案确认后建子会话 | 子会话内迭代；执行循环独立 |
| **C4** | 协作任务 | 多任务/多角色并行 | **父级自动建 3–4 个子会话（不建父级 Task）**；每个子会话内部各自建 Task | 子会话总量不限 | 总方案消息 | 总方案确认后建子会话 | 多智能体协作；执行循环独立 |

补充：

- **C2 才是父级建 Task（当前会话，不建子会话）**；
- **C3/C4 父级只建子会话，不建父级 Task**；Task 在子会话内部按需创建；
- C3 的“1 个子会话”和 C4 的“3–4 个子会话”是父级本次自动创建范围；总量/深度不设产品硬上限，只受同时活跃/预算/速率约束；
- C1 的临时 Worker 是短生命周期执行单元，不是用户可见会话、不进入会话树、不持久化为正式 Task；
- 子会话不是 Task；父会话只维护 `childSessionIds`，不把子会话当任务。

### 1.1 会话/任务关系（引用既有契约）

依据：[`m10-contract.md`](m10-contract.md) §1（第 4、8–10 行）、[`design-core.md`](design-core.md) §1（第 18–21、30 行）。

- **会话 = 容器/工作区/交互视图**；**任务 = 会话内最小执行单元**；
- **一个会话可有 N 个 Task**；Task 属于会话，不是会话的兄弟/子节点；
- **子会话不是 Task**：C3/C4 父级创建的是子会话，不是父级 Task；
- 父会话只维护 `childSessionIds`（子会话关系）；子会话内部各自建 Task；
- Task 可随会话迁移/拆分（迁移时随消息/会话归属）；子会话归档保留，不删除 Task 历史；
- API/数据模型不得把子会话映射成 Task，也不得让 C3/C4 父级伪造 Task 来表达“协作”。

## 2. 各级行为

### C0 即时

- 触发：单步、明确、1–2 分钟内完成、无需追踪/不需要后台；
- 行为：直接执行；**不发复述、不建任务、不建会话**；只回结果/必要说明；
- 适用：读一个值、改一个错字、回答一个已知问题、单条查询；
- 例外：执行中发现需要多步/超过约 2 分钟/产生副作用需追踪 → **升级到 C1/C2**，先发对应复述/方案，不静默继续。

### C1 轻任务

- 触发：比 C0 多一步，但仍可一次完成；需要让用户知道“正在做什么”；不需要正式任务追踪；
- 行为：先发一条**复述消息**（说清要做什么，不等待确认）→ fork 临时 Worker 直接做 → 结果正常回复；
- 不建正式任务/子会话；临时 Worker 受超时/预算限制；
- 失败/超预算：可降级为解释，或升级 C2 建任务（需补方案消息）；
- 适用：整理一段文本、跑一个短脚本、做一次小查询组合。

### C2 任务执行

- 触发：多步/需要后台/需要进度追踪/可能超过短时；
- 行为：在**当前会话**建 **1 个正式 Task**；先发**方案消息**；方案确认后执行；**不建子会话**；
- 交互循环与执行循环解耦：任务异步执行，用户可以继续对话/插话；不要求用户守在消息前等待；
- 适用：普通开发/分析/生成任务。

### C3 子会话任务

- 触发：需要隔离上下文、多轮迭代、独立工作区，但仍是一个父级协作单元；
- 行为：**父级自动建 1 个子会话，不建父级 Task**；父级先发方案、确认后建子会话；子会话内部可按需建 Task；
- 子会话可继续增加；总量/深度不设产品硬上限，只受同时活跃/预算/速率限制；
- 用户可在主会话继续；子会话归档后保留，不删 Task 历史；
- 适用：较长功能/需要独立对话上下文的子任务。

### C4 协作任务

- 触发：多个角色/工作流可并行，需要多智能体协作；
- 行为：**父级自动建 3–4 个子会话，不建父级 Task**；父级先给**总方案**，确认后建子会话；**每个子会话内部各自建 Task**；
- 子会话可继续拆分；子会话总量/深度不设产品硬上限，只受同时活跃/预算/速率限制；
- 适用：多模块并行、调研+实现+验收等。

## 3. 子会话与并发边界

- **总量不设上限、深度不设产品硬上限**：可递归创建子会话；旧子会话**归档保留**，不因数量/层级被自动删除；
- 只限制：**同时活跃数**（按全局/单任务并发配置）、**预算**（token/时间/工具调用）、**速率**（创建/调用频率）；
- 超限行为：排队/拒绝新并发，不静默丢任务；用户可看到原因；
- 归档只影响活跃列表，不删历史/消息/记忆；
- C3/C4 自动建子会话的数量是“本次自动范围”，不是产品上限；用户明确要求可增加，仍受并发/预算约束。

## 4. 消息/状态/循环解耦

- **消息**：C0 无复述；C1 一条复述；C2+ 方案消息；确认/取消/回执按 C 级；
- **任务开始/结束消息**与交互循环解耦：任务开始消息不依赖当前 turn 结束；任务完成可独立结束并汇报，不要求聊天流先结束；
- **执行循环**在 C2+ 可异步进行；用户插话/纠正不应阻塞已在跑的任务，除非显式“停/改”；
- **未确认无副作用**：C2+ 在方案确认前不建 Task/子会话、不执行副作用；C0/C1 本身不需要确认，但高危动作仍按审批规则；
- **C0 无任务/无会话**；**C1 无正式任务/无正式会话**（临时 Worker 不算）；
- 所有等级都不得伪造“已完成”；失败/未执行必须明确。

## 5. 与 K/C 规则映射

| 复杂度规则 | session-core K/C | 说明 |
|---|---|---|
| K1 方案力度 | K1 | 按 C 级：C0 无方案；C1 复述；C2 一句话/完整方案；C3/C4 完整/总方案 |
| K2 方案消息 | K2 | **C0 例外（无）**；C1 复述（不等待确认）；C2+ 方案 |
| K5 执行时机 | K5 | C1 复述后直接执行；C2+ 确认后执行 |
| C1 确认判断 | C1 | C0 直接；C1 复述后直接；C2+ 方案确认；高危仍强制 |
| 任务开始/结束消息 | K5/C9/B3.3/B3.4 | 与交互循环解耦；C2 当前会话 Task；C3/C4 子会话内 Task |
| 子会话 | C3/C4 + B4 | 自动创建；总量/深度不设硬上限，限制活跃/预算/速率 |

## 6. 验收 A1–A10

| # | 场景 | 通过标准 |
|---|---|---|
| A1 | C0 即时 | 不建任务/会话；不发复述；直接做并回结果；1–2 分钟内完成 |
| A2 | C1 轻任务 | 先发一条复述消息（不等待确认）→ 临时 Worker 直接做；不建正式任务/会话 |
| A3 | C2 任务执行 | 建 1 个正式任务；方案消息先于任务/副作用；确认后才执行；不建子会话 |
| A4 | C3 子会话任务 | 父级自动建 **1 个子会话**、**父级不建 Task**；子会话内部可按需建 Task；方案确认后建子会话/执行 |
| A5 | C4 协作任务 | 父级自动建 **3–4 个子会话**、**父级不建 Task**；每个子会话内部各自建 Task；总方案确认后协作执行 |
| A6 | 子会话边界 | 总量/深度不设产品硬上限；旧子会话归档保留；只限制同时活跃/预算/速率 |
| A7 | 用户插话 | C2+ 执行中用户插话不阻塞已跑任务；仅显式停/改才调整；交互循环可继续 |
| A8 | 未确认无副作用 | C2+ 方案确认前不建 Task/子会话、不执行副作用；C0/C1 按级直接，但高危仍审批 |
| A9 | C0 无任务 | C0 不产生 task 记录、不建会话、不写正式任务状态 |
| A10 | B3.3/B3.4 落地 | 任务开始/结束消息与交互解耦；任务完成不依赖消息流结束；有状态/审计证据 |

## 7. 升级/降级

- **升级**：C0 发现需多步→C1/C2；C1 需追踪/多轮→C2；C2 需隔离上下文→C3；C3 需多角色并行→C4。升级前按新级别补消息（C1 复述/C2+ 方案），不静默改变承诺。
- **降级**：仅在没有副作用/任务已结束且用户同意时；C2+→C1 需说明并保留任务记录；不得用降级隐藏失败。
- 任何级别发现高危动作：仍按审批，不因 C0/C1 绕过。

## 8. 反模式

- 把 C0 做成正式任务/发一堆复述；
- C1 等用户确认后才做（错：复述后直接做）；
- C2+ 未确认就创建 Task/子会话/副作用；
- C3/C4 把子会话数量/深度当产品硬上限，或自动删除旧子会话；
- 用“消息流结束”判断任务完成，或用任务完成阻塞聊天；
- 用旧 K2“所有任务必须先方案”套 C0/C1。
