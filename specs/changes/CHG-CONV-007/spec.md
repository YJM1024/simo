## 1. 背景与问题

P1 会话域已经完成建域并签收（12 个 PRD `covered`，33 条 AC `pass`，见 `docs/testing/ACCEPT-CONV-10-20261122.md`）。本包不在这个域上重建任何东西，只在已建成的会话域里补 `PRD-CONV-009` 一项能力，因此变更类型为**增量型变更**。域已存在时读长期 spec、写增量补丁，口径见 `docs/process/PROCESS.md` 第 2 节。

`PRD-CONV-009` 已在产品 spec 定稿：15 条目标行为（`:320-334`），18 条 AC（`:343-363`），场景 I（`:52`），A9（`:377`），状态 `unimplemented` / `gap`（`:395-397`），裁决 ⑧（`:406`）；四项待确认已于 2026-11-23 裁决并写回（`:323`、`:329`、`:336-341`、`:345`、`:357`、`:359`、`:408`）。原型九屏已由用户于 2026-11-23 确认。仓库里已有 B1 parked 的 tasks 模块（`backend/internal/modules/tasks/`，受 `cfg.Modules["tasks"]` 开关控制），提供任务记录、依赖编排、取消与交付物接口；P1 的会话面没有建：消息流没有任务卡片分支，右栏仍是 `PRD-CONV-008` 的只读投影（`frontend/src/components/library.tsx:1097` 的 `OverviewContent`、`:1164` 的 `RightPanel`），没有概览、任务、交付物三标签，没有任务详情与任务图，交付物没有按任务分组的下载入口，18 条 AC 没有断言脚本与 test-plan 用例。

本包与既有工作的边界：

- 执行器与生命周期状态机归 `P2-TASK`（编号不动，当前 parked）；本包只消费其状态，不实现引擎。
- 交付物存储、类型识别与原文件读取归 `P4-FILE`；本包只约束列表、分组、下载入口与字节一致性判据。
- 右栏只读投影 `PRD-CONV-008` 保持有效；本包在其上增加任务专属的标签、卡片、详情与任务图，不改动既有四态与 ETag 行为。

## 2. 目标

1. 让用户从消息流直接看出“这是一个任务”，卡片带 `task_id`，批量发起折叠为一张汇总卡。
2. 让右栏成为任务的操作面：三标签、40px 竖条、角标、概览四节、厚卡与四筛选，收起与展开宽度按判据可测。
3. 让计划与边做边想两种执行模式各有可读的只读详情，步骤、轨迹、时间顺序按模式区分。
4. 让任务之间的并发、串行、三种等待语义、取消级联与任务图状态可被验证。
5. 让任务严格属于发起会话：权限路径越界仍返回 403；跨会话查询与跨会话详情返回 404（不泄露存在性）且不返回任务正文，查询结果为 0 条。
6. 让交付物按任务分组、显示来源与类型、下载得到原文件。
7. 为上述行为建立 18 条自动断言与变更级验收，证据缺失写 `missing`。

## 4. 与 B1-01 的关系：任务卡片消息取代开始消息

`docs/plan/DECISIONS.md:64` 的 B1-01 规定：单任务开始消息取 `role="agent"`、`category="progress"`，带 `task_id`；历史 `messages` 数据不迁移、不补写、不改写。`PRD-CONV-009` 第 4 条把智能体发出的任务消息定为新的消息类型，在消息流渲染为任务卡片。两条规则在“任务开始消息用什么类型”上冲突。

本包按以下口径执行，并在 `docs/plan/DECISIONS.md` 追加 DEC-25 记录这层部分取代关系；DEC-26（`:121`）随后把消息字段写定为可断言口径：

1. 新建任务的开始消息由**任务卡片消息**承载，不再发 `category="progress"` 的开始文本。
2. 任务卡片消息的 `role` 仍为 `agent`，`task_id` 保留且必填；消息流按 `category="task"` 走任务卡片渲染分支。
3. `category` 取 `task`。`PRD-CONV-009` 第 4 条现已写出字面值 `role="agent"`、`category="task"`、`task_id` 必填（`specs/product/P1-CONV/spec.md:323`），DEC-26（`docs/plan/DECISIONS.md:121`）把三项写成可断言口径；本包此处与产品 spec 一致，不再保留「PRD 若补字面值」的待定。
4. B1-01 继续约束两处：历史任务开始消息保持 `category="progress"`，不迁移；任务终态汇报仍取 `role="agent"`、`category="progress"`。
5. 既有四类消息的样式与渲染分支不变；新增第五个类别只影响任务创建消息。

这层关系的直接后果是：同一个任务在数据里可能有一条历史 `progress` 开始消息和一条新的 `task` 卡片消息，两者通过 `task_id` 关联；消息流不为历史消息补卡片，也不删除旧消息。

## 8. 影响、风险与回滚

影响面：

- 消息表增加第五个 `category` 值 `task`，既有四个值的渲染分支不变；历史消息不迁移。
- 右栏在既有投影之上增加三标签与竖条，`PRD-CONV-008` 的四态、ETag 与 304 行为保持不变。
- 新增任务记录、编排关系、归属查询与等待语义的数据结构与接口，均由后端 W2 设计；本包不预设表名与字段名。
- 前端新增任务卡片、右栏任务面板、详情、任务图、交付物列表五组组件与对应测试。

风险：

1. `P2-TASK` 与 `P4-FILE` 未就绪会阻断端到端；W2 先冻结接口桩，W5 再换真实实现，接口变化要回到本文件补口径。
2. 类别值 `task` 已由产品 spec `:323` 与 DEC-26 写定；若后续再改字面值，消息渲染与断言脚本要同步改，不改 AC 编号。
3. 几何判据依赖 CDP 或真机；环境不可用时记 `missing`，不以 jsdom 结果代替。
4. 取消级联的 30 秒窗口与时限的 1 分钟窗口需要可控时钟；用真实等待会拉长回归时间，测试实现要在证据里写明时钟控制方式。
5. 历史 `progress` 开始消息与新 `task` 卡片消息并存，消息流按 `task_id` 去重展示的规则由前端 spec 定义，不能在实现里隐式补卡片。

回滚：

- 文档层按文件 revert。
- 数据层：`category="task"` 的消息与任务记录是新增数据，回滚时保留表、停用写入，不删历史；迁移回滚脚本由 W2 提供。
- 前端层：任务卡片、右栏三标签、详情、任务图、交付物五组组件按卡独立回滚，右栏回退到 `PRD-CONV-008` 的只读投影。
