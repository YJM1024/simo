# CHG-CONV-005 · 未读与通知收口：提案

状态：**blocked**（2026-11-21；缺产品定义，主动停在这里而不是假装推进）
Implements: PRD-SYNC-004、PRD-SYNC-005
Domains: `SYNC`
Owner：产品（必须先定口径）/ 前端 + 后端（待定后实现）；协调：Lead
design.md：N/A —— 方案未定，不能写设计；见 §4 阻塞原因。

## 1. 为什么做

P1 有两个"看起来有、实际上没有"的能力：

- **SYNC-004 未读与已读游标**：产品 spec 写"未读计数/已读游标"，实现只有 `app.tsx` 里的一个内存 `unread`（用于"回到底部 · N 条新消息"按钮）+ tabsync 内存游标广播。**无后端**（`backend/internal` grep `unread|read_cursor` 零匹配），刷新即失，左侧会话列表没有未读徽标。
- **SYNC-005 远程访问与通知中心**：`unimplemented`，`specs/product/P1-CONV/spec.md` 只有一句目标行为，无鉴权模型、无通知渠道、无数据模型。系统当前是 `127.0.0.1:8787` 无鉴权 + 单用户桌面应用，**远程访问与现有安全基线冲突**，需要产品先决策。

本包的价值不是交付实现，而是把"为什么现在不能做、缺什么决策、决策后怎么落地"写成可执行记录，防止后续把"未读"当成小改动塞进别的包。

## 2. 做什么

- 固定现状事实：未读/游标只有前端内存态；后端无表无 API；通知中心不存在。
- 列出两个 PRD 的决策清单与依赖（鉴权模型、数据模型、渠道、隐私）。
- 给出 blocked 的任务卡（明确"等什么"），而不是 todo 的伪任务。

## 3. 不做什么

- 不实现未读表、不实现远程访问、不实现通知。
- 不改产品 spec 的 AC（行为未定义，不能先写实现级 AC）。
- 不改代码/测试/部署。

## 4. 阻塞原因（blocked 的具体条件）

1. **未读口径未定**：是"当前会话徽标"还是"跨会话持久未读"？是否按消息游标还是按会话时间？多标签如何合并？没有答案就无法定数据模型。
2. **鉴权模型缺失**：远程访问必须先有身份/会话/授权模型；当前后端无鉴权（CONV 域 P1 安全基线是"本机单用户"）。加鉴权会波及所有 API，属系统级变更（SYS 域），不是 P1 单包能决定。
3. **通知渠道未定**：桌面通知/站内通知/邮件？离线与隐私要求？无产品结论。
4. **范围冲突**：用户已确认本轮只做会话域收口，P2–P10 冻结；远程访问与通知中心实际上依赖 SYS/权限域，属于跨域前置未就绪。

## 5. 解锁条件（DoR）

- 产品给出 SYNC-004 未读口径（含多标签与已读时机）与数据保留策略；
- 产品 + 安全给出远程访问鉴权模型（或明确"不做"，将 SYNC-005 移出 P1 范围）；
- Lead 确认跨域前置（SYS-001 权限）是否先做。

三项至少前两项完成后，本包才从 `blocked` 转 `draft` 并补 design.md。
