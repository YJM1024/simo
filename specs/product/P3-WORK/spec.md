# P3 · 工作台与视图（产品域 Spec）

状态：**active**（产品域 spec；实现状态逐项标注，不把接口存在当产品完成）
> 产品域：`P3`；技术域码：`WORK`；ID 规则见 [`../../../docs/product/ID-SPEC.md`](../../../docs/product/ID-SPEC.md)。
> 对应测试计划：[`../../test/P3-WORK/test-plan.md`](../../test/P3-WORK/test-plan.md)；功能树：[`../../../docs/product/TREE.md`](../../../docs/product/TREE.md)；追溯：[TRACEABILITY.md](../../../docs/product/TRACEABILITY.md)。

## 1. 目标

把“工作台与视图”从零散接口/旧 FE 规格收敛成可验收的产品能力：明确场景、行为、AC 与实现状态；**未实现的能力标 `unimplemented`，不得写成已完成**。

本域覆盖 5 个 L3 功能点：implemented 3、partial 1、unimplemented 1。

## 2. 非目标

- 不在本 spec 定义具体组件视觉与代码结构；组件契约见 `specs/COMP-*`，变更开发 spec 见 `specs/changes/<CHG>/`。
- 不把后端路由/数据库表存在等同于用户可用；没有入口或没有证据的能力最多算 `partial`。
- 不为本域每个功能点新建独立 spec；功能点在本文档内以 PRD 章节维护。
- 不在本轮修改代码、测试或部署。

## 3. 场景

- S1 入口与导航：用户从工作台与视图入口完成入口与导航相关任务；正常、空、加载、错误与权限不足都必须有可见结果。
- S2 统计与趋势：用户从工作台与视图入口完成统计与趋势相关任务；正常、空、加载、错误与权限不足都必须有可见结果。
- S3 交付物入口：用户从工作台与视图入口完成交付物入口相关任务；正常、空、加载、错误与权限不足都必须有可见结果。
- S4 自定义视图：用户从工作台与视图入口完成自定义视图相关任务；正常、空、加载、错误与权限不足都必须有可见结果。

## 4. 功能点与需求

> 每个功能点包含：PRD、优先级、实现状态、落地前差距、目标行为、AC。目标行为是**产品要求**，不是“已经实现”的声明。

## 5. 验收标准（A1–A8）

| ID | 验收标准 | 适用性 |
|---|---|---|
| A1 | 本域全部 P0 PRD 的主路径可走通，结果与状态一致 | 必验 |
| A2 | 空、加载、错误、权限不足至少各有一条可见反馈，不静默失败 | 必验 |
| A3 | 有 UI 的功能点可用键盘完成主路径，焦点可见；纯后端域标 N/A 并说明 | 有 UI 必验，否则 N/A |
| A4 | 有 UI 的功能点在 375px 宽度不横向溢出、不遮挡主操作；纯后端域 N/A | 有 UI 必验，否则 N/A |
| A5 | 不展示假 0/假成功；未实现/无证据项在界面与文档中明确标注 | 必验 |
| A6 | 权限/隔离类功能默认拒绝，越权路径不因前端隐藏按钮而被视为安全 | 涉及权限/团队/文件必验 |
| A7 | `unimplemented` 项在 TREE/TRACEABILITY/spec 中一致标注，且不被计入 covered | 必验 |
| A8 | 每个 A/PRD 至少映射一个测试用例；当前证据缺失的写 `missing`，不得写“通过” | 必验 |

## 7. 依赖、风险与待确认

- 依赖：`WORK` 的能力必须与现有 FE/COMP/契约一致；冲突时以本 spec 的产品行为为准，并开变更包修正。
- 风险：旧 `docs/tasks/frontend.md` 与后端能力面不一致；本 spec 不把“后端有接口”当“前端可用”。
- 待确认：未实现项的排期与 owner（PRD-WORK-005）。
- 证据：测试计划 [`../../test/P3-WORK/test-plan.md`](../../test/P3-WORK/test-plan.md)；未执行项一律 `missing`。
