# P8 · 设置与系统（产品域 Spec）

状态：**active**（产品域 spec；实现状态逐项标注，不把接口存在当产品完成）
> 产品域：`P8`；技术域码：`SET`、`SYS`；ID 规则见 [`../../../docs/product/ID-SPEC.md`](../../../docs/product/ID-SPEC.md)。
> 对应测试计划：[`../../test/P8-SET/test-plan.md`](../../test/P8-SET/test-plan.md)；功能树：[`../../../docs/product/TREE.md`](../../../docs/product/TREE.md)；追溯：[TRACEABILITY.md](../../../docs/product/TRACEABILITY.md)。

## 1. 目标

把“设置与系统”从零散接口/旧 FE 规格收敛成可验收的产品能力：明确场景、行为、AC 与实现状态；**未实现的能力标 `unimplemented`，不得写成已完成**。

本域覆盖 12 个 L3 功能点：implemented 1、partial 8、unimplemented 3。

## 2. 非目标

- 不在本 spec 定义具体组件视觉与代码结构；组件契约见 `specs/COMP-*`，变更开发 spec 见 `specs/changes/<CHG>/`。
- 不把后端路由/数据库表存在等同于用户可用；没有入口或没有证据的能力最多算 `partial`。
- 不为本域每个功能点新建独立 spec；功能点在本文档内以 PRD 章节维护。
- 不在本轮修改代码、测试或部署。

## 3. 场景

- S1 模型与权限：用户从设置与系统入口完成模型与权限相关任务；正常、空、加载、错误与权限不足都必须有可见结果。
- S2 外观与快捷键：用户从设置与系统入口完成外观与快捷键相关任务；正常、空、加载、错误与权限不足都必须有可见结果。
- S3 数据与能力：用户从设置与系统入口完成数据与能力相关任务；正常、空、加载、错误与权限不足都必须有可见结果。
- S4 安全与备份：用户从设置与系统入口完成安全与备份相关任务；正常、空、加载、错误与权限不足都必须有可见结果。
- S5 运维与安装：用户从设置与系统入口完成运维与安装相关任务；正常、空、加载、错误与权限不足都必须有可见结果。

## 4. 功能点与需求

> 每个功能点包含：PRD、优先级、实现状态、落地前差距、目标行为、AC。目标行为是**产品要求**，不是“已经实现”的声明。
