## 10 条检查

1. **首屏 3 秒理解**：通过。左会话树、中消息、右会话概览/任务，主任务与输入区一眼可见。
2. **单一记忆点**：通过。唯一持续变化的是消息时间轴（聚合横条 + 运行脉冲），其余为静态结构。
3. **字号/间距/圆角层级**：通过。12/13/14/15/16/24；8/12/16 圆角；4px 基准间距；等宽只用于 ID/时间/命令。
4. **无 AI 模板特征**：通过。冷白+电光蓝（非暖米/赤陶）；无全站卡片墙/统一软阴影；无每块 fade-in；等宽不装技术感。
5. **375 无横向滚动/截断**：通过。360px 实测 `scrollWidth == clientWidth`（index / workbench / gallery 三页均通过）。
6. **Tab 顺序与焦点**：基本通过。交互元素均为原生 button/a，`:focus-visible` 有 3px 焦点环；时间轴支持 ↑/↓/Enter。完整 Tab 走查需在浏览器手动确认（原型未做焦点陷阱）。
7. **hover/active/focus/disabled 四态**：通过（组件画廊展示；按钮/输入/任务行/卡片已实现）。loading 态在画廊以"处理中…"示例展示。
8. **空/加载/错误三态**：通过。空态（`?state=empty`）、Skeleton、错误框在画廊；页面空态有明确下一步。
9. **文案**：通过。按钮为动词（确认并执行/取消/重试/归档会话），空态给下一步，无"赋能/一站式"套话。
10. **无重叠/溢出/低对比度**：通过（截图与量测）。注意：任务栈展开会压缩消息可视区，非覆盖；如生产需要可改为浮层锚定。

## 量测证据（本机 Chrome，file://）

- `360px`：index / workbench / gallery 均 `scrollWidth == clientWidth == 360`。
- 页签稳定性：`index.html` 与 `workbench.html` 的 `.tabs` 左边界均为 `x = 408`（面包屑固定 136px）。
- 时间轴：`4` 个聚合 turn（父 2 + 本会话 2），横条与消息垂直对齐；点击可定位；`?top=1` 显示父会话分隔线。
- 卡片确认：点击后 `#sourceCard.is-done = true`，消息数 +1，Toast = "已确认，后台任务已开始"。
- 任务栈：点击第一张卡后步骤区可见（`hidden=false`），三组步骤齐全。
- 画廊：`.gmain.scrollTop` 可到 1400，左侧导航 active 随滚动更新（"徽标 / 状态"）。
- 375 / 768 / 1280 / 1440 / 1600 截图均无元素重叠或截断（见上表）。

## 停止判据

- 本轮已完成"设计稿 → 组件 → 页面 → 截图"闭环；剩余为**生产接入**（真实 API/WS、错误恢复、真实流式、键盘全流程、深色/主题），不是原型微调。
- 按 skill 的停止判据，不再做像素级微调；上述生产项列入下一阶段。

## 未验证 / 风险

- 未在真实 React/Tailwind 工程内验证，仅静态原型；组件拆分与 token 映射需在实现阶段确认。
- 未接真实数据与 WebSocket；流式、断线重连、任务状态同步、卡片幂等未实测。
- 父会话回溯仅视觉与滚动定位；真实拉取/合并消息需 API 支持。
- 1024–1100 折叠区间只做了 CSS 断点，未逐档截图。
- 无障碍：对比度按 token 计算达标，但未跑 axe/Lighthouse；焦点陷阱与读屏标签需实现阶段补。
