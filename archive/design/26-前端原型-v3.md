# 司墨前端原型 v3 · 设计计划（design-first）

> 状态：**待确认**。本文件是 v3 的唯一风格来源；确认前不改生产前端。
> 取代：`DESIGN.md` v2（纸张 + 墨 + 靛蓝）与 `frontend/prototype/` 的视觉基线。
> 依据：用户 2026-11-11～11-12 的原话（下文引用）+ `docs/visual-language.md`（M62 浅色科技风）+ `docs/task-stack-component.md` + `docs/m41-card-contract.md`。

## 1. Brief

- **产品**：司墨（simo），本地单用户 AI 秘书；Go 单体 + 本机 Web。
- **受众**：一位长期使用者，桌面 1280–1600 为主；375 只保证可读可用。
- **本轮唯一主任务**：在一个会话里持续对话，同时看清"会话结构 + 消息进展 + 后台任务"。
- **成功标准**：打开 3 秒内知道在哪个会话、消息到哪、后台在跑什么、输入框在哪；切换会话/页签时布局不位移；时间轴可扫读、可跳转；右栏概览与任务列表和消息一致。
- **范围**：对话页、工作台页、组件画廊。任务/智能体/团队/记忆页本轮不做（用户 11-12 明确先收起）。
- **技术栈**：原型用原生 HTML/CSS/JS（无依赖）；确认后用 React 19 + TS + Tailwind 4 落地。

## 2. 为什么 v2 不行（根因）

1. **视觉方向偏离用户 M1 决策**：用户明确"默认浅色科技风/未来感，浅底、冷色点缀（电光蓝/青）、细边框、轻玻璃感"；v2 用了暖纸 `#FAF9F6` + 靛蓝 `#3D3DE0`，整体像文档工具，不是科技工具。
2. **布局是"居中聊天"而不是"工作台"**：页签居中、聊天列居中，左右两条大留白；切页签时面包屑宽度变化带着页签位移。
3. **时间轴是逐条消息的装饰**：没有聚合、没有缩略预览、没有父会话语义；窄、间距大，扫读成本高。
4. **右栏信息不完整**：只有概览，没有任务列表；后台任务无处可见，只能靠消息流猜。
5. **组件没有单一来源**：token 之外还有页面级魔数，导致"原型好好的，一用就退化"。

## 3. 视觉方向：冷光工作纸（Light Tech, quiet）

一句话记忆点：**一条会呼吸的消息时间轴**——冷白画布上唯一持续变化的东西是轨道上的聚合横条与运行中的青色脉冲；其余全部安静。

- 冷色浅底、白面板、1px 冷灰线；电光蓝只做选中/焦点/进度，青色只做"正在运行"，紫只出现在品牌标记与页签下划线渐变。
- 页面顶部一层极淡三色径向氛围（蓝 5.5% / 紫 4.5% / 青 3.5%），只做氛围，不进入卡片/正文。
- 不用大面积渐变、不用发光、不用玻璃卡片墙；玻璃只用于顶栏（轻模糊）。
- 布局左对齐、密度偏紧凑（4px 基准），信息靠分隔线与留白分层，不靠卡片堆。
- 刻意避开 AI 模板：无暖米色、无衬线大标题、无 `01/02/03` 装饰编号、无每块 fade-in。

### 3.2 字体与字号

- 无衬线：`"Segoe UI Variable Text", "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`
- 品牌/大标题：`"Segoe UI Variable Display", "Segoe UI", ...`（不用衬线，避免"文档感"）
- 等宽：`Consolas, "Cascadia Mono", monospace`，只用于 ID/token/命令/时间轴日期
- 阶梯：12 / 13 / 14 / 16 / 20 / 24（正文 14、辅助 13、元信息 12；不用 10/11）
- 行高 1.65 正文；1.3 标题；数字 `tabular-nums`；字重 400/500/600，无 700。

### 3.3 间距 / 圆角 / 阴影

- 间距：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64；三栏 gutter 16。
- 圆角：控件 8、卡片/面板 12、浮层 16；同容器不套两层圆角。
- 阴影：`--shadow-sm` 只给输入区/浮层/任务栈；列表不使用阴影；顶栏用 1px 线与轻模糊。

## 5. 关键组件规格

### 5.1 时间轴 TimelineRail（本轮重点）

- 轨道 44px；横条 30×14px（6px 用户段 + 1px gap + 6px 司墨段），当前条 34px 并带 2px 蓝色左边线；横条与其所属 turn 的第一条消息**垂直对齐**，滚动时随消息一起移动（不是悬浮缩略图）。
- **聚合规则**：一条用户消息 + 其后连续的司墨消息 = 一个 turn 条；无用户开头的司墨消息单独一条。仅两种角色。
- 悬停：右侧 280px 预览卡（角色 · 时间 · 首 60 字 · 司墨回复条数）；点击平滑定位并闪一下消息。
- 父会话：条与条之间插入 20px 间隔 + 横向短刻度 + `↑` 图标；消息列表对应一条带标签的横向分隔线；点击分隔线加载父会话消息（可逐级）。
- 日期：只在跨天处出现 9px 等宽日期，不每屏重复。
- 键盘：↑/↓ 移动，Enter 跳转；`aria-current` 标记当前条。
- 隐藏条件：<900 宽、空会话（显示空态引导）。

### 5.2 右栏 Inspector

- **会话概览**（只读）：当前会话、模式（主窗口/子会话·深度 N）、消息（总/你/司墨）、模型 V4.1 Flash、上下文占用（细进度条 + 百分比/上限）、交付物数。
- **任务列表**：只放执行任务（不含会话）。每行：状态点 + 标题 + 当前步骤 + 耗时；点击行内展开步骤（完成/进行/待办三段）；空态"当前没有后台任务，长任务开始后会出现在这里"。
- 两个区块之间 12px 分隔线；右栏独立滚动；数据来自 API，无假数字（原型为演示数据，页面角落标注）。

### 5.3 TaskStack 悬浮任务概览

- 位置：消息列底部、Composer 上方，同宽 840；不覆盖最后一条消息。
- 折叠：最多 3 张卡（标题 13/600、副标题 12、状态 + 耗时、左侧 2px 青/蓝条），>3 显示"还有 N 个任务"；点击"展开"打开第一个任务的步骤。
- 展开：手风琴，只展开一个；步骤三段（已完成 ✓ / 进行中 ● / 未完成 ○），内部滚动 max 40vh；再点收起。
- 无活跃任务：整个组件隐藏（不是空卡）。
- 动效：展开 180ms；运行中状态点 1.6s 脉冲；`prefers-reduced-motion` 关闭。

### 5.4 交互卡片 InteractionCard

- 结构：标题 + 状态（进行中/已确认/已取消/失败 + 版本）+ 说明 + 选项（单选行，不是原生 select）+ 底部"取消 | 确认"。
- 未选时确认禁用并说明原因；确认后卡片变"已确认"，选项只读，并**新增一条系统/司墨消息**："已确认：…，开始执行。"
- 取消同样产生一条消息；失败保留已选值并可重试（M41 幂等语义）。
- 卡片支持 options / 输入 / 确认三种形态的视觉容器统一；fallbackText 始终存在。

### 5.5 消息与父会话分隔

- 双方左对齐、无气泡；24px 方形 monogram（用户 ink，司墨渐变描边）+ 12px 元信息（名字 · 会话标签 · 时间）+ 14/1.65 正文。
- 上级会话消息：左缩进 16px + 2px 竖线 + "主会话"标签；分隔线通栏，文案"以上来自上级会话 · 主会话（2026-11-11）"，右侧"回到当前会话"。
- 悬停操作：复制 / 引用 / 重试（图标 + tooltip），不长期占位。

### 5.6 页签与顶栏

- 面包屑固定 136px（超长省略），页签从固定 x 开始：`对话`、`工作台`；32px 高、active 2px 渐变下划线；右侧：运行状态 pill（"1 个任务运行中" + 脉冲点）、连接、权限 pill、搜索、通知、头像。
- 页签切换只换内容，不移动自身；面包屑文本变化不影响页签位置。

### 5.7 侧栏会话树

- 248px；主会话 + 子会话（缩进 14 + 1px 竖向导引线 + 层级点）；运行中点脉冲，未读数字；置顶/重命名/归档在 hover 出现；搜索过滤；底部用量与用户。
- 会话与任务严格分离：任务不进入会话树。

## 6. 状态 / 动效 / 可访问性

- 必备状态：hover / active / focus-visible / disabled / loading；空/加载/错误三态；流式中；断线；卡片已确认/已取消/失败；任务运行/暂停/等待确认/完成/失败；右栏空。
- 唯一编排时刻：切换会话时消息列 160ms 淡入一次（只一次）；其余为用户触发（hover 120ms、展开 180ms、弹窗 140ms）。
- 焦点环 3px `rgba(47,91,255,.28)`；Tab 顺序：侧栏 → 顶栏 → 上下文 → 时间轴 → 消息 → 任务栈 → 输入 → 右栏；`prefers-reduced-motion` 全关。
- 对比度：正文 ≥ 4.5:1；元信息 ≥ 3:1；焦点环可见；触控目标 ≥ 40px（移动端）。

## 7. 自检（对照 ai-tells.md）

| 命中 | 处理 | 理由 |
|---|---|---|
| 暖米色 + 衬线 + 赤陶 | 改为冷白 + 无衬线 + 冷色点缀 | 用户明确浅色科技风 |
| 统一圆角卡片 + 软阴影 | 列表用分隔线，只有浮层/任务栈用阴影 | 层级靠结构与留白 |
| 顶部 nav + hero + 三列营销骨架 | 工具型 AppShell，无 hero | 产品是工作台 |
| 每块 fade + slide | 只保留切会话一次 | 减少噪音 |
| 等宽装技术感 | 等宽只用于 ID/时间/命令 | 真实需要 |
| 蓝紫渐变铺满 | 渐变只在品牌标记与页签下划线 | 状态/身份语义 |

## 8. 验收计划

- 档位：1600 / 1440 / 1280 / 1024（折叠）/ 375；每档截图存 `archive/prototypes/prototype-v3/review/`。
- 必过：无横向滚动；页签在切页时不位移（量 x 坐标）；时间轴条数=turn 数（不是消息数）；父会话分隔线可点；任务栈无任务时隐藏；卡片确认后出现消息；右栏任务与消息状态一致；键盘可走完主流程；对比度达标。
- 浏览器：本机 Chrome/Edge；不引入外部字体/图标/CDN。

## 9. 实施顺序（确认后）

1. tokens + 基础组件 + 画廊（本原型）；
2. AppShell / Sidebar / Topbar / ContextBar；
3. TimelineRail + MessageList + ParentDivider；
4. InteractionCard + TaskStack + Composer；
5. Inspector（概览 + 任务）；
6. 工作台；
7. 接真实 API/WS、删除演示数据；
8. 全档位截图 + REVIEW.md + 验收。

## 10. 待确认的假设

1. 用 **浅色科技风（冷白+电光蓝/青）** 取代 v2 的暖纸+靛蓝；如需保留纸张感，只换 token 值，不动结构。
2. 本轮先做对话/工作台/画廊三页，任务/智能体/团队/记忆页后面再加。
3. 时间轴按"turn 聚合"而不是逐条消息；父会话回溯先做视觉 + 点击定位，真实拉取走 API。
4. 右栏任务列表只放后台执行任务，不放会话；任务详情在行内展开，不做独立页。
