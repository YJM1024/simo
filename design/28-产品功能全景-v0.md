# 28 · 产品功能全景 v0（功能树 × 六视图 × 场景包）

> **状态**：产品功能讨论稿 v0（2026-11-18）。**只写产品功能，不写实现设计。**
> **已被取代**：全量补全版见 [30-产品功能全景 v0.1](30-产品功能全景-v0.1.md)（135 个产品功能 + 35 个横切功能 = 170 个功能点）；本文保留为 v0 历史稿。
> **目标**：按你的要求“**先求全、后排序**”——把系统要实现的功能**完整**列出来，再用六种拆法交叉校验，最后留优先级框架；不急着排版本。
> **与 27 的关系**：[27-多智能体协作与自主能力-方案v1](27-多智能体协作与自主能力-方案v1.md) 是系统设计稿（目前完成架构与数据绑定，协作/自治/万级章节待补）；本文是它的**产品功能投影**，不依赖其实现细节。
> **用法**：Part A 是**唯一功能清单**（每个功能有 ID，后续文档只引用 ID）；Part B 是**六种视图**（同一批功能的不同切法，不重复定义）；Part C 是**场景包**（功能的组合模板）；Part D 是**覆盖检查**；Part E 是**优先级框架**（先给方法，不排死）。
> **标记**：`P0/P1/P2` 仅为**候选档位**，最终以 Part E 的排序结果为准；横切能力（X1–X5）是规模化/企业化才需要的能力组。

---

## 0. 一分钟读法

1. **功能树 = 10 个产品能力域 + 5 个横切能力**，共约 100 个功能点；每个功能有唯一 ID（`F1.1`、`X1.1`）。
2. **10 个域**回答“它有哪些能力”；**六种视图**回答“从不同角度看是否漏了”；**场景包**回答“拼起来能不能用”。
3. **本次补强了三块**：输入与感知（多模态）、行动与交付（工具/产物）、学习与适应（反馈/经验）；还补了组织、可靠性、安全、商业化、生态五个横切能力。
4. **场景不是功能**：设计协作、客服运营、研发、销售等是“场景包”，挂在扩展能力下，不塞进功能树。
5. **优先级后置**：Part E 只给排序维度和候选档位，等你确认全景后再排版本。

## 0.1 产品目标摘要（与功能树的关系）

- **定位一句话**：给“被外部事件和跨角色协作淹没”的团队，一个能自己接事、自己规划、自己找人协作、并且记得住的组织级数字员工——从事件发生，到结果被验收。
- **北极星（建议）**：每周被**可靠接管**的端到端任务数（可靠 = 验收通过 + 无返工 + 预算内）。
- **产品承诺（8 条）**：接得住、记得住、想得到、干得成、会合作、懂分寸、可追责、用得起。
- **功能树的位置**：这 8 条承诺靠 Part A 的 10 个能力域 + 5 个横切能力落地；Part B 用来查漏，Part C 用来验证组合。

## 1. 使用原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | **全量覆盖** | 先求全，再求序；宁可多列，后续再裁 |
| 2 | **一个功能一个 ID** | 视图只引用 ID，不另起清单；避免“六个版本互相打架” |
| 3 | **功能 ≠ 场景** | 场景包是组合模板，不占功能 ID |
| 4 | **功能 ≠ 实现** | 这里只写“系统要能做到什么”，不写怎么做到 |
| 5 | **每个功能可感知** | 每个功能补一句“用户能感受到什么”，避免自嗨 |
| 6 | **优先级可后置** | 先画全，再按价值/依赖/风险/成本排序 |

# Part A · 功能清单（Canonical Inventory）

## A.1 产品能力域（10 个）

### 1. 输入与事件（Input & Events）

**目标**：让系统接得住所有外部输入，并把它们变成“有归属、有状态、有下文”的事件。

| ID | 功能 | 系统要做到什么 | 用户可感知 |
|---|---|---|---|
| F1.1 | 多源接入 | 接消息、邮件、工单、评论、日程、告警、Webhook、第三方系统事件 | “所有渠道的事它都能收到” |
| F1.2 | 多模态解析 | 读懂文本、语音、图片、文档、表格、网页、截图 | “发图、发文件、发语音它也能处理” |
| F1.3 | 归一与去重 | 同一件事合成一个事件，带上下文、实体、优先级 | “同一件事不会被问三遍” |
| F1.4 | 分诊与路由 | 判断要不要处理、谁处理、什么时候处理 | “它知道什么事该找谁” |
| F1.5 | 归属与状态 | 每条事件有负责人、状态、截止、依赖 | “我知道每件事现在到哪了” |
| F1.6 | 处理闭环 | 接单 → 响应 → 执行 → 结果 → 验收，全程可追踪 | “事情有始有终” |
| F1.7 | 异常与升级 | 超时、失败、高风险自动升级给人或上级 | “卡住了会喊人，不装死” |
| F1.8 | 事件视图与检索 | 收件箱、时间线、筛选、搜索、聚合统计 | “一眼看到所有事” |

### 2. 自主推进（Autonomy & Initiative）

**目标**：不等指令也能发现“该做什么”，并自己往前推——但始终在授权与预算内。

| ID | 功能 | 系统要做到什么 | 用户可感知 |
|---|---|---|---|
| F2.1 | 目标管理 | 目标、成功标准、优先级、截止时间、约束 | “我说一次目标，它一直记着” |
| F2.2 | 主动发起 | 定时、目标停滞、异常、机会、外部订阅 → 自己开任务 | “它会自己找活干” |
| F2.3 | 自主执行 | 在任务内自己决定下一步、自己推进 | “不用我一步步指挥” |
| F2.4 | 反思与自检 | 做完复盘：哪里对、哪里错、下次怎么改 | “它会吃一堑长一智” |
| F2.5 | 请示与停手 | 不确定、高风险、缺授权时停下来问 | “该问的时候它会问” |
| F2.6 | 自主等级与开关 | 按域设置 L0–L3，随时暂停/恢复/降级 | “我能控制它多主动” |
| F2.7 | 注意力与多目标 | 多目标排序、打断、让路、避免同时铺太开 | “它知道先做哪件” |
| F2.8 | 机会发现（P2） | 发现未知、缺口、新信息带来的机会 | “它会提醒我没想到的事” |
| F2.9 | 自主策略配置 | 内驱组合、频率、静默时段、升级规则 | “我能调它的性格” |

### 3. 规划、执行与交付（Planning, Execution & Delivery）

**目标**：把目标变成可执行、可调整、可交付、可验收的结果。

| ID | 功能 | 系统要做到什么 | 用户可感知 |
|---|---|---|---|
| F3.1 | 任务拆解 | 目标 → 任务 → 步骤，粒度可执行 | “再大的事它也能拆” |
| F3.2 | 计划表达 | 依赖、里程碑、并行/串行、预算、风险 | “我能看到它打算怎么做” |
| F3.3 | 工具与行动 | 浏览器、代码执行、API、文件、第三方系统操作 | “它真能动手，不只给建议” |
| F3.4 | 执行跟踪 | 状态、进度、产物、日志、耗时 | “做到哪了我随时知道” |
| F3.5 | 重规划 | 阻塞、新信息、失败 → 改计划而不是死磕 | “路走不通它会换路” |
| F3.6 | 中断与恢复 | 暂停、人接管、继续、崩溃恢复 | “停了还能接着做” |
| F3.7 | 产物与交付 | 文档、表格、PPT、图、代码、邮件、链接 | “能直接拿走用” |
| F3.8 | 验收与证据 | 自检、独立验收、证据链（测试/对比/引用） | “说完成就真完成” |
| F3.9 | 汇报 | 进展、卡点、下一步、结论，分层可展开 | “汇报像人话，不是流水账” |

### 4. 多智能体协作（Multi-agent Collaboration）

**目标**：按需组队，分工、协作、评审、汇总；不是“一群 Agent 聊天”，而是“一件事被更好地完成”。

| ID | 功能 | 系统要做到什么 | 用户可感知 |
|---|---|---|---|
| F4.1 | 角色定义 | 职责、能力、边界、人格、工具 | “每个角色干什么很清楚” |
| F4.2 | 团队模板 | 角色组合、汇报关系、继承规则 | “能一键组一个团队” |
| F4.3 | 派工 | 选谁、为什么、预算、优先级 | “它知道该找谁、为什么” |
| F4.4 | 协作模式库 | 委派、流水线、评审、辩论、投票、黑板、市场、群体等 | “不同的事用不同干法” |
| F4.5 | 协作会话 | 线程、状态、协议、轮次、参与者 | “协作过程我能看” |
| F4.6 | 交接与升级 | handoff、escalation、责任转移 | “换人/升级不掉链子” |
| F4.7 | 汇总 | 结论、产物、未决项、证据、分歧 | “不用我自己整理” |
| F4.8 | 协作边界 | 轮数、时长、成本、扇出、收敛检测 | “不会聊到天荒地老” |
| F4.9 | 团队视图 | 谁在做什么、进度、阻塞、成本 | “团队状态一目了然” |
| F4.10 | 协作质量与归因 | 评审通过率、返工、谁提的/谁批的 | “出了问题找得到人” |

### 5. 记忆与学习（Memory & Learning）

**目标**：记得住、找得到、改得动、忘得掉；并从反馈与经验中变好。

| ID | 功能 | 系统要做到什么 | 用户可感知 |
|---|---|---|---|
| F5.1 | 记忆写入 | 对话、事实、决策、偏好、经验、任务状态 | “说过的事它记着” |
| F5.2 | 记忆读取 | 按人、项目、任务、时间、语义召回 | “它能在对的时候想起对的事” |
| F5.3 | 记忆分层 | 个人/团队/组织；短期/长期；工作/情景/语义/规范/程序 | “该记的记，该忘的忘” |
| F5.4 | 记忆纠错 | 用户纠正、冲突标记、遗忘、回滚 | “记错了能改” |
| F5.5 | 记忆可见 | 用户能看、能查、能导出 | “它记得什么我能看见” |
| F5.6 | 记忆隔离 | 敏感信息不跨域、跨域只读、权限控制 | “我的事不会串给别人” |
| F5.7 | 学习与适应 | 从反馈、纠错、复盘中提炼偏好与经验 | “越用越懂我” |
| F5.8 | 遗忘与保留 | TTL、归档、合规删除、冷热分层 | “该忘的能忘掉” |
| F5.9 | 知识库与检索 | 文档、知识、规范、案例的入库与检索 | “团队知识它能查到” |

### 6. 人机协作与分寸（Human-Agent Interaction）

**目标**：像一位靠谱同事——该说说、该问问、该停停，不刷存在感。

| ID | 功能 | 系统要做到什么 | 用户可感知 |
|---|---|---|---|
| F6.1 | 对话与指令 | 自然语言、多轮、打断、纠正、追问 | “沟通像跟人说话” |
| F6.2 | 请示与审批 | 高风险/不确定时给选项、给建议、等人拍板 | “大事它不擅自决定” |
| F6.3 | 接管与交回 | 人随时接手、处理完再交回 | “我随时能插手” |
| F6.4 | 打扰预算 | 频率、级别、静默时段、聚合通知 | “不烦我” |
| F6.5 | 汇报风格 | 自然、要点、分层、可展开、可追溯 | “汇报读得下去” |
| F6.6 | 人格与语气 | 角色一致性、多角色切换、语气适配 | “像同一个人，不是精神分裂” |
| F6.7 | 多模态交互 | 语音、图片、文件、富文本、屏幕共享 | “怎么方便怎么来” |
| F6.8 | 反馈与纠错 | 评价、纠正、满意度、投诉 | “我说不好它能改” |

### 7. 信任、安全与治理（Trust, Safety & Governance）

**目标**：敢把事交出去——每个动作可解释、可审计、可回滚、可叫停。

| **P0-B 自主** | F2.1–F2.7、F3.1–F3.9 | “像同事”的核心：会推、会拆、会交付 |
| **P0-C 协作** | F4.1–F4.10 | 按需组队；前两步不稳时不建议先做 |
| **P0-D 底线** | F6.1–F6.4、F7.1–F7.4、F9.1–F9.2 | 没有分寸/审计/叫停/预算，不敢上线 |
| **P1** | F2.9、F5.7–F5.9、F6.5–F6.8、F7.5–F7.8、F8.1–F8.5、F8.7、F9.3–F9.6、F10.1–F10.4、X1 | 长期用、团队化、商业化 |
| **P2** | F2.8、F8.6、F10.5–F10.6、X2–X5 | 规模化、生态、差异化；企业化时 X2/X3 可提前 |

## E.3 排序原则

1. **先闭环，再增强**：P0 必须能跑通“事件→自主→规划→交付→验收”一条线；
2. **安全底线不后置**：审计、叫停、预算即使属 P1 域，也建议随 P0 一起做；
3. **协作不先做**：多 Agent 是成本放大器，前两步不稳时组队会放大混乱；
4. **场景包不缩功能**：POC 可以只跑一个场景，但功能树不因场景砍掉；
5. **优先做“可验收”的功能**：能证明好坏的功能，优先于“听起来很酷”的功能。

# Part F · 非目标与开放问题

## F.1 非目标（本阶段）

- 不做通用问答/搜索产品；
- 不做纯 workflow/RPA 搭建器（但必须能接进流程）；
- 不做无边界自主、不替代人做高风险决策；
- 不把“多 Agent 群聊”当卖点；
- 不做 AGI、不做意识/情感承诺；
- P2 前不做插件市场、跨组织 A2A、多租户计费。

## F.2 开放问题（需要拍板）

1. **产品形态**：个人助理 / 团队数字员工 / 平台？三者功能取舍不同。
2. **多用户/组织**：X1 是 P0 还是 P1？决定要不要先做席位/权限/汇报关系。
3. **第一个场景包**：C1 设计协作 / C2 客服运营 / C8 个人助理？
4. **自主等级承诺**：对外承诺到 L2 还是 L3？
5. **交付与计费**：本地/云、席位/按任务/按结果？
6. **“像真人”的边界**：哪些动作必须人批？哪些可以自动？
