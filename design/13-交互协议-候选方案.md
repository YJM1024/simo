# 交互协议 v1.0.3 —— 候选方案（讨论中）

> **状态**：供讨论的**候选方案**，**不是定稿**；只写设计，不写代码。
> **日期**：2026-11-03（**v1.0 = 用户 2026-11-03 连续拍板后的增补**）
> **方案名**：**连续步进 + 三速响应 + 语义段抢占检查点 + 撤回重答 + 中断点可恢复**。
> **版本**：v1.0.3（本稿）= v1.0.2 +「**发消息不打断后台工作**」（对话回路 / 执行回路分离；默认并行，仅显式修正才抢占；撤回只作用于流式对话回复，不作用于后台任务）；变更摘要见下方。
> **依据用户拍板——基础（v0.2 已成立，原话见 [`10-设计对话记录.md`](10-设计对话记录.md) 第 7、9、10 节）**：
> 1. 用户随时发消息、agent 随时实时应答；**不要一问一答**，**不要用户可感知的消息队列**；
> 2. 打断要**智能调整**（不是"立刻停/说完再处理"二选一）；用户会持续发，系统要持续处理；
> 3. 反应必须**比较快**——可给数字（§13），但不能"做完手头事再回应"；
> 4. 上下文**实时**，不是快照；
> 5. **用户永远只跟秘书说话**，点子任务只是把「当前子会话」切过去，不是换对话对象。
> **依据用户拍板——本轮（2026-11-03）**：
> 1. 【**撤回**】流式输出中被打断：**撤回未完成的回复**，看完最新消息再回复；**已完成的消息不撤回**。
> 2. 【**调整执行**】一条新消息会改变"正在做的事"时：**调整这件事的规划与执行方法**，不是把旧的做完再说。
> 3. 【**中断点**】把当前现状写下来：做到哪、为什么换方式、新方案是什么，**可恢复**——不只是存一段草稿文本。
> 4. 【**歧义**】真歧义**先确认再执行**；但**琐碎、可逆、自己能决定的事不要问**——自己定并说明；自己决定不了的才让用户定，或先解释清楚。**不猜。**
> 5. 【**长任务**】长任务应**划分阶段**；界面**三栏**，最右边显示当前正在执行的长任务，点开可看执行到哪一步、哪些已完成、哪些还在执行（视图见 [`14-总体设计-v1.md`](14-总体设计-v1.md) §5）。
> 6. 【**人格**】以上属于 Agent 的**整体思路 / 人格 / 执行原则**，不是框架问题（总述见 14 §8）。
> 7. 【**撤回呈现**】撤回的消息在对话历史里**只显示"已撤回"标记，不展示被撤回的具体内容**；后台审计日志可保留，但不进入对话。
> 8. 【**调整 vs 重做**】用户认可这条界线：**目标/关键约束变 → 重做；细节变 → 调整**。
> 9. 【**右栏**】不是"最活跃的一个任务"，而是**长任务列表页**（执行中 + 已完成），选中看详情、列表项可内联展开、细看单独开窗（视图见 14 §5.2）。
> 10. 【**术语统一**】只用「**会话 / 子会话**」；**不再用"副会话 / 子视图 / 线程 / 焦点"**这些说法；需要表达"正在看哪个"时用「**当前会话 / 当前子会话**」。
> 11. 【**V1 会话固定**】会话结构**不可拆分、不可合并**；**可以改名，改名纯显示、无任何语义影响**；灵活调整留到 P1。
> 12. 【**标签**】V1 **暂不引入标签**（待用户最终确认）；标签定义（贴在会话上的分类属性，用于分组/筛选，不改变结构与可见范围）只作为 **P1 候选**记在 14 附录。
> 13. 【**记忆可见性**】V1 记忆对用户**可见但只读**（记忆页：列表 + 作用域 + 来源 + 时间）；**不提供直接编辑控件**，修改一律通过"跟秘书对话"完成。
> 14. 【**产物**】V1 要**文件预览 + 下载**（长任务/汇总的产物条目带预览与下载入口）。
> 15. 【**通知**】只做**站内提示**（顶栏/任务面板），**不做浏览器通知/声音**；与打扰预算合并。
> 16. 【**主窗口与消息显示模型**】每条消息**归属唯一**（属于一个会话/子会话），**主窗口不是归属容器**；任意会话节点可选「**仅本会话消息**」或「**本会话 + 所有递归子会话消息（按时间展开）**」；**主窗口 = 根节点的聚合视图**（含全部子会话）；同一渲染规则**逐层递归一致**；**向上同步 = 祖先聚合视图的自然结果**，不需要单独的"转发/同步"机制（只显示摘要属 P1）；消息上展示**归属会话标签**，点击可跳转。用户 2026-11-03 已确认。
> 17. 【**会话生命周期**】会话/子会话 = **长期里程碑**（可含多个任务；**没有自动完成 / 超时关闭**；可长期空闲后接着做，状态不丢）；生命周期状态：**进行中 / 空闲（长期无活动，保留）/ 已归档（可选，非必须）**；**是否停止由用户决定**；父会话可随时查看子会话状态（进度、未决）。用户 2026-11-03 已确认。
> 18. 【**交付机制已取消：父会话按需取用 + 对话验收**】父会话通过**聚合视图**查看子会话消息；需要文件/产物时，用户在父会话对秘书说"**去子会话看看，把相关文件拿出来**"，秘书**按需取用**。**验收走对话**：接受 / 不接受 / 改需求都用对话表达，**不引入验收按钮或状态机**；**不再有自动推送与独立验收状态**。会话**没有"关闭"**，**归档可选、不是必须动作**。**任务列表只放执行任务，会话不出现在任务列表**。用户 2026-11-03 已确认。
> 19. 【**归档与跨会话取用**】**归档后 = 只读查看**（不能继续聊）；**默认允许取消归档 / 恢复**（技术实现细节标"待实现确认"）。**跨会话取用**：秘书可直接查看子会话消息、处理对应文件，**就像在自己会话里一样**；**不复制文件到父会话**，按引用 / 原地处理。**"按需取用 + 对话验收"是 V1 的一等能力**。用户 2026-11-03 已确认。
> 20. 【**Spec 不可见原则（用户 2026-11-06 已确认）**】内部 Spec（需求真相）**永远不进入用户可见文本**：不出现"Spec / 规格 / 需求文档 / 验收标准 / 基线 / 增量"等词汇；所有 Spec 操作**投影为自然对话**（见 §11.9 映射表）。**只有三类情况打扰用户**：风险门（不可逆/动线上/删数据/花钱/影响他人）、真歧义（影响大）、用户主动要求；其余内部自己过门。**内部状态机/证据绑定不因此取消**（18 §5）。
> 21. 【**发消息不打断后台工作（用户 2026-11-06 已确认）**】用户发消息 → 秘书**即时回复** + 视需要**派发新任务**；**正在进行的任务继续跑，不取消、不暂停**。只有**显式修正/停止**（"别做 X / 停掉 / 改成 Y"）才 steer/cancel。**两条回路分离**：**对话回路**（始终可用、不等任务）与**执行回路**（后台任务/子智能体独立推进、完成回流）。**撤回只作用于流式未完成的对话回复，不作用于后台任务**；资源约束靠**并发上限/预算**，不靠"等上一个做完"（详见 §11.10）。
> **范围调整（用户 2026-11-03）**：**偏好/习惯记忆 + 每日复盘 + 偏好页属于【人格/偏好层】，暂缓**，不计入本期架构；本稿只在 §5.5 保留"决策时可查询偏好"的接口占位，不展开（12 §2.8、14 §9）。

## 0. 一句话

把"**轮**"换成"**步**"：用户每句话随时进入当前步。秘书**没在流式输出时**在语义段边界吸收；**一旦正在流式输出**，用户发来改变性消息就**立即停下、撤回未完成的回复、看完最新消息再重答**。**发消息不打断后台工作**：普通消息默认并行（对话回路即时回复 + 视需要派新任务，执行回路继续跑），只有**显式修正/停止**才调整执行；调整时把"做到哪、为什么改、怎么继续"写成**可恢复的中断点**。系统内部允许有队列，但**队列对用户不可见**。

## 1. 目标、判据与非目标

### 1.1 三条可检验的判据

| # | 判据 | 反例（必须避免） |
|---|---|---|
| J1 | **首响可感**：任何消息在硬上限内必有可感知信号 | 用户发完盯着空屏，不知道收没收到 |
| J2 | **不丢话**：消息、更正、约束一个都不丢——包括被撤回回复对应的原始输入 | 用户连发 5 条，agent 只回了第 1 条的语气 |
| J3 | **可打断且可恢复**：未完成回复能撤回并基于最新消息重答；已完成内容与中断状态能恢复、可追溯 | 打断后继续按旧理解说完；或撤回了却既说不清撤了什么、也接不上原来的活 |

### 1.2 非目标

- UI 布局与交互细节（三栏、右栏长任务列表页、折叠）→ [`14-总体设计-v1.md`](14-总体设计-v1.md) §5；
- 记忆条目 schema、合并规则、污染防线 → [`12-记忆模型-候选稿.md`](12-记忆模型-候选稿.md)；
- 多实例调度与并发上限、模型选型、API/事件格式（本稿只给**语义级**协议）。

## 2. 术语（v0.6：会话 / 子会话统一，含本轮新增）

| 词 | 定义 | 备注 |
|---|---|---|
| **步（step）** | 从一个目标被提出，到该目标有了结论/结果（或被撤销）的交互单元 | 替代"轮" |
| **段（segment）** | 秘书一次输出中的**语义单元**（一个结论、一个动作说明、一个清单项） | 段边界 = 抢占检查点 |
| **流式中 / 已 done** | 一条秘书回复**尚未输出完** / **已正常输出完** | 决定"能不能撤回"的分界线 |
| **撤回（retract）** | 把一条**未完成**的回复从对话视图撤下（标 `retracted`），不继续输出、不再作为"已说内容" | **已完成消息不撤回**（【拍板·11-03】）；episode 仍留档（见 §9、§12） |
| **硬抢占（撤回重答）** | 流式输出中收到改变性消息 → 停止、撤回该条未完成回复、基于最新消息重答 | 本轮拍板 1 |
| **段间吸收**（原"软抢占"） | **没在流式输出时**（思考中/工具等待/段间）收到消息 → 在下一个段边界吸收，不必撤回 | 没有在流的东西，就无所谓撤回 |
| **重规划（re-plan）** | 正在做的事被新消息改变时，重新决定"继续/调整/改派/中止" | 本轮拍板 2 |
| **中断点（checkpoint）** | 被打断/换方式时写下的"做到哪、为什么改、新方案、从哪继续" | 本轮拍板 3；见 §9 |
| **自主决定阈值** | 判断"这事该自己定还是该问"的标准 | 本轮拍板 4；见 §5.5 |
| **帧（Intent Frame）** | 秘书对"这一步要什么"的结构化理解 | §6；可修订，派发时冻结 |
| **会话 / 子会话** | V1 的两级组织单位；**会话 / 子会话 = 长期里程碑**（可含多个任务；没有自动完成/超时关闭） | 结构 **V1 固定：不可拆分、不可合并**；**可改名（纯显示、无语义影响）**；生命周期见 §11.8（用户 2026-11-03 已确认） |
| **任务 / 阶段** | 会话/子会话里的**执行单位**（阶段 = 有明确完成标准的里程碑）；右栏长任务列表对应"执行任务" | 用户 2026-11-03 已确认 |
| **会话生命周期** | **进行中 / 空闲（长期无活动，保留）/ 已归档（可选，非必须）** | 用户 2026-11-03 已确认；**没有"关闭"**；无自动完成 / 超时关闭 |
| **归档** | 可选的整理动作：**归档后只读查看**（不能继续聊）；**默认可取消归档/恢复**（技术实现细节标"待实现确认"） | 用户 2026-11-03 已确认 |
| **按需取用** | 用户在父会话说"去子会话看看，把相关文件拿出来"，秘书**按需**读取/转述/预览/下载；**不推送、不自动回流** | 用户 2026-11-03 已确认（替代已取消的旧机制） |

| **主窗口** | **根节点的聚合视图**（含全部子会话），所以显示所有消息；**不是归属容器**，每条消息仍只属于它的会话 | 用户 2026-11-03 已确认；见 §11.7 |

## 3. 三速响应（本协议的核心承诺）

三档响应**并行存在**，编号越小越早。

| 档 | 名称 | 什么时候发 | 内容约束 | 谁产生 | 目标延迟【讨论中·建议值】 |
|---|---|---|---|---|---|
| **S0** | **收到信号** | 消息到达即发，**不等模型、不等合并窗口** | 只表示"收到了/正在看"，**不得含未验证结论**；同一合并窗口最多一条 | 确定性路径（规则 + 模板/状态指示） | p50 ≤100ms，p95 ≤300ms，**100% ≤1s**（硬承诺） |
| **S1** | **首段实质** | 合并窗口关闭 + 快判完成（或歧义判定完成）后 | **短**：确认理解/方向、或一个确认问题、或简单问题的直接答案（见 3.3） | 主模型流式 | p50 ≤1.5s，p95 ≤4s |
| **S2** | **推进段** | 之后每个语义段；执行期间按心跳 | 增量结论、阶段/进度、待确认项；**执行期间不得静默** | 秘书/执行进度 | 段间空档 p95 ≤800ms；无新内容 >5s 必须发心跳（≤10s 一次） |

### 3.1 三档的硬规则

1. **S0 不许等模型**：模型慢、分类失败、执行体卡住，S0 都要按时发。
2. **S1 不许编结果**：可以说"我先按 X 理解，正在查"；不能说"已经完成"。
3. **S2 不许静默**：长时间执行必须有心跳或阶段结论；"再等等"本身也是一条 S2。
4. **三档不许合并成"我想好了再说"**：合并窗口只影响 S1，不影响 S0。

### 3.2 撤回的作用范围（【拍板·11-03】）

| 对象 | 能不能撤回 | 说明 |
|---|---|---|
| 一条**未完成**的秘书回复（流式中） | **必须撤回** | 被打断即停、即撤回、基于最新消息重答 |
| 一条**已 `done`** 的秘书回复 | **不撤回** | 已完成内容不被后到消息改写；如需修正，用后续回复明确更正 |
| S0 状态信号 | 不算"回复"，不进入撤回 | 随状态更新或消失 |
| 已经执行的外部动作（发消息、提交、删除等） | **不可撤回** | 报告"已发生"，然后按新意图调整后续（见 §8.4） |
| episode / 记忆里的原始记录 | 不删 | 撤回只作用于对话视图；原文留档于审计/episode（§12 I2），**不展示在对话里** |
| **后台任务/子智能体（执行回路）** | **不适用撤回** | **发消息不打断后台工作**（§11.10）：后台任务不是"流式回复"；要停止只能显式 cancel（保留中断点），不是"撤回" |

**撤回呈现（用户 2026-11-03 确认）**：

- **对话历史**：被撤回的那条消息**只显示"已撤回"标记，不展示被撤回的具体内容**；
- **审计后台**：保留撤回记录与原文（谁、何时、为什么撤、撤前说到哪），可审计，但**不进入对话**；
- **重答**：紧接在"已撤回"标记之后；不引用被撤回内容（除非用户明确要求"刚才说的那个"）；
- 这条同时适用于"硬抢占撤回"和"用户说停"两种情况。

### 3.3 S1 首段策略（v0.3 收紧，【讨论中·由拍板 1 推出】）

**原则：首段短、先对齐、再展开。** 因为未完成回复会被撤回——越长的首段，撤回时越浪费，也越容易让用户先看到"后来被撤下的错内容"。

| 场景 | S1 首段内容 | 建议长度 |
|---|---|---|
| 判定为**真歧义** | **只给确认问题** + 我的建议（带选项） | ≤2 句 |
| 无歧义、任务复杂 | 确认理解 + 计划（分几个阶段/几步） | ≤3 行 / ≤80 字 |
| 简单问答 | 直接答案 | 不受限 |
| 正在执行、用户只是补充 | 一句"记下了，我调整一下计划" + 调整点 | ≤2 句 |

**禁止**：在 S1 里展开长结论、长推理、长代码/清单；这些放 S2，并且**按段输出**，让撤回代价可控。

### 3.4 反模式对照（v0.3 更新）

| 用户看到的坏形态 | 本协议要求的好形态 |
|---|---|
| 发完 5 秒无任何反应 | ≤1s 内出现"收到"信号，随后给出首段 |
| 连发 3 条，每条都触发一次完整回答 | S0 只发一次；3 条合并成一个理解，S1 里体现全部要点 |
| "正在处理，请稍候"后长时间空白 | 状态 + 心跳 + 阶段性结论；**不出现"排队"字样**【拍板·原】 |
| 用户插话后，agent 继续把旧内容说完再理新消息 | **立即停 + 撤回未完成回复 + 基于最新消息重答**（【拍板·11-03】） |
| 撤回后假装没说过、不解释 | 一句"上一条我撤回了，按你最新的说法重来" |
| 每条打断都整段重开、把已确认内容再背一遍 | 只重答受影响的部分 + 一句说明 |
| 为了"干净"把进度也删了 | **文本撤回、进度保留在中断点**（§9） |
| 没歧义也反复确认、问很细的问题 | 真歧义才问；琐碎/可逆自己定并说明（§5.5） |

## 4. 状态机：Idle / Speaking / Acting

### 4.1 三个状态

| 状态 | 含义 | 用户可感知 | 当前步的进展由谁推动 |
|---|---|---|---|
| **Idle** | 无进行中的步：没有输出、没有在跑的执行 | 静默可输入 | — |
| **Speaking** | 秘书正在向对话通道产出（流式） | 看到流式文字 | 秘书 |
| **Acting** | 已把工作交给执行实例，等待/接收结果 | 看到"执行中/进度"（右栏可展开，见 14 §5） | 执行实例 |

【讨论中】**Acting 是后台态**：不占用对话通道，所以 **Acting 与 Speaking 可以并存**。约定：

- 3 个基本态 → 4 种可达组合：`Idle`、`Speaking`、`Acting`、`Speaking+Acting`；
- **抢占决策看前台态**（Idle / Speaking），后台态（Acting）只影响"这句话要不要改派执行 / 重规划"。

### 4.2 迁移表（v0.3 更新）

| 当前 | 触发 | 下一 | 动作 |
|---|---|---|---|
| Idle | 用户消息到达（S0 即发出） | Speaking | S0 → 慢判（含歧义判定）→ S1；简单问题直接答，复杂问题 S1 后转 Acting |
| Idle | 用户消息明确要求"去做" | Speaking+Acting | 先 S0/S1（确认理解 + 计划/阶段），再派发；**先回应、后执行** |
| **Speaking** | **Refine**（流式中） | Speaking（撤回重答） | 停 → 撤回该条未完成回复 → 把新增约束并入理解 → 重答（只重答受影响部分） |
| **Speaking** | **Correct**（流式中） | Speaking（撤回重答） | 停 → 撤回 → 复述更正 → 重答；若同时有执行，进入重规划 |
| **Speaking** | **NewTask**（流式中） | Speaking（撤回重答，旧步保活） | 停 → 撤回 → 旧步一句收尾 → 开新步；旧执行继续 |
| **Speaking** | **Ack** | Speaking | **不撤回**（Ack 不改变内容），继续输出/收束 |
| Speaking | 段自然结束 | Idle / Acting / Speaking | 还有下一段就留在 Speaking；没有则关闭本步或转 Acting |
| **Acting** | **Correct / 改变性 Refine** | Acting+Speaking | 先回一句"我调整一下" → **重规划**：继续 / 改派 / 分叉 / 中止 → 写中断点 → 简报执行侧 |
| Acting | 普通 Refine（补充细节） | Acting+Speaking | 即时回一句"已记下"，把增量附加到执行简报（不打断执行） |
| Acting | **NewTask** | Acting+Speaking | 旧执行不打断，开新步；当前子会话可切 |
| Acting | **Ack** | Acting | 只更新确认状态 |
| Acting | 子会话任务结果 / 候选记忆就绪（12 §5） | Speaking（+Acting 结束） | 校验结果完整性 → 转述摘要 + 指针；**不向父会话自动推送**；记忆写回走候选 |
| 任意 | 用户说"停/算了" | Idle | 停流式并撤回未完成回复；取消可逆动作；不可逆动作**报告已发生** |
| 任意 | 连接断/超时 | 同态 + 降级 | 见 §10 |

### 4.3 每个状态里必须记住的东西（语义字段）

- `stepId` / `revision`：当前步与理解版本；
- `sessionId`：这条消息/回复的**唯一归属会话**（每条消息只属于一个会话/子会话；主窗口不是归属容器）；
- `currentSessionId`：当前会话/当前子会话（UI 视图状态，见 14 §5.1）；
- `frame`：Intent Frame（§6）；
- `inFlightReply{messageId, cursor, retracted}`：正在流的那条回复、说到哪、是否已撤回；
- `pendingInputs[]`：已收到但尚未被吸收的消息（**不允许"已丢弃"**）；
- `activeJobs[]`：在跑执行 + 阶段 + 最近一次进度时间；
- `checkpointId`：最近一次中断点（§9）；
- `lastUserSignalAt` / `lastUserVisibleAt`：S0/S2 计时依据。

### 4.4 关闭规则

- 一步只有在**目标有结论、被撤销、或转交给执行**时才关闭；关闭时产生一条**步摘要**（供汇总与记忆候选）。
- **被撤回的回复不算"已说内容"**：不能拿它当用户已确认的依据；但它的原文留在 episode 里可追溯（§12 I2）。
- 关闭不等于清空：已确认的约束/决定按记忆候选提交（12 §5）。

## 5. 消息分类：Refine / Correct / NewTask / Ack

### 5.1 四类定义与作用（v0.3 更新）

| 类 | 定义 | 典型信号 | 对当前步的影响 | 流式中怎么处理 |
|---|---|---|---|---|
| **Ack** | 对已说出内容的确认/接受 | "嗯/对/可以/就这样/好" | **不改变目标**，把当前理解/方案标记为"已确认" | 不撤回，继续 |
| **Refine** | 在当前目标内**补充/细化** | "要快一点""优先做 A""加个日志" | 目标不变，**增加约束/细节**；**后台任务继续跑**，增量进 brief/下一阶段 | 对话回复**撤回重答**（只重答受影响部分）；**不打断执行** |
| **Correct** | 指出理解错、结论错、或**推翻已确认内容** | "不对""不是这个意思""我说的是 X""刚才那个改掉" | 目标是**被修正**；**显式修正 → 对受影响任务 steer / cancel** | 对话**撤回重答** + 执行侧调整（§11.3） |
| **NewTask** | 与当前目标无关的**新目标/新对象** | "先放一下，另外…""还有个事""换一个" | 旧任务**继续跑（保活）**，**新开一条并行线**；不是"抢断" | 对话即时回复（旧回复已完成则不撤回）；执行回路开新任务 |
| （补充）**停止** | 明确要求停 | "停/等一下/别说了/停掉那个" | 显式停止：**cancel 对应任务**（保留中断点） | 对话撤回 → Idle；执行回路停对应任务 |

> **关键（用户 2026-11-06 确认）**：本表只决定**对话动作**与"是否显式 steer/cancel"；**后台任务默认并行**（§11.10）。除 Correct/停止外，任何消息都**不取消、不暂停**正在跑的任务。

### 5.2 两阶段判定

| 阶段 | 时机 | 判定内容 | 手段 | 延迟预算 |
|---|---|---|---|---|
| **快判** | 消息到达后、S0 之后立即 | 只判两件事：**会不会改变当前对话回复**（撤回/不撤回/待定）；**是不是显式 Correct/停止**（才影响执行；普通 Refine/NewTask 不打断后台任务） | 规则为主：否定词、更正词、新目标词、主题重合度、当前子会话对象、显式停止 | ≤200ms【讨论中】 |
| **慢判** | 合并窗口关闭后 | 完整分类 + 歧义判定 + 更新 Intent Frame + 决定动作（含重规划） | 主模型 + Frame 增量更新 | 计入 S1 |

- **快判必须保守**：出现"不对/不是/错了/改成/我说的是/停"之一 → 先按"要改变"处理（先停）；慢判发现是 Refine 且不影响已输出内容，再继续（此时已撤回也不亏，重答更短）。
- **已知误报要接受**：例："别动线上"其实是新增约束（Refine），但含"别"，快判会先停一下；慢判归为 Refine 后重答。这类"误停"是设计内代价（§8.5）。
- **分类不授予任何权限**：分类只决定交互动作；写公共记忆仍必须走候选（12 §5）。

### 5.3 判定依据表（快判可用的确定性规则）

| 信号 | Ack | Refine | Correct | NewTask |
|---|---|---|---|---|
| 长度 | 短（≤10 字） | 中长均可 | 中短常见 | 中长 |
| 是否含否定/矛盾指向 | 否 | 否 | **是**（"不/别/不是/错/改"） | 否 |
| 是否含停止词 | 否 | 否 | 可能（"停"） | 否 |
| 是否引入新对象/新交付物 | 否 | 否 | 否 | **是** |
| 与当前目标关系 | 回应 | 支撑 | 冲突 | 无关 |
| 是否明确"先/另外/顺便" | 否 | 可能 | 否 | 可能 |

### 5.4 分类歧义与兜底（默认动作写死）

| 情形 | 默认处理 | 理由 |
|---|---|---|
| Ack vs Refine（"对，而且…"） | 按 **Refine**（Ack 部分照样生效） | 不丢新信息 |
| Refine vs Correct（"改成每天跑"） | 含**显式修正/停止**信号 → 按 **Correct**：对话撤回重答 + 对受影响任务 steer；**否则按 Refine 处理，不打断执行** | 只有显式修正才改变执行（§11.10） |
| NewTask vs Refine（"顺便看下另一个"） | 按 **NewTask**：对话即时回复 + **默认并行**开新任务；**旧任务继续跑，不关闭、不抢占** | 两条都不丢，且不打断后台工作（§11.10） |
| **两种解释会导致不同且实质的动作**（真歧义） | **先确认再执行**（§5.5） | 【拍板·11-03】不猜 |
| 分类失败/超时 | 走降级 D2（§10）：复述 + 等确认，不自行选一种执行到底 | 降级要可见 |

**问题预算**：一次确认**最多 1 个问题**，且必须**带选项 + 我的建议**；不能连环追问（>2 个问题视为协议失败，改为先做可逆部分并把待定项列清楚）。【讨论中】

### 5.5 歧义先确认 + 自主决定阈值（v0.3 新增，【拍板·11-03】）

**用户的拍板原话要点**：一条消息有歧义，要先确认之后再执行；但不要问那种太细、你自己可以决定的问题；自己决定不了的，再让用户决定，或者解释清楚。**不猜。**

#### 5.5.1 什么算"真歧义"（必须先确认）

同时满足才确认：

1. 存在**至少两种合理解释**；且
2. 不同解释会导致**不同的实质动作/产物/外部影响**（不是措辞差别）；且
3. 现有信息（对话、记忆、常识默认）**无法排除**其中一种。

典型：对象指代不明且选错代价高（"把那个服务停掉"——哪个服务？）；范围/边界不明（"上线"= 合并还是发布？）；互相矛盾的要求；不可逆动作前的最后确认。

#### 5.5.2 确认怎么做（不烦人）

- **只问 1 个问题**，给 2–3 个选项 + **我的建议**；
- 先**解释清楚**背景再问（用户可能不熟的技术细节，不要拿术语考人）；
- **并行做不受歧义影响的部分**（不要干等）；
- **不执行不可逆/会改变状态的部分**，直到确认；
- 用户确认前，不用默认值"悄悄推进"关键决策。

#### 5.5.3 自主决定阈值（自己定，不打断）

**全部满足**才自己决定：

- **可逆**（能低成本改回来）；
- **低风险**（无对外发送、无花钱、无删除、无改已确认约束）；
- **不影响产品形态/完成标准**；
- **成本低**（不需要额外资源或很长等待）；
- **有合理默认**（惯例、用户以往偏好、记忆里的约束）。

自己做主后**一句说明**（"我按 X 处理了，要改告诉我"），并记进 Intent Frame 的 `selfDecisions[]`（§6.1）。

#### 5.5.3b 偏好驱动阈值（【人格/偏好层 · 暂缓】）

> **范围调整（用户 2026-11-03）**：偏好/习惯记忆、每日复盘、偏好页属于**人格/偏好层**，"跟当前做的 Agent 架构不是一回事，先记下来，后面再说"——**暂缓、不计入本期架构**。这里只留接口占位，不展开实现（详见 12 §2.8、14 §9）。

- **接口占位**：决策时预留一个查询钩子 `preferenceLookup(action, domain) → {policy: ask | act} | none`；
- **本期行为**：没有偏好记忆 → 一律回落到上面的**默认自主决定阈值**（可逆/低风险/低成本 → 自己做并说明；不可逆/对外/花钱/改已确认约束 → 先问）；
- **未来启用时的优先级**：**任务的显式指令 > 长期偏好 > 默认阈值**（本次说"直接做"就本次直接做，长期偏好不能反过来压过显式指令）；
- **不展开**：偏好怎么采集、怎么复盘、怎么确认、怎么衰减，全部留到后续单开讨论（12 §2.8 末尾清单）。

#### 5.5.4 明确两类错误

| 错误 | 表现 | 处置 |
|---|---|---|
| **猜**（该问不问） | 关键决策用默认值静默推进；不可逆动作没确认 | 禁止；走了就是协议失败，需在回复里显式纠正 |
| **过度确认**（不该问的问） | 琐碎/可逆的事也问；一次给 3 个以上问题 | 禁止；阈值内自己定，或合并为 1 个选择题 |

> 边界：**"该不该问"本身也可能有歧义**。默认取"问一次成本更低"的一侧：不可逆/对外/花钱/改约束 → 问；其余 → 自己定并说明。【讨论中】

## 6. Intent Frame：秘书"听懂了多少"的结构化表示

### 6.1 字段表（v0.3 增补）

| 字段 | 内容 | 何时更新 | 说明 |
|---|---|---|---|
| `stepId` / `taskId` | 归属的步与任务 | 开步时 | 任务对应记忆的 task 作用域（12 §3） |
| `currentSessionId` | 当前会话/当前子会话 | 切换/自动切时 | 只影响展示与上下文起点，不影响记忆权限；**只是 UI 状态，不是换 Agent** |
| `label` + `confidence` | 四类分类结果 | 每消息/每窗口 | §5 |
| `goal` | 一句话：这一步要达成什么 | 新任务/更正时 | 必须能被用户 Ack 或否认 |
| `constraints[]` | 硬约束（含来源：用户原话 / 记忆条目 / 系统规则） | Refine/Correct 时 | 已确认约束不可被续写内容暗改（I3） |
| `acceptance[]` | 怎么算完成 | 开步时 | 判断"段说完了没""阶段是否可验收" |
| `phases[]`（v0.3） | 长任务的阶段：目标/验收/产物/依赖/可中断点 | 开步/重规划时 | 阶段是进度与右栏展示单位（§11.4、14 §5.2/§5.3） |
| `refs[]` | 引用的任务/记忆条目/文件/对象 | 引用时 | 支持"引用任意任务上下文"（10 节 7） |
| `affects` | `none` / `augment` / `amend` / `replace` / `abort` | 每消息 | 决定撤回/重答/重规划 |
| `tier` | `S0_only` / `S1_then_stop` / `execute` | 每窗口 | 决定"只回应还是要派发" |
| `ambiguity`（v0.3） | `{level, options[], question}` | 慢判时 | 真歧义才填，最多 1 个问题（§5.5） |
| `selfDecisions[]`（v0.3） | 自己拍的小决定：`{decision, reason, reversible}` | 自主决定时 | 用于"一句说明"与事后回看（§5.5.3） |
| `mustAsk[]` | 必须问用户的问题 | 每窗口最多 1 条 | §5.5 |
| `revision` | 理解版本号 | 每次吸收/更正 +1 | 输出可引用"我按第 N 版理解" |
| `provenance` | 依据的消息 id / 记忆 id / 版本 | 随更新 | 写回候选时用作 `Sources`（12 §5.8） |
| `checkpointRef`（v0.3） | 最近中断点 id | 写/恢复中断点时 | 见 §9 |
| `frozenAt` | 派发时冻结的版本 | 派发时 | 冻结后旧版作废，执行侧拿执行视图 |

### 6.2 生命周期（v0.3 更新）

```
开步（新目标） → 增量更新 revision++ → 冻结（派发执行） → 执行中只读 → 关闭（结论/撤销/转交）
                         │
                         ├─ 被打断：流式回复撤回（不回滚 Frame，只按最新消息修订 revision）
                         └─ 换方式：先写中断点（§9），再解冻 → 新 revision → 改派简报
```

- **冻结不等于不能再改**：Correct / 换方式会解冻 → 新 revision → 执行侧收到"改派简报"（§11.3）。
- **Frame 是交互层状态，不是记忆**：不进公共记忆；结论/决定写回时按候选提交（12 §5），用户 Ack 可升级来源为 `user_confirmed`。

### 6.3 与记忆的接口（只引用）

- **读**：按 12 §4.3 组装（常驻块 + pin + 检索 + 冲突横幅）；**读实时**，变更以"更新提示"注入（12 §3.3/§6.6）。
- **写**：不直接写；产出候选，由记忆管理器合并（12 §5）。
- **冲突**：`disputed` 条目在对话里**主动提示**（"两条记忆有冲突，需要你定"），不静默选一条（12 §5.9）。

## 7. 合并窗口与"持续发消息"的增量理解

### 7.1 参数【讨论中·建议值】

| 参数 | 值 | 作用 |
|---|---|---|
| 静默窗口 | 300ms | 收到一条后等这么久看是否还有后续（仅用于组织 S1/慢判） |
| 硬上限 | 800ms | 从窗口第一条起最多等这么久，防连续发导致永不响应 |
| 长消息立即处理 | 单条 >200 字，或含明确新目标词 | 不再等窗口 |
| 单窗口消息上限 | 5 条 | 超过则只做"合并摘要 + 1 个确认/待定" |

**关键**：

- 窗口只延迟 **S1/慢判**，**不延迟 S0**；
- **窗口不拦撤回**：流式中收到改变性消息 → **立即撤回**，不等窗口（否则旧内容会多流出一段）。

### 7.2 窗口内合并规则

1. 同一窗口内的消息按到达顺序组成输入批，**一次分类、一次 S0、一次 S1**；
2. 批内互相冲突时**以最后一条为准**，旧表述不删除（记入 episode 与旧 revision）；
3. 批内有 Correct 时，整个批按"更正 + 补充"处理，不拆成两个回答；
4. 批内出现新目标时，**先回应旧步收尾一句**（≤1 行），再开新步；
5. **流式中连续来多条**：只**撤回一次**，把最新一批合并后重答一次（避免反复撤回/闪烁）。

### 7.3 增量理解三操作

| 操作 | 触发 | 效果 | 留痕 |
|---|---|---|---|
| **append** | Refine（新增约束/细节） | Frame 增加 constraint/refs，不撤销已有内容 | 新 revision |
| **override** | Correct（同字段改新值） | 新值生效，旧值标"已被更正" | 新 revision + 旧值可追溯 |
| **withdraw** | "刚才说的不算/忽略上一条" | 从当前理解移除（不物理删除） | `withdrawn` 标记 + 原话 |

### 7.4 应答契约（v0.3 更新）

1. **首段短**：S1 只确认理解/方向或给 1 个确认问题（§3.3）；
2. **撤回要说明**：重答前一句"上一条撤回了，按你最新的说法重来"；
3. **只答 diff**：不重复已确认内容，只说"新增/改了什么、我准备怎么变"；
4. **Ack 之后不再复述**：同一 revision 不重复确认；
5. **每条增量段能独立读懂**（用户可能没看全），开头带"接着刚才…"锚点；
6. **连续发 5 条以上**：只给"合并理解 + 1 个待确认点"，不逐条背诵。

### 7.5 不丢话（硬要求）

- 每条用户消息都落为不可变 episode（12 §2.5），**先落库再处理**；
- 每条消息最终必须被某个 Frame revision 吸收，或**显式标注"未纳入及原因"**；
- **撤回不等于丢话**：被撤回的回复原文也留在 episode；**禁止静默丢弃**。

## 8. 语义段与抢占检查点（v0.3 重写抢占规则）

### 8.1 段边界怎么判定（四类）

| 类型 | 判定 | 用途 |
|---|---|---|
| **结构边界** | 句末标点 / 段落结束 / 列表项结束 | 非流式时的吸收点 |
| **语义边界** | 一个结论或动作说明完成（生成时显式标记 `segment.end`） | 最佳检查点：不截断推理 |
| **工具边界** | 即将调用工具 / 即将产生不可逆动作之前 | **强制检查点**（8.2） |
| **时间边界** | 单段 >6s 或 >120 tokens【讨论中】仍无自然边界 | 强制切"可撤回短段" |

### 8.2 强制检查点

1. 每个**段结束**；
2. **每次工具调用前**（尤其有副作用）；
3. **每次修改执行计划前**（重规划，§11.3）；
4. **每次提交记忆候选前**（12 §5.2）；
5. **每 6s / 120 tokens**；
6. **每 10s** 心跳（即使没新内容）。

### 8.3 抢占决策矩阵（v0.3）

| 消息类 | **Speaking（流式中）** | Acting（执行中，无流式回复） | Idle |
|---|---|---|---|
| **Correct（显式修正）** | **停 → 撤回未完成回复 → 复述更正 → 重答**；**对受影响任务 steer/cancel** | 先回"收到更正"→ 对受影响任务 steer/cancel → 写中断点 | 正常处理 |
| **Refine（普通补充）** | 撤回与否看是否影响已输出内容：影响 → 撤回重答；不影响 → 可继续，下一段吸收；**不打断执行** | 附加到执行简报（**不打断执行**） | 正常处理 |
| **NewTask** | 对话即时回复；旧执行**保活**、开新并行任务；旧回复已完成则不撤回（仍流式且被影响才撤对话） | 旧执行继续，**默认并行**开新任务 | 正常处理 |
| **Ack** | **不撤回**，继续/收束 | 只更新状态 | 正常处理 |
| **显式停止** | 停 → 撤回 → Idle | **cancel 对应任务**（保留中断点）；不可逆动作报告已发生 → Idle | 正常处理 |

> **矩阵只覆盖对话回路**：执行回路默认**不被普通消息抢占**；只有 **Correct / 显式停止** 才 steer/cancel 后台任务（§11.10，用户 2026-11-06 确认）。
>
> 一句话：**"流式中"没有软抢占——只要新消息会改变当前回复，就撤回重答**；"段间吸收"只适用于**没有正在流的回复**的时刻（思考中、工具等待、段间）。**撤回针对回复，不针对后台任务。**

### 8.4 不可抢占的原子区（对外部动作，不针对文本）

- **不可逆动作进行中**（发送消息、提交代码、删除、写公共记忆）：**不中断**，完成后立即报告"已完成 X"，再撤回文本/按新意图调整；
- 原子区目标 ≤2s【讨论中】；超过 2s 的动作必须拆"可中断的子动作 + 已做部分说明"；
- 可逆动作（查资料、读文件、生成草稿）随时可中断；
- **文本回复永远可撤回；外部动作永远不可撤回**——这是两条不同的线，别混。

### 8.5 撤回的产物（v0.3 重写）

| 情况 | 处理 |
|---|---|
| 流式中被打断 | 停止；该条回复标 `retracted`（对话历史**只显示"已撤回"标记、不展示内容**，不再继续输出）；episode/审计留档；重答前一句说明"上一条撤回了，按你最新的说法重来" |
| 重答 | 只重答**受影响部分**；已确认/未受影响的内容不重复输出（可引用） |
| 误撤回（慢判发现其实不影响） | 不丢脸：直接继续/补一句"我接着说完"，必要时把撤回内容重说一遍；记一次误撤回指标 |
| 已完成消息需要修正 | **不撤回**；用后续回复明确更正（引用被更正内容） |
| 打断时正在执行 | 可逆动作撤销并告知；不可逆动作报告"已发生，无法撤销"；写中断点（§9） |
| 后台/日志 | 撤回记录（谁、何时、为什么）保留，可审计；用户可见视图可隐藏 |

### 8.6 什么时候可以"段间吸收"（延迟处理的合法边界）

- **没有正在流式输出**（思考中、工具调用等待、段结束后的间隙）；
- 当前段剩余 ≤100 tokens【讨论中】的收尾；
- 用户消息是低优先补充（非约束、非更正、不改变执行）；
- 执行侧 Correct 需要走完整"改派"时：**先回复用户，再改派**，不反过来。

## 9. 中断点：状态记录与恢复（v0.3 新增，【拍板·11-03】）

> **用户原话要点**：把当前这种现状写下来；比如做到一半我让你换种方式，你可以把这种状态记下来。→ **不只是存草稿文本，而是可恢复的中断点**。

### 9.1 什么时候必须写

1. 用户打断/换方式/改主意，且**已有实质进展**（已做的阶段、已产出的东西）；
2. 真歧义确认后**方向改变**；
3. 长任务**阶段切换**；
4. 执行失败/超时/中止/重试；
5. 用户说"停一下/记一下/回头继续"，或秘书主动中止；
6. **重规划**（§11.3）发生前——先记现状，再改计划。

### 9.2 记什么（字段表，语义级）

| 字段 | 内容 |
|---|---|
| `checkpointId` / `taskId` / `stepId` | 唯一标识与归属 |
| `phase` | 当前阶段（长任务分阶段，§11.4） |
| `progress` | `{done[], doing[], todo[], blocked[]}`：做到哪、卡在哪 |
| `interruptReason` | `user_changed_mind` / `user_switched_approach` / `ambiguity` / `execution_failed` / `new_task` / `user_paused` |
| `oldPlan` | 原方案摘要（为什么原来那么做） |
| `newPlan` | 新方案摘要（换方式后怎么做）；未定则标"待定" |
| `resumePoint` | **从哪继续**：哪个产物/哪一步/哪些前置已完成 |
| `artifacts[]` | 已完成产物的指针（不复制大内容，12 §4.3 Inline & Spill 思路） |
| `baseVersion` | 写回时用于冲突检测（12 §3.5） |
| `createdAt` / `status` | 时间；`active` / `resumed` / `superseded` |

### 9.3 写到哪里（三层分离）

| 层 | 落点 | 说明 |
|---|---|---|
| **记忆层** | `task` 作用域的 `progress` 条目 +（若方案已定）`decision` 候选人 | 走候选制/单写者（12 §2.2、§5），不直接写公共层 |
| **对话层** | 一句摘要："中断点已记下：X 已完成、Y 没做；按新方式从 Z 继续" | 不让用户读长清单 |
| **视图层** | 右栏长任务列表页读 checkpoint + progress（14 §5.2） | 面板是视图，不另造状态 |

**episode 保原文**（12 §2.5）：用户怎么说的、当时做到哪，都留档；中断点只是"可读的索引与恢复点"。

### 9.4 怎么恢复

- 用户说"继续" → 按**最近 checkpoint** 恢复：保留 `done`，从 `resumePoint` 继续 `doing`，`todo` 按新方案重排；
- 用户说"换种方式" → 旧方案**保留**（可对比、可回滚），新方案另起，标 `superseded` 不删；
- 恢复前确认一次：涉及不可逆动作 / 已确认约束变更时，先问再动（§5.5）；
- 恢复要更新 Frame 的 `revision` 并留痕，不覆盖旧理解。

### 9.5 硬规则

1. **中断点必须可读**：人能看懂"做到哪、为什么换、从哪继续"；
2. **中断点必须可恢复**：至少一个明确的 `resumePoint`；
3. **撤回 ≠ 丢进度**：撤回的是对话文本，进度在 checkpoint；
4. **不删旧方案**：旧方案与旧理解保留（失效/归档，不物理删除，12 §2.7）；
5. **不因"看起来干净"而省略记录**：宁可多一条 progress，不可让用户重新解释一遍。

## 10. 降级策略

| # | 触发 | 降级行为 | 用户可见 | 恢复 |
|---|---|---|---|---|
| D1 | S1 超时（>4s） | 发模板段"我理解到的是 X，正在做 Y"，**不等模型** | 一句计划 | 模型返回后接正常 S1 |
| D2 | 分类/歧义判定失败或超时 | 按 Correct 安全子集：复述理解 + 等确认，**不自行执行到底** | 一句确认请求 | 用户 Ack/否认后恢复 |
| D3 | 模型超时/不返回（>30s） | 心跳 + 三选一（继续等 / 换个说法 / 先按现有信息做） | 明确选项 | 用户选择或模型恢复 |
| D4 | 执行体无进展（>60s 无 progress） | 显示"执行中但无新进展"；可中止/重派 | 状态 + 中止入口 | 执行恢复或重派 |
| D5 | 记忆候选被拒（12 §5.3） | 告知"这条没写进长期记忆（原因）"，**不影响本轮对话** | 原因 + 可重试 | 修正候选后重提 |
| D6 | 高风险动作需人审（12 §5.4） | 列出要确认的事项，**不静默等待** | 待确认清单 | 用户确认后执行 |
| D7 | 连接断 | 重连 + 按 `stepId + segmentSeq` 幂等续接，补发漏段，去重 | 短暂"重连中" | 补齐后继续 |
| D8 | 上下文/记忆预算不足 | 降到"常驻块 + 摘要 + 指针"，明说"这部分按摘要处理" | 一句说明 | 预算恢复后补细节 |
| D9 | 误撤回 | 直接继续/补一句"我接着说完"；必要时重说撤回内容 | 一句更正 | 记指标，调阈值 |
| D10（v0.3） | 用户打断时回复**刚好已完成**（无法撤回） | **不撤回**；用更正说明"上一条已说完，我按新的改" | 一句更正 | 后续回复体现新要求 |
| D11（v0.3） | 中断点写入失败 | 告知"这次中断点没记上（原因）"，内存中保留并稍后重试；**不假装记下了** | 一句说明 + 可重试 | 重试或降级为对话摘要 |

**降级三条铁律**：

1. **降级必须可见**：宁可多一句状态，不可静默；
2. **降级不丢已确认约束**：D2/D3/D8 都不许把用户已 Ack 的约束丢掉；
3. **降级不编事实**：任何降级路径都不得输出未验证结论（与 12 §7 污染防线一致）。

## 11. 与子任务/执行实例的交互

### 11.1 单向对话原则【拍板·原·10 节 10】

- 用户**只跟秘书**说话；执行实例**不直接对用户说话**，输出只进"执行轨迹"（默认折叠，见 14 §5.9）。
- 点子任务 = 秘书把「当前子会话」切过去；用户的话仍先归秘书判断。

### 11.2 派发

秘书把 Frame 的**执行视图**交给执行实例：

| 简报项 | 内容 |
|---|---|
| goal / constraints / acceptance | 来自 Frame（已冻结版本） |
| **phases[]** | 长任务阶段：每阶段目标、完成标准、预计产物（§11.4） |
| reads[] / writes[] | 读哪些记忆作用域 / 候选只能写哪些（12 §3.3/§3.4） |
| baseVersion | 提交时的版本向量（12 §3.5） |
| replyTo | 结果与候选记忆回流给**秘书**（不是用户；也**不向父会话自动推送**） |
| checkpointPolicy | 哪些中断点/阶段切换必须回报（§9） |

### 11.3 执行期间：显式修正/停止才调整执行（用户 2026-11-06 确认）

> **前提**：普通新消息**不会**改变正在做的事——默认并行：**对话回路即时回复 + 视需要派新任务，执行回路继续跑**（§11.10）。只有**显式修正/停止**（"别做 X / 停掉 / 改成 Y / 不是这个意思"）才进入下面的"调整执行"。

一条**显式修正/停止**消息如果会让"正在做的事"不再正确，秘书**不是等它跑完**，而是：

1. 先回用户一句"我调整一下计划"（S1 级，≤2 句）；
2. **写中断点**（§9，先记现状再改计划）；
3. **重规划四选一**：
   - **继续**：只调整参数/约束（比如"别动线上"→ 去掉部署步骤）；
   - **改派**：发新执行简报，可给同一实例或换实例；
   - **分叉（fork）**：保留旧路线继续跑（12 §4.1），新路线并行；
   - **中止**：取消可逆动作；不可逆动作报告"已发生"；
4. 把决定与影响告诉用户（一句话），右栏阶段状态同步更新（14 §5.2）。

**调整 vs 重做（用户 2026-11-03 已确认这条界线）**

| 变化 | 处理 |
|---|---|
| **目标 / 关键约束变**（做什么、做到什么程度、红线） | **重做**：停旧线 → 写中断点 → 新方案（可 fork 保留旧线）→ 换简报 / 换实例 |
| **细节 / 实现方式变**（怎么做、顺序、参数、措辞） | **调整**：保持目标与已完成产物，改计划与参数，发增量简报 |
| 分不清 | 按"**重做**"一侧处理（更保守），一句话说明理由，并写进中断点 |

**原则**：用户的更正优先于"把旧活干完"；已完成的部分尽量复用，不推倒重来；**重做时旧产物也保留**（可对比、可回滚，标 `superseded`）。

### 11.4 长任务的阶段化（【拍板·11-03】）

- **阶段 = 有明确完成标准的里程碑**（完成标准在对话里可讨论，**不引入验收按钮 / 验收状态机**），不是"想到哪算哪"；
- 每阶段至少声明：目标 / 完成标准 / 预计产物 / 依赖 / 可中断点；
- 阶段数建议 **3–7 个**【讨论中·建议值】；太粗看不出进度，太细变噪音；
- **阶段结束** → 阶段小结（1–3 行）+ 写 checkpoint + 右栏更新 + 结果写回候选记忆（12 §5）；
- 阶段之间是**天然检查点**：抢占/重规划优先在阶段边界发生（流式中仍按 §8.3 撤回）；
- 阶段状态（已完成/进行中/待办/阻塞）是**右栏长任务列表页**的数据来源（14 §5.2）。

### 11.5 结果、产物与验收（交付机制已取消）

- **交付机制已取消：父会话按需取用 + 对话验收**（用户 2026-11-03 已确认）：没有自动推送、没有独立交接包、没有独立验收状态；
- 任务结果与候选记忆按 12 §5 写回（候选 → 记忆管理器合并）；**不向父会话自动推送**；
- **父会话查看**：随时用**聚合视图**看子会话消息（§11.7）；要看**文件/产物**时，用户在父会话对秘书说"**去子会话看看，把相关文件拿出来**"，秘书**按需取用**（只读、可转述/预览/下载，不自动复制到父会话）；
- **验收走对话**：接受 / 不接受 / 改需求都用**对话**表达；**不引入验收按钮或状态机**；
- **产物**：产物条目带**文件预览 + 下载**入口（用户 2026-11-03 已确认）；对话里只给摘要 + 指针，细节在产物/执行轨迹中打开；
- 秘书在子会话里转述结果：**摘要 + 证据指针**，不贴全文；细节展开执行轨迹。

### 11.6 子任务与当前子会话

- 切到某子会话：只是换「当前子会话」，**执行不受影响**（视图切换不打断执行）；
- 子任务完成时用户不在该子会话：是否主动回流 = **待拍板 P2（§14）**；
- 秘书可自动把「当前子会话」切过去并告知 = **待拍板 P1（§14）**；
- **会话结构 V1 固定**：不可拆分、不可合并、可改名（纯显示）；协议**不依赖"会话可重组"**这个假设（【拍板·11-03】会话模型，见 14 §5.1）。

### 11.7 主窗口与消息显示（用户 2026-11-03 已确认）

**归属与显示分离**：

- 每条消息（用户/秘书/执行轨迹）**归属唯一**：只属于一个会话/子会话；`sessionId` 是消息的属性；
- **主窗口不是归属容器**：它只是**根节点的聚合视图**（含全部子会话），显示所有消息，但"消息属于谁"不变；
- 任意会话节点有两种显示方式：
  1. **仅本会话**：只显示该会话直属消息；
  2. **本会话 + 所有递归子会话**：按时间展开，显示本会话 + 全部后代子会话的消息；
- **递归一致**：同一渲染规则在每一层重复——子会话节点同样有"仅本会话 / 含其后代"两种方式，规则不变；
- **向上同步 = 聚合视图的自然结果**：祖先视图本来就会显示后代消息，所以**不需要**额外的"转发 / 同步"机制，也不存在"把子会话消息复制到父会话"的动作；
- 若要做"祖先只显示摘要、不显示全文"，属 **P1**（不是 V1）。
- **UI 呈现层（用户 2026-11-03 已确认，不属于核心架构讨论）**：聚合视图显示**双方消息（用户 + 秘书）按时间排列**；**深层消息带会话标签 + 轻缩进**标出层级。

**对协议的最小要求**：

| # | 要求 |
|---|---|
| 1 | 消息/回复/进度落库时带 `sessionId`（归属）；**不因为被聚合显示而改归属** |
| 2 | 秘书在某个子会话里的输出归属该子会话；被打断后重答仍是同一归属 |
| 3 | 在"主窗口/父会话"里发言：归属**你正在看的当前会话/当前子会话**，不因为聚合视图而变成"根会话消息"；除非你明确切到根会话再发 |
| 4 | 切换显示方式、点消息标签跳转**只影响显示**：不触发记忆写入、不中断执行、不改变归属 |
| 5 | 每条消息旁展示**归属会话标签**（会话名/子会话名），点击 = 切到该会话查看（即切当前子会话） |
| 6 | 协议里**没有"向上转发"的消息类型**；聚合由显示层按 `sessionId + 会话树` 计算 |

> 与打扰预算的区别：聚合只影响"能看到什么"，**不产生新的主动提示**；主动回流/站内提示仍按 §14 P2 的打扰预算。

### 11.8 会话生命周期与按需取用（用户 2026-11-03 已确认）

**1. 会话 = 长期里程碑，不是一次性任务外壳**

- 会话/子会话可包含**多个任务**；**没有自动完成 / 超时关闭**；
- 是否停止会话由**用户决定**；**会话没有"关闭"**，只有**可选归档**（归档不是必须动作）；
- 空闲一周后可以**接着做**，状态不丢。

**2. 生命周期状态（2 态 + 可选归档）**

| 状态 | 含义 | 进入 | 退出 |
|---|---|---|---|
| **进行中** | 有活动（对话 / 执行） | 新建会话、从空闲恢复 | 转空闲 |
| **空闲** | 长期无活动；**保留**，可随时恢复 | 进行中且无活动达阈值（阈值属【讨论中】） | 用户说话 / 任务恢复 → 进行中 |
| **已归档**（可选） | 不代表"关闭"，只是收起来；**归档后只读查看（不能继续聊）**；**不是必须动作** | 用户主动归档 | **默认允许取消归档 / 恢复**（技术实现细节标"待实现确认"） |

- 状态属于**会话/子会话**（组织层），不等于某一任务/阶段的执行状态。
- **没有"关闭"语义**：不设"关闭按钮 / 关闭状态机"；归档只是可选的整理动作。

**3. 交付机制已取消：父会话按需取用 + 对话验收（用户 2026-11-03 已确认）**

- 父会话了解子会话：**聚合视图看消息**（§11.7）+ 随时查看状态（进度、未决）；
- **文件 / 产物按需取用**：用户在父会话对秘书说"**去子会话看看，把相关文件拿出来**"，秘书按需读取 / 转述 / 预览 / 下载，**不自动推送、不自动复制**；
- **跨会话取用**：秘书可直接查看子会话消息、处理对应文件，**就像在自己会话里一样**；**不复制文件到父会话**，按引用 / 原地处理（**V1 一等能力**）；
- **验收走对话**：接受 / 不接受 / 改需求都用对话表达；**不引入验收按钮或状态机**；
- **没有自动推送、没有独立交接包、没有独立验收状态**。

**4. 向上同步：暂不做（P1）**

- 父会话了解子会话，靠两件事：**查看状态** + **聚合视图**；
- 不做额外的"向上同步 / 转发"机制；"只显示摘要"的聚合属 P1。

**5. 层级**

```
会话 / 子会话（长期里程碑）
  └─ 任务 / 阶段（执行单位；阶段 = 有明确完成标准的里程碑）
```

- **任务列表只放执行任务，会话不出现在任务列表**；
- 右栏"长任务列表"对应**任务/阶段（执行）**，**不是会话本身**；
- 会话树显示里程碑层级；任务/阶段在执行面板里展开（14 §5.2/§5.3）。

**6. 对协议的影响**

- 消息归属（§11.7）不变；归档不删除消息与记忆，也不中断执行；
- 空闲 → 恢复是常规路径：读状态 + 中断点继续（§9）；
- 没有独立交付与独立验收状态流转，所以协议里**不需要这类事件、也不需要验收状态机**；
- 通知 / 打扰预算：事件提示（"任务结束 / 需要拍板"）按 §14 P2，但**不是"任务完成"通知**。

**仍待讨论（不阻塞，先按默认）**：按需取用的边界（哪些文件可跨会话读取、是否允许写回）、归档恢复的技术实现（标"待实现确认"）。

### 11.9 Spec 不可见原则：所有 Spec 操作投影为自然对话（用户 2026-11-06 已确认）

> 背景：执行流程是 SDD，但 **Spec 是 Agent 的内部真相层**（见 [`18-SDD流程-v0.md`](18-SDD流程-v0.md)）。用户只提交需求与背景、只看到对话结果；**用户侧永远不出现 Spec/规格/需求文档/验收标准/基线/增量等内部词汇**。

**投影映射（内部操作 → 用户可见的话）**：

| Spec 内部操作 | 用户看到的话（投影） |
|---|---|
| **Spec 建立/更新** | 通常**不说**；需要时一句"好的，我记下了 / 按这个理解做" |
| **Spec 拆分** | "我把它拆成两条线：X 和 Y，可以吗？"（**仅需确认时**说） |
| **Spec 澄清** | 直接问"你说的 X 是指 A 还是 B？" |
| **Plan 需确认（风险门）** | 展示**方案摘要** + "确认这么执行吗？" |
| **执行进展** | 只说**结果/状态**（如"第一步做完了，在跑验证"） |
| **验收** | "结果如下…这样可以吗？" |
| **风险动作前** | "这一步会改线上 / 删数据 / 花钱，确认吗？" |
| **Spec 归档** | **不说**，除非用户问 |

**何时打扰用户（只有三类）**：

1. **风险门**：不可逆 / 动线上 / 删数据 / 花钱 / 影响他人；
2. **真歧义**：至少两种解释会导致实质不同的动作/产物/外部影响（§5.5）；
3. **用户主动要求**（问了/要求确认/要求解释）。

**其余内部自己过门**：Spec 建立/更新、拆分（不需要确认时）、澄清（自己能定的）、Plan（无风险时）、执行进展、归档，均**不打扰用户**。这与 §5.5 的"自主决定阈值"一致；**内部状态机与证据绑定不因此取消**（18 §5），只是"人类确认"从每次审 Spec 改为按风险触发。

**与 18 的关系**：本节只定义"Spec 操作如何投影为对话"，是交互协议的补充；SpecCore 的对象/流程/门禁以 [`18-SDD流程-v0.md`](18-SDD流程-v0.md) 为准。

### 11.10 发消息不打断后台工作：对话回路 / 执行回路分离（用户 2026-11-06 确认）

> 核心语义修正：**用户发消息 ≠ 打断当前任务**。发消息只进入**对话回路**；**执行回路**独立推进。只有**显式修正/停止**才 steer/cancel。

**两条回路**

| 回路 | 负责 | 何时可用 | 与另一回路的关系 |
|---|---|---|---|
| **对话回路** | 读消息、即时回复、澄清/确认、派发/调度任务 | **始终可用**，不等执行 | 派发后不等待；执行完成/需确认时回流到对话 |
| **执行回路** | 后台任务 / 子智能体 / 长任务推进 | 后台持续；完成/失败/需确认时回流 | 不因普通新消息自动暂停/取消 |

**默认判定（替代"新消息抢占任务"）**：

- 新消息 → **默认并行**：即时回复 + 视需要派发新任务；**旧任务继续跑**；
- 只有**显式修正/停止**才进入 steer/cancel：
  - "别做 X / 停掉 / 改成 Y / 不是这个意思" → 对受影响任务 **steer**（调整简报/重规划）或 **cancel**（停止并保留中断点）；
  - 普通补充 / 新任务 / 闲聊 → **不触碰执行回路**。
- **撤回只作用于流式未完成的对话回复**（§3.2），**不作用于后台任务**；后台任务的产出是"已完成/需确认"，不是"可撤回的流式回复"。
- 资源约束靠**并发上限 / 预算 / 内部排队**，**不靠"等上一个做完"**；超并发时新任务内部排队（对用户不可见），对话回路仍即时可用。

**三消息示例**（用户 2026-11-06 示例）：

1. 用户连发三条不同任务 → **对话回路**分别即时回复（S0/S1），互不阻塞；
2. **执行回路**开三条并行线（三个子智能体/任务），各自推进；
3. 完成回流：各自汇报（或阶段汇报），秘书在对话里汇总；
4. 若其中一条是"停掉刚才那个" → **只 cancel 对应任务**，其余继续。

**与子会话/任务的关系**：每条任务可落到独立子会话/子 Spec；三条并行 = 三个执行单元，主会话仍是唯一对话入口（§11.1）；完成后按 §11.5 汇报、14 §5 展示。

**不变量（新增 I6）**：**对话可用性与执行进度解耦**——执行中任何时刻，用户新消息都能得到 S0/S1 响应；不存在"任务在跑所以不回复"（除非用户明确要求只报结果）。

## 12. 六条不变量（v1.0.3 增 I6）

| # | 不变量 | 判定方式 |
|---|---|---|
| **I1 有响必到** | 任何用户消息从服务端接收起 **1s 内**必有可感知信号（S0）；执行期间 **10s 内**必有可感知进展 | 埋点统计 `t0→S0`、`最后进展→now` |
| **I2 不丢话** | 每条用户消息都被 episode 持久化；被撤回的回复原文也留档；每条消息最终被某 revision 吸收或无歧义标注"未纳入原因" | 抽样审计：消息 ↔ episode ↔ revision 三方对账 |
| **I3 已确认不可暗改** | 用户 Ack 过的约束/决定，只能通过显式 Correct 修改，且修改必须被复述 | 回放用例：Ack 后注入 Refine，断言约束不变 |
| **I4 撤回规则（v0.3/v0.4）** | **流式中被打断的未完成回复必须撤回并基于最新消息重答；已完成消息不撤回**（只能被后续更正）；撤回必须说明、**对话里只显示"已撤回"标记、不展示被撤回内容**，原文留档于审计/episode；**撤回不得丢进度**（中断点必须落地） | 回放用例：流式中注入 Correct/Refine/NewTask/停止，断言"撤回 + 重答 + 可恢复"；断言已完成消息不被改写；断言对话中看不到被撤回内容 |
| **I5 队列不可感知** | 协议输出中不出现"排队/请稍候/等这条处理完"这类阻塞式表达；等待只以状态/心跳呈现 | 文案规则扫描 + 用户可见性抽查 |
| **I6 对话不被执行阻塞（v1.0.3）** | **发消息不打断后台工作**：新消息默认并行（即时回复 + 视需要派新任务），旧任务继续；只有显式修正/停止才 steer/cancel；撤回只作用于流式对话回复，不作用于后台任务 | 回放：任务执行中连发 N 条新任务，断言每条都有 S0/S1、旧任务不取消；显式"停掉"仅取消对应任务 |

（"用户只跟秘书说话"归入总体设计的不变量，见 14 §2.4；本表只列交互协议自身的 6 条。）

## 13. 可测 SLA（v0.3 增补撤回/中断点指标）

### 13.1 测量口径

| 记号 | 定义 |
|---|---|
| `t0` | 服务端收到该批**第一条**用户消息的时间 |
| `t_S0` | 服务端发出首个"用户可见信号"事件的时间 |
| `t_S1` | 首个**实质内容 token** 的时间 |
| `t_retract` | 收到改变性消息 → 停止输出并撤回该条未完成回复的时间 |
| `t_reanswer` | 撤回完成 → 首个**重答内容**的时间 |
| `gap` | 相邻两个用户可见事件的最大间隔 |
| `t_ckpt` | 触发中断点 → task 作用域记录完成 + 右栏状态可见的时间 |
| 统计 | p50 / p95；本地单机环境；按步统计，冷启动单独看 |

### 13.2 SLA 表【讨论中·建议值，全部待校准】

| 指标 | 目标 | 硬承诺 | 备注 |
|---|---|---|---|
| `t_S0` | p50 ≤100ms，p95 ≤300ms | **100% ≤1s** | 不得等模型/分类器 |
| `t_S1` | p50 ≤1.5s，p95 ≤4s | 100% ≤12s（超时走 D1） | 首段已收紧（§3.3） |
| `t_retract` | p50 ≤150ms | **100% ≤200ms** | 流式中收到改变性消息；不可逆原子区豁免 |
| `t_reanswer` | p50 ≤1.5s，p95 ≤4s | 100% ≤12s | 撤回后**不等合并窗口**，立即重答 |
| 段间 `gap` | p95 ≤800ms | 无新内容 >5s 必须发心跳 | 心跳 ≤10s 一次 |
| 合并窗口 | 静默 300ms | 总等待 ≤800ms | 不阻塞 S0 与撤回 |
| 快判 | ≤200ms | 超时即按 D2 | 不允许拖慢 S1 |
| `t_ckpt` | ≤2s | 100% ≤5s | 中断点写入 + 右栏可见 |
| 派发确认 | ≤2s 内回"已交给 X" | 100% ≤5s | 只表示已派发，不是完成 |
| 任务结果可见 | 子任务结果就绪 → 秘书可读 ≤2s | — | 读实时，写版本化（12） |
| 结果转述 | 秘书可读 → 用户可见 ≤5s | — | 仅当在当前子会话内 |
| 断线续接 | 重连后 ≤2s 补齐遗漏 | — | 幂等去重 |

### 13.3 失败处理

- 连续 **3 步**违反同一 SLA → 视为该指标失守，触发对应降级（§10）并记入指标面板；
- 指标必须**可归因**：区分"模型慢 / 分类慢 / 撤回失败 / 执行慢 / 连接问题"，否则调优就是瞎调。

## 14. 需要你拍板的 2 个点（v1.0 收敛后）

> 本轮拍板已把原 P1（问 vs 做）和"急停力度"定掉（见下方"已收敛"）；剩下这两个是纯体验类型的分叉，默认值选了也会持续影响手感。

### P1. 「当前子会话」能不能由秘书自动切？

- **A. 可以自动切并告知**（"我们已经切到订单那个子会话"）：少一步操作，但可能猜错、让人跳来跳去；
- **B. 必须你显式进入**：稳定，但每次要手动点；
- **我建议**：**A + 一定约束**——只在"你明确提到某会话/子会话"时自动切，且**告知 + 一句话可撤回**（"切回上一个会话"）。
- **影响**：14 §5.1/§5.11、13 §11.6。

### P2. 打扰预算：秘书多主动？

- **A. 无条件即时回流**（子任务完成、冲突待决、高风险记忆候选，都立刻说）；
- **B. 汇总批处理**（攒到一次对话里说，减少打断）；
- **C. 只看当前子会话**（不在当前子会话就不主动说，切过去才看得到）；
- **我建议**：**按事件分级**——"任务完成/需要你拍板/失败"即时；"进展/候选记忆"汇总；其余静默。
- **通知通道（用户 2026-11-03 已确认）**：只做**站内提示**（顶栏 / 任务面板），**不做浏览器通知/声音**；频率与时机并入上面的打扰预算。
- **影响**：13 §11.3/§11.6、14 §5.2 右栏的实时程度与摘要粒度。
