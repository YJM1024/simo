# 29 · MVP/POC 脑爆 v0（发散版）

> **状态**：脑爆稿（2026-11-18）。**先发散、不筛选；后续再收敛。**
> **背景**：产品初期设计，功能全景见 [28-产品功能全景-v0](28-产品功能全景-v0.md)；系统设计见 [27](27-多智能体协作与自主能力-方案v1.md)。本文只回答一件事：**用什么最小实验证明值得做，以及怎么证明**。
> **规则**：一个 POC 只赌一个假设；允许疯狂；**预注册 kill criteria**（先写失败条件，防止自欺）；能不做就不做，能借就借。

---

## 0. 怎么用这份脑爆

1. 先看第 1 节“还没定的产品维度”——这些不是 POC，但会决定 POC 选哪个；
2. 再看第 2 节“赌注”——POC 是赌注的载体，不是功能演示；
3. 第 3 节是 44 个点子库，按赌注分组，别全做；
4. 第 5 节是 6 个套餐，选一个主 POC + 1–2 个影子实验；
5. 第 6 节是判据模板，**先写失败条件再开工**。

## 2. 赌注清单（POC 到底在赌什么）

| # | 赌注 | 如果成立 | 如果证伪 | 最先做哪个实验 |
|---|---|---|---|---|
| H1 | **记忆会复利** | 越用越值钱，形成壁垒 | 只是“上下文长一点” | 数据飞轮 POC |
| H2 | **主动有价值** | 用户少操心、愿意放手 | 变成噪音 | 影子周 |
| H3 | **多 Agent 更好** | 质量/速度赢过单 Agent | 只是贵 | 1v3 对赌 |
| H4 | **动态派生降本** | 一句话造专家 | 类型爆炸、不可维护 | 类型工坊 |
| H5 | **分级事件扛得住** | 万级不炸 | 语义被牺牲 | 事件风暴日 |
| H6 | **信任机制够用** | 敢托付自主 | 不敢放手 | 红队周 / 信任阶梯 |
| H7 | **零数据能冷启动** | 新团队也能用 | 必须靠历史数据 | 零数据冷启动 |
| H8 | **记忆可迁移** | 不被模型/厂商锁死 | 换模型即断崖 | 记忆护照 |
| H9 | **成本可接受** | 单位结果成本 < 人力 | 用不起 | 成本对赌 |
| H10 | **用户愿意付费** | 有付费意愿 | 只是“好玩” | 按结果收费试点 |
| H11 | **组织愿意采用** | 能进流程、能过合规 | 卡在采购/权限 | 设计伙伴计划 |
| H12 | **单 Agent 就够了**（反赌注） | 多 Agent 是负资产 | 协作确有收益 | 单 Agent 基线对照 |

> H12 是**反向赌注**：每个多 Agent POC 都必须先跑一个“单 Agent 基线”，否则不知道协作到底赢在哪。

## 3. POC 点子库（44 个，按赌注分组）

> 成本：低 = 几天到 1 周；中 = 2–4 周；高 = 4–8 周。风险指“做完可能白做/伤用户信任”。

### A. 记忆 / 数据（7 个）

| POC | 做法 | 证明什么 | 成本 | 风险 |
|---|---|---|---|---|
| **失忆对照** | 同一任务：带记忆 vs 清空记忆，比质量/时间/重复提问 | 记忆的真实价值（H1） | 低 | 低 |
| **记忆护照** | 记忆从 A 迁到 B（换模型/换 Agent），比迁移前后能力 | 数据可迁移（H8） | 中 | 中 |
| **数据飞轮** | 一个工作流跑 4 周，任务沉淀记忆/模板/评测，周对比 | 复利（H1） | 中 | 低 |
| **零数据冷启动** | 不给历史数据，靠访谈/导入文档起步 | 冷启动（H7） | 中 | 中 |
| **数据考古** | 扫现有设计稿/需求/评审/工单，画“组织知道什么、缺什么” | 数据可诊断 | 中 | 低 |
| **数据体检** | 找过期/冲突/重复/无来源记忆，给健康分 | 数据可治理 | 低 | 低 |
| **数据遗嘱** | 导出/删除/继承记忆；换供应商不丢数据 | 数据主权 | 低 | 低 |

### B. 自主（6 个）

| POC | 做法 | 证明什么 | 成本 | 风险 |
|---|---|---|---|---|
| **影子周** | 只观察不行动，每天给“我本来会做什么”，人审 | 主动价值 + 误报率（H2） | 低 | 低 |
| **假期测试** | 人离开 3 天，Agent 维持项目推进，每天汇报 | L2 自主 | 中 | 中 |
| **黑灯工厂** | 一晚跑 50 个任务，早上验收 | 端到端自动化 | 中 | 中 |
| **无人值守周** | 一周不干预，只看日报；记录失控点 | 自主上限 | 中 | 高 |
| **审批疲劳** | 调不同打扰频率，测接受率/烦躁度 | 打扰预算 | 低 | 低 |
| **信任阶梯** | 逐级放权：建议→执行低风险→执行中风险→自动 | 信任机制（H6） | 中 | 中 |

### C. 协作（6 个）

| POC | 做法 | 证明什么 | 成本 | 风险 |
|---|---|---|---|---|
| **1v3 对赌** | 同任务，单 Agent vs 3 Agent 团队，盲评质量/时间/成本 | 协作收益边界（H3/H12） | 中 | 中 |
| **设计评审室** | maker + critic + user advocate 评审设计稿 | 多视角提升质量 | 中 | 低 |

## 4. POC 方法创新（怎么做，比做什么更容易被忽略）

1. **预注册 kill criteria**：开工前写“什么结果算失败、失败就停”，防止事后合理化。
2. **Wizard of Oz**：先用真人假装 Agent，测体验需求，再决定要不要建。
3. **Concierge MVP**：先卖“人 + Agent”的服务，再逐步自动化。
4. **影子模式**：Agent 只记录不行动，零副作用地验证判断质量。
5. **Dogfood**：用这套系统来设计这套系统（本工作群就是现成场景）。
6. **5 天冲刺**：纸面原型 + 角色扮演 + 一天 demo，先验证“值不值得做”。
7. **设计伙伴 cohort**：3 个团队，每周复盘，换真实反馈。
8. **公开构建**：把记忆格式/评测集开源，换社区反馈与信任。
9. **红队常设**：每周一次对抗测试，把安全变成习惯。
10. **成本仪表盘**：每个 POC 都带“单位结果成本”，防止用钱买 demo。

## 5. 六个 MVP 套餐（选一个主 POC + 1–2 个影子实验）

| 套餐 | 范围 | 主赌注 | Wow | 成功判据 | 风险 |
|---|---|---|---|---|---|
| **A 记忆优先**（2–3 周） | 单 Agent + 一个真实项目 + 记忆 + 失忆对照 | H1 | “它记得比我还清楚” | 重复提问减半、一周后不愿失去 | 记忆污染、隐私 |
| **B 自主优先**（4–6 周） | 事件收件箱 + 目标监控 + 影子周 + 审批/预算 | H2 | “它自己找活，且不闯祸” | 主动任务接受率、误触发率 | 打扰、误判 |
| **C 协作优先**（4–6 周） | 设计评审室 + 1v3 对赌 + 汇总 | H3/H12 | “三个 Agent 比一个强” | 盲评质量赢、成本可接受 | 15× 成本、责任稀释 |
| **D 平台优先**（6–8 周） | 类型工坊 + 一个数据源 + 组织图 | H4 | “一句话造一个专家” | 新能力上线时间、类型不爆 | 难演示、类型爆炸 |
| **E 规模优先**（4–6 周） | 事件风暴 + 分级 + 成本表 | H5 | “万条不炸” | 覆盖率、成本/事件、延迟 | 语义质量被牺牲 |
| **F 数据飞轮**（2–4 周） | 一个团队 + 一个工作流 + 记忆/模板/评测沉淀 | H1/H9 | “越用越懂我们” | 第 4 周 vs 第 1 周：返工↓、重复提问↓、复用↑ | 数据质量、冷启动 |

**组合建议**：

- 想要**产品感**：A + B 合并 → “一周数字员工”（7 天真实角色 + 失忆对照 + 影子周 + 每日汇报）。
- 想要**设计团队落地**：C 的“设计评审室” + A 的记忆。
- 想要**长期壁垒**：F 数据飞轮（复利是唯一越跑越宽的护城河）。
- 想要**平台故事**：D 类型工坊。
- 想要**规模故事**：E 事件风暴。
- **不建议先做 E**：规模是架构约束，不是价值证明；先证明“值得做”，再证明“扛得住”。

## 7. 我的推荐（供你拍）

**如果只做一个主 POC**：**F 数据飞轮**（2–4 周）。

理由：

- 它同时验证 H1（复利）、H9（成本）、H10（付费意愿）三条最关键假设；
- 它不依赖多 Agent/万级/复杂 UI，**最容易在初期做**；
- 它的结果会直接决定后面 A–E 的优先级：如果数据不复利，整个“记忆为中心”的叙事就要重写。

**配两个影子实验**：

1. **失忆对照**（1 周）：给“记忆价值”一个硬数字；
2. **影子周**（1 周）：给“主动价值”一个误报率。
