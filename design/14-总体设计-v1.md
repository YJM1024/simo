# 总体设计 v1.8.4 —— 记忆优先的个人秘书（讨论稿）

> **状态**：**供讨论的总体设计，不是定稿**。本稿只给全貌与取舍，细节一律引用其他文档，不重复。
> **日期**：2026-11-03
> **依据用户拍板——基础（v1.0）**：
> 1. **本体**：一个秘书 + 一套记忆 + 一段连续对话；模型是可替换算力；专家/子实例只执行、不直接对用户说话；
> 2. **记忆**：结构化条目 + 自由文本附件；公共/领域层写入只允许「候选 + 记忆管理器单写者合并」；权威按类型分轴；作用域 global→domain→task→instance；读实时、写版本化；失效优于删除；
> 3. **视图**：会话 = UI 视图（不是 Agent 结构）；点节点 = 进入子会话；用户永远只跟秘书说话；默认可见祖先链，引用可实时拉取任意上下文，兄弟可实时共享；实时而非快照；
> 4. **场景**：暂不锁定，先做通用底座；产品形态 = 本地 Web 应用（React 前端 + Go 单体后端）。
> **依据用户拍板——2026-11-03 第二批（执行原则 / 撤回 / 长任务）**：
> 5. **撤回**：流式输出中被打断 → 撤回未完成的回复，看完最新消息再重答；**已完成消息不撤回**；
> 6. **调整执行**：新消息改变正在做的事 → 调整规划与执行方法；调整前写**中断点**（做到哪/为什么改/新方案/从哪继续，可恢复）；
> 7. **歧义**：真歧义先确认再执行；琐碎/可逆自己定并说明；**不猜**；
> 8. **长任务**：划分阶段；界面三栏，右栏显示长任务执行状态；
> 9. **人格**：以上属于 Agent 的整体思路 / 人格 / 执行原则，不是框架问题。
> **依据用户拍板——2026-11-03 第三批（三处 UI 细节）**：
> 10. **撤回呈现**：对话历史里被撤回的消息**只显示"已撤回"标记，不展示被撤回内容**；审计留后台、不进对话；
> 11. **调整 vs 重做**：**目标/关键约束变 → 重做；细节变 → 调整**；
> 12. **右栏**：不是"最活跃的一个任务"，而是**长任务列表页**（执行中 + 已完成；选中看详情；列表项可内联展开；细看单独开窗）。
> **依据用户拍板——2026-11-03 第四批（会话模型与术语）**：
> 13. **术语**：只用「**会话 / 子会话**」；表达聚焦用「**当前会话 / 当前子会话**」，不再用"副会话 / 子视图 / 线程 / 焦点"；
> 14. **V1 会话固定**：**不可拆分、不可合并**；**可改名，改名纯显示、无语义影响**；灵活调整留 P1；
> 15. **标签**：**V1 暂不引入**（待用户最终确认）；标签定义只作 **P1 候选**（见 §14 附录）。
> **依据用户拍板——2026-11-03 第五批（产品层）**：
> 16. **记忆可见性**：V1 记忆对用户**可见但只读**（记忆页：列表 + 作用域 + 来源 + 时间）；**不提供直接编辑控件**，修改一律通过"跟秘书对话"完成；
> 17. **产物**：V1 要**文件预览 + 下载**（长任务/汇总的产物条目带预览与下载入口）；
> 18. **通知**：只做**站内提示**（顶栏 / 任务面板），**不做浏览器通知 / 声音**；与打扰预算合并。
> **依据用户拍板——2026-11-03 第六批（主窗口与消息显示）**：
> 19. **消息显示模型**：每条消息**归属唯一**（属于一个会话/子会话），**主窗口不是归属容器**；任意会话节点可选「**仅本会话消息**」或「**本会话 + 所有递归子会话消息（按时间展开）**」；**主窗口 = 根节点的聚合视图**；同一渲染规则**逐层递归一致**；**向上同步 = 聚合视图的自然结果**（不做单独转发/同步；只显示摘要属 P1）；消息上展示**归属会话标签**、点击跳转。
> **依据用户拍板——2026-11-03 第七批（会话生命周期）**：
> 20. **会话 = 长期里程碑**：子会话可含多个任务；是否停止由用户决定，**无自动完成/超时关闭**；空闲一周可接着做、状态不丢。生命周期：**进行中 / 空闲（长期无活动，保留）/ 已归档（可选）**；**会话没有"关闭"**；**归档后只读查看**（不能继续聊），**默认允许取消归档/恢复**（技术实现标"待实现确认"）。**向上同步暂不做（P1）**，靠"查看状态 + 聚合视图"。层级：**会话/子会话（里程碑）→ 任务/阶段（执行）**，右栏长任务列表对应"执行任务"，不是会话本身。
> **依据用户拍板——2026-11-03 第八批（UI 呈现）**：
> 21. **主窗口显示（UI 呈现层）**：聚合视图显示**双方消息（用户 + 秘书）**，按时间排列；**深层消息带会话标签 + 轻缩进**标出层级；这两条属 **UI 设计（呈现层）**，明确**不属于核心架构讨论**。
> **依据用户拍板——2026-11-03 第九批（交付机制已取消 + 按需取用 + 归档/跨会话取用）**：
> 22. **交付机制已取消**：父会话通过**聚合视图**查看子会话消息；需要文件 / 产物时**按需取用**（用户在父会话对秘书说"去子会话看看，把相关文件拿出来"）。**验收走对话**：接受 / 不接受 / 改需求都用消息表达，**不引入验收按钮或状态机**；**不再有自动推送与独立验收状态**。会话**没有"关闭"**，归档可选、不是必须动作。**任务列表只放执行任务，会话不出现在任务列表**。
> 23. **归档与跨会话取用**：**归档后 = 只读查看**（不能继续聊）；**默认允许取消归档/恢复**（技术实现标"待实现确认"）。**跨会话取用**：秘书可直接查看子会话消息、处理对应文件，**就像在自己会话里一样**；**不复制文件到父会话**，按引用/原地处理。**"按需取用 + 对话验收"是 V1 的一等能力**。
> **依据用户拍板——2026-11-03 第十批（路线图前提）**：
> 24. **第一个验证场景 = 个人助理**（通用底座上的首个落地场景，见 §9）。
> 25. **旧 v0.1 骨架复用策略 = 参考其"中间件 / 工程件"**（HTTP、SSE、embed、前端构建、测试），**核心领域逻辑按新设计重写**。
> 26. **允许分阶段交付**：每个里程碑结束可**试用**；路线图按里程碑推进，不等全部做完才交付。
> **依据用户拍板——2026-11-06（Spec 不可见）**：
> 27. **Spec 永远不可见**：不出现"Spec / 规格 / 需求文档 / 验收标准 / 基线 / 增量"等内部词汇；所有 Spec 操作**投影为自然对话**；**只有三类情况打扰用户**——风险门（不可逆/动线上/删数据/花钱/影响他人）、真歧义（影响大）、用户主动要求；其余内部自己过门。**内部状态机与证据绑定不因此取消**（18 §5；本文 §4.1）。
> **依据用户追加——2026-11-06（视觉与主题）**：

> **依据用户拍板——2026-11-06（发消息不打断后台工作）**：
> 29. **发消息不打断后台工作**：用户发消息 → 秘书**即时回复** + 视需要**派发新任务**；**正在进行的任务继续跑，不取消、不暂停**。只有**显式修正/停止**（"别做 X / 停掉 / 改成 Y"）才 steer/cancel。**两条回路分离**：**对话回路**（始终可用、不等任务）与**执行回路**（后台任务/子智能体独立推进、完成回流）；**撤回只作用于流式未完成的对话回复，不作用于后台任务**；资源约束靠**并发上限/预算**，不靠"等上一个做完"（本文 §4.2；13 §11.10）。

## 1. 一句话定位

> **一个以记忆为主体的个人秘书**：你与它只有**一段连续对话**，它记得你说过的一切；需要干活时它把任务派给**专家实例**执行，专家不跟你说话。界面是**三栏**：左边**会话树**（会话 / 子会话），中间**当前子会话的对话**，右边**长任务列表页**（执行中 + 已完成，可看阶段与步骤）。产物可**预览与下载**，记忆可**看**但本期**只读**。

它**不是**：

- 不是"一问一答的聊天机器人"——对话连续，可随时插话、随时更正；
- 不是"多个 agent 各说各话的团队界面"——你永远只跟秘书说；
- 不是"事件 → 工单 → 执行"的调度系统——你的输入才是驱动力。

## 2. 本体：一个秘书 + 一套记忆 + 一段对话

### 2.1 五条骨架

| # | 组成 | 一句话 | 依据 |
|---|---|---|---|
| 1 | **一个秘书** | 唯一的人机接口：理解、讨论、拆解、派工、验收、汇总、转述 | 【拍板】10 §4、§9、§10 |
| 2 | **一套记忆** | 身份、知识、连续性、沉淀都在记忆里；秘书与专家共读同一套 | 【拍板】10 §5 |
| 3 | **一段连续对话** | 人可读的消息只有一份；会话 / 子会话是对它的视图 | 【拍板】10 §9 |
| 4 | **模型 = 可替换算力** | 换模型不改变"这个 agent 是谁"；身份 = 记忆 + 作用域 | 【拍板】10 §5 |
| 5 | **专家实例 = 记忆的临时视图** | 按需 spawn、有私有工作集、只执行不对话、结束提交候选记忆与产物 | 【拍板】10 §5、§10 |

### 2.3 概念归属：哪些在 Agent 侧，哪些只是界面

| 概念 | 归属 | 说明 |
|---|---|---|
| **对话** | Agent 侧（数据） | 你和秘书之间唯一的人可读消息流；每条消息带 `sessionId`（归属唯一） |
| **任务 / 阶段** | Agent 侧（结构） | 会话里的**执行单位**（阶段 = 有明确完成标准的里程碑）；右栏长任务列表对应执行任务 |
| **记忆作用域** | Agent 侧（数据） | 记忆的归属与可见范围，global→domain→task→instance |
| **长任务阶段 / 中断点** | Agent 侧（数据） | 阶段划分、做到哪、可恢复点；是右栏的**数据源**，不是右栏本身 |
| **产物** | Agent 侧（数据） | 长任务/汇总产出物；**预览与下载是 UI 能力**，产物本身是文件/条目 |
| **执行轨迹** | Agent 侧（数据，默认折叠） | 专家的工具调用与内部过程；不混入对话 |
| **会话 / 子会话 / 会话树** | **组织层（UI 视图 + 里程碑）** | 长期里程碑：可含多个任务；**V1 固定：不可拆分/合并；可改名（纯显示）**；生命周期见 §5.1c |
| **会话生命周期** | **组织层（状态）** | 进行中 / 空闲（长期无活动，保留）/ 已归档（可选）；**没有"关闭"**；无自动完成/超时关闭 |
| **归档** | **组织层（状态 + 视图约束）** | 归档后**只读查看**（不能继续聊）；**默认允许取消归档/恢复**（技术实现待确认） |
| **跨会话取用** | **Agent 侧能力（读取/处理）** | 秘书可直接查看子会话消息、处理对应文件，像在自己会话里一样；**不复制文件到父会话**，按引用/原地处理 |
| **当前会话 / 当前子会话** | **UI 侧（状态）** | 你此刻正在看的那一个；切过去 ≠ 换 Agent，也不叫"焦点" |
| **主窗口 / 聚合视图** | **UI 侧（视图）** | 根节点的聚合视图；显示双方消息按时间排列；**不是归属容器**（归属仍在各自会话） |
| **长任务列表页 / 记忆页 / 站内提示** | **UI 侧（视图）** | 展示层；不另存状态、不直接改数据 |

**支点**：记忆不因会话归档而消失；权限挂在数据上，不挂在"会话"上；会话 V1 结构固定，**改名只是换显示**。

### 2.4 四条全局硬规则

1. **用户只跟秘书说话**——专家不直接对用户输出（只出执行轨迹 / 候选记忆）【拍板】；
2. **记忆是唯一真相**——实例可随时被杀，重启不丢连续性；"身份"不在进程里，也不在会话里；
3. **公共/领域层单写者**——执行实例永远不直接改公共记忆，只能提交候选（12 §5）；
4. **当前子会话不改变权限**——切到哪个子会话只改变"展示什么、优先加载什么"，秘书始终拥有全部记忆的读权【拍板 10 §10】。

## 4. 交互（摘要，细节见 13）

> **一句话**：把"轮"换成"步"——用户随时说；**没在流式输出时**在语义段边界吸收，**正在流式输出时**被打断就撤回未完成回复、看完最新消息再重答。

你只需要知道五件事：

1. **三速响应**：任何消息 1 秒内必有可感知信号（S0）→ 首段实质（S1）→ 执行期间推进/心跳（S2），**永不无响应**；
2. **四类消息智能处理**：Ack（确认，不撤回）、Refine（补充，对话撤回重答但不打断执行）、Correct（显式纠偏，撤回重答 + steer/cancel 受影响任务）、NewTask（新目标，**默认并行**：旧任务继续、新开一条线）；
3. **撤回与中断点**：未完成回复撤回后**只留"已撤回"标记**；换方式/被打断时写**可恢复的中断点**；
4. **先确认 or 直接做**：真歧义先问；琐碎/可逆自己定并说明；不猜。**偏好学习层暂缓**，本期按默认阈值（13 §5.5）；
5. **发消息不打断后台工作**：普通消息默认并行；只有显式修正/停止才 steer/cancel（§4.2）。

完整协议（状态机、Intent Frame、合并窗口、抢占边界、降级、不变量、SLA、2 个待拍板点）在 [`13-交互协议-候选方案.md`](13-交互协议-候选方案.md)。

### 4.1 Spec 不可见原则：内部执行流程对用户完全透明（用户 2026-11-06 已确认）

> 执行流程是 SDD（Spec → Development），但 **Spec 是 Agent 的内部真相层**：用户只提交需求与背景，**不操作、不感知 Spec**。用户侧**不出现**"Spec / 规格 / 需求文档 / 验收标准 / 基线 / 增量"等内部词汇；所有 Spec 操作**投影为自然对话**。

| Spec 内部操作 | 用户看到的话（投影） |
|---|---|
| **Spec 建立/更新** | 通常**不说**；需要时一句"好的，我记下了 / 按这个理解做" |
| **Spec 拆分** | "我把它拆成两条线：X 和 Y，可以吗？"（**仅需确认时**） |
| **Spec 澄清** | 直接问"你说的 X 是指 A 还是 B？" |
| **Plan 需确认（风险门）** | 展示**方案摘要** + "确认这么执行吗？" |
| **执行进展** | 只说**结果/状态**（"第一步做完了，在跑验证"） |
| **验收** | "结果如下…这样可以吗？" |
| **风险动作前** | "这一步会改线上 / 删数据 / 花钱，确认吗？" |
| **Spec 归档** | **不说**，除非用户问 |

**只有三类情况打扰用户**：① **风险门**（不可逆 / 动线上 / 删数据 / 花钱 / 影响他人）；② **真歧义**（影响大，13 §5.5）；③ **用户主动要求**。其余内部自己过门。

- 与记忆的关系：**记忆页只读可见（§5.6）↔ Spec 不可见**，两条线不混；
- 内部状态机/证据绑定**不因"不可见"而取消**（详见 [`18-SDD流程-v0.md`](18-SDD流程-v0.md) §5）；用户的"验收"仍走对话（§4 第 4 条），无验收按钮/状态机。

### 4.2 对话回路 / 执行回路分离：发消息不打断后台工作（用户 2026-11-06 确认）

> 核心：**用户发消息 ≠ 打断当前任务**。发消息只进入**对话回路**；**执行回路**独立推进。只有**显式修正/停止**（"别做 X / 停掉 / 改成 Y"）才 steer/cancel。

| 回路 | 负责 | 何时可用 | 与其他回路的关系 |
|---|---|---|---|
| **对话回路** | 读消息、即时回复、澄清/确认、派发/调度任务 | **始终可用**，不等执行 | 派发后不等待；执行完成/需确认时回流 |
| **执行回路** | 后台任务 / 子智能体 / 长任务推进 | 后台持续 | **不因普通新消息暂停/取消**；完成回流 |

**默认规则**：

1. 新消息 → **默认并行**：即时回复 + 视需要派新任务；**旧任务继续跑**；
2. 只有**显式修正/停止**才进入 steer/cancel：影响哪条任务就调整哪条（steer），或停对应任务（cancel，保留中断点）；
3. **撤回只作用于流式未完成的对话回复，不作用于后台任务**（后台任务是"已完成/需确认"，不是可撤回的流式回复）；
4. 资源约束靠**并发上限 / 预算 / 内部排队**，**不靠"等上一个做完"**；队列对用户不可见。

**示例（用户 2026-11-06）**：用户在秘书做一件事时连发三条不同任务 → 对话回路分别即时回复（互不阻塞）→ 执行回路开三条并行线（三个子会话/任务）→ 完成后各自汇报、秘书汇总；若其中一条是"停掉刚才那个"，只 cancel 对应任务，其余继续。

**与 13 的关系**：细节（消息分类、抢占矩阵、I6 不变量）见 [`13-交互协议-候选方案.md`](13-交互协议-候选方案.md) §11.10；本文只定交互层原则。

### 5.1b 主窗口与消息显示（UI 呈现层，【用户 2026-11-03 已确认】）

| 规则 | 内容 |
|---|---|
| **归属唯一** | 每条消息（用户/秘书/执行轨迹）只属于一个会话/子会话；**主窗口不是归属容器** |
| **主窗口** | = **根节点的聚合视图**（含全部子会话），所以显示所有消息；所有权仍在各自会话 |
| **两种显示方式** | 任意会话节点可切「**仅本会话消息**」/「**本会话 + 所有递归子会话消息（按时间展开）**」 |

### 5.1c 会话生命周期与按需取用（【用户 2026-11-03 已确认】）

**1. 会话 = 长期里程碑**

- 子会话可包含**多个任务**；**没有自动完成 / 超时关闭**；
- 是否停止由用户决定；**会话没有"关闭"**，只有**可选归档**（不是必须动作）；
- 空闲一周后可**接着做**，状态不丢（读状态 + 中断点继续，13 §9）。

**2. 生命周期状态（2 态 + 可选归档）**

| 状态 | 含义 | 进入 / 退出 |
|---|---|---|
| **进行中** | 有活动（对话 / 执行） | 新建或从空闲恢复；转空闲 |
| **空闲** | 长期无活动；**保留**，可随时恢复 | 无活动达阈值（【讨论中】）；用户说话 / 任务恢复即回到进行中 |
| **已归档**（可选） | 不代表"关闭"，只是收起来；**归档后只读查看（不能继续聊）** | 用户主动归档；**默认允许取消归档 / 恢复**（技术实现标"待实现确认"） |

- **没有"关闭"语义**：不设关闭按钮 / 关闭状态机；归档只是可选的整理动作。

**3. 交付机制已取消：父会话按需取用 + 对话验收（用户 2026-11-03 已确认）**

- 父会话了解子会话：**聚合视图看消息**（5.1b）+ 随时查看状态（进度、未决）；
- **按需取用**：用户在父会话对秘书说"去子会话看看，把相关文件拿出来"，秘书按需读取 / 转述 / 预览 / 下载，**不自动推送、不自动复制**；
- **跨会话取用（V1 一等能力）**：秘书可直接查看子会话消息、处理对应文件，**就像在自己会话里一样**；**不复制文件到父会话**，按引用 / 原地处理；
- **验收走对话**：接受 / 不接受 / 改需求都用消息表达；**不引入验收按钮或状态机**；
- **没有自动推送、没有独立交接包、没有独立验收状态**。

**4. 层级**

```
会话 / 子会话（长期里程碑）
  └─ 任务 / 阶段（执行单位；阶段 = 有明确完成标准的里程碑）
```

- **任务列表只放执行任务，会话不出现在任务列表**；
- 右栏对应"里程碑下的执行任务"，不是会话本身。

**5. 向上同步暂不做（P1）**：父会话了解子会话靠"**查看状态 + 聚合视图**"（5.1b），不做额外机制。

### 5.2 右栏：长任务列表页（【拍板·11-03】）

**不是**"当前最活跃的一个任务"，而是**列表页**：

| 元素 | 内容 |
|---|---|
| **列表** | **执行中的长任务 + 已完成的长任务**（不是只显示一个） |
| **列表项** | 任务名、状态（进行中/已完成/失败/阻塞）、阶段进度、最后更新时间 |
| **内联展开** | 列表项可直接展开：阶段 / 步骤概要（不跳页） |
| **选中看详情** | 展开该任务的阶段、步骤、已完成/进行中/待办、中断点、**产物入口** |

### 5.3 长任务阶段化（【拍板·11-03】）

- **阶段 = 有独立验收的里程碑**；每阶段至少声明：目标 / 验收 / 预计产物 / 依赖 / 可中断点；
- 阶段数建议 **3–7 个**【讨论中】；
- 阶段结束 → 阶段小结 + 写中断点 + 右栏更新 + 汇总候选；
- 长任务的**阶段/步骤状态**（未开始/进行中/已完成/失败/阻塞）就是右栏展示的主内容；
- 阶段之间是天然检查点；抢占/重规划优先在阶段边界发生（流式中仍按 13 §8.3 撤回）。

### 5.5 撤回在界面上怎么呈现（【拍板·11-03】）

- 被撤回的消息在**对话历史里只显示"已撤回"标记**，**不展示被撤回的具体内容**；
- 原文与撤回记录留在**审计后台**（可追溯：谁、何时、为什么、撤前说到哪），**不进入对话**；
- 重答紧接在"已撤回"标记之后，不引用被撤回内容（除非你明确要求"刚才说的那个"）；
- "用户说停"与"被打断撤回"用同一种呈现。

### 5.6 记忆页：可见但只读（V1，【拍板·11-03】）

| **能查到什么** | 来源可追溯到 episode（12 §2.5）；冲突条目有 `disputed` 标记（12 §5.9） |
| **偏好页** | 属人格/偏好层，**暂缓、不在本期界面**（§9） |

### 5.7 通知：只做站内提示（V1，【拍板·11-03】）

| 项 | V1 约定 |

| **与对话的关系** | 站内提示只是"入口 + 一句话状态"；完整内容在当前子会话里读，不另开通知中心（V1） |

### 5.8 上下文可见性（【拍板 10 §7】）

| 规则 | 内容 |
|---|---|
| **默认** | 只自动看到**祖先链**的上下文（会话树上的父链） |
| **引用** | 引用任意会话 → 可**实时拉取**它的上下文（不限于祖先） |
| **兄弟** | 兄弟子会话之间**可实时共享**（同一个父之下） |
| **时效** | **实时，不是快照**：子会话运行期间，父/兄弟的新消息也要看得到 |

**Agent 侧规则与 UI 侧规则分开**（10 §9 未收口的点）：

- **Agent 侧**：执行时按**任务作用域**取上下文（默认祖先 + 显式引用）；
- **UI 侧**：按**同一棵会话树**呈现（默认祖先链可见、引用可展开）；
- **当前子会话本身不构成权限**，秘书始终能读全部记忆。
- 落位见 12 §8.2/§8.3；【讨论中】"默认祖先链"在 Agent 侧的具体取用规则仍需与记忆视图组装（12 §4.3）对齐。

### 5.9 两份流

| 流 | 内容 | 默认 |
|---|---|---|
| **对话流** | 你和秘书的往来（人可读；含"已撤回"标记） | 常显（中栏） |
| **执行轨迹** | 专家的工具调用、内部推理、产物 | **折叠**，按需展开（可单独开窗） |

两者不能混在一份日志里，否则对话会被工具调用淹没（10 §10）。

### 5.10 术语表（v1.7 统一）

| 词 | 含义 |
|---|---|
| **对话** | 你和秘书之间唯一的人可读消息流（只有一份） |
| **会话 / 子会话** | 长期里程碑（可含多个任务）；V1 固定结构、不可拆分/合并、可改名（纯显示） |
| **会话生命周期** | 进行中 / 空闲（长期无活动，保留）/ 已归档（可选）；**没有"关闭"**；无自动完成/超时关闭 |
| **归档** | 可选整理动作；归档后**只读查看**（不能继续聊）；**默认允许取消归档/恢复**（技术实现待确认） |
| **任务 / 阶段** | 会话里的执行单位；右栏长任务列表对应执行任务，不是会话本身 |
| **按需取用** | 在父会话里要求秘书"去子会话看看，把相关文件拿出来"；不推送、不自动回流 |
| **跨会话取用** | 秘书可直接查看子会话消息/处理文件，像在自己会话里一样；**不复制文件到父会话**，按引用/原地处理（V1 一等能力） |
| **当前会话 / 当前子会话** | 你此刻正在看的那一个（UI 状态）；不再用"焦点" |
| **会话树** | 会话 / 子会话的层级导航（UI 组织，不是 Agent 状态） |
| **主窗口 / 聚合视图** | 根节点的聚合视图；显示双方消息按时间排列；不是归属容器；可切「仅本会话 / 含递归子会话」 |
| **长任务列表页** | 右栏视图：执行中 + 已完成长任务的列表与详情入口 |
| **产物** | 长任务/汇总的文件产出；V1 支持预览 + 下载 |
| **记忆页** | V1 可见只读的记忆列表（作用域/来源/时间需可见） |
| **站内提示** | V1 唯一通知通道（顶栏/任务面板），无浏览器通知/声音 |
| **中断点** | 被打断/换方式时写下的"做到哪、为什么改、从哪继续"（13 §9） |
| **执行轨迹** | 专家/子实例的内部过程，默认折叠 |
| **记忆作用域** | 记忆的归属（Agent 侧），与会话无关 |

**停用**：副会话、子视图、线程、焦点（作名词）。

### 5.12 视觉与主题系统（用户 2026-11-06 追加）

**默认主题 = `theme-light-tech`（浅色科技风 / 未来感）**：

- **浅底 + 冷色点缀**（青/蓝/紫），细边框（1px、低对比）、**轻玻璃感**（半透明 + 背景模糊，仅用于顶栏/浮层/弹层）、**克制动效**（≤150–200ms，尊重 `prefers-reduced-motion`）；**首版不做暗黑风**。
- 视觉目标：干净、未来感、信息密度高但不拥挤；避免"暗黑 + 霓虹"风格。

**主题 = 语义 token 集（唯一着色入口）**：

| 类别 | token（示例） |
|---|---|
| 颜色 | `bg / surface / elevated / border / text / textMuted / accent / accentSoft / success / warning / danger / info / focusRing` |
| 字体 | `fontFamily / baseSize / typeScale / lineHeight / weight` |
| 间距 | `space-1..8`（4/8/12/16/24/32/48/64） |
| 圆角 | `radius-sm / md / lg / full` |
| 阴影 | `shadow-sm / md / lg / glass` |
| 动效 | `motion-duration-fast/base / motion-easing` |

- **组件只消费 token，禁止硬编码颜色/圆角/阴影**；新增 token 必须进主题注册表并过 schema。
- 主题 = 一份 token 值集合；组件不感知主题名，只读 CSS 变量。

**主题注册表 + 校验 + 预览 + 持久化**：

- **注册表**：`themes`（DB/JSON）字段 `id / name / tokens / extends? / version / preview / status`；内置 `theme-light-tech`（V1 唯一正式主题）。
- **完整性校验**：必填 token 齐全、引用存在、token 类型正确；缺项拒绝启用（不允许"半套主题"）。
- **对比度 AA 校验**：正文 ≥4.5:1、大字号 ≥3:1、focus ring 可见；不达标拒绝上线/标 warning。
- **预览**：设置页可切换预览（不保存也能看）；**持久化**：用户偏好存 DB/配置；渲染层用 `data-theme` + CSS 变量注入，组件层不感知。
- **可访问性**：焦点态、键盘可达、动画减弱三件套随主题一起校验（不单列"无障碍"大工程）。

**未来 256 个主题（P1）**：

- 由 **16 基础色板 × 16 强调/质感变体**组合生成（或 4 轴组合：base hue / contrast / radius / glass+motion），**不手工画 256 套**；
- 复用同一注册表/校验/预览/持久化；**主题市场式扩展**（导入/导出/社区主题）P1 之后；
- V1 只交付 `theme-light-tech` + token 架构；**切换接口用 `data-theme` 预留**（M1 不做切换 UI，只留接口）。

**边界**：主题只影响呈现，不影响 Spec/记忆/权限/交互协议；不做暗黑风、不做移动端适配、不做多语言（§9）。

## 6. 汇总：结果写回记忆 + 按需查看（交付机制已取消）

**触发**：任务结束 / 阶段结束 / 用户要求汇总 / 用户主动问"子会话怎么样了"。

```
专家实例结束（或阶段结束）
  → 结果与候选记忆（按 12 §5 写入；不向父会话推送）
  → 秘书在子会话里转述（摘要 + 指针；产物给预览/下载入口）
  → 记忆管理器按候选合并，蒸馏写回父作用域（12 §5）
  → 你在当前子会话、或通过聚合视图看到；需要时对秘书说"去子会话看看，把相关文件拿出来"
```

- **交付机制已取消：父会话按需取用 + 对话验收**（用户 2026-11-03 已确认）——结果不会自动出现在父会话；父会话要看就切子会话或开聚合视图；要文件就对秘书说那句话，按需取用；
- **验收走对话**：你在对话里说"可以 / 不行 / 改成…"，没有验收按钮和状态机；
- **产物按需取用 + 跨会话取用**：秘书可以直接查看/处理子会话文件，**不复制**（按引用 / 原地）。

三层分开看：

| 层 | 汇总产物 | 给谁 |
|---|---|---|
| **对话层** | 几行摘要 + 待确认项 + 产物指针（可预览/下载） | 你（子会话内） |
| **任务层** | 任务结果 + 阶段小结（结构化，可审计） | 秘书 / 右栏 |
| **记忆层** | 新版本条目（决策、进展、经验候选） | 之后所有实例 |

**仍待讨论**：汇总由秘书做，还是起专门的汇总实例（当前建议：秘书；推断）。

## 7. 形态与技术形态

### 7.1 产品形态【拍板 10 §2】

- **本地 Web 应用**：本机跑服务，浏览器打开使用；
- **前端 React**；**后端 Go 单体**；单机、单实例，不做分布式。

### 7.2 工程建议（未拍板，供路线图讨论）

| 项 | 建议 | 理由 |
|---|---|---|
| 部署 | Go `embed.FS` 内嵌前端，单二进制 | 部署 = 拷一个文件 |
| 传输 | POST 提交 + SSE 推送 | 比 WebSocket 简单，可换 |
| 存储 | SQLite（纯 Go 驱动） | 单文件、易备份 |
| 并发 | 单写者入口，DB 是持久化投影 | 与记忆管理器同构 |
| 三栏前端 | 左树 / 中对话 / 右列表页，可单独开窗 | 常规 Web 布局，不引入额外机制 |
| 产物 | 静态文件 + 下载接口（带最简访问校验），预览走单独窗口 | 本机场景够用 |
| 站内提示 | 走 SSE 事件到顶栏/右栏，**不接系统通知 API** | 与"不做浏览器通知/声音"一致 |

### 7.3 v0.1 骨架复用策略（【用户 2026-11-03 已确认】）

- **只复用"中间件 / 工程件"**：HTTP 服务、SSE 通道、`embed.FS` 内嵌、前端构建链、测试骨架——这些与领域无关，v0.1 已验证可用；
- **核心领域逻辑按新设计重写**：会话/消息归属、记忆作用域与候选写入、长任务/阶段、中断点、撤回、主窗口聚合、按需取用——都不沿用 v0.1 的占位实现；
- 判断标准：**能替换 `Reply`/`Store` 就保留**，**需要改领域模型就重写**；不在旧骨架上继续演进（10 §3、§11）。

### 7.4 门禁与分阶段交付（【用户 2026-11-03 已确认：允许分阶段交付】）

- **硬门禁**：① 设计讨论清楚并由你拍板；② 你确认"设计没问题"；③ 产出开发路线图；④ 之后才写实现代码。
- **分阶段交付**：路线图按里程碑推进，**每个里程碑结束即可试用**（一个可运行版本 + 已知限制），不等全部做完才交付；
- 每个里程碑验收看"**能用**"而不是"**全做完**"：典型第一里程碑 = 三栏 + 对话 + 会话树 + 记忆只读页 + 站内提示的最小闭环；
- 本文档是**设计文档**，不指导现在写码。

## 8. 执行原则（人格）：可检查的协议行为，不是口号

> **用户原话要点（2026-11-03）**："这可能不是在说框架设计的问题，而是在说 Agent 的整体思路、人格或者执行原则问题。假设一件事情不确定，你就应该问我，问清楚之后再执行。"【拍板·11-03】

### 8.1 六条原则

| # | 原则 | 一句话 |
|---|---|---|
| 1 | **不猜** | 不确定就问清楚再执行；不把默认值当用户意图 |
| 2 | **真歧义先确认** | 两种解释导致实质不同的动作 → 先问（1 个问题 + 选项 + 我的建议） |
| 3 | **琐碎/可逆自己定** | 设自主决定阈值，自己做主并一句说明，不打断 |
| 4 | **被打断先撤回** | 流式中被打断 → 撤回未完成回复，看完最新消息再重答；已完成不撤回 |
| 5 | **正在做的事会被改变就调整** | 重规划（继续/改派/分叉/中止）；先写中断点再改；目标/关键约束变 → 重做，细节变 → 调整 |
| 6 | **长任务分阶段、可恢复** | 阶段化推进，阶段可见；中断点可恢复 |

### 8.2 原则落到机制（可检查）

| 原则 | 落到哪 | 检查点 |
|---|---|---|
| 不猜 / 先确认 | 13 §5.5 真歧义判定 + 问题预算 ≤1 | 回放：歧义消息必须出现确认，且不得推进不可逆部分 |
| 自主决定阈值 | 13 §5.5.3（可逆/低风险/不影响验收/成本低/有默认） | 回放：琐碎决策有"一句说明"，无追问 |
| 撤回 | 13 §3.2/§8.3/§8.5、本文 §5.5 | 回放：流式中注入改变性消息 → 撤回标记 + 重答 |
| 调整/重做 | 13 §11.3 | 回放：目标变 → 重做；细节变 → 调整；均有中断点 |
| 中断点 | 13 §9；右栏展示（§5.2） | 中断点可读、可恢复、可追溯 |
| 长任务阶段 | 13 §11.4；右栏（§5.3） | 阶段/步骤状态可见，阶段结束有小结 |

### 8.3 边界（防止"人格"变成越权）

- **自主 ≠ 没说明**：自己决定的事要一句说明，并记入 Frame 的 `selfDecisions[]`（13 §6.1）；
- **撤回的是文本，不是事实/动作**：外部动作不可撤回，只能报告"已发生"（13 §8.4）；
- **完成的消息不撤回**：修正只能通过后续回复明确更正；
- **偏好/习惯学习本期不做**：只留"决策时可查询偏好"接口占位（13 §5.5.3b、12 §2.8）；不因此启用任何"人格档案"。

### 9.3 产品功能设计（概要）

> **用户 2026-11-03 已确认**：第一个验证场景 = **个人助理**；本节只给模块概要（是什么 / 怎么用 / 关键规则），细节见 13（交互）、12（记忆），实现细节留给路线图。

| 模块 | 是什么 | 怎么用 | 关键规则 |
|---|---|---|---|
| **对话** | 你和秘书的唯一入口（中栏） | 随时发消息、连续步进；插话/更正/新任务都直接说 | 流式中被打断 → 撤回重答；四类消息（Ack/Refine/Correct/NewTask）；真歧义先问、琐碎自己定并说明（13） |
| **会话树与消息归属** | 左栏的会话 / 子会话树；每条消息归属唯一会话 | 点节点 = 切当前子会话；改名只改显示 | 主窗口 = 根节点聚合视图；双方消息按时间、深层消息带标签 + 轻缩进；可切「仅本会话 / 含递归子会话」；V1 不可拆分/合并（14 §5） |
| **长任务** | 右栏的列表页：执行中 + 已完成 | 内联展开看阶段/步骤；选中看详情；细看单独开窗 | 长任务分阶段 + 中断点可恢复；任务列表只放执行任务，不放会话（13 §9/§11.4） |
| **记忆** | 记忆页（V1 只读） | 按列表看内容、作用域、来源、时间 | 无直接编辑控件，修改一律通过对话；候选 + 单写者；本期不含偏好学习（12 §5、§10） |
| **跨会话取用** | 秘书在会话之间读取/处理的能力 | 在父会话说"去子会话看看，把相关文件拿出来" | 可直接查看子会话消息、处理文件，像在自己会话里一样；**不复制文件**，按引用/原地处理（V1 一等能力） |
| **通知** | 站内提示（顶栏 / 任务面板） | 任务完成 / 需要拍板 / 失败时出现入口 | 不做浏览器通知/声音；频率并入打扰预算（13 P2） |
| **设置** | 最小设置入口（概要） | 模型、存储位置、仅本机/局域网、通知开关、归档恢复等 | 只保留必要项，细节与实现留给路线图；人格/偏好设置**暂缓** |
| **个人助理 V1 能力** | 首个验证场景的四件事 | 见下方拆分 | 通用底座 + 助理场景包，不写死在核心里 |

**个人助理 V1 能力（概要）**：

| 能力 | 是什么 / 怎么用 | 关键规则 |
|---|---|---|
| **待办** | 从对话与记忆里整理待办；在会话里查看、完成、改期 | 抽取为候选，你确认后建；不自动替你决定优先级（讨论中） |
| **提醒** | 到点在站内提示（顶栏/任务面板） | 不做系统通知/声音；时间、重复、提前量用对话设置 |
| **文件处理** | 上传 / 引用文件；预览、下载；在会话间按需取用 | 不复制到其他会话，按引用/原地；产物带预览/下载（14 §5.4） |
| **信息整理** | 把对话、文件、记忆整理成摘要/清单/文档 | 产物可预览/下载；整理结果写回走候选记忆（12 §5） |

> 以上是**功能概要**，不是交互细节清单；每条的具体流程与验收在技术路线图阶段展开。

## 11. 与 Super-agent 参考素材的取舍

> 参考素材：[`../archive/research/super-agent-report.md`](../archive/research/super-agent-report.md)、[`01-基线-Super-agent机制.md`](01-基线-Super-agent机制.md)、[`02-参考架构建议.md`](02-参考架构建议.md)。

### 11.1 一句话对比

| | Super-agent（参考素材） | 本设计 |
|---|---|---|
| 驱动源 | 环境事件，人可不在场 | **人在对话里持续输入**，人始终在场 |
| 组织单位 | 工单 + 事件流（参考素材的概念） | **任务 + 会话树（会话 / 子会话）**，会话只是视图 |
| 并发单位 | Worker Session（一工单一 Session） | **专家实例**（按需 spawn，共享同一套记忆） |
| 汇总 | 报告 + 人肉验收 | **结果写回候选记忆**；父会话按需查看/取用 |
| 人的角色 | 退到验收层、平时静默 | **随时在场**；不确定就问，不猜（§8） |

一句话：它是「**事件 → 工单 → 执行**」，我们是「**记忆 → 实例 → 执行 → 沉淀**」。

### 11.2 借的四条机制（不借概念）

| 借什么 | 落到哪 |
|---|---|
| **秘书不下场干活** | 单一接口 + 派发的结构原因 |
| **上下文用引用而非全量** | 检索 + 证据指针（12 §4.3） |
| **并发与隔离的做法** | 一实例一私有工作集、并发上限、可换模型 |
| **单写者 + append-only + 恢复注记** | 记忆管理器（12 §5）、只追加版本（12 §2.7）、崩溃重放 |

### 11.3 明确不借

- **工单作为一等公民**：结构单位是任务 + 会话树，不是工单；
- **事件驱动总线 / 准入授权模型**：单人单机不需要；
- **事件流订阅模型**：上下文共享用"作用域 + 引用 + 实时"，不用订阅承载权限；
- **A2A / 存算分离 / BYOM**：单机不碰；
- **"人会退到验收层、平时静默"**：你的设计是人随时在场、随手插话。

**原则**：借**机制**，不借**领域模型**。
