1. **六个扩展维度**：功能、场景、用户、交互、商业、创新概念。
2. **功能维度补 14 个方向**（约 60 条想法），重点补“时间/关系/情绪/创造/模拟/谈判/组织/具身/多模态/知识资产/个性化/跨端”。
3. **场景维度补 24 个场景**，筛出 3 个 POC 候选。

6. **12 个 POC 实验 + 12 个风险/反模式**，最后给筛选矩阵。

# 4. 用户维度扩展（6 类角色）

| 角色 | 要什么 | 怕什么 | 用/买/批 |
|---|---|---|---|
| 个人贡献者 | 少干活、少被打断 | 不可控、抢功劳 | 用 |
| 团队负责人 | 进度、质量、成本可控 | 失控、背锅 | 用 + 买（小） |
| 运营经理 | 事件不丢、SLA、报表 | 漏事、假完成 | 用 + 买 |
| 高管 | ROI、风险、组织效率 | 事故、合规、失控 | 批 + 买（大） |
| 外部客户 | 快速响应、准确 | 机器人感、泄露 | 用（被动） |
| IT/合规 | 安全、权限、审计、集成 | 数据泄露、越权 | 批 |

**产品启示**：

- **用的人、买的人、批的人不是同一个**——功能树要有“管理者视图/审计视图/ROI 视图”，不能只做“执行者视图”；
- 个人贡献者要“省事”，负责人要“可控”，高管要“可衡量”，IT 要“可管”。这四套视图建议进 28 v1 的“人机协作/治理”域。

# 6. 商业维度扩展（9 种模式）

| # | 模式 | 怎么收钱 | 优点 | 缺点 | 适配 |
|---|---|---|---|---|---|
| B1 | 席位订阅 | 按人/月 | 简单、可预测 | 与用量脱节 | 团队版 |
| B2 | 按任务 | 按任务/工作项 | 公平、易理解 | 计量复杂 | POC 后 |
| B3 | 按结果 | 按验收通过付费 | 强信任、好卖 | 验收争议 | 高风险场景 |
| B4 | 按节省时间分成 | 省下的人力成本分成 | ROI 直观 | 归因难 | 企业 |
| B5 | 行业包 | 按行业方案收费 | 客单价高 | 交付重 | P1 |
| B6 | 私有化/混合部署 | license + 实施 | 大客户 | 销售周期长 | P1 |
| B7 | Agent 市场抽成 | 交易抽成 | 生态 | 早期没量 | P2 |
| B8 | 开源 + 企业版 | 社区免费、企业收费 | 获客快 | 商业化慢 | P2 |
| B9 | 咨询/实施 | 人天 | 现金流 | 不规模化 | 早期 |

**早期建议**：席位订阅（B1）+ 按任务（B2）双轨；按结果（B3）作为差异化试验，不要一开始全押。

# 8. 风险与反模式（12 条）

| # | 风险/反模式 | 表现 | 缓解 |
|---|---|---|---|
| R1 | 过度自主 | 不该做的也做、越权 | 自主等级、审批、预算、kill switch |
| R2 | 责任真空 | 出错没人认 | 单一 owner、审计、决策回放 |
| R3 | 幻觉/自信错 | 说得像真的 | 证据链、独立验收、引用 |
| R4 | 记忆污染 | 错误记忆扩散 | 候选制、来源分级、回滚、纠错 |
| R5 | 隐私泄露 | 跨人/跨域串数据 | 记忆隔离、最小权限、脱敏 |
| R6 | 提示注入 | 被外部内容带偏 | 程序 Gate、内容隔离、工具白名单 |
| R7 | 成本失控 | 多 Agent 扇出烧钱 | 预算、按模式计费、收敛上限 |
| R8 | 打扰过度 | 主动变噪音 | 打扰预算、静默、聚合 |
| R9 | 依赖/技能退化 | 人不会干了 | 可解释、可接管、保留人工路径 |
| R10 | 群体思维 | Agent 互相附和 | 独立证据、红队、匿名投票 |
| R11 | 功能堆砌 | 什么都有、什么都不好用 | 场景包、优先级、砍功能 |
| R12 | 拟人化过度 | 用户期待错位 | 明确“它是工具/同事”，不承诺意识 |

# 9. POC 实验清单（12 个）

| # | 实验 | 假设 | 方法 | 通过标准 |
|---|---|---|---|---|
| E1 | 单场景端到端 | 设计评审闭环能被人接受 | 一个场景包跑 20 个真实任务 | 接受率 ≥ 60%，返工 ≤ 30% |
| E2 | 跨会话记忆 | 记忆能减少重复解释 | 同一用户跨 5 天/3 个会话 | 重复提问率下降 ≥ 50% |
| E3 | 主动任务 | 主动发起有价值 | 目标监控触发 20 次 | 接受率 ≥ 40%，误触发 ≤ 20% |
| E4 | 单 Agent vs 多 Agent | 协作确有收益 | 同一批任务两种跑法 | 质量提升 ≥ 15% 或时间降 ≥ 20%，成本可接受 |
| E5 | 审批/接管 | 人敢托付 | 10 个高风险动作 | 100% 有审批路径，接管后不丢上下文 |
| E6 | 成本 | 成本可预算 | 100 个任务计量 | 单任务成本可预测（方差 ≤ 30%） |
| E7 | 失败恢复 | 崩了能继续 | 随机杀进程 10 次 | 60s 内恢复，不重复副作用 |
| E8 | 绑定覆盖 | 一个 Agent 能跨 3 个数据源 | 设计/客服数据混合 | 不越权、不串数据 |
| E9 | 类型派生 | 能从缺口生成新类型 | 构造 1 个 gap | 不改内核生效，评测通过 |
| E10 | 打扰预算 | 主动不变成噪音 | 一周真实使用 | 人均日打扰 ≤ 3 次，接受率 ≥ 50% |
| E11 | 可解释 | 用户能看懂“为什么” | 抽查 20 个动作 | 80% 能说清触发/依据/结果 |
| E12 | 信任/付费 | 用户愿意付费 | 5 个潜在客户访谈 | ≥ 2 个愿意试用/付费 |
