# 术语表（统一词汇用）

> 凡是容易各说各话的词，先钉在这。你如果对某个词有不同定义，直接改这一行。

| 术语 | 定义 | 别称/易混 |
|---|---|---|
| **Source** | 一条事件流的适配器（IM 群、GitHub、邮件、CI、文件监听） | 事件源、渠道 |
| **Trigger** | 一条不可变的外部事件 + 来源元数据；幂等单位 | 事件、消息 |
| **Thread** | 同一 PR / 同一 IM 话题 / 同一邮件串下按时间排序的 Trigger 序列 | 事件流、会话线程 |
| **Gate** | 准入的确定性第一层（程序判定：来源/白名单/是否 @/是否 bot） | Fast Path、快速路径 |
| **Assessment** | 准入的语义第二层（模型研判"要不要动"） | Slow Path、研判 |
| **Decision** | 研判结果：`accept` / `stop` / `ignore` / `unavailable` | 判定 |
| **Policy** | 带版本的准入与研判规则（谁能通过哪个入口发起工作） | 策略 |
| **Mandate** | 一次 accept 授予的授权凭证：范围、强度、依据的 Policy 版本；不可变、可撤回 | 授权、许可证 |
| **Ticket** | 一个已授权工作的单位；**自持状态**，不跟随执行体 | 工单、任务 |
| **Assignment** | Ticket 到一个执行器实例的绑定；Ticket 先后可有多个 | 派工 |
| **Subscription** | Ticket 与 Thread 的多对多关系；让上下文流动，**不流授权** | 订阅 |
| **Report** | 执行器状态回传，六态：`progress`/`waiting`/`ready`/`blocked`/`failed`/`dropped` | 汇报 |
| **Evidence** | 验收要求的可检查证据（复现脚本、测试通过、改动范围、回滚方式） | 证据 |
| **Acceptance Gate** | 验收门：证据齐备才允许进入 `person/review` | 验收契约 |
| **Router** | 决策层：研判 + 分派 + 全局记忆；**不执行具体任务** | 主会话、调度器 |
| **Worker** | 执行层：隔离上下文、完整工具、强模型；只向 Router 汇报 | 执行器 |
| **acceptMode** | `off` / `observe`（影子模式，默认）/ `auto` | 放权档位 |
| **Shadow / 影子模式** | 只记录"本来会做什么"，不做真实动作 | dry-run、观察模式 |
| **Speculative Execution** | 投机执行：不确定会被采用时后台先干，有价值才交付 | 静默复现 |
| **Inline & Spill** | 近期高相关信息内联进窗口，低频超预算信息留引用 | 上下文缓存化 |
| **Chain of Recall** | 对象唯一 ID + 内联下一跳 ID，模型逐跳展开 | 链式召回、引用图 |
| **Slot** | 并发执行的名额；另有 +1 "人优先"名额 | 并发名额 |
| **Effect** | 持久化的副作用记录（先落库，commit 后执行） | 副作用队列 |
| **Recovery Note** | 重启后给新执行器的注记："先核对目录/git/远端，再重复外部动作" | 恢复注记 |
| **Watchdog** | 主系统之外的独立控制回路，判断"有没有实质进展" | 看门狗 |
| **Scenario Pack** | 可插拔场景包：准入规则 + 证据契约 + Worker 策略 + 工具集 + 输出规范 + 指标 | 场景 |
| **Attention Budget** | 打扰预算：量化人的注意力消耗 | 注意力成本 |
