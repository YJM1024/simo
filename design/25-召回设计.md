## 0. 一分钟读法

1. **两层分工**：22 是"检索引擎"（给定 query 怎么查、怎么排、怎么裁、怎么带 cite）；本稿是"**召回策略**"（问什么、找谁、走哪条关系、够不够、要不要再问）。**本稿不重写 22 的打分与截断**。
2. **查询理解四件**：实体提及（mention）、实体类型、关系模式、查询计划。输入用 Intent Frame + Spec 片段 + 最近对话；**不把用户原话直接丢给 FTS**。
3. **实体层是派生索引，不是图数据库**：`Entity` + `mentions` + `entity_edges` 全部可从记忆条目/`links`/episode 重建（12 §2.1）；**不引入图 DB**，与 22 §9.3 的边界一致（区别只在"1 跳 vs 多跳"，见 §3.7/§5）。
4. **多路召回四选**：A FTS/关键词（V1 必有）、B 别名/精确（V1 必有）、C 向量（P1，可选）、D 图谱邻域（V1 1 跳，P1 2 跳）。四路各自出**实体候选 + 分数**，再融合。
5. **融合用 RRF 为主**（k=60），加权为可选；**实体分 ≠ 记忆分**：实体分只决定"先看哪些实体"，记忆分沿用 22 §4.6（rel+imp+rec+str），二者不混成一个数。
6. **top-K 实体 → 每实体 top-N 记忆**：默认 K=5、N=3；**注入仍受 E2/22 的 topK=8、≤8% A、单条 ≤400 token 约束**（K、N 是内部召回参数，不放大上下文配额）。
7. **关系约束下钻**：用"类型 + 关系 + 方向 + 时间/scope 约束"表达（如 `纪念品 -购买于→ 店铺 -位于→ 城市`），BFS 带上限执行；每条边必须带证据 cite；无路径就降级/追问，不编。
8. **agentic 召回循环**（P1 起）：触发于"多跳/歧义/首轮低置信"；Plan→Recall→Assess→Refine→（必要时）Ask；**≤3 步、每步 ≤1 次辅助模型调用、可随时停**；V1 只做"一次改写重试"，不调模型。
9. **V1 无向量的降级路径**：别名表 + 规范化 + FTS5 trigram + 2 字 LIKE + 类型/关系结构过滤 + 1 跳邻域 + 规则同义词/语音纠错；**不假装语义相似**（跨表述召回弱时标记 `no_semantic_path` 并给"换个说法/问一句"的出口）。
10. **可观测**：每次召回产出 `recallTrace`（查询计划 / 各路候选与排名 / 融合 / 实体分 / 走下钻的路径 / 选中与丢弃原因 / 步数 / 成本 / 延迟），让"为什么没想起它"可诊断。
11. **评测**：任务成功率（E2E/L2）、实体召回率@K、记忆命中率@K、关系路径成功率、追问率与正确率、**召回成本**（注入 token + 辅助调用 + 延迟）；全部先采基线，目标 TBD。
12. **本稿交付**：查询理解、实体层、四路召回、融合与打包、关系下钻、agentic 循环、预算/延迟/可观测、V1 无向量降级、评测、V1/P1、**5 条已定结论**（Lead 拍板，§11）。

## 1. 定位、边界与契约

### 1.1 是什么 / 不是什么

| 维度 | 结论 |
|---|---|
| **是什么** | ① **查询理解**：把"当前 Spec/任务/意图"变成实体提及、类型、关系模式与查询计划；② **实体层**：派生实体索引（实体、提及、实体边），支撑结构化召回；③ **多路召回 + 融合**：FTS/别名/向量（P1）/图邻域 → 实体排序 → 每实体记忆；④ **关系约束下钻**：按关系链 + 约束做有界遍历；⑤ **agentic 召回循环**：多步改写/换层级/追问；⑥ **可观测与评测**。 |
| **不是什么** | 不是检索引擎实现（22：FTS/打分/截断/cite/预算）；不是记忆模型（12：schema/写回/失效）；不是上下文装配（20：层序/压缩）；不是 Planner（23：Plan/Task 拆分）；不是提示词（21）；不是权限系统（15，但受 `boundary`/敏感约束）。 |
| **交付形态** | 文档 + 查询计划/实体层/关系链格式 + 评分/预算/降级规则 + 用例清单；实现分两档：**R1（无向量）先落**，R2（P1 增强）在其上叠加（§1.6/§10）。 |
| **成功标准** | ① **想起来**：用户提到的人/物/地点/事件能召回相关记忆（命中率相对基线提升）；② **不瞎想**：无依据时不编、不越 scope、不超预算；③ **可解释**：每条结果能说"从哪条路来、为什么排这"；④ **可降级**：无向量/图坏/模型不可用/预算不足都有确定行为。 |

### 1.2 与 22 的分层与接口（关键）

```text
25（本稿，召回策略层）
  RecallRequest {
    purpose, intentFrame, specView, taskBrief, recentDialogue,
    scopeChain, boundary, budget, evidenceNeeds?, allowAgentic?
  }
  → 查询理解 → 实体召回 → 融合 → （关系下钻 / agentic 循环）
  → 对每个实体/关系调用 22 的检索原语（多次调用）
  RecallResult {
    entities[{id,type,name,score,why}],
    items[{memId,kind,rev,score,snippet,tokens,cite,trust,entityId}],
    paths[{edges[],evidence[]}], trace, budgetReport, warnings
  }

22（design/22，检索执行层）
  RetrievalRequest { purpose, query, kinds, scopeChain, filters, topK, tokenBudget, requireCite }
  → 返回 items（已过滤/打分/截断/带 cite/带 trust）
```

- **22 不改语义**：本稿只**多次调用** 22 的检索原语（按实体名、按关系链、按别名），不重写它的过滤/打分/截断/cite/信任规则。
- **口径继承**：注入 token 仍受 E2 §3.4 的 T3/T6 桶（≤8% A）与 22 §2.5 的降级顺序；**本稿不新增配额桶**，只新增"怎么花"的策略。
- **22 的 `query` 字段由本稿派生**（22 §1.2 已写"由意图派生"），本稿把派生过程显式化。
- **差异声明（需 22 后续吸收）**：22 v0.2 §4.1 只有"沿 `links` 展开一跳、只作可展开标注"；本稿把"实体级关系 + 约束 + 多跳下钻"作为新增能力（V1 只 1 跳，P1 2 跳），**在 22 §9.3 的"不做图数据库"约束下用派生索引实现**（§3.7）。

### 1.4 不变量（违反即实现错误）

| # | 不变量 | 含义 |
|---|---|---|
| INV-R1 | **只读** | 召回不写记忆/不改状态；实体层与缓存都是派生、可重建 |
| INV-R2 | **预算不放大** | 注入 ≤ E2 配额；辅助模型调用有独立上限；超了走降级而不是"再多查一点" |
| INV-R3 | **作用域与敏感** | 只读 `scopeChain ∩ boundary.readScopes`；`sensitivity` 不跨 scope；实体合并不得把敏感实体跨域暴露 |
| INV-R4 | **cite 与可解释** | 每条注入记忆带 cite；每条关系边带证据；trace 能回答"为什么召回它/为什么没召回" |
| INV-R5 | **无向量可运行** | V1 无向量时功能不缺失（质量降级可接受），不得因缺向量返回错误/空转 |
| INV-R6 | **不编造** | 无结果 → 空 + 说明/追问；不得用"我记得"补空（12 §1.1 I4/22 §2.7） |

### 1.5 非目标（本稿不做）

- 图数据库/图算法平台（PageRank、社区发现等）——**不做**（与 22 §9.3 一致；实体边只是 SQLite 派生表）；
- 训练/微调 embedding 或实体抽取模型；
- 跨用户/跨租户共享实体库；
- 自动爬取外部知识库；
- 重写 22 的打分/截断/信任/写回路径；
- 重做 23 的规划/任务拆分；
- 在多用户/多 agent 团队场景下共享实体（后续单开）。

## 2. 查询理解

> 目标：把"当前这一步要什么"变成**可执行的召回计划**。V1 规则优先、不调模型（省成本、可解释）；R2 才允许一次小模型辅助。

### 2.1 输入（只读）

| 输入 | 来源 | 用途 |
|---|---|---|
| `frame`（goal/constraints/acceptance/specBinding/stopPolicy） | 19 §3.4 Intent Frame | 主目标关键词、约束、验收键 |
| `specView` 片段 | 18 v0.3（Requirement/acceptanceKeys） | 需求实体、验收目标；`acceptanceKeys` 作过滤键 |
| `taskBrief` | 18/23（Task 摘要 + writeScope/requiredEvidence） | 当前任务的实体与证据需求；brief 已覆盖的不重复召回 |
| 最近 2–3 轮对话 | surface（20 T4） | 指代消解（"它/那家店/上次那个"）、时间线索 |
| `scopeChain` + `boundary.readScopes` | 12 §3.5 / 18 v0.3 | 召回上限（取交集） |
| `allowAgentic` / 预算 | 19/E2 | 是否允许多步循环 |

### 2.2 五步流水线

```text
Q1 规范化：全半角/大小写/同音纠错（10 §46 的语音别名表）/繁简/去停用词（保留时间与数字）
Q2 提及识别：词典（实体表 + 别名表）最长匹配 + 规则（引号、书名号、地名后缀、时间表达式）+ 类型词表
Q3 类型判定：每个 mention 给候选类型（person/place/org/item/event/time/document/project/concept/unknown）
Q4 关系模式：识别关系触发词/介词/结构（"在…买""属于…""上次见的…"）→ 关系链候选
Q5 查询计划：QueryPlan{intent, mentions[], typeConstraints[], relationPatterns[], filters, hopLimit, evidenceNeeds}
```

- **不追求句法完美**：V1 允许"部分理解"——理解到实体就够开始召回；类型/关系不确定时用 `unknown` + 放宽（§2.7），而不是直接放弃。
- **不重复造轮子**：规范化与分词复用 22 §4.5 的 FTS 约定（trigram + 短查询 LIKE）；英文/数字/路径按原样保留。

### 2.3 实体类型（v0，**已定**：10 类 + unknown 兜底）

| 类型 | 例子 | 常见来源 | 备注 |
|---|---|---|---|
| `person` | 张工、妈妈、客户 A | 对话、记忆 text/data | 同名不同人靠 scope/上下文区分 |
| `place` | 京都、上海、公司 3 楼 | 对话、记忆 data | 支持层级（城市 ⊂ 国家） |
| `org` | 某店铺、某公司、某团队 | 记忆 data、文档 | 与 `place` 可多类型（店铺既是 org 又在 place） |
| `item` | 纪念品、相机、合同 | 记忆 data | 个人助理高频（物品→购买地→店铺） |
| `event` | 复盘会、上周的发布、旅行 | 记忆 data/时间 | 带时间窗 |
| `time` | 每周三 15:00、10 月 | 对话/记忆 | 作为**约束**而非实体结果（不强求返回） |
| `document` | 某文件、某报告 | 文档/产物 | 与 22 的 doc 索引 P1 对齐 |
| `project` | 某项目、某需求 | Spec/Task | 与 18 的 Spec 对齐 |
| `concept` | "记忆优先"、某个术语 | 记忆/文档 | 兜底语义类 |
| `unknown` | 识别不出类型 | 任意 | **必须允许**：按名字召回，不做类型过滤 |

- **多类型允许**：一个实体可有 `types[]`（店铺 = `org` + `place`）；过滤时"任一类型匹配"即可。
- **类型不是硬门**：`typeMatch` 只影响排序（§6.1），不因类型不匹配直接删（除非用户显式限定类型）。
- **【推断】类型体系保持 10 类 + unknown**：再细会加标注与维护成本；P1 可扩展（如 `pet`、`account`）。

### 2.4 提及（mention）与别名

| 项 | 规则 |
|---|---|
| **canonical 名** | 实体主名（写入时归一化：去空格/统一全半角/去"那家/这个"等指代前缀） |
| **别名 aliases[]** | 同义/缩写/旧名/昵称/同音字（语音识别常见，10 §46）；别名不单独成实体 |
| **提及识别** | V1：实体表 + 别名表的最长匹配 + 规则（引号/书名号/地名后缀/时间表达式）；**中文无空格**，不做通用分词也能先靠"已知实体匹配" |
| **指代** | "它/那家/上次那个" → 优先绑最近对话中的实体（20 的 T4）；绑不上则进入歧义处理（§2.7） |
| **【推断】P1 抽取** | R1 只用"词典 + 规则 + 写入时结构化字段"；R2 可加小模型抽取（结果只作候选，不直接写记忆，避免污染） |
| **边界** | mention 只用于**召回**，不用于自动写记忆；写回仍走 12 §5 候选制 |

### 2.5 关系模式与关系注册表

| 关系 rel | domain → range | 例子 | 方向 |
|---|---|---|---|
| `purchased_at` | `item` → `org/place` | 纪念品→购买于→店铺 | 正向（item→店） |
| `located_in` | `org/place` → `place` | 店铺→位于→城市 | 正向（店→城） |
| `works_at` | `person` → `org` | 张工→任职于→公司 | 正向 |
| `part_of` / `belongs_to` | 任意 → 任意 | 相机→属于→设备清单 | 正向 |
| `attended` / `held_at` | `person` → `event`；`event` → `place/time` | 复盘会→地点 | 正向 |
| `about` / `mentions` | `document/event` → 任意 | 报告→关于→项目 | 正向 |
| `caused_by` / `depends_on` | `event/item/project` → `event/project` | 故障→由于→变更 | 正向 |
| `owner_of` / `owned_by` | 双向 | 合同→属于→人 | 支持反向查询 |

- **注册表是封闭集合 + 版本号**（V1 先 8–10 个）；新增关系类型需要改 schema（避免关系类型爆炸、无法校验）。
- **domain/range 约束**：用于过滤"明显不合理"的边（例如 `purchased_at` 的目标必须是 `org/place`），也是下钻时的剪枝依据。
- **关系的真值条件**：每条 `entity_edge` 必须绑定 `sourceMemId@rev` + `evidence[]`；**没有证据的边不建立**（与 12 §2.5 证据纪律一致）。

### 2.6 输出：`QueryPlan`（可解释、可落 trace）

| 字段 | 说明 |
|---|---|
| `intent` | `recall_fact` / `recall_experience` / `verify` / `enumerate`（列举） / `relation_query`（多跳） |
| `mentions[]` | `{text, offset, candidates[{entityId,type,score}], chosen?}` |
| `typeConstraints[]` | 用户显式类型（"那家**店**"）；无则空（不强制） |
| `relationPatterns[]` | `{subjectType?, rel, objectType?, direction, constraints[]}`，可组成链（§5.1） |
| `filters` | 时间窗、kind、scope、acceptanceKeys、`includeDisputed` |
| `hopLimit` | 0（平铺）/ 1（R1 允许）/ 2（R2 允许） |
| `evidenceNeeds` | 是否必须带 Evidence（验收/追溯类为 true） |
| `budgetHints` | 建议的实体 K、记忆 N、是否允许改写重试 |

### 2.7 歧义与不确定（先降级、后追问）

| 情况 | V1（R1）行为 | R2 行为 |
|---|---|---|
| 同一 mention 多个候选实体（同名不同人） | 都保留（不替用户选），在结果里分实体返回；若差异影响结论 → 标记 `ambiguous` | 可追问："你说的 X 是 A 还是 B？"（一次一问，带候选） |
| 类型判不出 | `unknown`，按名字召回（不做类型过滤） | 可追问类型（仅在影响大时） |
| 关系触发词有、但链不完整 | 只做已确定的那一跳 | 可补问"是问 X 的什么？" |
| 没有任何可识别实体 | 用 `frame.goal` 的关键词走 22 的平铺检索（退化路径） | 允许一次"换个说法/给个线索"的追问 |

> **原则**：**召回阶段不替用户做实体消歧**（除显式追问）；消歧可以"并以候选返回"，由模型在回答时取舍或问用户。理由：消歧本身是判断，属于 E1/秘书职责，不属于检索。

## 3. 实体层（派生索引，不是图数据库；**Q1 已定：R1 即引入**）

### 3.1 实体对象（派生，非记忆真相）

| 字段 | 说明 |
|---|---|
| `entityId` | 稳定 id（`ent-<type>-<hash>`）；**可重建**，不作为跨库外键的长期承诺 |
| `types[]` | 类型集合（§2.3） |
| `canonicalName` | 归一化主名 |
| `aliases[]` | 别名/同音/缩写（含来源：用户输入/语音纠错/人工） |
| `scope` | 主作用域（实体归属哪层；跨层同名**不自动合并**） |
| `confidence` | 抽取/合并置信度（受来源分级影响，12 §7.3） |
| `evidenceRefs[]` | 产生它的记忆/ episode 指针 |
| `status` | `active` / `merged` / `archived`（随源记忆失效可归档，不物理删） |
| `firstSeen` / `lastSeen` | 时间（用于时近与去抖） |

### 3.2 实体与记忆：`mentions` 与 `entity_facts`

| 表（派生） | 内容 | 来源 |
|---|---|---|
| `mentions(entityId, memId@rev, field)` | 实体在记忆的哪个字段被提到（`content.text` / `content.data.subject` / `value` / `tags`） | 抽取规则（§3.4） |
| `entity_facts(entityId, rel, valueEntityId|valueLiteral, sourceMemId@rev)` | 结构化三元组（事实） | 从 `content.data` 的 `subject/relation/value` 抽取（12 §2.2 的 `fact`） |
| `entity_edges(fromEntityId, rel, toEntityId, sourceMemId@rev, confidence, validFrom/validUntil)` | 实体间关系（可下钻的边） | `entity_facts` + `links[]` + 关系触发词（§3.3） |

> **可重建性**：三张表全部可从 `memory_items` + `links` + episode 重建（12 §2.1 的"派生索引可丢弃"）。**删掉实体层不丢任何记忆**；重建是运维动作，不是语义变更。

### 3.3 实体边（`entity_edges`）的建立规则

1. **优先结构化**：`content.data.subject` + `relation` + `value`（`fact` 类）→ 直接成边；`relation` 映射到注册表（§2.5），映射不上则存为 `rel=unknown`（**不用于约束下钻**，只用于同实体关联）。
2. **其次 `links[]`**：`relates_to` / `depends_on` / `derived_from` / `affects` → 映射到实体边（弱关系，参与邻域打分、不参与强约束）。
3. **再次规则/文本**：`content.text` 里的"X 在 Y 买了 Z"类表达，V1 只在**同一句内**、且两侧都是已知实体时建边（保守）；R2 可用模型抽取（候选，进人工/规则复核）。
4. **证据强制**：每条边必须有 `sourceMemId@rev` + `evidence[]`；**无证据不建边**（INV-R4）。
5. **冲突**：同一 `(from, rel, to)` 多条来源 → 合并留最强来源，保留全部证据；相反方向/矛盾值 → 标 `disputed`（不选边），交给记忆层（12 §5.9）处理。

### 3.4 抽取规则（按 kind，V1 确定性）

| kind | 抽取什么 | 字段 |
|---|---|---|
| `fact` | subject/relation/value | `subject`→实体（类型按值/词典判）；`value` 若为实体则成边，否则为字面量 |
| `decision` | question/decision 涉及的对象 | question 中 mention → `mentions`；decision 值可能是实体/枚举 |
| `requirement` | item/acceptance 的对象 | mention → `mentions`；验收键不抽实体 |
| `progress` | task + 状态 | task 名/对象 → mention；不建强边 |
| `experience` | trigger/condition/action 中的对象 | trigger 里的实体 → mention；**signature 不进实体层**（是聚类键） |
| `preference` | topic | topic 文本 → mention（偏好对象） |
| `constraint` | rule 中的对象/系统 | 对象 → mention；不建"可下钻"边（红线是数据，不是路径） |
| `open_question` | question/options | 提及对象 → mention |
| `spec`（内部） | Requirement/Acceptance 对象 | 只进**内部检索**；用户可见检索不返回（18 §8.5） |

> **原则**：**能抽错，但不能抽脏**——抽取失败只意味着"这条记忆少一条召回路径"，不影响记忆本身；抽取结果全部可重建、可回滚。

### 3.5 增量维护与失效同步

| 事件 | 动作 | 一致性 |
|---|---|---|
| 记忆新增 / 新 rev | 解析并 upsert `mentions`/`entity_facts`/`entity_edges`；旧 rev 的派生行按 `(memId@rev)` 替换 | 最终一致（异步/批处理均可），读路径按主库过滤兜底（22 §3.5） |
| 记忆失效/归档 | `entity_edges` 按 `validUntil` 过滤；实体 `status` 可归档 | 读时过滤，不物理删 |
| `retracted` | 派生行移除 + 读过滤双保险 | 强 |
| 实体合并 | 重写别名与边（保留证据） | 可回滚（记录合并决策） |
| 索引损坏 | 全量重建（从记忆库） | 以记忆库为准 |

### 3.6 合并、别名与敏感

- **合并条件（V1 保守）**：同名/同别名 + 同类型（或类型兼容）+ **同 scope 或全局** + 证据不冲突；否则**不合并**（宁可两个实体，也不要错误合并）。
- **别名来源**：用户显式（"以后就叫它 X"）、语音纠错表（10 §46）、规范化（全半角/大小写）；**同音别名不跨 scope 自动合并**。
- **敏感实体**：源记忆 `sensitivity=sensitive` → 实体只在该 scope 内可见，**不参与跨域召回、不进实体公共别名表**（与 22 Q4 的"进本地 FTS、永不进向量/远程"一致）。
- **PII**：实体层不额外存 PII；敏感值不落实体名（用 `person#hash` 或掩码）。

### 3.7 与 22 §9.3"不做图数据库"的边界（重要）

| 说法 | 本稿的解释 |
|---|---|
| "不做图数据库" | **不做**独立图 DB、不做图查询语言、不做图算法平台；实体边存在 **SQLite 派生表**里，随记忆重建。 |
| "12 的 `links` 展开一跳已够 V1" | 22 指的是**记忆条目级**的 1 跳、且只作"可展开"标注；本稿的**实体级**关系下钻是新增能力，V1 只做 **1 跳、且带类型/关系约束**，仍不引入图 DB。 |
| 多跳（≥2） | **R2（P1）才做**，且必须做预算与剪枝（§5.7）；若评测证明收益不足，退回 1 跳。 |

## 4. 多路实体召回

### 4.1 四路（V1 三路 + R2 第四路）

| 路 | 名称 | V1 | R2 | 输入 | 输出 |
|---|---|---|---|---|---|
| **A** | FTS/关键词 | ✅ | ✅ | 实体名/别名 + 查询关键词 | 候选记忆 → 反推实体（`mentions`） |
| **B** | 别名/精确 | ✅ | ✅ | 规范化 mention → `aliases[]` 精确匹配 | 候选实体（含精确分） |
| **C** | 向量 | ❌ | ✅（本地 ONNX，22 Q1 已定 P1） | mention 文本 embedding | 候选实体/记忆（余弦） |
| **D** | 图谱邻域 | ✅（1 跳） | ✅（2 跳） | 已确认种子实体 | 邻居实体（沿 `entity_edges`） |

> **A 与 B 的区别**：A 是"从记忆文本找实体"（召回面宽、噪声多）；B 是"从名字直接命中实体"（精确、覆盖窄）。两路互补。

### 4.2 各路细节

- **A FTS/关键词**：
  - 调用 22 的 `RetrievalRequest{query=实体名/别名,+关键词}`（`kinds` 不限、`topK` 按预算）；
  - 对返回的记忆按 `mentions` 反查实体，累计实体分（每命中一条记忆 +1，按该记忆的 22 分数加权）；
  - 失败/空 → 该路空，不影响其它路。
- **B 别名/精确**：
  - mention 规范化后精确匹配 `canonicalName`（1.0）/`aliases`（0.9）/前缀（0.6）；
  - 命中即**强候选**（可跳过类型过滤）；同名多实体 → 全部给候选（§2.7）。
- **C 向量（R2）**：
  - 实体侧：实体名+别名+简介 embedding（写入时算，可后台）；
  - 查询侧：mention embedding；`cosine` 转实体分；
  - **限制**：只对非敏感、非跨域实体建向量（22 Q4）；模型版本与索引版本绑定（22 §4.4）。
- **D 图谱邻域**：
  - 输入：A/B/C 已确认的种子实体 + QueryPlan 的 `relationPatterns`；
  - 沿 `entity_edges` 走 1 跳（R1）/2 跳（R2），**优先沿关系约束匹配的边**，其余边只作弱关联；
  - 邻居实体分 = 边置信度 × 关系匹配度 × 种子分衰减（0.6^hop）；
  - **反向遍历**：关系方向允许 `reverse`（如"京都的店"从 place 反向走 `located_in`）。

### 4.3 融合（RRF 为主）

- **每路输出一个实体排名列表**；用 **RRF** 融合（`k=60`）：
  - `rrf(e) = Σ_path 1/(60 + rank_path(e))`；
  - 归一化到 [0,1] 作为 `entityFusionScore`；
- **为什么 RRF**：四路分数量纲不同（FTS 排名、别名 0/1、cosine、图距离），RRF 免调权、对缺失路鲁棒（V1 只有三路也成立）。
- **可选加权**（R2 再评估）：`w·rrf`，w 按路可靠性（B 精确最高、D 次之、A 再次、C 最后）；**V1 不调权**（少一个调参面）。
- **缺失路处理**：某路不可用（无向量/图损坏）→ 只用可用路；**不因缺路直接判空**。

### 4.4 实体重排（在融合分之上）

实体分（用于排序，**不是注入分**）：

```text
E(e) = 0.35·nameMatch + 0.25·ctxMatch + 0.20·graphScore + 0.10·typeMatch + 0.10·prior
```

| 项 | 计算 |
|---|---|
| `nameMatch` | 精确主名=1.0；别名=0.9；前缀=0.6；FTS 词命中=0.5；否则 0 |
| `ctxMatch` | mention 与查询目标在同句/同窗口（最近对话）出现的程度；指代绑定到当前焦点实体时加分 |
| `graphScore` | 1 跳=1.0、2 跳=0.6、无=0；沿关系约束匹配的边额外 ×1.2（封顶 1.0） |
| `typeMatch` | 用户显式类型匹配=1.0；兼容=0.6；`unknown`=0.4；不匹配=0（但仍可保留为候选，见 §2.3） |
| `prior` | 该实体关联记忆的 22 分聚合（top-3 记忆的 `score` 均值）；无记忆=0 |

- **默认权重（占位，非承诺）**：0.35/0.25/0.20/0.10/0.10；R2 用真实数据校准。
- **多样性（可选，R2）**：同类型实体最多占 K 的 60%，避免"全是同一个城市的店"；V1 不加（先保证召回）。
- **确定性 tie-break**：E 差 <0.02 → 类型权威（person/place/org 优先于 unknown）→ `lastSeen` 新 → `entityId` 升序（同状态同结果）。

### 4.5 top-K 实体 → 每实体 top-N 记忆

| 参数 | R1 默认 | 说明 |
|---|---|---|
| `K`（实体） | 5 | 内部参数，不注入；K 越小越省 |
| `N`（每实体记忆） | 3 | 每实体先取 22 分最高的 N 条 |
| 记忆总条数 | **≤ min(K×N, E2 的 topK=8)** | **注入永远不超过 E2 的 topK**（§1.2）；K×N 只是候选池 |
| 分配 | 至少 1 条/实体（按 E 降序），剩余名额按"实体分 × 记忆分"轮转填充 | 防止一个高分实体吃掉全部名额 |
| 排除 | `pin`/常驻块不进本流程（22 §4.3 必进项）；同一记忆只出现一次 | 去重（§4.6） |

> **关键澄清**：本稿的"top-K 实体"**不是** E2 的 `topK=8`。E2 的 topK 是**最终注入记忆条数**；实体 K 是召回内部步数。两者通过"候选池 → 全局预算裁剪"衔接，**不叠加**。

### 4.6 去重

| 层次 | 规则 |
|---|---|
| 实体 | 合并别名后同 `entityId` 只留一个；同名不同实体**不合并**（保留并标记） |
| 记忆 | 22 的 `(id, rev)` 去重；同一记忆被多实体命中只注入一次（取最高实体分来源，但记录多来源） |
| 边 | 同 `(from, rel, to)` 多条来源合并；相反方向按需保留 |
| 查询 | 多轮/多步产生的重复候选按 `(entityId, memId@rev)` 去重；重复查询检测（§7.7） |

### 4.7 V1 无向量时的降级路径（R1 的核心）

**原则：没有向量 ≠ 不能召回；只是"跨表述相似"弱。用结构化与词典补，并诚实标注。**

| 场景 | R1 替代手段 | 标注/出口 |
|---|---|---|
| 同义词/近义表述（"买的东西" vs "纪念品"） | 别名表 + 类型词表 + 关系触发词（"买"→`purchased_at`）+ `tags` | 仍缺 → 标记 `no_semantic_path`，回答里说"按名字没找到"或问一句 |
| 同音/错字（语音输入） | 10 §46 的同音纠错表 + 编辑距离阈值 | 纠错命中记 `alias_corrected` |
| 跨语言/英文缩写 | 别名表（手工/写入时）；R1 不做机器翻译 | 缺 → 降级为 FTS 关键词 |
| 模糊描述（"上次那个特别贵的东西"） | 时间窗 + `importance` + 类型（item）+ 最近记忆排序 | 多候选 → 并列返回或追问（R2） |
| 无任何命中 | 22 的平铺检索（`frame.goal` 关键词）→ 空 + 说明 | **不编造**（INV-R6） |

**R1 的"不假装"声明**：向量缺失时，**不得**把"FTS 词面命中"说成"语义相似"；trace 与 `warnings` 里标 `no_semantic_path=true`，供上层决定是否追问/换说法。

## 5. 关系约束下钻

### 5.1 关系链表达（给模型/规则看的规范）

```text
关系链 := 起点类型? -(rel[方向]? 约束*)-> 中间类型? -(rel...)-> 终点类型?
例：item -(purchased_at)-> org/place -(located_in)-> place
问法："我在京都买的那家店" → 终点 place=京都，反向走 located_in / purchased_at
```

- **方向**：`forward`（默认）/ `reverse`（从目标反查）；同一链里可混用。
- **类型**：可空（`?` = 不限）；有类型时作为强约束（不匹配不扩展，但保留为"弱候选"用于纠错）。
- **约束**：时间窗（购买时间/事件时间）、scope、`acceptanceKeys`、来源最低等级、证据必须存在。

### 5.2 约束类型

| 约束 | 例子 | 作用于 |
|---|---|---|
| 类型约束 | `item→org` | 边的 domain/range |
| 方向约束 | "京都的店"→反向 | 遍历方向 |
| 时间约束 | "去年买的" | 边的 `validFrom/validUntil` + 源记忆时间 |
| 作用域约束 | 只看 task/domain | 与 `scopeChain ∩ boundary.readScopes` 取交集 |
| 来源约束 | 只要 `system_verified`/`user_confirmed` | 边权重/过滤 |
| 证据约束 | 验收/追溯类必须带 Evidence | 无证据边不进入结果（但可作弱候选） |

### 5.3 执行算法（有界 BFS/DFS）

```text
输入：种子实体集 S（来自 §4）、关系链 P = [step1..stepH]、约束 C、预算 B
1) frontier = S；已访问 = ∅；结果实体 = ∅
2) 对 hop i = 1..H：
   a. 对 frontier 中每个实体，沿 step_i 的 rel（+方向）取边，过滤 domain/range/方向/时间/scope/来源/证据
   b. 对每条边：候选 = 目标实体；累计路径分 = 种子分 × 0.6^i × 边置信度
   c. 剪枝：每层保留 ≤ M 条（默认 50），按累计分；超出记录 dropped
   d. 结果记录路径（edges + 每边证据 cite）
3) 若 H 层走完且结果非空 → 返回实体 + 路径；否则触发降级（§5.4）
```

- **上限**：`H≤1`（R1）/`H≤2`（R2）（**Q2 已定**）；每层候选 ≤M；总边访问 ≤E（默认 500）；**保证有限**（关系链本身有限，边有界）。
- **反向遍历**：从终点实体出发，沿 `rel` 的反向索引（`entity_edges` 建 `(to, rel, from)` 索引）匹配。
- **剪枝**：类型不匹配 → 降为弱候选（不扩展，但保留"疑似"）；时间不匹配 → 直接剪；证据缺失 → 弱候选/丢弃（按约束）。
- **缓存（R2）**：`(seedEntity, relChain)` 级别的结果缓存（短 TTL），避免重复下钻。

### 5.4 结果与失败降级

| 情况 | 行为 |
|---|---|
| 路径存在 | 返回实体 + 完整路径 + 每边证据 cite；实体分 = 路径分（§6.1 的 `graphScore` 取最高路径） |
| 无路径（图里没有） | 降级：① 放宽类型（只保留 rel）② 缩短到已走的跳数 ③ 用平铺 FTS 兜底；记录 `path_not_found` |
| 路径冲突（同一问题两个答案） | 两条并存返回 + 标 `disputed_path`；不替用户选（与 12 §5.9 冲突显式一致） |
| 约束不满足（时间/scope） | 不返回该路径；若用户明确要求该约束 → 空 + 说明"记忆里没有满足该条件的记录" |
| 图索引不可用 | 退化为平铺检索 + `warnings: graph_unavailable`（不阻塞） |

### 5.5 例子：纪念品 → 购买于 → 店铺 → 位于 → 城市

**问**："我上次在京都买的那家店，纪念品是在哪儿买的来着？"（用户想确认纪念品购买地点）

1. **查询理解**：mentions = {京都: place, 店: org/unknown, 纪念品: item, 买: rel 触发词}；关系模式 = `item -purchased_at-> shop -located_in-> place(京都)`；方向：从京都反向。
2. **实体召回**：B 精确命中 `京都`、`纪念品`（若记忆里有）；A FTS 命中"京都/纪念品/店"相关记忆；D 从 `京都` 反向走 `located_in` 得到若干店铺候选。
3. **融合 + 排序**：`纪念品` 与 `京都` 为强种子；店铺候选按边置信度 + 路径分排序。
4. **下钻**：沿 `purchased_at` 反向（从店铺到 item）找与"纪念品"一致的 item（类型匹配），得到候选（如"清水寺的御守"）。
5. **每实体记忆**：对命中的实体取 22 分最高的 3 条记忆（购买记录/收据/行程），拼成 ≤8 条、≤8% A 的注入。
6. **证据**：每条记忆带 cite（`[mem:...@rev]`），每条边带来源（哪条记忆说的"在京都买了 X"）。
7. **若图里没有"京都→店"边**：降级到平铺 FTS（"京都 纪念品 购买"）+ 说明；不编造。

### 5.6 与 22 的"1 跳 links 展开"区别

| | 22 §4.3 的展开 | 本稿下钻 |
|---|---|---|
| 层级 | 记忆条目级 `links` | 实体级 `entity_edges` |
| 跳数 | 1 跳 | R1 1 跳 / R2 2 跳 |
| 约束 | 无（只标"可展开"） | 类型 + 关系 + 方向 + 时间 + scope + 证据 |
| 用途 | 让模型知道"还有关联" | 回答"通过关系链才能回答"的问题 |
| 预算 | 不计入（只给指针） | 计入召回预算（边遍历上限） |

### 5.7 预算与组合爆炸控制

- 关系链最多 3 段（R2），每段最多 1 个关系类型（不支持 OR 关系链，V1/R2 都不支持；复杂需求拆多次查询）；
- 每层候选上限 M=50、总边访问 E=500（默认，可调）；
- **反向索引**必须建（`(to, rel, from)`），否则反向遍历会退化为全表扫描；
- **组合爆炸**：多实体 × 多关系链 → 先按实体分取前 K 个种子（K=5），再下钻；不并行铺开所有组合；
- **成本观测**：每跳记录访问边数/候选数/剪枝原因（§8.3）。

## 6. 融合评分与重排（可实现）

### 6.1 实体分（用于选实体；与记忆分分离）

见 §4.4 的 `E(e)` 公式；要点：

- 实体分**只决定"选哪些实体、按什么顺序"**，不直接进上下文；
- `prior` 用 22 的记忆分聚合（top-3 均值），**不重新实现 22 的打分**；
- 同一实体多路命中 → RRF 已融合一次，实体分再以 `nameMatch/ctxMatch/graphScore` 微调（避免"路多就赢"）；
- 默认权重见 §4.4（占位）。

### 6.2 记忆分（完全复用 22 §4.6）

```text
memoryScore = 0.50·rel + 0.25·imp + 0.15·rec + 0.10·str   （22 §5.4）
```

- 本稿**不改** 22 的权重与 tie-break；
- 实体分对记忆分的唯一影响：**同一记忆被多个实体命中时，取"实体分 × 记忆分"最高的实体归属**（用于解释"这条记忆是为哪个实体取的"）。

### 6.3 打包（候选池 → 注入）

```text
1) 实体排序：按 E 降序，取前 K（默认 5）
2) 每实体：取 22 分最高的 N（默认 3）条记忆；排除 pin/块、已选、失效
3) 全局合并：每条记忆算 packScore = E(entity) × memoryScore
4) 贪心选包：按 packScore 降序；强制每个实体至少 1 条（若该实体有合格记忆）
5) 预算：总条数 ≤ E2 topK（8）；总 token ≤ 8% A；单条 ≤ 400 token（22 §5.5 截断）
6) 超预算：先减 K×N（去尾实体）→ 再减 N → 再按 22 §2.5 的三级降级
7) 记录 dropped（原因：entity_budget / memory_budget / dedupe / threshold / scope）
```

- **实体本身不注入**（不占 token）；注入的只有记忆条目（+ 22 的 cite/trust/截断）。
- 若用户问题只需"哪个实体"（如"我上次去的店叫什么"），可返回实体名 + 1 条最强记忆；仍走同一预算。

### 6.4 阈值、空结果与降级

| 情况 | 行为 |
|---|---|
| 最高实体分 < `entity_min`（默认 0.15） | 不注入该实体；若全低 → 空 + `no_hit`（可触发一次改写/追问，R2） |
| 实体命中但记忆全失效/无权限 | 返回实体 + `warnings: no_memories`；不把实体当答案（可能是空壳） |
| 只命中 `unknown` 类型 | 允许返回（按名字），但 `why` 标 `type_unknown` |
| 冲突实体（同名不同人） | 并列返回、不合并、`ambiguous=true`（R2 可追问） |
| 预算不足 | 22 §2.5 的三级降级；本稿额外可"去尾实体"（先去掉 E 最低的实体） |

## 7. agentic 召回循环（R2，P1）

### 7.1 触发条件（默认关闭 vs 开启）

| 条件 | 是否触发 | 说明 |
|---|---|---|
| 查询含关系链（H≥1）且首轮无路径 | ✅ | 多跳/关系类最需要 |
| 首轮实体分全低 / 空结果 | ✅ | 换关键词/别名/放宽类型 |
| mention 有多个接近候选（歧义） | ✅（可转追问） | 差异影响结论时 |
| 用户显式"你想想/回忆一下/查查记忆" | ✅ | 意图要求多查 |
| 简单事实查询、首轮已高分命中 | ❌ | 不浪费调用 |
| 阶段 `executing` 且 brief 已覆盖 | ❌ | 22 §2.1 的"不该检索"同理 |
| 预算已用 >90% A | ❌ | 先压缩（20 §6.4/22 §2.1） |

### 7.2 循环结构（最多 3 步）

```text
Step 0  one-shot 召回（§4–§6）；计算 assess（覆盖率/置信/歧义）
  │  足够 → 返回
  ▼
Step 1  Refine（规则或 1 次小模型）：换关键词 / 扩别名 / 放宽类型 / 升/降 scope 层级 / 补关系链
  → Recall → Assess
  │  足够 → 返回
  ▼
Step 2  再次 Refine（不同策略，避免重复）
  → Recall → Assess
  │  足够 → 返回；仍不足 → Ask（若允许）或 返回空+说明
  ▼
Step 3  Ask：只问 1 个关键澄清（候选实体/缺失关系）；问完即停（不自行猜测继续）
```

### 7.3 每轮允许的动作（白名单）

| 动作 | 说明 | 次数上限 |
|---|---|---|
| `rewrite_keywords` | 换词/同义/上位词（"纪念品"→"礼物/特产"） | 1 |
| `expand_alias` | 用 `aliases[]` 扩展 mention | 1 |
| `relax_type` | 去掉类型约束（unknown 兜底） | 1 |
| `change_scope_level` | 换层级：task→domain→global（在 `boundary.readScopes` 内） | 1 |
| `extend_relation` | 增加/替换关系链的一段（R2 允许 2 跳） | 1 |
| `lower_threshold` | 降 `entity_min` 一次 | 1 |
| `ask_user` | 只问一个问题 | 1（终止） |

- **禁止**：无限重试、同一 query 重复、越过 scope/敏感、把"检索内容"当指令（22 §6）。
- **模型调用**：R2 允许每步最多 1 次辅助调用（小模型，输出结构化 `RefineAction` + `assess` 理由）；V1（R1）不允许调模型，只做规则重试（§10.1）。

### 7.4 追问用户的规则（与 13 一致；**Q4 已定：R1 不追问，R2 只问三类、一次一问**）

- **只问三类**：① 歧义影响大（两个候选实体给出不同事实）；② 缺关键实体/关系（没有它无法回答）；③ 用户要求确认（"你是指 X 吗"）。
- **一次一问**：给出候选（A/B 或"是/不是"），不连环问。
- **不打扰**：能从记忆里查到的，不转问用户；`executing` 阶段、非阻塞问题不打断。
- **不越权**：追问时不泄露其它 scope 的内容（只描述当前候选）。
- **格式**：自然语言一句 + 选项（由 13/21 定措辞）。

### 7.5 预算与停止

| 预算 | 默认 | 说明 |
|---|---|---|
| 步数 | ≤3 | 含追问 |
| 每步辅助调用 | ≤1 次（R2） | R1 为 0 |
| 辅助调用 token | ≤2K 提示 + ≤1K 输出（单次，占位） | 不计入 E2 的 A（A 是注入预算），但计入 **总成本指标**（§9.1） |
| 注入预算 | 不变（≤8% A / topK=8 / 400 token） | 多步不放大注入 |
| 时延 | 每步 ≤X ms（TBD，§8.2） | 超时 → 停在上一步结果 |
| 不收敛检测 | 连续 2 步结果集合无新增（相似度 >0.9） | 立即停，返回空/说明 |
| 重复查询 | 同 query 第 2 次出现 | 跳过并记 `duplicate_query` |

### 7.6 归属：E4 内部，对 E1 透明（**Q3 已定**）

- **选择**：agentic 召回放在 **E4 内部**（一次 `RecallRequest` 内完成多步），**不新增 E1 的 Step**。理由：① E1 的 Step 已足够重（组装/决策/执行/观察/更新/判断），召回多步若变成 Step 会让 Loop 与预算复杂化；② 召回是"取数据"，不是"做决策"。
- **代价**：一次召回可能多次模型调用 → 必须限量（§7.5），并在 trace 里可见；若未来证明需要"用户可见的检索过程"，再上移为 E1 显式步骤（P2）。
- **与 19 的接口**：`RecallRequest.allowAgentic` 由 Loop 按阶段/预算传入；返回 `RecallResult`（含 `steps[]`）供 E2 组装。

### 7.7 失败与不收敛

| 情况 | 行为 |
|---|---|
| 辅助模型不可用/超时 | 降级为规则 Refine（V1 能力）；仍不行 → 返回上一步结果 + warning |
| 连续无新增 | 停止；返回空 + `no_progress`（R2 可问一句） |
| 预算耗尽 | 停；返回已有结果（部分结果有效） |
| 与首轮结果矛盾 | 不合并；标记 `refined_conflict`，交给上层判断 |
| 追问后用户不答 | 停；以已有候选继续（不阻塞） |

### 7.8 可观测

`recallTrace`（见 §8.3）必须记录每一步的 `RefineAction` / 候选变化 / 成本；**没有 trace 的 agentic 循环不允许上线**（不可归因=不可调）。

| 故障 | 行为 | 输出保证 |

| 预算不足 | 22 §2.5 三级降级 + 去尾实体 | 有结果但更少 |
| 超时 | 返回部分结果 + `partial` | 不阻塞主流程 |
| 敏感/越权 | 不返回 + `policy_denied` | 不泄露 |

### 8.5 隐私

- 实体层、图、向量（P1 本地）**全部本机**；不出网（22 §8）。
- 敏感实体不跨 scope、不进公共别名表、不进向量/远程（22 Q4）。
- 追问不泄露其它 scope；trace 脱敏（实体名可掩码）。
- 实体层可整块删除重建（用户要求"忘掉"时，随记忆 `retracted` 同步移除派生行）。

| **关系下钻** | 关系路径成功率 | 期望路径（实体+关系链）被正确走出的比例 |
| | 关系约束满足率 | 返回路径满足全部约束的比例（时间/scope/类型） |
| | 多跳召回率 | 需要 2 跳的 case 中成功比例（R2） |
| **交互** | 追问率 | 触发追问的召回 / 总召回 |
| | 追问正确率 | 追问后用户确认"是"的比例（离线可标） |
| **成本** | 注入 token / 召回 | `injectedTokens` 均值（≤8% A 内） |
| | 辅助调用次数/token | agentic 的成本（R2） |
| | 召回时延 | p50/p95（本地） |
| | 每次成功召回的成本 | 总成本 / 成功召回（综合指标） |
| **退化** | 空结果正确率 | 真无记忆时空结果的比例（不误报"没有"） |
| | 编造率 | 无召回却给出"我记得…"的比例（硬 0 目标） |

> **硬指标**：`编造率 = 0`（INV-R6）、`越权召回 = 0`（INV-R3）；与 17 的安全项一致，不看 Δ。

### 9.2 L1 用例（新增 R-1..R-10，供 17 的 L1 扩展）

| ID | 场景 | 期望 |
|---|---|---|

## 11. 已定结论（Lead 拍板，5 条）

> **拍板**：Lead 于 **2026-11-08** 按用户授权拍板；结论**已生效**并写入正文（各落点已标「已定」）。如需变更：先改本节 + 版本记录，再同步落点章节。

### Q1（已定）：R1 引入轻量派生实体层
- **结论**：**R1 就引入**轻量派生实体层（`Entity` / `mentions` / `entity_facts` / `entity_edges`，SQLite 派生表，可整块重建），R1 用 **A/B/D 三路**召回（FTS/关键词、别名/精确、1 跳邻域）。
- **落点**：§3 实体层、§4.1/§4.2、§10.1。
- **影响**：多一份索引维护与重建成本；**不引入图 DB**；抽取错误可重建/回滚（不影响记忆本身）。

### Q2（已定）：关系下钻跳数
- **结论**：**R1 1 跳、R2 2 跳**；每层候选与总边访问仍受上限（§5.7）。
- **落点**：§1.6、§5.3/§5.7、§10.1/§10.2。
- **影响**：R2 才支持"纪念品→店→城"的完整多跳；R1 先验证 1 跳收益，避免过早背 2 跳的工程/评测成本。

### Q3（已定）：agentic 召回循环归属 E4 内部，对 Loop 透明
- **结论**：agentic 循环放在 **E4 内部**（一次 `RecallRequest` 内多步），**不新增 E1 的 Step**；步数/预算/成本见 §7.5，`recallTrace` 必须记录（§8.3）。
- **落点**：§7.6、§8.1、§8.3。
- **影响**：Loop 不因召回变重；代价是内部预算更严（≤3 步、每步 ≤1 次辅助调用）。

### Q4（已定）：追问边界
- **结论**：**R1 不追问**（空结果→说明/换说法）；**R2 才允许**，且只问三类（歧义影响大 / 缺关键实体或关系 / 用户要求确认），**一次一问**；不越权、不泄露其它 scope（§7.4）。
- **落点**：§2.7、§7.4、§10.1/§10.2。
- **影响**：R1 遇歧义只能并列返回（用户多看一眼）；R2 的追问质量依赖实体层质量。

### Q5（已定）：实体类型 v0
- **结论**：**10 类 + `unknown`（封闭注册）**：person/place/org/item/event/time/document/project/concept/unknown；**扩展需升注册表版本**（不静默扩展）。
- **落点**：§2.3、§2.4、§10。
- **影响**：类型约束下钻与剪枝可用；新增类型走版本升级，避免关系/类型体系失控。
