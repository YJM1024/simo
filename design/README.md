# 设计工作台

> 这个目录是「你设计、我当参谋」的主战场。目标不是一次写出一份漂亮文档，而是把**设计决策**一条条磨出来，并让代码跟着决策走。

## 我们的协作方式

**你负责**：说你的设计——直接聊天里说、或在 [`03-你的设计.md`](03-你的设计.md) 里写、或随手甩几段文字都行。不用写完整，碎片也接。

**我负责**：
1. 把你的想法**收敛成决策条目**（记进 [`00-决策台账.md`](00-决策台账.md)，标明"已采纳/待定/我建议改"）；
2. 每条决策给**推荐 + 理由 + 代价 + 什么时候该反过来**，不替你拍板；
3. 决策一落地，**同步改骨架**（`../skeleton/`），并跑 demo/测试给你看证据；
4. 每轮末尾列出「现在最值得你决定的一件事」，避免决策摊子铺太大。

**原则**：设计先行、代码做证。我不做「我觉得这样好」的说服，只做「这样选会付出什么代价」的摊牌。

## 当前阶段

- 你出设计意向 → 我把 D-01…D-13 逐条落定 → 骨架按决策重写。

**阶段三：接 DSH Harness（作为宿主之一）**，或在你的场景里独立部署。

## 一句话提醒

这套架构里最容易被"抄错"的东西，是把它做成「一个更花哨的 Agent Team」。Super-agent 的判据是：**主会话有没有下场干活**。主会话不下场、只做研判分派——那就是双层；主会话既规划又执行——那只是团队。这个判据会一直用来检验你的设计。
