### E0 评测骨架（横切，与 M1/M2 并行；不占 M 序号）

**目标**：尽早建立"改动有没有变好"的可复核基线；让 prompt/loop/上下文/记忆/检索/权限的每次改动都有 `WITH/W/OUT/Δ` 证据，而不是盲改。**用户 2026-11-06 已确认提前到 M1/M2。**

**设计依据**：[10](10-设计对话记录.md) §27–29；[16](16-架构对照表.md) D16 与 §3 借鉴清单；design/17（E0 设计稿，v0 已完成）；[archive/research/claude-agent-sdk-mechanisms.md](../archive/research/claude-agent-sdk-mechanisms.md) 评测节。

**包含**
1. **三层评测**：L1 组件级（分类/路由、记忆写回、检索、工具调用、撤回正确率）；L2 场景级（个人助理 golden set，隐藏期望，WITH/W/OUT 对照）；L3 线上指标（S0/S1 P95、无响应空窗、token 成本、人工纠正率、误撤回率、记忆冲突率）。
2. **三列基线**：无干预基线 → `WITH`（启用被测能力）/ `W/OUT`（关闭）/ `Δ`（差值）；同一 case 两臂都跑；两臂都满分说明该 case 对该能力不敏感，应换 case 或补 case。
3. **六种分层 grader**：`regex` / `tool_used` / `tool_order` / `file_exists`（确定性、零成本打底）+ `llm`（judge 三投二中，仅辅助并记录 judge 版本）+ `baseline`（与参考 transcript 比"至少一样好"）。
4. **grader 排除**：在 W/OUT 臂必然失败的 grader（如 `tool_used: 某能力`）在两臂都从总分排除，只作 WITH 臂指示器；排除规则本身版本化。
5. **默认跑 3 次取均值**，记录方差；不达标时看分布，不只看均值。
6. **golden set**：V1 起步 10–20 个场景 × 每场景 3–5 步（个人助理场景）；case 定义对被测 agent 隐藏；版本化（版本号 + 冻结日期 + 变更记录）；保留 dev/holdout 防止过拟合。
7. **隔离与回放**：每个 case 用全新隔离 session，只加载被测物（不加载用户设置/记忆/skills/MCP）；mock 工具 + 录制回放；可注入延迟/失败/半截流。
8. **回归门禁**：prompt/loop/上下文/记忆/检索/权限变更必须跑 E0；默认 threshold=1.0（或按基线校准）；Δ 不允许显著为负；失败阻断合并/进入下一里程碑；输出 JSON 报告 + 人工可读摘要。
9. **与里程碑**：M1 建骨架（确定性 grader + 小 golden set + 事件日志/token 数据）；M2 加交互指标（撤回/歧义/steer）；M7 校准目标与性能基线。

**不包含**：外部公开 benchmark（SWE-bench 等）、多框架横向排名、LLM judge 单独作为硬门禁、生产 A/B 平台。

**可演示成果**：你能在本地跑一次评测，看到 `WITH/W/OUT/Δ` 三列、3 次均值与方差、被排除的 grader、golden set 版本；能亲眼看到一次"改动让 Δ 变负 → 回归门禁失败"。

**演示脚本（你亲手做）**
1. 在干净数据目录运行评测（命令名实现时定，例如 `eval run --suite golden@v1 --repeat 3`）；预期：每个 case 输出三列 + Δ + 均值/方差，报告落盘。
2. 临时关闭一项能力（如撤回重答或持久规则）再跑；预期：对应 case 的 Δ 变负或 W/OUT 下降，报告能指出是哪项能力。
3. 查看一个被排除的 grader（如 `tool_used: 某能力`）在两臂都排除、只在 WITH 臂作指示器；给 golden set 增加一条 case，版本号 +1、变更记录可查。
4. 让某次改动跑出 Δ 显著为负；预期：回归门禁失败并给出对比报告（阻断），不是"跑了但没人看"。

**验收标准**

| # | 验收项 | 判定方法 |
|---|---|---|
| A1 | 三列/Δ 自动生成；同一 case 两臂隔离、只加载被测物；默认 3 次且报告均值 + 方差 | 跑评测 + 报告检查 |
| A2 | 六种 grader 至少确定性四种可跑；llm/baseline 有版本记录；grader 排除在两臂生效 | 测试 + 报告 |
| A3 | golden set 版本化（版本号/冻结/变更记录），case 对被测 agent 隐藏；有 holdout | 版本记录 + 隔离检查 |
| A4 | 回归门禁可阻断：Δ 低于阈值时非零退出并产出报告；本地可复现 | 故意回退一次 |
| A5 | L3 指标能从事件日志/token 计量算出（S0/S1/空窗/token/纠正率/误撤回/冲突率） | 指标对账 |
| A6 | M2 起 E0 成为固定 gate；design/17 评审通过后骨架定稿 | 门禁记录 |

**依赖关系**：M1 的事件日志与 token 计量（软依赖，可先并行搭 harness）；design/17 评审；不阻塞 M1 其余部分。

**本里程碑产出**：design/17 评审稿 + 评测 harness + golden set v1 + 基线报告 + 回归门禁脚本。

**主要风险**：golden set 过拟合、评测自身不可信；见 §5.3 R15。

### M1 基础骨架：证明技术形态能成立

**状态：accepted（2026-11-07，Lead 独立验证；带 2 项非阻塞遗留，见本节末）**

**目标**：在不接真实模型、不做记忆的前提下，跑通"浏览器 ↔ Go 单体 ↔ SQLite ↔ 事件通道"的最小闭环（M1 实际交付为 WS；SSE 为等价备选），并让三栏有可靠的壳；**同时把事件日志、三屏障检查点、token 单一计量三个地基做成可验证的最小实现**（M2/M5 依赖它们）。

**设计依据**：[14](14-总体设计-v1.md) §7.1/§7.2/**§5.12（视觉与主题）**；[10](10-设计对话记录.md) §2/§3/§11/§29；[16](16-架构对照表.md) D5/D6/D14/D17；[13](13-交互协议-候选方案.md) §12（I1/I5 的基础设施）。

**包含**
1. Go 单体：`serve` 子命令、默认 127.0.0.1、静态资源内嵌、健康检查、配置（端口/数据目录/模型占位）、结构化日志。
2. SQLite：最小表（会话、消息、事件日志、单实例锁）；迁移；WAL；单写者写入口；消息**先落库再推送**。
3. **事件溯源日志（新增地基）**：append-only typed events 作为唯一真相；**"模型可见 ⟺ 已记录"**；surface 视图支持 `replace{startSeq,endSeq}` 区间替换（撤回/裁剪/压缩统一为"改视图不改日志"）；projection 纯函数、可重放；每个流恰好一个终止事件 + usage 随结束事件。
4. **三屏障 fail-closed 检查点（新增地基）**：请求前 / 顶层工具副作用前 / 每步前各写检查点；**检查点写失败则不继续执行**；失败/取消三态（unknown / not-started / aborted-before-dispatch）；恢复先拿写所有权（单实例锁已具备）。
5. **token 单一计量（新增地基）**：provider usage 优先，缺失时才用日志 fold/估算兜底；压缩、预算、UI、评测共用**同一个数**；计量服务本身单写者、可重放对账。
6. 事件通道：提交 + WS 推送（M1 实际交付；SSE 为等价备选）；事件 id/序号；断线重连续接；客户端消息幂等 id（重复提交不重复落库）。
7. React 三栏空壳：左树（单根）、中对话（消息流、流式光标、连接状态、空状态）、右长任务占位；窄屏最低可用的折叠策略可留到 M7，但布局不能崩。**视觉（用户 2026-11-06 追加）**：交付 **`theme-light-tech`（浅色科技风/未来感）**+ **语义 token 架构**（颜色/字体/间距/圆角/阴影/动效）；组件只消费 token、**禁止硬编码颜色**；`data-theme` 属性与 CSS 变量注入预留（M1 不做切换 UI）。
8. Mock 秘书：确定性回显 + 人为的三速节奏（S0/S1/S2 占位），只用于证明链路，不是最终交互。
9. 单实例保护：第二个进程启动被文件锁拒绝（避免 SQLite 双写）。
10. 本机诊断：诊断接口或日志输出版本、数据目录、队列深度、SSE 订阅数、事件序号、token 计量。
11. 构建与测试脚本：`go vet`、`go test ./...`（环境支持时加 `-race`）、前端构建、一键启动；E0 骨架所需的确定性 grader 接口可先并行搭。

**不包含**：真实模型、记忆、会话树、长任务、通知、归档；E0 的完整评测集（只先搭接口与少量确定性 grader）。

**可演示成果**：浏览器里有一个能启动、能发消息、刷新/重启不丢、断线能续的三栏空壳；**界面为浅色科技风（`theme-light-tech`，token 化、无硬编码颜色）**；诊断里能看到**事件序号、检查点、token 用量**；单二进制可拷走运行。

**演示脚本（你亲手做）**
1. 在干净数据目录启动服务，浏览器打开 `http://127.0.0.1:8787`；预期：三栏空壳 + 空状态说明 + 连接状态"已连接"。
2. 在中栏发一条消息；预期：1 秒内出现"收到"类信号（S0），随后出现流式文字；刷新页面消息仍在。

5. 再启动一个实例（同数据目录）；预期：第二个实例启动失败并给出明确原因（单实例锁）。

### M2 对话核心：从"聊天"到"可打断、可纠正的连续对话"

**状态：accepted（2026-11-07，Lead 独立验证；带 2 条已知限制，见本节末）** — M1 accepted 前置已满足；E1/E3/E2 设计稿 v0.x 已完成，实现按对齐口径进行。

**目标**：接真实模型，跑通连续步进、三速响应、撤回重答、纠偏/调整、歧义确认与自主阈值；让"不排队"成为可验证的手感，而不是口号。

**设计依据**：[13](13-交互协议-候选方案.md) §3/§5/§7/§8/§9/§10/§12/§13；[14](14-总体设计-v1.md) §4/§5.5/§8；[10](10-设计对话记录.md) §7/§13/§15/§29；[16](16-架构对照表.md) D2/D3/D5/D7/D12/D13。

**包含**
1. 模型适配器：流式输出、超时、失败重试/熔断、provider 配置可切换；mock 模式保留（测试/离线演示用）。换模型不改协议语义。
2. 连续步进与合并：静默窗口/硬上限（默认 300ms/800ms，可配）；窗口只影响 S1/慢判，不影响 S0，也不拦撤回。
3. 四类消息 + 停止：Ack/Refine/Correct/NewTask 两阶段判定（快判规则 → 慢判模型）；Stop 单独处理；分类歧义按 13 §5.4 兜底。
4. 三速响应与心跳：S0/S1/S2；执行/等待期心跳；禁止"排队/请稍候"等阻塞文案；D1/D2/D3/D4 最小降级。
5. 撤回：流式中被打断 → 停止 → 标 `retracted` → 对话里只显示"已撤回"、不显示内容 → 基于最新消息重答；已完成消息不撤回（D10）；重答前一句说明。
6. 调整/重做：Correct 与改变性 Refine 的区分；目标/关键约束变 → 重做，细节变 → 调整；先写中断点再改计划；一句话说明用了哪种。
7. 歧义先确认 + 自主阈值：真歧义 ≤1 个问题（选项 + 建议 + 解释）；琐碎/可逆/低风险自己定并说明；不可逆/对外/花钱/改已确认约束 → 先问；不猜。
8. 中断点最小版：被打断/换方式时记录"做到哪、为什么改、新方案、从哪继续"，先落运行态存储；M3 接记忆作用域（只换存储/接口，不改语义）；对话里给一句摘要。
9. 协议回放测试骨架：脚本化模型（分片输出、延迟、报错）+ 可注入时钟 + 事件断言；覆盖 13 §8.3 矩阵。
10. 崩溃/重启口径：进行中的回复标记"中断/已撤回"，不把半截当已说；原文留 episode（M3 前用事件日志留档）。
11. **steer / queue 两原语（新增）**：steer 并入当前轮（可立即合流/重答，不新开轮），queue 排到下一轮（不打断当前）；两者都不丢、都不让用户感知"队列"；用户消息先落事件日志再进入对应通道。
12. **六步权限求值顺序（新增，判定接口）**：hook → deny → ask → mode → allow → fallback；hook 的 allow 不能跳过 deny/ask；bypass 下 deny 仍生效；前序自动批准的调用不经过兜底回调（Go 把"权限检查"与"批准回调"拆开）；无自动批准白名单；全程 fail-closed。M2 先做判定矩阵 + mock 工具，M5 落真实执行层。
13. **plan 模式对子代理生效（新增）**：父会话为 plan 时，子代理即使声明 `acceptEdits` 仍以 plan 运行，不能通过委派绕过人工审阅；M2 用 mock 子代理验证规则，M5 接真实子代理。
14. **持久规则每轮重注入（新增）**：AGENTS.md 式项目规则发现链（向上找项目根 → 向下拼装 → 就近覆盖 → 字节上限）；**每轮重注入、与压缩解耦**；规则变更下一轮生效；只放项目约定，不把人格/偏好层塞进来（偏好层仍暂缓）。
15. **撤回与事件日志联动（新增）**：撤回是 surface 区间替换（`replace{startSeq,endSeq}`），不是删日志；模型可见内容不含被撤文本，原文/审计保留；重答紧接，重放结果一致。

**不包含**：长期记忆写回、会话树、真正的执行实例/长任务（用受控 mock Acting 验证 S2 心跳即可）、真实工具权限执行（M5）、真实子代理（M5）、站内通知。

**可演示成果**：你能亲手制造一次"说错 → 撤回 → 重答"，看到一个歧义问题、一次自主决定、steer 与 queue 的行为差异，以及 plan 模式对子代理的约束。

**演示脚本（你亲手做）**
1. 问一个需要展开的问题（示例："帮我把下周的待办排一下，顺便写个周计划"）；在流式输出中发"不对，先别排日程，先把清单按优先级列出来"；预期：旧回复立刻变"已撤回"（看不到被撤内容），秘书一句"按你最新的说法重来"，重答中体现"先列清单、不排日程"；事件日志/审计里能查到这次撤回记录，模型可见内容不含被撤文本。
2. 先发一句真歧义指令（示例："把那个提醒关掉"——候选可以是"周三复盘会提醒"或"每月报销提醒"）：预期只问 1 个问题、给 2–3 选项 + 建议、回答前不执行不可逆动作；再发一件琐碎且可逆的事（示例："把这条待办改短"）：预期直接做 + 一句说明、不追问。
3. 在流式输出中发一条补充（steer，示例："补充：只列工作项"）：预期并入当前轮、不新开轮；当前回复结束后再发一条（queue，示例："另外把出差准备加上"）：预期排到下一轮、不打断当前回复，且不出现"排队/稍候"。
4. 在 AGENTS.md 里加一条项目规则（示例："周报先列待办，再写摘要"）；下一轮让它做周报：预期规则生效；再让它进入 plan 模式只出计划，并尝试派一个 mock 子代理去改文件：预期子代理仍只出计划、不写文件（plan 对子代理生效）。
5. 流式中说"停"；预期：立即停 + 撤回标记 + 回到可输入；随后说"继续"，预期：按中断点继续（至少能看到"从哪继续"的可读记录）。

### M3 记忆地基：让"记忆是唯一真相"可验证

**状态：accepted（2026-11-07，Lead 独立验证；带 3 条已知限制，见本节末）** — M2 accepted 前置已满足；E4（记忆 + RAG）设计稿 v0.1 已完成，实现按对齐口径进行。

**目标**：把记忆做成**结构化条目 + 作用域 + 版本/溯源 + 候选单写者合并**，并给用户一个**只读**记忆页；证明"改记忆只能通过对话"。

**设计依据**：[12](12-记忆模型-候选稿.md) §1/§2/§3/§5/§7/§10；[14](14-总体设计-v1.md) §3/§5.6；[10](10-设计对话记录.md) §5/§18/§29；[16](16-架构对照表.md) D8/D9。

**包含**
1. 条目 schema：kind（本期 8 类，不含 habit）、scope、content、provenance、confidence、status、validFrom/validUntil、rev；旧版本全留（ADD-only 语义）。
2. 三层最小实现：常驻块/pin（渲染层）、可检索条目、**不可变 episode**（消息/工具/产物指针）；episode 从 M1 的事件日志派生/索引，**不另写第二份历史**（16 §3.3 不借双份历史）；条目必须能指回证据，指不回去的只能标 `agent_inferred`。
3. 作用域：global/domain/task/instance；本期至少 global/task 可写，domain 可用种子数据；跨域只读引用最小实现。
4. 候选写入 + 记忆管理器单写者：schema/权限/去重/置信度/敏感/baseVersion 校验；按 kind 的合并规则；冲突 → `disputed` + `open_question`，不静默覆盖；回执（merged/rejected/pending/disputed）。
5. 读侧组装：常驻块 + pin + 检索（结构化过滤 + 全文检索 + importance/recency），预算报告（为什么某条没进来可诊断）；读实时、写版本化。
6. 通过对话改记忆：用户说"记住/改成/忘掉" → 秘书提交候选 → 新版本；旧版本保留；记忆页**没有编辑控件**。
7. 记忆页（只读）：列表 + 作用域 + 来源 + 时间 + status（含 disputed）+ 搜索/筛选；"跟秘书说"入口。
8. 审计/诊断：按条目看版本链、按 episode 看来源；本机诊断接口/命令。
9. 测试：合并规则表驱动、并发提交、污染回放（低来源覆盖高权威）、敏感信息不外溢。

**不包含**：偏好/习惯/每日复盘/偏好页（人格层，暂缓）；记忆直接编辑；向量检索作为可选增强，不作为验收硬门槛；多用户共享记忆。

**可演示成果**：你能在只读记忆页看到一条记忆条目的作用域/来源/时间；能看到一条记录被改成新版本而旧版仍在；能看到两条冲突记忆并存并标 `disputed`。

### M4 会话树与主窗口：消息归属、聚合视图、标签跳转

**状态：accepted（2026-11-07，Lead 独立验证）** — M3 accepted 前置已满足；Q3 复合消息口径按 §8.2 建议默认（A）实现并验收。

**目标**：让"一个主窗口 + 会话树 + 每条消息归属唯一 + 每节点两种显示"成立；证明会话只是视图/组织层，不承载权限与状态。

**设计依据**：[10](10-设计对话记录.md) §17/§19/§20/§21/§23；[14](14-总体设计-v1.md) §5.1/§5.1b；[13](13-交互协议-候选方案.md) §11.7。

**包含**
1. 会话表：id/parentId/name/status/时间；根会话唯一；**V1 固定结构：不可拆分/合并/移动**。
2. 消息归属：每条消息必须带且只带 1 个 `sessionId`；归属由秘书决定：显式进入子会话时归属当前；在上层发言按内容路由；秘书可自建子会话（并给一句提示）。
3. 主窗口 = 根节点聚合视图；每节点两种显示：**仅本会话** / **本会话 + 所有递归子会话（按时间展开）**；递归一致。
4. 显示细节：双方消息按时间排；深层消息带归属会话标签 + 轻缩进；稳定排序（时间 + 稳定 tie-break）。
5. 标签跳转：点消息上的归属标签 → 切到该会话查看；只影响显示，不写记忆、不中断执行、不改归属。
6. 改名：纯显示、无语义影响；没有拆分/合并/移动入口。
7. 左树最小状态：名称、进行中/空闲、一行摘要；未读标记可作为增强，不进硬验收。

### M5 长任务与产物：从"会聊"到"会干活"

**状态：accepted（2026-11-07，Lead 独立验证）** — M4 accepted 前置已满足；E5（Planner + 长程）设计稿 v0.1、E1/E2 相关接口已完成并验收。

**目标**：把执行任务接到会话里：阶段/步骤可见、可取消/重试、有产物预览下载；对话与执行轨迹分离，不互相淹没。

**设计依据**：[14](14-总体设计-v1.md) §5.2/§5.3/§5.4/§5.9；[13](13-交互协议-候选方案.md) §9/§11.2–§11.5；[10](10-设计对话记录.md) §13/§15/§22/§24/§29；[16](16-架构对照表.md) D12/D15/D21。

**包含**
1. 任务/阶段/步骤：任务属于会话/子会话（**会话不进任务列表**）；阶段 3–7 个（建议值）；步骤状态：未开始/进行中/已完成/失败/阻塞；阶段 = 有完成标准的检查点。
2. 右栏：执行中 + 已完成任务列表；内联展开阶段/步骤概要；选中看详情；细节可单独开窗（浏览器新窗口）；排序/过滤最小可用。
3. 执行引擎：秘书派发 → 专家实例（先 mock worker 跑通，再接一个真实 worker）；执行进度经 SSE；心跳；取消（可逆动作停、不可逆动作报告"已发生"）；重试/续跑按 resumePoint。
4. 中断点与阶段小结：阶段切换/打断/失败/重试时写；右栏可见；恢复按 resumePoint；旧尝试保留（不删）。
5. 产物：登记、存储、元数据；预览（文本/Markdown/JSON/图片/PDF；Office 先下载，预览视成本补，见 §2.5）；下载（本机访问校验）；对话里只给摘要 + 指针。
6. 执行轨迹：独立于对话的第二份流，默认折叠，可展开/单独窗；不进入对话正文。
7. 结果与记忆：任务结束提交候选（走 M3 单写者路径），不自动写公共层；不向父会话自动推送（按需查看/取用）。
8. 测试：worker 失败/超时/半途取消/重试；产物路径安全；执行轨迹不串入对话。
9. **权限执行层（新增，按六步顺序落地）**：真实工具/文件/命令执行前走 hook → deny → ask → mode → allow → fallback；fail-closed；hook 的 allow 不跳 deny/ask；bypass 下 deny 仍生效；无自动批准白名单；V1 只保留 ask/act/deny 三态，审计每次决策；受保护路径/工作区外默认拒绝或要求审批。
10. **子代理输出指令形态中和（新增）**：父读子代理最终消息前，对控制标签模仿、行首轮次标记做转义（**不删原文**），命中加 `[harness:]` 标记；不可信内容不得直接触发写记忆/写文件；中和记录可在执行轨迹查看。

**不包含**：归档/跨会话取用（M6）；站内提示最终形态（M7，M5 只做右栏状态）；交付/验收状态机（已取消）；自动向上同步；完整 OS 级沙箱（V1 先策略层 + 路径白名单 + 受保护路径，见 16 D11）。

**可演示成果**：你能在右栏看到分阶段任务和步骤进度；执行中取消/重试并看到中断点；越界写操作被拒绝/要求审批；子代理伪造标签被中和；任务完成后预览/下载产物。

### M6 归档与跨会话取用：生命周期收尾 + 去掉交付机制

**状态：accepted（2026-11-07，Lead 独立验证；带 1 条已知限制，见本节末）** — M5 accepted 前置已满足；E5 设计稿已完成。

**目标**：让会话可以"收起来"而不丢状态；让父会话能按需读取子会话内容/文件；同时确认"交付/handoff/验收状态机"已彻底移除。

**设计依据**：[10](10-设计对话记录.md) §22/§24/§25；[13](13-交互协议-候选方案.md) §11.5/§11.8；[14](14-总体设计-v1.md) §5.1c（按取消交付后的口径修订）。

**包含**
1. 归档/取消归档：仅手动；归档后**只读**（服务端拒绝发消息/新建任务/执行）；默认树隐藏归档会话，可"显示已归档"；取消归档恢复正常；归档不删除任何消息/记忆/任务/产物。
2. 空闲状态：无活动达阈值（默认 7 天，可配）显示"空闲"，**不自动关闭/归档**；恢复活动即回"进行中"。
3. 运行中归档守卫：有运行中任务时，默认要求先停止或显式确认；避免"归档后后台还在跑"的自相矛盾。
4. 跨会话按需取用：在父会话对秘书说"去 X 子会话看看，把相关文件拿出来"；秘书读取源会话消息/产物，摘要/转述/预览/下载；**不复制文件、不自动推送**；审计记录读取来源。
5. 移除交付：API/DB/UI 不再有 delivery/handoff/待验收/接受/打回等状态与按钮；验收/接受/改需求通过对话；阶段"完成标准"保留，但不产生状态机。
6. 归档在聚合视图中的口径：父会话聚合默认**包含**已归档子会话的消息（标签上标"已归档"），可过滤；归档不影响消息归属。
7. 权限与安全：归档只读服务端强制；跨会话读取不越出本地数据目录；产物按 ID 访问，不接受任意路径。

**不包含**：向上同步摘要（P1）、拆分/合并/移动（P1）、标签（P1）、自动归档/自动关闭、跨用户。

**可演示成果**：你能归档一个会话并以只读方式查看；从父会话让秘书取来子会话的报告；取消归档后一切恢复；全站找不到"交付/待验收"入口。

## 4. 依赖与顺序

### 4.1 依赖图（串行推荐）

```
设计线（不占 M 序号）：
  E0 评测(17) ──横切──► M1/M2
  SpecCore(18) ──基础──► E1–E5（Spec/Plan/Task）
  E1 Agent Loop(19) ──► M2 前
  E2 上下文(20) ──► M2/M3 前
  E3 提示词(21) ──► M2 前
  E4 记忆+RAG(22) ──► M3 前
  E5 Planner+长程(23) ──► M5 前

实现线：
G0 设计确认
  └─ G1 路线图确认
       └─ M1 骨架（含事件日志/检查点/token 计量）
            └─ M2 对话核心（含 steer/queue、六步权限判定、plan 子代理、规则重注入）
                 ├─ M3 记忆地基 ─┐
                 └─ M4 会话树 ───┴─ M5 长任务与产物（含权限执行、输出中和）
                                      └─ M6 归档与跨会话取用
                                           └─ M7 打磨与端到端验收
```

- **硬串行**：M1→M2；M4→M5→M6；M6→M7。
- **软依赖**：M3 对 M2 的 ContextProvider/记忆读写接口有集成需求；M5 对 M3 的 progress/checkpoint 有集成需求。接口先冻结，实现可后接。
- **可并行**：**E0 与 M1/M2 并行**（从 M1 起积累基线，M2 起进回归门禁）；M3 与 M4（在 M2 之后）；M5 内部"任务引擎"与"右栏 UI"可拆两条线；测试基础设施从 M1 起持续建设，不算独立里程碑。
- **设计门**：E1/E3 在 M2 相关实现前评审；E2 在 M2 上下文/M3 前；E4 在 M3 前；E5 在 M5 前。设计未过先做实现 = 违反门禁。
- **不建议并行**：M1 与 M2；M5 与 M6；M7 与其他（M7 需要全量结果）；E1–E5 设计稿已完成，评审顺序按 E0→E1→E2→E3→E4→E5，避免后一项推翻前一项。

### 4.2 并行时的边界（防止互相踩）

| 并行对 | 谁拥有什么 | 必须冻结的接口 | 集成验收 |
|---|---|---|---|
| **E0 ∥ M1/M2** | E0：评测 harness/golden set/报告/门禁；M1/M2：事件日志、token 计量、对话实现 | 事件日志与 token 计量的**只读**接口；评测 case 的输入/输出契约 | E0 能基于 M1/M2 数据产出基线；不得反向改业务数据 |
| M3 ∥ M4 | M3：记忆表/条目/候选/记忆页；M4：会话/消息/树/聚合/标签跳转 | ContextProvider（读记忆）、MemoryWriter（候选提交）、消息 `sessionId` 契约 | 在 M4 会话里发消息 → M3 记忆可写/可读，且归属不乱 |
| M5 内 UI ∥ 引擎 | UI：右栏列表/详情/独立窗；引擎：任务/阶段/执行/取消/重试 | 任务/阶段/步骤事件契约（SSE 事件类型与字段） | 同一任务在 UI 的进度与引擎状态一致 |
| 测试 ∥ 功能 | 功能线不改测试数据格式 | 事件/API 契约测试 | 每里程碑 gate 必须绿 |

### 4.3 顺序的两种变体

- **推荐（单线程/单人）**：M1→M2→M3→M4→M5→M6→M7。理由：M3 是记忆地基，先稳再做树；M4 的聚合需要消息归属稳定。
- **E0 不许后补**：E0 与 M1/M2 并行，M2 起成为固定 gate；"最后再补评测"会失去基线，等于没有评测。
- **设计线先于实现**：E1/E3 在 M2 前、E2 在 M2/M3 前、E4 在 M3 前、E5 在 M5 前；设计评审可与 M1 并行，但不能晚于对应实现。
- **并行（多智能体/多人）**：M1→M2→(M3 ∥ M4)→M5→M6→M7。前提是 §4.2 的接口先冻结；否则集成返工可能超过并行收益。
- **若你更看重"记忆页先可见"**：可把 M3 提到 M2 之后、与 M2 后半并行；代价是 M2 的上下文接口要提前冻结，且 M2 验收要包含"记忆接入后不回归"。
- **若你更看重"会话树先可见"**：可 M4 先于 M3；代价是记忆接入时可能改动上下文组装，需要在 M4 验收里增加"后续可接记忆"的兼容检查。
- **不做**：为了赶进度把 M5/M6 合并（归档守卫、跨会话取用、任务/产物互相依赖，合并会掩盖边界问题）。

## 5. 风险与应对

> 只列**具体风险**；每条给"早期信号"，避免事后才知道。等级为相对判断，不代表工期。

### 5.1 高风险（最可能让 V1 失败）

**R1 交互语义复杂度：误撤回 / 过度确认 / 该停不停**

- 具体表现：把普通补充判成 Correct 导致频繁撤回；一次问 3 个问题；用户说"不对"但旧回复已说完；流式中停不下来；"排队"文案漏出。
- 早期信号：误撤回率（回放集）>5%；单轮问题数 >1；用户重复同一更正 ≥2 次；t_retract p95 >200ms；出现"稍候/排队"。
- 应对：快判保守 + 慢判纠正；问题预算 ≤1；回放集覆盖 §8.3 矩阵；S0 与模型解耦；撤回在分段边界可抢占；提供"保守模式"开关。
- 止损：若误撤回持续超阈值，V1 降级为"只对明确停止/明确更正立即撤，其余在段边界处理"，并把差异写进已知限制；**不放宽"已完成不撤回"**。

**R2 记忆污染：错误记忆变成全体事实**

- 具体表现：低来源推断覆盖用户确认；无证据条目进入高权威位；冲突被静默选一条；敏感信息出任务作用域；回滚不彻底。
- 早期信号：`disputed` 异常增多；用户频繁纠正记忆；active 条目中无 episode 证据比例上升；同一事实多版本互相矛盾。
- 应对：候选 + 单写者；来源分级/置信度上限；证据强制；冲突并存 + open_question；敏感检查；按作者/时间窗批量撤销；污染回放测试进 gate。
- 止损：一键关闭本域/领域自动合并（全部人审）；冻结写入通道；按 episode 批量 retract + 下游 needs_review；保留旧版本以便恢复。

**R3 长历史性能：主窗口/聚合越用越慢**

- 具体表现：消息上万后主窗口首屏 >2s；切换会话卡；"含子会话"查询慢；记忆页/任务列表滚动掉帧。
- 早期信号：M4 聚合查询 p95 >100ms；M7 seed 首屏 >2s；SQLite 慢查询日志出现全表扫描；前端长列表 DOM 节点数暴涨。
- 应对：M4 就建 `(session_id, created_at)` 索引、递归子树查询、分页/游标；前端虚拟列表；默认只加载最新窗口 + "加载更多"；归档会话默认不做热查询。
- 止损：加"限制首屏条数"配置；聚合改为按需懒加载；仍不达标则把"含全部子会话"改为显式展开（不改变语义，只改默认性能策略）。

**R4 模型延迟/不可复现：SLA 与测试都不稳**

- 具体表现：S0 等模型导致 >1s；t_retract 被模型阻塞；同一回放两次结果不同；真实模型与 mock 行为差异大；provider 超时/限流。
- 早期信号：S0 p95 >300ms；S1 p95 >4s；同一场景多次跑分类结果不一致；测试偶发失败。
- 应对：S0 走确定性路径；模型适配器统一超时/熔断；流式分段；mock + 脚本化模型用于 CI；真实模型只做冒烟与人工验收；SLA 区分"模型时延"与"协议时延"。
- 止损：provider 不稳定时 demo 用 mock，但验收报告必须注明；不把模型时延算进协议硬承诺；必要时降级为"先 S0 + 模板计划，模型恢复后补"。

### 5.2 中风险（不致命，但会拖慢或留坑）

**R5 单机 SQLite 并发/文件锁**

- 表现：`database is locked`、写入丢失、第二个实例同时跑、备份时读到半状态。
- 信号：重试日志增多；并发测试偶发失败；数据目录出现多个进程。
- 应对：单实例文件锁；单写者串行；WAL + busy_timeout；事务短、无长读事务；备份用 SQLite backup/停服拷贝；并发测试进 gate（环境支持时加 `-race`）。
- 止损：写队列积压时返回"忙"而不是无限重试；禁止绕过单写者直写 DB。

**R6 撤销与回滚不彻底**

- 表现：撤回后原文仍出现在对话/检索；记忆回滚留下派生条目未标 needs_review；外部动作被当成可撤销。
- 信号：撤回用例断言失败；审计中 retracted 仍可检索；用户看到"撤回了但还在"。
- 应对：文本撤回/记忆失效/外部动作三线分开；撤回只作用于对话视图；记忆回滚 = 新版本；派生反查；回放测试。
- 止损：对已发生的外部动作只报告不假装撤销；无法回滚的写路径默认禁用。

**R7 设计漂移/范围蠕变**

- 表现：实现中顺手加入标签、偏好、交付、向上同步；P1 功能混入 M4/M5；UI 新增"接受/打回"按钮。
- 信号：代码/DB 出现 §7 清单关键词；验收脚本外的新功能；"既然都做了"式追加。
- 应对：G0/G1 冻结；§7 清单扫描进每个 gate；新需求先回设计文档；路线图版本变更记录。
- 止损：已混入的 P1 功能默认关闭/隐藏，迁到 P1 backlog，不阻塞 V1。

**R8 跨会话取用与产物的安全/一致性**

- 表现：模型/用户给出 `../` 路径读到数据目录外；产物被隐式复制/同步到父会话；归档后仍能写。
- 信号：路径校验测试失败；父会话出现重复文件；跨会话读审计缺失。
- 应对：产物按不透明 ID 访问；路径归一化 + 根目录限制；只读引用、不复制；审计记录；服务端强制归档只读。
- 止损：关闭跨会话文件读取，只保留摘要/消息级取用；先修安全再放功能。

**R9 归档与运行中任务冲突**

- 表现：归档后后台仍在执行/写库；取消归档后状态错乱；聚合视图包含已归档消息但标签不标。
- 信号：归档时仍有 active task；写请求未拒绝；树与聚合不一致。
- 应对：归档前置检查 + 显式确认；服务端拒绝写入；聚合带归档标记；状态机测试。
- 止损：默认禁止归档运行中会话（必须先停），作为保守默认。

**R10 前端 JS 无类型导致契约漂移**

- 表现：事件字段改名前端不报错、页面空白；SSE 字段缺失；分页/排序边界错。
- 信号：前端 runtime error 增多；契约测试失败；mock 与真实 API 字段不一致。
- 应对：JS + JSDoc 标注关键契约；API 契约测试（golden JSON）；前端对未知事件容错；构建期做字段校验（可轻量）。
- 止损：以 API 契约为唯一真相；前端不自行推断字段；破坏性变更必须版本化。

**R11 会话树 UX 在深/多节点时失控**

- 表现：左侧树折叠/展开难用；深层缩进挤占对话；节点状态不刷新；标签跳转后迷失。
- 信号：用户找不到某个子会话；M4 演示中需要多次点击；树节点 >100 时卡。
- 应对：默认折叠非当前路径；状态摘要；面包屑/返回；树虚拟滚动；键盘可达（最低限）。
- 止损：V1 先保证"能找到 + 能回来"，美化/高级导航留 P1。

### 5.3 v1.2 新增机制风险（事件日志 / 检查点 / 权限 / 评测）

| # | 风险 | 具体表现 / 早期信号 | 应对 | 止损 |
|---|---|---|---|---|
| **R12** | **事件日志与视图漂移** | 模型看到未记录内容；区间替换后重放不一致；撤回后原文仍可见或日志被删。信号：E0 重放 diff、消息数对不上、审计查不到原文 | 单写通道；"模型可见 ⟺ 已记录"不变量测试；`replace` 只改 surface 不改日志；重放确定性测试 | 冻结撤回/压缩特性开关，退回全量视图；修好再开 |
| **R13** | **检查点 fail-open / 副作用重复** | 崩溃恢复后重复执行工具；检查点写失败但仍继续；三态结果错（unknown 被当成功）。信号：故障注入用例失败、恢复后重复扣费/重复写文件 | 三屏障 fail-closed；幂等键；unknown/not-started/aborted 三态；恢复先拿写所有权 | 恢复时禁用有副作用的工具，只报告"未知/已发生"；人工确认后再继续 |

| **R15** | **E0 评测自身不可信 / 过拟合** | golden set 越跑越高但真实使用退化；Δ 波动大；LLM judge 不稳定；case 泄漏给被测 agent。信号：3 次方差大、holdout 掉分、judge 版本变化导致翻转 | 确定性 grader 打底；holdout；judge 版本记录；默认 3 次；case 隐藏与隔离 | 不以 llm-only 作为硬门禁；人工复核；冻结 golden set 版本后重新校准 |
| **R16** | **token 计量多源不一致 / 成本失控** | UI 显示与 provider usage 不一致；压缩/预算各算各的；provider usage 缺失时估算偏差大。信号：对账差异 > 阈值、预算耗尽但 UI 显示正常 | 单一计量服务；provider usage 锚点 + 日志 fold 兜底；压缩/预算/UI 同源；对账测试 | 预算相关功能回退到 provider usage；关闭依赖估算的自动压缩 |
| **R17** | **持久规则（AGENTS.md）失效或膨胀** | 长对话/压缩后规则不再生效；规则文件过大挤占预算；规则冲突无提示。信号：第 N 轮规则不遵守、token 突增、规则加载日志异常 | 发现链/就近覆盖/字节上限；每轮重注入、与压缩解耦；规则版本与生效范围可见 | 限制规则来源与大小；诊断页展示"本轮实际加载的规则"；异常时回退到项目根规则 |
| **R18** | **子代理输出注入未中和** | 子代理文本伪造 `<system-reminder>`/轮次标记，父级被劫持；不可信内容直接触发写记忆/写文件。信号：注入回放用例未命中、对话里出现可疑控制标签 | 指令形态中和（转义不删原文 + `[harness:]`）；不可信内容写记忆/文件走硬策略；执行轨迹可见 | 从父上下文丢弃未中和的子代理输出；人工复核后再纳入 |

> R12–R14 属**正确性/安全**风险，优先级高于功能进度；相关用例不通过不得进入下一里程碑。

### 5.4 风险排序（按"会不会毁掉 V1"）

1. R1 交互语义（用户每天都能感知）
2. R2 记忆污染（会毁掉信任，且难发现）
3. R14 权限绕过（安全边界，错一次就不可信）
4. R12/R13 事件日志/检查点（正确性与恢复，错了会丢/重复动作）
5. R3 长历史性能（越用越差，最后不可用）
6. R15 评测不可信（会让人误以为"变好了"）
7. R4 模型延迟/不可复现（影响验收可信度）
8. R5–R11、R16–R18（工程与体验坑，逐个 gate 消化）

## 6. 测试策略

### 6.1 分层

| 层 | 测什么 | 工具/方式 | 何时必须绿 |
|---|---|---|---|
| L1 Go 单元/属性 | 单写者、合并规则、聚合查询、状态机、归档守卫、路径安全 | `go test`（环境支持时加 `-race`）、表驱动 | 每个里程碑 |
| L2 API 契约 | REST 状态码/错误、SSE 事件序列、幂等、断线续接 | golden 事件 + 契约测试 | M1 起每个里程碑 |
| L3 协议回放 | 四类消息 × 状态矩阵、撤回/重答、歧义、中断点、SLA | 脚本化模型 + 可注入时钟 + 事件断言 | M2 起 |
| L4 前端 smoke | 三栏渲染、关键交互、错误/空态、无 TS | 组件测试 + 构建 + mock API | 每个里程碑 |
| L5 E2E 浏览器 | 用户脚本自动化、跨页面（树/记忆/任务/产物/归档） | Playwright 优先；环境不允许则 API 级 E2E + 人工 | M4 起，M7 全量 |
| L6 性能/soak | 长历史、聚合、内存/连接泄漏 | seed 数据 + 压测 + 30 分钟 soak | M7（M4 先做正确性基线） |
| **L7 评测/回归（E0）** | WITH/W/OUT/Δ、六种 grader、grader 排除、golden set、Δ 回归门禁 | 评测 harness：隔离 case + 默认 3 次 + holdout + JSON 报告 | **M2 起固定 gate；M7 全量** |

**原则**：真实模型不进 CI；CI 用 mock/脚本化模型保证确定性；真实模型只在人工冒烟与验收时使用，并记录版本/时延。

### 6.2 每个里程碑的测试门禁

| 里程碑 | 必须通过 |
|---|---|
| **E0** | 评测 harness 自身通过：golden set 可复现、默认 3 次、grader 排除生效、Δ 门禁可阻断；M1/M2 指标有基线 |
| M1 | L1 + L2 + 事件日志/replay + 三屏障检查点故障注入 + token 计量对账 + 前端构建 + 并发/单实例测试 |
| M2 | L1 + L2 + L3（矩阵/撤回/歧义/中断点）+ steer/queue + 六步权限矩阵 + plan 子代理 + AGENTS.md 重注入 + 真实模型冒烟 + **E0（L7）** |
| M3 | L1（合并/权限/冲突/回滚/污染）+ L2 + 记忆页 smoke + **E0（记忆相关 case）** |
| M4 | L1（归属/聚合/递归）+ L2 + L4 + 切换不中断场景 + **E0 回归** |
| M5 | L1（任务状态/取消/重试/产物路径/权限执行/输出中和/plan 真实子代理）+ L2 + L5 长任务场景 + **E0 回归** |
| M6 | L1（归档只读/聚合归档/审计）+ L2 + L5 跨会话场景 + 交付移除扫描 + **E0 回归** |
| M7 | 全部 + L5 全量 + L6 + **L7 全量** + 备份恢复 + 文档核对 |

**每个 gate 的固定动作**：跑本里程碑脚本 + 跑全部旧里程碑脚本（回归）+ 更新验收记录；任何一项不通过不得开下一个（除非用户书面"有条件通过"）。

### 6.3 个人助理端到端验收场景（8 个，M7 全跑；E0 评测集另计）

> 验证场景 = **个人助理**（Q2 已确认：待办、提醒、信息整理、文档处理、本地日程清单）；**每日回顾属 P1，不在这些场景里**。
> 这 8 个场景验证"用户路径能走通"；E0 的 golden set 验证"改动有没有变好"，**两套不互相替代**。
> 新机制（事件日志/三屏障检查点/token 计量/steer-queue/六步权限/plan/规则重注入/输出中和）由 M1/M2/M5 的专项验收与 E0 覆盖，不塞进这 8 个用户场景。

| # | 场景（个人助理示例） | 覆盖里程碑 | 通过判据 |
|---|---|---|---|
| S1 | 冷启动 + 发"帮我建一个明天的待办清单" + 刷新/重启 + 断线重连 | M1 | 不丢/不重；S0 ≤1s |
| S2 | 流式中纠正（"先别排日程，先列清单"）→ 撤回 → 重答 | M2 | 只显示"已撤回"；重答体现新约束 |
| S3 | 歧义确认（"把那个提醒关掉"：复盘会/报销两个候选）+ 琐碎自决（待办改短） | M2 | ≤1 问带选项；琐碎不追问 |
| S4 | 记忆（"记住：每周三 15:00 固定复盘会"）只读 + 改走对话 + 冲突可见 + 回滚 | M3 | 无编辑控件；版本保留；disputed 可见 |
| S5 | 复合需求（整理下周日程 + 上季度报销归档）+ 消息归属 + 主窗口聚合 + 仅本/含子 + 标签跳转 + 改名 | M4 | 每条消息 1 归属；聚合无重复；改名无语义 |
| S6 | 长任务（会议记录 → 周报 + 待办）阶段/取消/重试/产物 | M5 | 状态真实；可恢复；产物可预览下载 |
| S7 | 归档"下周日程" + 取消归档 + 从"上季度报销"跨会话取清单/发票 | M6 | 服务端拒绝写；不复制文件；可恢复 |

**S5 特别注意**：主窗口不是归属容器；点标签跳转只切"当前会话"，不产生写入、不改变归属。
**S7 特别注意**：归档不等于关闭；取消归档后状态完整；跨会话取用是"读取/引用"，不是"复制/同步"。

### 6.4 测试数据与确定性

- 数据目录隔离：每个测试用临时目录/临时 DB；不碰真实用户数据。
- 种子生成器：生成 200 会话/20k 消息/50 任务/若干产物，固定随机种子，保证可复现。
- 脚本化模型：按场景返回固定分片、可注入延迟/超时/半截/报错。
- 时间：协议测试用可注入时钟，不 sleep 等真实秒数（除少量 SLA 冒烟）。
- 真实模型：记录 provider/模型版本/时延；不作为 CI 依赖。
- **评测数据（E0）**：golden set 版本化（suite 版本 + 冻结日期 + 变更记录）；case 对被测 agent 隐藏；dev/holdout 分离；报告记录 suite 版本、judge 版本、运行次数与方差。
- **权限数据**：mock 工具/文件系统 + 越界/受保护路径清单；权限矩阵每次 gate 全跑，不抽样。
